Burp-Labs Level 1 - 前端验证绕过与请求篡改

2026年10月2日 Burp-Labs Web安全 Burp Suite 逻辑漏洞

一、题目信息

  • 题目名称：Burp-Labs Level 1 (前端验证绕过与请求篡改)
  • 题目平台：Burp-Labs 本地靶场 (Docker 环境)
  • 题目类型：Web安全 / 逻辑漏洞 / HTTP代理拦截
  • 靶场链接：http://localhost:8080/burp-labs/level1/
  • 涉及工具：Burp Suite Community/Professional、Chrome浏览器、Firefox浏览器

二、解题步骤

1. 分析题目考什么

本题核心考察的是前端验证的不可信性以及HTTP 代理拦截工具（Burp Suite）的基础使用。在 Web 开发中，很多开发者出于方便，仅使用 JavaScript 在浏览器端（前端）对用户输入进行限制，例如限制输入框只能填数字，或者长度不能超过 10。但 HTTP 请求是客户端发出的，攻击者完全可以利用代理工具拦截这个请求，在发送给服务器之前修改数据，从而绕过这些限制。

2. 怎么想（破题思路）

  • 打开靶场页面，发现是一个“重置密码”或“修改金额”的表单。尝试在输入框输入超出限制的字符或负数，会被浏览器弹出的 JavaScript 警告框直接拦截。
  • 此时思考：既然前端 JavaScript 拦截了输入，那我们是不是可以不经过浏览器？
  • 使用 Burp Suite 开启代理拦截，重新在页面操作。此时数据包会被 Burp Suite 截停。由于此时数据还没有发送到服务器，前端 JS 代码根本无法执行校验。
  • 在 Burp Suite 中直接修改数据包中的参数值（例如改为负数、超大数值、或者特定管理员ID），然后把包放行（Forward）。
  • 观察服务器响应，如果服务器返回了成功修改的提示或页面，说明前端验证绕过成功。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Burp Suite 开启后浏览器无法访问网络

踩坑情况：配置了 Burp Suite 为代理后，浏览器打不开任何网页，报错 ERR_PROXY_CONNECTION_FAILED。

原因分析：浏览器代理插件（如 SwitchyOmega 或系统代理）将流量转发到 Burp Suite 的端口（如 8080），但 Burp Suite 没有开启监听，或者端口冲突，或者 HTTPS 证书未安装。

改进方式：检查 Burp Suite 的 Proxy -> Options，确保 127.0.0.1:8080 正在运行。随后，在浏览器访问 http://burpsuite，下载并安装 PortSwigger CA 证书到受信任的根证书颁发机构。

踩坑记录二：修改了请求包，但服务器依然返回“参数不合法”

踩坑情况：拦截并修改了请求体中的参数，但 Forward 转发后，页面依然报错。

原因分析：服务器端也做了校验，或者是数据包是 Content-Type: application/json，修改了 JSON 字符串但没有注意格式。也可能是修改了请求的 GET 参数，但请求用的是 POST。

改进方式：仔细检查 HTTP 请求的方法和参数位置，确保修改后的数据包格式正确。如果服务器二次校验，说明这道题的核心是利用参数污染或越权（如修改 ID 为 1）等其他逻辑漏洞，而非单纯的绕过前端。

详细实操步骤（HTTP数据包逐字解析）

第一步：Burp Suite 拦截请求

打开代理拦截（Intercept is on），在靶场页面点击提交按钮。Burp Suite 成功拦截到请求，原始请求如下：

POST /burp-labs/level1/reset.php HTTP/1.1
Host: localhost:8080
Content-Type: application/x-www-form-urlencoded
Content-Length: 24
Connection: close

username=test&new_password=123456

第二步：逐字翻译与修改

  • POST：HTTP请求方法，代表向指定资源提交数据进行处理请求。
  • /burp-labs/level1/reset.php：请求的路径，即处理逻辑的PHP文件。
  • HTTP/1.1：使用的HTTP协议版本。
  • Host: localhost:8080：请求的目标主机和端口。
  • Content-Type: application/x-www-form-urlencoded：说明请求体的数据以URL编码形式发送（键=值&键=值）。
  • Content-Length: 24：请求体的长度（字节数）。
  • username=test：第一个参数，用户名。若要越权修改管理员密码，可以将其改为 username=admin。
  • new_password=123456：第二个参数，新密码。

第三步：成功响应

修改参数为 username=admin&new_password=hacked 后，按 Forward 放行。此时浏览器收到服务器的响应：HTTP/1.1 200 OK，页面回显 Password reset successfully for admin!。这证明通过篡改请求体实现了越权修改管理员密码。

4. 怎么迁移（如何联想到其他领域）

  • 寄信与快递拦截：前端验证就像是你自己在家里写草稿，写完才贴邮票。代理拦截工具就是“快递站”，它在信件半路截停你，把信封里的内容换掉再寄给收件人。服务器就是收件人，他只看到最终寄来的信，不知道你在快递站换了内容。
  • 商业系统逻辑：在电商应用中，如果前端限制“购买数量不能超过 5 件”，通过 Burp Suite 修改请求包为 1000 件，如果后端没校验，就可造成经济损失。
  • 社会工程学与制度漏洞：前端验证就像公司门卫只检查外表（看工牌），攻击者通过“Burp Suite”（伪装成送外卖的）走进机房，跳过了门卫的检查。这是“防外不防内”的典型体现，真正的安全防线永远应该在服务器（核心资产所在处）构建。

三、名词大全与原理深度复盘

1. HTTP (HyperText Transfer Protocol) 超文本传输协议

万维网的基础协议，定义了浏览器（客户端）和服务器之间如何传递数据。它是“明文的”，意味着数据包在传输过程中可以被中间人（如 Burp Suite）看到和修改。

2. 代理 (Proxy) 与 中间人攻击 (MITM)

代理指客户端和服务器之间的中介。Burp Suite 作为本地代理，接管了浏览器的所有网络请求。由于浏览器信任了 Burp Suite 的 CA 证书，Burp Suite 就能解密 HTTPS 流量，充当中间人，实现对请求和响应的完全控制。

3. 前端验证 vs 后端验证

前端验证是指在浏览器（用户电脑）上执行的校验（通常用 JavaScript）。因为用户对自己电脑有完全控制权，所以这种验证极其容易被篡改或绕过。后端验证是在服务器端进行的校验，用户无法直接修改服务器代码，因此才是真正可靠的安全防线。

4. Payload (有效载荷)

在安全领域，Payload 指攻击者发送给目标系统的、带有攻击意图或篡改意图的实际数据（如上面的 username=admin）。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入的区别：SQL注入是利用后端代码拼接漏洞，让数据库执行恶意命令。Burp-Labs 第一题是利用代理工具修改合法的请求参数，属于“篡改数据”的逻辑漏洞。
  • 与 XSS 的区别：XSS 是攻击者构造恶意脚本，存储在服务器上，其他用户访问时触发执行（攻击其他用户）。而 Burp 截包是攻击者自己拦截自己的请求，修改后发送给服务器（攻击自己提交的数据）。
  • 通用性区别：SQL注入、XSS通常是因为代码过滤不严。而前端验证绕过是因为架构设计上的信任边界错误（错误地信任了客户端）。

2. 这种题目的出现原因（历史与底层）

在互联网早期，网页的主要功能是展示静态信息。后来随着 Web 2.0 的兴起，用户交互增多。为了减轻服务器压力，也为了提升用户体验（不用等待服务器响应就能提示密码格式错误），大量校验逻辑被放在了前端。

从计算机底层的网络模型（OSI 七层模型或 TCP/IP 四层模型）来看，HTTP 协议位于应用层，是明文传输的。在用户到服务器的网络链路上，只要安装了代理证书，数据包就可以被拦截和篡改。服务器无法区分发来的请求是经过用户正常表单验证的，还是由黑客用脚本直接构造的。这就导致了如果后端盲目信任前端传来的数据，系统就会产生漏洞。

3. 这种应用在实际中如何体现？

在实际的安全测试中，这是最常见的第一步测试。测试人员会尝试修改请求参数（如价格、数量、用户ID、角色权限），观察系统是否只依赖前端验证。很多金融、电商或后台管理系统的逻辑漏洞，都是这样被发现的。

4. 如何抽象理解概念（大白话）

把靶场比作一个“考场的安检”：

  • 前端验证：考场门口保安检查你准考证。他随便看一眼，只要是个准考证就让你进。
  • Burp Suite：你其实是一个“特工”，你在半路用高科技把准考证上的照片换成了别人的。
  • 服务器：考场的阅卷老师，他只看到交上来的卷子上写着“满分”，就直接给你满分了。老师不知道你半路换了准考证。如果老师（后端）严格核对卷子上的名字和系统里的名字，你的攻击就失效了。

做一道题，就要往自己脑子里装点东西。
