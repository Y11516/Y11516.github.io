2026年9月20日 Pikachu Web安全 目录遍历

一、题目信息

  • 题目名称：目录遍历（Directory Traversal）
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 目录遍历漏洞 / 路径穿越
  • 靶场链接：http://localhost:8080/vul/dir/dir_list.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是目录遍历漏洞（Directory Traversal）。后端提供了一个文本阅读功能，根据用户请求的文件名读取并显示内容。如果后端未对用户输入的路径进行严格过滤，攻击者就可以利用相对路径符号（../）跳出 Web 根目录，访问文件系统中的任意敏感文件。

2. 怎么想（破题思路）

页面提示“...

  • 点击页面上的文本链接（如 we're jarheads!），观察地址栏的变化，发现 URL 为 ?title=jarheads.php。
  • 参数名 title 控制着要读取的文件名，这表明后端存在路径拼接。
  • 尝试将参数值替换为系统敏感文件路径 /etc/passwd。但由于当前脚本在深层目录中，必须使用 ../ 向上跳转。
  • 构造最终的 Payload 并访问。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：路径穿越层数不正确导致读取失败

踩坑情况：输入 ../etc/passwd 或 ../../etc/passwd 时，页面提示文件不存在或读取失败。

原因分析：当前脚本位于 /vul/dir/dir_list.php。要到达系统根目录 /，需要向上跳转 2 层（回到 /），但在不同环境中目录深度可能不同，稳妥起见通常使用 4 层或 5 层。

改进方式：使用足够层数的穿越符号 ../../../../。由于 Linux 系统在到达根目录后，多余的 ../ 会被自动忽略，因此多写几层不会报错，反而能确保到达根目录。

终极解法：利用路径穿越读取系统文件

在浏览器地址栏输入以下 URL 并回车：

http://localhost:8080/vul/dir/dir_list.php?title=../../../../etc/passwd

代码逐个符号深度解析：

  • dir_list.php?：请求目录遍历漏洞所在的接口。
  • title=：后端用于接收文件路径的参数名。
  • ..：代表上一级目录（Parent Directory），是 Linux 系统中标准的路径层级表示法。
  • /：目录分隔符。
  • ../../../../：连续向上穿越 4 层目录。如果当前处于深层目录，足以使其跳出 Web 应用的根目录，直达文件系统根目录 /。
  • etc：存放 Linux 系统配置文件的目录。
  • passwd：存储用户账户信息的核心文件，通常所有用户都可读。

提交后，页面成功回显了系统用户列表（包含 root、daemon、bin 等），证明目录遍历攻击成功。

4. 怎么迁移（跨领域联想）

  • 结合文件下载漏洞：如果将目录遍历与之前的“不安全文件下载”结合（后端将读取的文件作为附件返回），则可以下载更深的系统文件，如数据库配置文件、SSH 密钥等。
  • 代码审计：在 PHP 代码审计中，如果看到使用了 readfile()、file_get_contents()、fopen()、include() 等函数，且参数拼接了用户输入，应立即怀疑存在目录遍历或文件包含漏洞。
  • Web 防御体系：防止目录遍历的核心方案是对用户输入进行白名单校验。例如，如果只允许读取球员名字，就在代码中写死 if (!in_array($name, ['kobe', 'allen'])) die('Not allowed');，或者使用 basename() 函数剥离路径信息，只保留文件名。

三、名词大全与原理深度复盘

1. 目录遍历（Directory Traversal）

一种 Web 安全漏洞，攻击者利用路径穿越字符访问 Web 服务器根目录之外的文件。它可以读取系统配置文件、源代码、密码文件等敏感信息，是危害极大的信息泄露漏洞。

2. 目录遍历与文件包含的区别

文件包含（LFI/RFI）是将文件的内容包含进 PHP 代码并执行，可能直接导致 RCE；目录遍历是将文件内容读取并显示在页面上，属于信息泄露（除非配合源码泄露导致审计漏洞）。

3. 为什么路径穿越符号会被忽略？

在 Linux 系统中，如果通过 ../../../../../../etc/passwd 访问，当路径已经到达根目录 / 时，多余的 ../ 会被内核直接忽略，最终等价于 /etc/passwd。因此，攻击者通常故意写多层穿越符，以应对不同的目录深度。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与文件包含相比：文件包含是“让服务器执行文件”（如把图片马当 PHP 解析）；目录遍历是“让服务器读出文件内容给你看”。一个重在执行，一个重在读取。
  • 与不安全文件下载相比：下载是把文件作为附件发给你，你是下载到本地打开；遍历是把文件内容直接显示在网页上，你只能在网页上浏览。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在实现“根据参数读取不同文件”的功能时，直接使用了字符串拼接（例如 readfile($_GET['title'])），没有对用户输入的 ../ 等特殊字符进行过滤或转义。

3. 这种应用在实际中如何体现？

在真实的渗透测试中，攻击者往往会利用目录遍历漏洞读取 /etc/shadow（密码哈希）、/proc/self/environ（环境变量）、或者应用的 config.php（数据库账号密码）。这通常是攻击者获取敏感信息、扩大战果的第一步。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作一个图书馆：

  • 正常功能：你告诉管理员“我要看《Kobe 传》”（title=jarheads.php），管理员去书架把书拿给你。
  • 目录遍历：你告诉管理员“我要看《../../../../etc/passwd》这本书”（用一个特殊的书名）。管理员没多想，直接走出图书馆，走到了地下室的水电表房，把整个图书馆的员工密码本翻出来给你看。这就是路径穿越的核心——你的“书名”可以操控管理员去图书馆外面的任何地方拿东西。
