DVWA-Medium-CSRF (跨站请求伪造)

2026年10月2日 DVWA Web安全 CSRF 跨站请求伪造

一、题目信息

  • 题目名称：DVWA Cross Site Request Forgery (CSRF) (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 逻辑漏洞 / 跨站请求伪造
  • 靶场链接：http://192.168.242.80/vulnerabilities/csrf/
  • 涉及工具：Google Chrome 浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是在 Medium 安全级别下绕过 CSRF 防御机制。与 Low 级别相比，Medium 级别增加了 Referer 头检查，要求请求来源必须包含当前服务器的域名（192.168.242.80）。如果 Referer 头不包含该域名，服务器会拒绝请求，提示 That request didn't look correct.。

2. 怎么想（破题思路）

  • 尝试 Low 级别的恶意链接，发现被拦截。
  • 分析 HTTP 请求头，发现增加了 Referer 字段的检查。
  • 由于 Referer 是由客户端（浏览器或代理）发送的，攻击者可以通过抓包工具（如 Burp Suite）手动伪造一个合法的 Referer。
  • 将 Referer 修改为包含 192.168.242.80 的地址，即可绕过检查。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：直接访问恶意链接导致失败

踩坑情况：在浏览器直接访问 http://192.168.242.80/vulnerabilities/csrf/?password_new=hacked&password_conf=hacked&Change=Change，页面报错 That request didn't look correct.。

原因分析：Medium 级别后端加入了 stripos($_SERVER['HTTP_REFERER'], $_SERVER['SERVER_NAME']) 检查，要求 Referer 头必须包含当前服务器名。浏览器直接访问该 URL 时，Referer 可能为空或是外部域名，因此被拦截。

改进方式：使用 Burp Suite 拦截修改密码请求，手动在请求头中添加或修改 Referer: http://192.168.242.80/vulnerabilities/csrf/，再放行请求。

详细实操步骤（Payload逐字解释）

第一步：正常拦截请求

在页面上输入任意密码，点击 Change，使用 Burp Suite 拦截该 POST 请求。

第二步：伪造 Referer 头

在拦截到的请求中，找到 Referer 字段。将其值修改为：

http://192.168.242.80/vulnerabilities/csrf/

如果没有 Referer 字段，可以手动添加一行。

第三步：放行请求

点击 Forward 放行请求，页面提示 Password Changed.，说明绕过成功。

4. 怎么迁移（跨领域联想）

  • 钓鱼攻击的演进：早期 CSRF 攻击只需诱导点击链接即可。现在很多系统加了 Referer 校验，攻击者就必须先找到一个允许发布内容（如论坛发帖）的地方，把恶意页面发布到该网站上，这样 Referer 就会自动带上合法的域名，从而绕过检查。
  • 防御的局限性：Referer 头是客户端发送的，本身并不可靠。攻击者完全可以通过代理工具伪造。因此，最有效的 CSRF 防御仍然是在请求中加入不可预测的 CSRF Token。

三、名词大全与原理深度复盘

1. Referer 头

HTTP 请求头的一部分，用于标识请求是从哪个页面链接过来的。在 CSRF 防御中，服务器通过检查 Referer 是否来自本站，来判断请求是否可信。

2. CSRF Token

一种防御 CSRF 的机制。服务器在页面中嵌入一个随机生成的 Token，每次提交请求都必须携带该 Token。由于攻击者无法预测这个随机值，也无法从跨站页面中读取它，因此无法构造有效的恶意请求。这是 High 级别采用的防御手段。

3. 同源策略 (Same-Origin Policy)

浏览器的安全机制。它限制了来自不同源的脚本对当前页面的读取权限，但**允许**发送跨站请求（比如 <img> 标签的 src 可以请求任何网站）。CSRF 正是利用了同源策略对“发送请求”的宽容。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何防护，构造恶意链接即可。Medium 级别引入了 Referer 检查，需要抓包伪造请求头才能绕过。
  • 与 High 级别的区别：High 级别引入了动态 Token，彻底杜绝了跨站请求伪造，除非结合 XSS 漏洞获取 Token。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于Web 应用没有对用户的“操作意图”进行二次验证。开发者默认只要请求携带了正确的 Cookie，就是用户本人发起的。Referer 校验虽然增加了一定的安全性，但它依赖于客户端的发送，因此可以被绕过。

3. 这种的应用

在护网演练中，CSRF 常用于攻击后台管理员。攻击者通过 XSS 漏洞或社工手段，让管理员在后台执行添加管理员账号、修改密码等操作，从而控制整个系统。

4. 如何抽象理解概念（大白话）

把 CSRF 比作“冒充老板签字”：

  • 你在一家公司上班，你的工牌（Cookie）可以打开公司的大门。
  • 攻击者捡到了你的工牌，或者趁你工牌挂在脖子上时，拿来刷了一下门禁，并在签字本上签了字。
  • 门卫（服务器）只认工牌和笔迹，不会问你“这是你本人签的吗？”
  • 于是，攻击者成功以你的名义做了事情。这就是 CSRF。

做一道题，就要往自己脑子里装点东西。
