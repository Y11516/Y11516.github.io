SQLi-Labs Less-16

2026年9月26日 SQLi-Labs Web安全 SQL注入 POST盲注

一、题目信息

  • 题目名称：SQLi-Labs Less-16 (POST - Blind- Boolian/Time Based - Double quotes)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / POST型布尔盲注 / 时间盲注
  • 靶场链接：http://localhost:8081/Less-16/（本地环境）
  • 涉及工具：Chrome浏览器 (F12开发者工具)、Python脚本（可选）

二、解题步骤

1. 分析题目考什么

本题的核心考点是基于双引号加括号闭合的 POST 型盲注。页面屏蔽了数据库报错信息，只能通过布尔状态（登录成功/失败）或时间延迟来判断条件真伪。闭合方式与 Less-12 类似，是双引号加括号 ")。

2. 怎么想（破题思路）

  • 测试 admin") and 1=1#（成功）和 admin") and 1=2#（失败），确认布尔盲注存在。
  • 确认闭合方式为双引号加括号 ")。
  • 利用 length()、substr()、ascii() 等函数逐字符猜解数据（脱库）。
  • 由于手工盲注极其耗时且容易遇到 POST 传输的字符截断问题，最终采用万能密码 admin")# 绕过密码验证直接登录通关。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：盲注阶段条件判断失效

踩坑情况：在验证了 1=1 和 1=2 成功后，尝试使用 ascii(substr(database(),1,1))>109# 猜解数据，页面却一直提示失败。

原因分析：在 POST 表单中直接提交 #，可能会被浏览器或后端当作锚点截断，导致 SQL 语法错误。此外，字符串比较如果引发字符集冲突（gbk vs latin1），即使不报错也会让条件判断失败。

改进方式：把 # 替换为 -- （注意破折号后必须有一个空格），或者对 # 进行 URL 编码（%23）。并且优先使用 ascii() 转数字比较，避免字符集冲突。

详细实操步骤（Payload逐字解释）

第一步：探测闭合方式与布尔盲注

Username 输入 admin") and 1=1#，Password 随意填。页面显示 SUCCESSFULLY LOGGED IN。
Username 输入 admin") and 1=2#，Password 随意填。页面显示 LOGIN ATTEMPT FAILED。
这证明闭合方式为双引号加括号 ")，且存在布尔盲注。

第二步：猜解数据库名长度

admin") and length(database())=8#

逐字解析：

  • admin")：闭合原 SQL 语句中的 ("。
  • length(database())：length() 函数计算字符串长度，database() 是当前库名。
  • =8：判断库名长度是否为8。如果成功，说明长度是8。
  • #：注释掉后面的密码校验和 LIMIT 语句。

第三步：逐字符猜解数据库名（二分法）

admin") and ascii(substr(database(),1,1))=115--

逐字解析：

  • substr(database(),1,1)：从库名第一个位置截取1个字符。
  • ascii()：将字符转换为 ASCII 码。字母 's' 的 ASCII 码是 115。
  • =115：判断 ASCII 码是否等于115。如果成功，说明猜对了。
  • -- ：注释符，替代 # 防止被截断，注意后面有一个空格。

终极逃课法（万能密码）：直接在 Username 输入 admin")#，Password 随便填，点击 Submit。因为 # 把后面的密码验证全注释了，SQL 变成 SELECT * FROM users WHERE username=("admin")#，直接登录成功。

4. 怎么迁移（跨领域联想）

  • 自动化测试与脚本编写：由于盲注需要发送成百上千次请求，手工测试不可行。这通常需要编写 Python 脚本（使用 requests 库发送 POST 请求，通过判断响应差异或时间差来自动化猜解）。在软件工程中，这属于自动化测试的范畴。
  • 信息论与二分查找：盲注猜解单个字符的过程，本质上就是信息论中的“信息熵减少”。使用二分法（如 >50, >75, >87...）可以使得每次请求获得最大的信息量，最快速度锁定字符的 ASCII 码。
  • 错误处理的艺术：在安全的开发规范中，确实不应该将数据库错误信息暴露给终端用户（防止信息泄露）。但仅仅关闭报错是不够的，真正的防御是使用参数化查询。Less-16 正说明“隐藏报错”可以防住“报错注入”，但防不住“盲注”。

三、名词大全与原理深度复盘

1. 盲注（Blind SQL Injection）

当页面没有回显位，且屏蔽了数据库错误信息时，攻击者无法直接看到数据。只能通过构造逻辑判断，根据页面返回的状态（成功/失败）、时间（延迟/不延迟）或内容长度，一点点推断出数据内容。

2. 布尔盲注（Boolian Based）

核心原理是“True/False”状态区分。当我们构造 and 1=1 时页面正常，and 1=2 时页面异常，我们就建立了一个二进制通道，通过这个通道向数据库提问，从而获取数据。

3. 时间盲注（Time Based）

当页面成功和失败的状态完全一致，连布尔盲注都无法判断时使用。利用 sleep() 函数，让数据库在条件成立时“睡几秒”，通过响应时间长短来判断条件是否成立。

4. 常用盲注函数

  • length(str)：计算字符串长度。
  • substr(str, pos, len)：从指定位置截取字符串。
  • ascii(char)：返回字符的 ASCII 码值。
  • if(cond, true_val, false_val)：如果条件为真，返回 true_val；否则返回 false_val。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-15 的区别：Less-15 是单引号 '，Less-16 是双引号加括号 ")。
  • 与 Less-11~14 的区别：Less-11~14 是报错注入（有回显），Less-16 是盲注（无回显，只能判断真假）。

2. 这种题目的出现原因（为什么存在）

开发者可能为了保护数据库结构不被泄露，在生产环境中关闭了 display_errors，把所有 SQL 异常吞掉并记录到日志里。但因为没有使用参数化查询，SQL 注入漏洞依然存在。这就像给房子加了防盗门却忘了锁窗户，入侵者虽然没法直接拿走财物（报错注入），但能通过听声音、看灯光来判断房子里有什么（盲注）。

3. 这种应用在实际中如何体现？

盲注是实际渗透测试中最常见的注入类型之一，因为它隐蔽性极强。很多企业级应用在错误处理上都比较规范，很少直接抛出报错。但这通常意味着手工利用非常耗时（往往需要配合 SQLMap 工具，或者写 Python 脚本自动化），因此也是安全加固的重点防御方向。

4. 如何抽象理解概念（大白话）

把数据库比作一个“只能回答是或否”的诚实门卫：

  • Less-11~14 是门卫会大声读出你的密码（报错注入）。
  • Less-16 的门卫什么都不说，但他会点头（登录成功）或摇头（登录失败）。
  • 你虽然听不到密码，但可以通过不断提问：“密码长度是8吗？”“第一个字符是a吗？”来一点点拼凑出真相。
  • 如果门卫连头都不摇，你就用“让他发呆（睡觉）3秒”作为暗号，问他“密码第一个字符是不是大于100？”（时间盲注），发呆就是“是”，不发呆就是“否”。

做一道题，就要往自己脑子里装点东西。
