反射型XSS(GET) - Pikachu 靶场 Writeup

2026年9月17日 Pikachu 靶场 Web安全 XSS 前端安全

这是我第一次接触 XSS（跨站脚本攻击）。之前的 SQL 注入是对付“后端服务器”，而 XSS 的攻击对象是“前端浏览器”。本篇 Writeup 记录了从“不知道这道题在干什么”，到用 URL 传参成功让浏览器弹窗的全过程。

一、这道题到底在考什么？

这道题叫“反射型 XSS (GET)”。它的目标是：让浏览器执行你输入的一串 JavaScript 代码。

如果你只输入一个正常名字（如 `kobe`），页面会把它显示出来。如果你输入的是 ``，页面同样把它显示出来——如果浏览器把这段标签当成代码执行了，就会弹窗。

二、大白话解释：什么是“反射型 XSS”？

比喻： 你对着山谷喊“你好”，山谷回复“你好”（正常的反射）。你对着山谷喊“”，山谷照样喊回来，如果你把这串话当成“命令”执行了，你就中招了。

本质： 服务器没有对用户输入的参数进行过滤，直接输出到了 HTML 页面中，导致浏览器把恶意代码当成合法脚本执行了。

三、陌生名词解释（新手必读）

  • XSS (Cross-Site Scripting)： 跨站脚本攻击。攻击者往网页里注入恶意 JS 代码，当其他用户访问该页面时，代码在他们浏览器里执行。
  • 反射型： 恶意代码不存进数据库，服务器直接把输入“反弹”回浏览器，类似于“一次性”的攻击。
  • alert()： JavaScript 内置的弹窗函数。在 CTF 或靶场里，只要它弹窗了，就证明代码执行成功了。
  • GET 请求： 数据通过 URL 传递（如 ?name=kobe）。优点是直观，缺点是参数暴露在地址栏。

四、踩坑全记录（每一步为什么错）

1. 踩坑一：找不到 maxlength，输入框限制

我想在输入框里输入 ``，但担心前端限制了输入长度。去 F12 的 Elements 面板搜 `maxlength`，死活找不到。

解决： 不要跟输入框死磕！这题是 GET 请求，直接在浏览器地址栏拼 URL 传参，完美绕过所有前端输入限制。

2. 踩坑二：网页被关掉了

在操作过程中我不小心关掉了浏览器标签页。

解决： 靶场是跑在 Docker 里的，只要 Docker 没停，直接在浏览器地址栏重新访问 `http://localhost:8080/vul/xss/xss_reflected_get.php` 即可。不要慌。

五、最终成功操作步骤（绝对百分百能弹窗）

  1. 在浏览器地址栏直接输入基础 URL：
    http://localhost:8080/vul/xss/xss_reflected_get.php
  2. 在页面输入框输入 `kobe`，点击 submit，观察地址栏变成了：
    ...?name=kobe
  3. 直接在地址栏把 `kobe` 替换为 Payload：
    http://localhost:8080/vul/xss/xss_reflected_get.php?name=<script>alert('xss')</script>
  4. 按回车，浏览器弹出了写着 `xss` 的警告框，通关！
