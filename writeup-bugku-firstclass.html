头等舱 - Bugku Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 HTTP头部信息泄露

这道题又是一道绝佳的信息搜集题。页面故意显示“什么也没有”，但题目名字“头等舱”已经给出了强烈的暗示：答案在 HTTP 的“头部（Headers）”里。

一、题目信息

  • 题目名称：头等舱
  • 题目平台：Bugku CTF
  • 题目类型：Web / HTTP头部信息泄露
  • 涉及工具：浏览器开发者工具（Network 面板）

二、解题步骤

1. 观察页面，结合题目名称思考

打开靶场后，页面只显示了几个换行和“什么也没有。”四个字。但结合题目名称“头等舱”，我立刻联想到了网络请求里的“头部（Headers）”。

2. 打开开发者工具，抓取网络请求

按 Fn + F12（或右键“检查”）打开开发者工具，切换到 Network（网络）面板。

3. 刷新页面，查看响应标头

按下 Command + R 刷新页面。在请求列表中，点击第一个资源（即当前页面本身）。在右侧弹出的详情面板中，向下滑动查看 Response Headers（响应标头）。

果然，在某个自定义的标头中（通常隐藏在头部信息的最后几行），找到了真正的 Flag。

最终 Flag： flag{...}

三、知识点总结（往脑子里装的东西）

  • HTTP 头部信息泄露：许多网站的敏感信息（如后端服务器版本、缓存策略、乃至自定义的机密信息）会被写入 HTTP 响应头中。
  • 信息搜集的广度：Web 安全中的信息搜集，不能只盯着网页上的文字，网络请求（Network）、注释、Cookies、甚至响应头，都是黄金藏匿点。
  • 题目语义暗示：“头等舱”就是一个典型的文字提示题，考的是你能否敏锐地将“头”与“Headers”联系起来。

做一道题，就要往自己脑子里装点东西。
