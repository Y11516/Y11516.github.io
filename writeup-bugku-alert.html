alert - Bugku Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 JS阻塞绕过

这道题是一道极其经典的“前端反调试”入门题。题目名叫“alert”，一进去就疯狂弹窗“来找找吧”，导致我们既无法右键查看源码，也无法正常操作 F12。本篇 Writeup 详细记录了我如何绕过这道题的前端阻拦，以及最后的解码踩坑之路。

一、题目信息

  • 题目名称：alert
  • 题目平台：Bugku CTF
  • 题目类型：Web / JS 阻塞反调试 / HTML实体编码
  • 涉及工具：view-source 协议、浏览器开发者工具（Elements、Console）

二、解题步骤（踩坑与破局过程）

1. 遭遇 JS 阻塞，常规手段失效

打开靶场，页面弹出一个 alert() 窗口显示“来找找吧”。只要点“确定”，页面就会变成空白，而且刷新后弹窗依旧存在。由于 JavaScript 单线程阻塞特性，直接右键查看源码或使用 F12 极其困难。

2. 绕过阻塞，拿到纯源码

为了避开执行 JavaScript，我使用了 view-source: 前缀（Mac 也可用 Option + Command + U）打开网页的原始源码。

3. 发现 HTML 实体编码

滑到源码最底部，在注释中发现了大量以 &# 开头的编码，这是一种典型的 HTML 实体编码（例如 f 代表字母 f），说明出题人故意把 flag 进行了编码，防止被简单的搜索发现。

4. 控制台解码与“自我 XSS”拦截

我将这串编码复制到浏览器的控制台（Console）打算进行解码。第一次粘贴时，触发了浏览器的安全机制：
Warning: Don't paste code into the DevTools Console that you don't understand...
于是我手动输入了 allow pasting 解除了限制。

5. 语法报错与最终成功

我尝试直接使用 document.write(f...)，结果报错：Uncaught SyntaxError: Unexpected token '&'。
原因在于：控制台执行的是 JavaScript，而 f 是 HTML 语法。在 JS 中，字符串必须用引号包裹！
修正代码如下： 

document.write("flag...");
加上双引号按回车，浏览器瞬间完成解码，成功拿到了 Flag！

最终 Flag： flag{1ffcfd65f5f0b17edf3c6521a775dba0}

三、知识点总结（往脑子里装的东西）

  • JS 阻塞反调试：利用 alert() 会挂起页面线程的特性，阻挠常规的信息搜集。对策是查看纯源码，或者直接禁用 JavaScript。
  • HTML 实体编码：将特殊字符转换为 &#数字; 的格式，绕过简单的字符串匹配。在真实漏洞利用（如 XSS 绕过）中非常常见。
  • 浏览器控制台的安全机制：Chrome 为防止用户被骗执行恶意代码，会拦截粘贴操作。输入 allow pasting 即可解除。
  • 语法环境区分：在控制台写 JS 时，一定要区分 HTML 实体和 JS 字符串，不能混为一谈，否则会报 SyntaxError。

四、拓展答疑：新手容易卡住的三个核心概念

在复盘这道题的时候，我发现自己对几个概念还停留在“似懂非懂”的状态，因此在这里做一个深刻的总结，方便日后复习。

1. 什么是 HTML 实体编码？

在 HTML 语言里，<、>、& 等符号有特殊的语法含义。如果想在网页上仅仅把它们当作文本显示出来，或者开发者想要把敏感词（比如 Flag）稍微伪装一下，就会使用 HTML 实体编码。它的格式通常以 & 开头，以 ; 结尾，中间可以是十进制或十六进制的数字。比如字母 f 的编码是 &#102;。出题人把 flag{...} 全部转成这种编码，正是为了防止被简单的关键词搜索抓到。

2. 控制台解码与“自我 XSS”拦截是什么意思？

我们在浏览器的控制台（Console）里输入代码，让浏览器把 &#102; 这样的编码“翻译”回正常字符，这个过程就是控制台解码。

而所谓的“自我 XSS”拦截，是现代浏览器（如 Chrome）为了保护小白用户而设置的安全机制。网络骗子经常在论坛或聊天群里诱导用户：“复制这段代码到浏览器的控制台，你就能看到好玩的！”一旦用户照做，骗子就能窃取到用户的 Cookie 或控制页面（这种行为叫 Self-XSS）。所以浏览器会警告：“别乱粘贴你不理解的代码！”你需要手动输入 allow pasting 才能解除这个限制。

3. JS 阻塞反调试是什么意思？

JavaScript 是单线程语言。当你执行 alert() 这种弹窗命令时，代码会进入“阻塞”状态，直到你点击“确定”后，后续的代码才能继续执行。在本题中，作者故意设置了不断的弹窗，让页面一直处于假死状态，从而干扰我们右键查看源码或使用 F12 开发者工具，这就叫JS 阻塞反调试。绕过它的终极武器就是使用 view-source: 协议（快捷键 Option + Command + U），它相当于直接查看浏览器的原始“底牌”，根本不会执行任何 JS 代码。

做一道题，就要往自己脑子里装点东西。
