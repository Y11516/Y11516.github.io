DVWA-Medium-文件上传 (File Upload)

2026年10月2日 DVWA Web安全 文件上传 MIME 绕过

一、题目信息

  • 题目名称：DVWA File Upload (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 文件上传 / MIME 类型绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/upload/
  • 涉及工具：Google Chrome 浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是在 Medium 安全级别下绕过 MIME 类型校验。Medium 级别源码增加了对 HTTP 请求头 Content-Type 的检查，只允许上传 image/jpeg 或 image/png 类型。攻击者可以通过 Burp Suite 抓包，修改请求头中的 Content-Type 值，从而绕过检测并上传 WebShell。

2. 怎么想（破题思路）

  • 在 Low 级别，直接上传 shell.php 即可。在 Medium 级别，直接上传会被拦截，提示只允许上传 JPEG 或 PNG 文件。
  • 使用 Burp Suite 抓取上传请求，观察请求头中的 Content-Type 字段。
  • 将 Content-Type 从 application/x-php 修改为 image/jpeg，欺骗服务器认为这是一个合法的图片文件。
  • 放行请求，即可成功上传 WebShell。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：直接上传 PHP 文件被拦截

踩坑情况：直接选择 shell.php 点击上传，页面报错 Your image was not uploaded. We can only accept JPEG or PNG images.。

原因分析：Medium 级别加入了 Content-Type 检查，只允许 image/jpeg 或 image/png，而 PHP 文件的默认 MIME 类型是 application/x-php，因此被拒绝。

改进方式：使用 Burp Suite 拦截请求，手动将 Content-Type 修改为 image/jpeg，伪装成图片文件。

详细实操步骤（Payload逐字解释）

第一步：准备并上传 WebShell

本地准备 shell.php，内容为：<?php @system($_GET['cmd']); ?>。

点击“选择文件”选中它，但先不要点 Upload。

第二步：Burp 抓包并修改 Content-Type

开启 Burp 拦截，点击 Upload。拦截到请求后，找到请求头中的：

Content-Type: application/x-php

将其修改为：

Content-Type: image/jpeg

解释：后端只通过 HTTP 头部声明的 MIME 类型来判断文件是否合法，修改该字段即可绕过检测。

第三步：放行请求并验证

点击 Forward，页面提示 ../../hackable/uploads/shell.php succesfully uploaded!。

访问以下 URL 验证 WebShell 是否生效：

http://192.168.242.80/hackable/uploads/shell.php?cmd=whoami

响应结果：页面成功输出 www-data，说明 MIME 绕过成功，获得了远程命令执行权限。

4. 怎么迁移（跨领域联想）

  • 护网实战：MIME 绕过是护网外网打点最常用的手段之一。如果目标网站只在前端或后端检查了 MIME 类型，攻击者就可以轻松绕过并上传 WebShell。
  • 安全开发启示：只检查 MIME 类型是不够的，因为它是客户端可伪造的。正确的做法是同时检查文件后缀名、文件头（Magic Number），并对上传文件进行重命名。

三、名词大全与原理深度复盘

1. MIME 类型 (Multipurpose Internet Mail Extensions)

HTTP 协议中用于标识文件类型的标头（如 Content-Type: image/jpeg）。它最初用于电子邮件，后来被广泛应用于 Web 传输。由于是客户端发送的，因此可以被轻易篡改。

2. Burp Suite 抓包改包

通过代理拦截 HTTP 请求，在请求到达服务器之前修改其内容。这是绕过客户端和部分服务端校验的核心技能。

3. WebShell

一种以网页文件形式存在的后门程序。攻击者上传后，可以通过 HTTP 协议与服务器交互，执行系统命令、上传下载文件等。

4. 文件头 (Magic Number)

文件开头的几个字节，用于标识文件的真实类型。例如 JPEG 文件以 FF D8 FF 开头。高级防御会检查文件头，而不仅仅是 MIME 类型。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何校验，直接上传即可。Medium 级别增加了 MIME 类型检查，需要抓包修改请求头。
  • 与 High 级别的区别：High 级别不仅检查 MIME，还检查文件后缀和文件头（getimagesize），需要制作“图片马”或利用文件包含漏洞组合攻击。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者过度信任客户端提交的数据。MIME 类型是浏览器告诉服务器的，攻击者完全可以伪造。这反映了早期 Web 开发中“信任前端”的思维误区。

3. 这种的应用

在护网中，攻击者通过 MIME 绕过上传 WebShell，进而控制服务器。这是红队获取权限的关键一步。蓝队则需要通过 WAF 规则和文件内容检测来防御此类攻击。

4. 如何抽象理解概念（大白话）

把 MIME 绕过比作“换衣服”的间谍：

  • 正常情况：门卫检查你的证件（Content-Type），发现你是“PHP 文件”，直接拦下。
  • 恶意情况：你把证件上的“PHP”改成了“JPEG”，门卫一看是图片，就放你进去了。这就是 MIME 绕过的本质——通过修改身份标识来欺骗检查者。
