  • 靶场链接：http://靶机IP:8080/less-6/

二、解题步骤

1. 分析题目考什么

黑名单再次升级，封禁了 cat|tac|head|tail|more。题目提示使用 less 命令。考察的是在常用读取工具被禁的情况下，如何寻找替代工具以及理解交互式命令在 Web 环境的限制。

2. 怎么解（详细步骤与输出解析）

源码核心逻辑

$pattern = '/cat|tac|head|tail|more/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload

尝试使用 less 命令进行高级分页查看：

?cmd=less /flag

备选方案（如果 less 卡住无回显）：

?cmd=nl /flag
?cmd=sed -n '1,10p' /flag
?cmd=grep . /flag

踩坑记录：非交互式终端导致网页卡死

情况：输入 ?cmd=less /flag 后，页面一直转圈圈，没有回显，甚至请求超时。

原因：less 和 more 都是交互式分页工具，默认需要等待用户按键（如空格翻页、q退出）。在 Web 靶场的 PHP system() 环境中，缺乏 TTY（终端），导致命令读取完第一页后陷入死等，进程挂起。

改进：遇到卡死，立刻换用非交互式的替代命令，如 nl、sed 或 awk 来秒杀题目。

三、名词大全与原理深度复盘

1. less 命令详细介绍

less 被称为“终极文本查看器”，Linux 圈子里有一句名言叫 “less is more”（少即是多）。它诞生于 1983 年，就是为了解决 more 无法向后翻页的痛点而设计的。

基础语法与核心参数

基础语法：less [选项] 文件名

  • -N：显示行号。 相当于 nl，但能在交互式查看时全程显示行号。less -N /flag
  • -S：单行截断。 默认情况下，如果文件某一行太长，less 会自动换行显示。加上 -S 会截断长行，保持屏幕整洁（按左右方向键查看截断部分）。
  • +F：实时追踪（等效于 tail -f）。 less +F /var/log/nginx/access.log。它会像 tail -f 一样实时滚动，按 Ctrl+C 可以退出追踪模式，进入普通浏览模式。
  • -G：关闭高亮。 禁止对搜索到的匹配项进行高亮显示（在特殊场景下加快显示速度）。

交互操作快捷键（在真实终端中）

  • 空格 / f / PgDn：向下翻一页。
  • b / PgUp：向上翻一页（这是它完胜 more 的地方）。
  • 上下左右方向键：逐行或逐字符移动。
  • /字符串：向下搜索，按 n 找下一个，按 N 找上一个。 ?字符串：向上搜索。
  • q：退出。

底层原理：为什么说它是“懒加载”的神器？

这是 less 最核心的底层优势：它不需要把整个文件加载到内存里。

  • cat 会把文件全部读到内存然后输出。
  • vim 打开大文件时也会尝试读取部分信息，有时会卡顿。
  • less 采用 按需读取（Lazy Loading） 机制。启动时，它只调用 read() 系统调用读取第一屏的内容，然后暂停。当你按 PgDn 向下翻页时，它才继续调用 read() 读下一屏的数据，并释放之前的内存缓冲区。因此，哪怕打开一个 100GB 的日志文件，less 也能在瞬间启动。

CTF/RCE 实战避坑指南（极其重要）

在真实终端里，less 无比强大，但在 PHP 的 system() 里，它可能会让你崩溃。

  • 卡死原因：和 more 一样，less 默认需要与用户（TTY）交互。它读完第一屏后，会等待你按“空格”翻页或“q”退出。但 Web 环境的 system() 没有键盘输入，进程就会永远挂起等待。
  • 解决方案：
    1. 管道强制非交互（推荐）：echo | less /flag。利用管道给 less 塞一个空的输入源，它发现没有真实的 TTY，就会一次性输出所有内容并自动退出。
    2. 使用 -F 参数：less -F /flag。表示“如果内容只有一页，直接退出”。
    3. 直接换命令：别跟它死磕，直接用 nl /flag 或 sed -n '1,10p' /flag，天然非交互，秒出结果。

跨领域迁移：为什么运维和开发都离不开它？

  • Git 日志查看：你敲下 git log 时，Git 默认调用的就是 less！你可以用上下键翻看提交历史，输入 /fix 搜索包含“fix”的提交记录。
  • 代码审计：审计大型项目源码时，用 less -N index.php 配合正则搜索，比直接用 IDE 翻找更轻量。

四、题目思考

1. 这跟前面关卡的区别

Level 1-5 考的是“单命令替换”，Level 6 进一步引入了“交互式命令在非交互环境中的坑”。这提醒我们：在 RCE 中，不仅要知道命令功能，还要知道它在 Web 环境下的运行特性。

2. 如何抽象理解概念（大白话）

把读取文件比作吃自助餐。cat 是把所有菜都堆在你面前的盘子里（可能溢出）；tail 是只给你上最后几道菜；而 less 是每次只端上来一盘，你吃完（按空格）它再端下一盘。在 Web 靶场里，你没有手（没有 TTY），端上来第一盘后你没法按空格，服务员（服务器）就只能端着盘子一直站在你旁边等，造成了“卡死”。
