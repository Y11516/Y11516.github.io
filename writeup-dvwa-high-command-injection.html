DVWA-High-命令注入 (Command Injection)

2026年10月2日 DVWA Web安全 命令注入 黑名单绕过

一、题目信息

  • 题目名称：DVWA Command Injection (High)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 黑名单绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/exec/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是在 High 安全级别下绕过极其严格的黑名单过滤，执行系统命令。High 级别使用了更完善的黑名单，过滤了 &、;、| （带空格）、-、$、(、)、`、|| 等字符。然而，黑名单依然存在盲区——它过滤的是“管道符+空格”，但没有过滤单独的管道符 |。

2. 怎么想（破题思路）

  • 尝试 Low 和 Medium 级别的 Payload（127.0.0.1; whoami 和 127.0.0.1 | whoami），均被拦截。
  • 查看源码，发现黑名单里包含了 | （管道符后带一个空格）。
  • 既然它匹配的是“管道符+空格”，我们可以尝试输入不带空格的管道符：127.0.0.1|whoami。
  • 成功绕过黑名单，命令执行成功。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：使用带空格的管道符被拦截

踩坑情况：输入 127.0.0.1 | whoami，页面没有回显 www-data。

原因分析：High 级别的黑名单中明确包含了 | （管道符后带一个空格），str_replace 会将其替换为空，导致命令拼接失效。

改进方式：去掉管道符后面的空格，直接输入 127.0.0.1|whoami。黑名单匹配不到这个组合，从而成功绕过。

详细实操步骤（Payload逐字解释）

第一步：验证黑名单过滤

输入：127.0.0.1; whoami 或 127.0.0.1 | whoami

响应结果：仅回显 ping 统计信息，无额外命令执行结果。

第二步：使用不带空格的管道符绕过

输入：127.0.0.1|whoami

响应结果：页面末尾成功回显 www-data。说明 | 未被过滤，命令注入成功。

第三步：进阶绕过（带参数的命令）

由于空格被过滤，如果需要执行带参数的命令，可以使用 ${IFS} 替代空格：

127.0.0.1|cat${IFS}/etc/passwd

解释：${IFS} 是 Linux 的内部字段分隔符，默认包含空格和 Tab。它不会被常规的黑名单拦截，常用于命令注入中的空格绕过。

4. 怎么迁移（跨领域联想）

  • WAF 绕过实战：在真实的护网中，WAF 常常基于黑名单来拦截命令注入。攻击者会尝试各种替代符号（如 |、%0a、${IFS}、%09）来绕过过滤。这与本题的逻辑完全一致。
  • 安全开发启示：黑名单防御是“防不胜防”的。只要漏掉一个符号，防御就会失效。正确的做法是使用白名单（只允许合法的 IP 格式），或者使用参数化调用（避免拼接系统命令）。

三、名词大全与原理深度复盘

1. 黑名单绕过 (Blacklist Bypass)

攻击者通过寻找被过滤规则遗漏的等价符号或编码方式，绕过防御机制。常见的命令拼接符有 ;、|、||、&、&&、%0a 等。

2. ${IFS} 变量

Linux Shell 中的内部字段分隔符（Internal Field Separator）。默认值为空格、Tab 和换行符。在命令注入中，常被用来替代空格，绕过对空格的过滤。

3. str_replace

PHP 的字符串替换函数。在本关中被用来将黑名单字符替换为空。这种简单的替换很容易被双写绕过（如 ;;）或等价符号绕过（如 |）。

4. 白名单防御

最安全的防御策略。例如，后端只允许输入符合 IPv4 正则表达式的字符串，或者只允许特定格式的输入，从根本上杜绝了命令拼接的可能。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何过滤，可以直接用 ; 拼接。High 级别加入了严格的黑名单，需要寻找新的拼接符。
  • 与 Medium 级别的区别：Medium 级别只过滤了 ; 和 &&，可以直接用 | 绕过。High 级别把 | （带空格）也过滤了，需要去掉空格才能绕过。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者试图用“黑名单”来防御攻击，但低估了攻击者的创造力。很多符号和编码方式都可以实现相同的命令拼接效果，只要漏掉一个，防御就会失效。

3. 这种的应用

在护网中，攻击者通常会用 Burp Suite 配合各种编码工具（如 ${IFS}、%0a、%09）来测试 WAF 的绕过。而防御者则需要不断更新规则库，并加入行为分析。
