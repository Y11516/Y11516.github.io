计算机 - Bugku Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 前端绕过

这道题名叫“计算机”，打开后是一个简单的算术验证码。本以为只是个普通的算术题，结果发现输入框竟然限制只能输入一位数字，这就是典型的前端限制场景。

一、题目信息

  • 题目名称：计算机
  • 题目平台：Bugku CTF
  • 题目类型：Web / 前端限制绕过
  • 题目描述：随机数字运算验证码
  • 涉及技能：F12 开发者工具、修改 HTML 属性

二、解题步骤

1. 正常思考与碰壁

页面显示了一道数学题，例如：69+95=?

正常计算结果显然是 164。但当我尝试在输入框中输入 164 时，发现只能输入一个字符。仔细查看 HTML 源码后发现，输入框被加上了 maxlength="1" 的限制。

2. 召唤开发者工具，修改前端代码

这种限制仅仅存在于浏览器端，我们完全可以通过 F12 绕过它：

  1. 按 Fn + F12（或右键“检查”）打开开发者工具，切换到 Elements（元素）面板。
  2. 找到输入框对应的 HTML 代码：
    <input type="text" id="check" class="input" maxlength="1">
  3. 双击 maxlength="1"，将其修改为 maxlength="10"，或者直接删掉这个属性。
  4. 按回车键确认修改。

3. 提交答案获取 Flag

此时回到页面上，输入框的限制已经被解除了！我们顺利输入 164，点击“验证”，成功弹出了 Flag。

最终 Flag： flag{...}

四、知识点总结（往脑子里装的东西）

  • 前端限制不可信：像 maxlength、readonly、disabled 这类 HTML 属性，统统只对“老老实实”的用户有效。对于安全测试人员来说，用 F12 改一下代码就能绕过。
  • 永远不要只依赖前端校验：这是安全开发的大忌。真正安全的做法是在后端对用户提交的数据进行严格的长度、格式和逻辑校验，前端校验只是为了提升用户体验。
  • F12 是 Web 安全的利器：再次验证了“在浏览器里，你能看到的一切都可以被修改”这一准则。

做一道题，就要往自己脑子里装点东西。
