一、题目信息

  • 题目名称：Unsafe Filedownload
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 任意文件下载漏洞 / 路径穿越
  • 靶场链接：http://localhost:8080/vul/unsafedownload/unsafedownload.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是任意文件下载漏洞（Unsafe File Download）。后端提供了一个下载头像图片的功能。如果后端代码没有对用户传入的文件路径进行严格校验，直接将参数拼接到文件读取逻辑中，攻击者就可以通过路径穿越字符（../），下载服务器上的任意敏感文件（如源码、配置、系统密码文件等）。

2. 怎么想（破题思路）

页面展示了 NBA 球员头像，提示“点击球员名字即可下载头像图片”。解题思路如下：

  • 尝试点击一个球员（如科比），观察浏览器的行为。发现浏览器直接弹出了下载框，且地址栏没有明显变化。
  • 打开 F12 的 Network 面板，捕获下载请求。发现请求的 URL 大概是 execdownload.php?filename=kb.png。
  • 分析参数 filename，既然它指向一个具体的图片文件，那么它大概率存在路径穿越漏洞。尝试将其替换为系统敏感文件路径，并利用 ../ 跳出 Web 目录。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：点击下载按钮后地址栏没有变化

踩坑情况：点击球员名字后，浏览器直接下载了文件，地址栏的 URL 并没有变成带有 filename 参数的新地址，导致初学者无法直接通过地址栏修改 Payload。

原因分析：该下载接口采用了直接返回文件流的方式，并携带了 Content-Disposition: attachment 响应头，触发浏览器直接下载，页面本身并不发生跳转（可能是通过 AJAX 或隐藏表单提交）。

改进方式：放弃通过直接观察地址栏获取参数，改为打开 F12 的 Network（网络）面板，点击下载后查看实际请求的 URL，或者根据后端接口命名规则，手动拼接 URL。

踩坑记录二：路径穿越层数不足导致下载失败

踩坑情况：手动拼接 URL 后，如果只写 ../etc/passwd，可能无法成功下载。

原因分析：当前脚本位于深层目录 /vul/unsafedownload/，需要足够的 ../ 向上跳转才能到达根目录 /。

改进方式：使用足够多层级（如 4-5 个）的 ../../../../，确保能穿透到系统根目录，再定位到 /etc/passwd。

终极解法：利用路径穿越下载敏感文件

在浏览器地址栏直接输入以下 URL：

http://localhost:8080/vul/unsafedownload/execdownload.php?filename=../../../../etc/passwd

代码逐个符号深度解析：

  • execdownload.php：处理文件下载请求的后端接口文件。
  • ?：URL 参数起始标识符。
  • filename=：后端用于接收文件名的参数名。
  • ..：代表上一级目录，是 Linux 系统中标准的路径层级表示法。
  • /：目录分隔符。
  • ../../../../：连续向上穿越 4 层目录，跳出 Web 服务器根目录，直达文件系统根目录。
  • etc：存放 Linux 系统配置文件的目录。
  • passwd：存储系统用户信息的文件。

提交后，浏览器自动下载名为 passwd 的文件，打开即可看到系统用户列表（root、daemon、bin 等），证明任意文件下载漏洞攻击成功。

4. 怎么迁移（跨领域联想）

  • 源代码泄露与代码审计：在实际渗透中，攻击者会利用此漏洞下载网站源码（如 index.php、config.php），从而获取数据库账号密码、API 密钥或进行白盒代码审计，为后续攻击铺路。
  • 结合文件包含（LFI）：如果无法直接下载文件，也可以尝试使用文件包含漏洞来读取该文件。文件包含是“执行/显示”，文件下载是“获取文件流”，两者可以互相补充。
  • 防御策略：在代码开发中，应避免将用户输入的路径直接用于文件读取。如果必须允许下载，应使用白名单机制，或者使用 ID 映射（例如：传 ID=1，后端映射为 kb.png），彻底阻断路径穿越的可能。

三、名词大全与原理深度复盘

1. 任意文件下载漏洞（Arbitrary File Download）

当 Web 应用提供文件下载功能时，如果下载的文件路径参数直接来自用户输入，且服务端未对该参数进行严格的过滤和限制，攻击者就可以构造特殊的路径，下载服务器上原本无法访问的敏感文件。

2. 路径穿越（Directory Traversal / Path Traversal）

攻击者利用 ../ 或 ..\ 等相对路径符号，跳出 Web 服务器限定的根目录，访问文件系统中的其他目录。这是文件下载漏洞利用的核心技术。

3. 与文件包含漏洞的区别

文件包含（LFI/RFI）是将文件包含进 PHP 代码中执行（可能解析为 PHP 代码，导致 RCE），而文件下载是直接将文件内容作为二进制流发送给浏览器（不解析执行）。因此，下载漏洞通常只造成源码、配置等敏感信息的泄露，无法直接 Getshell。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与文件包含漏洞相比：文件包含是“让服务器执行文件”，可能引发 RCE；文件下载是“把文件打包给你带走”，属于信息泄露类型。
  • 与目录遍历漏洞相比：目录遍历漏洞允许攻击者浏览服务器目录结构；文件下载漏洞允许攻击者直接获取特定文件的内容，两者常常相互配合（先遍历找目标，再下载）。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者为了图省事，直接将前端传过来的文件名或路径拼接到了文件读取函数中（例如 readfile($_GET['filename'])），而没有对 ../ 这种特殊路径符号进行过滤，导致用户可以读取 Web 目录以外的文件。

3. 这种应用在实际中如何体现？

在实际的安全事件中，任意文件下载漏洞常被用于窃取企业核心数据（如数据库配置、用户手册、内部源代码）。攻击者下载到源码后，可以进一步挖掘 SQL 注入、RCE 等更深层次的漏洞，对企业的数据安全构成严重威胁。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作一个图书馆：

  • 正常功能：你告诉管理员“我要借科比的海报”（filename=kb.png），管理员就把海报拿出来给你。
  • 任意文件下载漏洞：你说“我要借《../../../../etc/passwd》这本书”（强行给管理员一个奇怪的书名）。管理员没多想，直接去系统最深处的仓库里把这本“密码本”拿出来递给了你。这就是路径穿越的魅力——你的“书名”可以穿透层层壁垒，拿到别人看不到的机密。
