CTFHub RCE - 过滤目录分隔符

2026年9月22日 CTFHub Web安全 RCE 过滤目录分隔符

一、题目信息

  • 题目名称：命令注入-过滤目录分隔符
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程命令执行） / 命令注入 / 黑名单绕过
  • 靶场链接：http://challenge-6b7a7b5f62e436a9.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是过滤目录分隔符（/）后的命令注入绕过。后端代码使用 preg_match_all("/\//", $ip, $m) 检测并拦截了用户输入中的斜杠字符。攻击者无法使用绝对路径（如 /flag）来读取文件，必须利用 Linux 的相对路径特性（如 cd 命令切换目录）配合其他绕过技巧（如 ${IFS} 替代空格）来读取目标文件。

2. 怎么想（破题思路）

  • 页面提示“这次过滤了目录分隔符 /，你能读到 flag 目录下的 flag 文件吗”。
  • 源码中 preg_match_all("/\//", $ip, $m) 限制了输入中不能包含 /。
  • 既然无法写绝对路径，我们改用相对路径。使用 cd 命令进入目录，不需要斜杠。
  • 需要结合上一题的绕过技巧，使用 ${IFS} 代替空格。
  • 读取文件时，若 cat 触发解析导致空白，必须使用 base64。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：尝试使用绝对路径导致拦截

踩坑情况：直接输入 127.0.0.1; ls /，页面拦截。

原因分析：preg_match_all 检测到了斜杠 /，导致代码走向 else 分支。

改进方式：必须改用相对路径。

踩坑记录二：未使用 ${IFS} 导致空格拦截

踩坑情况：输入 127.0.0.1; cd flag_is_here，由于包含空格导致被拦截（上一题知识点）。

原因分析：题目还叠加了空格过滤。

改进方式：必须使用 ${IFS} 替代空格。

踩坑记录三：cat 读取 PHP 文件导致空白

踩坑情况：找到目标文件后，使用 cat 读取，页面空白。

原因分析：PHP 解析器吃掉了注释。

改进方式：必须使用 base64 读取并手动解码。

详细实操步骤（逐字解析）

第一步：探测当前目录

构造 Payload：127.0.0.1;ls

发现目录：flag_is_here。

第二步：列出目标目录内容

构造 Payload：

127.0.0.1;ls${IFS}flag_is_here

发现文件：flag_15555748631863.php。

第三步：使用 cd 进入目录并读取文件

构造 Payload：

127.0.0.1;cd${IFS}flag_is_here;base64${IFS}flag_15555748631863.php

Payload 逐字深度解析：

  • 127.0.0.1：让 ping 命令正常执行。
  • ;：命令分隔符。
  • cd：切换目录命令（Change Directory）。
  • ${IFS}：替代空格，绕过空格过滤。
  • flag_is_here：目标目录名（不含斜杠，绕过斜杠过滤）。
  • ;：再次分隔命令。
  • base64：读取文件并转码。
  • ${IFS}：替代空格。
  • flag_15555748631863.php：目标文件名。

第四步：解码并提交

页面回显 Base64 字符串，复制后去在线工具解码，得到 Flag：ctfhub{e3fbdcb395b1d82e2ae53ad8}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 通配符绕过：除了 cd，还可以使用通配符 * 或 ? 绕过黑名单。例如 ls flag* 或 cat flag*。
  • 环境变量拼接：用 $PWD 或 ${PATH:0:1}（截取路径首字符）来获取斜杠，绕过对 / 的过滤。
  • 安全开发（SDL）：黑名单过滤防不胜防，必须使用白名单。对用户输入进行 escapeshellarg() 转义，或直接避免使用系统命令。

三、名词大全与原理深度复盘

1. 相对路径与绝对路径

绝对路径以 / 开头（如 /var/www/html），从根目录开始。相对路径不以 / 开头（如 flag_is_here），以当前目录为基准。本题利用相对路径 cd 绕过了斜杠过滤。

2. cd 命令（Change Directory）

Linux 用于切换工作目录的命令。在命令注入中，它常被用于在不能使用绝对路径的情况下，逐级进入目标目录。

3. 正则表达式 / \/ /

PHP 的 preg_match_all("/\//", ...) 用于匹配斜杠。因为斜杠是正则表达式的定界符，所以需要转义为 \/。这体现了过滤规则在语法层面的设计。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“过滤空格”的区别：“过滤空格”针对的是命令分隔符；“过滤目录分隔符”针对的是文件路径的组成部分，是对文件系统访问的限制。
  • 与“无过滤”的区别：“无过滤”可以直接用 cat /flag 一条命令搞定；本题需要组合 cd、${IFS} 和 base64，考验多步骤命令拼接的能力。

2. 这种题目的出现原因

开发人员认为“只要禁止了斜杠，攻击者就不能指定文件路径了”。但 Linux 的相对路径和 cd 命令极其灵活，这种针对单一字符的黑名单防御注定失败。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，绕过 / 过滤是常见需求。攻击者常使用 cd、通配符 *、环境变量 ${PWD} 或 $(pwd) 等方式绕过，成功读取系统文件或配置文件。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个图书馆：

  • 绝对路径（/flag）：你直接对管理员说“请给我位于图书馆总目录下的 flag 文件”。但图书馆规定不能提到“总目录”（/）。
  • 相对路径 + cd：你灵机一动，对管理员说：“请带我走进你身后的那个房间（flag_is_here）”。管理员照做了。然后你说：“请把那个房间里的那本书（flag_xxx.php）拿给我”。
  • 结果：你没有违规说出“总目录”，却成功拿到了想要的东西。这就是相对路径的魔力。

做一道题，就要往自己脑子里装点东西。
