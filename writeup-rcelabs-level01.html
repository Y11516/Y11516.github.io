RCE-Labs Level 1 - 基础命令执行与文件读取

2026年10月3日 RCE-Labs 命令注入 信息收集

一、题目信息

  • 题目名称：RCE-Labs Level 1 (基础命令执行与文件读取)
  • 题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 命令注入
  • 靶场链接：http://靶机IP:8080/less-1/ (注：靶机IP可能会动态变化)
  • 涉及工具：浏览器、Burp Suite (可选，本关直接通过URL传参即可)

二、解题步骤

1. 分析题目考什么

本题核心考察的是服务器端代码执行漏洞。当 Web 应用程序将用户输入的数据（此处为 GET 参数）没有经过严格过滤，就直接传入执行系统命令的函数（如 system()）时，攻击者就可以通过构造特殊参数，让服务器执行任意系统命令，从而读取敏感文件或获取服务器权限。

2. 怎么想（破题思路）

  • 打开靶场页面，发现页面顶部直接输出了 PHP 源代码。这是一个“白盒测试”场景，出题人故意暴露源码，引导我们分析漏洞点。
  • 观察源码发现，变量 $cmd 接收了 URL 中的 cmd 参数，并直接将其拼接到 system() 函数中执行。这意味着我们可以直接在 URL 里输入 Linux 命令。
  • 源码注释 # ./flag 暗示靶场的目标是获取 flag 文件。因此，思路就是利用命令执行漏洞，寻找并读取 flag 文件。

3. 怎么解（详细步骤与逐字翻译）

源码逐字翻译与符号解析

<?php
# ./flag
highlight_file(__FILE__);
$cmd = $_GET['cmd'] ?? 'echo "<br>Ciallo~(∠・ω< )★"';
system($cmd);
  • <?php：PHP 脚本开始标签。
  • # ./flag：PHP 中的注释行。这是出题人留的提示，暗示最终目标文件是当前目录下的 flag。
  • highlight_file(__FILE__);：highlight_file() 是 PHP 内置函数，用于语法高亮显示指定文件的内容。__FILE__ 是一个 PHP 魔术常量，代表当前文件的完整路径和文件名。这行代码的作用就是“把本文件的源码打印在页面上”，所以一进页面就能看到代码。
  • $cmd =：声明一个变量，名为 $cmd。
  • $_GET['cmd']：PHP 预定义变量 $_GET 用于接收 URL 中通过 GET 方式传递的参数。此处接收参数名为 cmd 的值。
  • ??：Null 合并运算符。如果左侧的 $_GET['cmd'] 存在且不为 NULL，就将其赋值给 $cmd；如果不存在，则使用右侧的默认值。
  • 'echo "<br>Ciallo~(∠・ω< )★"'：默认值，如果用户没传参，就会在页面上输出这串颜文字。
  • system($cmd);：system() 是 PHP 中用于执行外部程序并显示输出结果的函数。它会将参数 $cmd 当作操作系统的命令行指令来执行。

踩坑记录一：直接读取当前目录失败

尝试 Payload：?cmd=cat flag

失败响应：页面上没有任何回显（没有显示文件内容，也没有报错信息）。

原因分析：Linux 系统中，如果文件不存在，cat 命令会向标准错误流（stderr）输出报错信息。而 PHP 的 system() 函数默认只打印标准输出流（stdout），错误流被丢弃了。这说明当前工作目录下没有名为 flag 的文件。

改进方式：先探测当前所处的位置及目录内容，不要盲目猜文件名。

踩坑记录二：确认环境与寻找文件

尝试 Payload 1：?cmd=pwd

结果 1：页面回显 /var/www/html/less-1，说明当前工作目录在 Web 服务的某个子目录下。

尝试 Payload 2：?cmd=ls -la

结果 2：回显信息显示当前目录下只有 .、.. 和 index.php。证实了当前目录确实没有 flag 文件。

尝试 Payload 3：?cmd=ls /

结果 3：列出根目录结构，发现根目录下存在 flag 文件。

改进方式：在 RCE 漏洞利用中，信息收集至关重要。先使用 pwd 定位，再使用 ls -la 查看当前目录，最后去常见的高危目录（如根目录 /）寻找目标文件。

最终成功 Payload

访问 URL：

http://靶机IP:8080/less-1/?cmd=cat /flag

成功响应：页面直接回显出了 Flag：flag{TEST_Dynamic_FLAG}。

4. 怎么迁移（跨学科与跨领域联想）

  • 系统运维领域：在 Linux Shell 脚本编写中，如果脚本接收外部参数并直接拼接进 rm -rf 或 eval 等命令，会造成灾难性的系统删除或权限被控。
  • 日常生活领域：这就好比你把所有想说的话（包括“请帮我买杯咖啡”）写在一张纸条上给助理，助理无脑照着执行。如果别人偷偷把纸条换成了“请把公司大门打开”，助理也会照做。系统同样缺乏这种“分辨指令是否安全”的能力。
  • 硬件控制领域：物联网设备（如早期路由器、摄像头）的 Web 管理后台，往往直接拼接系统命令来执行 ping 或重启操作，导致大量设备被僵尸网络控制。

三、名词大全与原理深度复盘

1. RCE (Remote Code Execution) 远程代码执行

指攻击者通过网络，利用目标系统存在的漏洞，在远程服务器上执行恶意代码或系统命令。RCE 是危害等级最高的漏洞之一，通常意味着服务器完全失守。

2. 命令注入 (Command Injection)

RCE 的一种常见形式。由于应用程序在调用系统命令时（如 PHP 的 system、Python 的 os.system），没有对用户输入进行过滤或转义，导致用户能够拼接并执行额外的系统命令。

3. 魔术常量 __FILE__

PHP 中预定义的常量，它随代码所在位置变化而变化。在这里它代表了当前 PHP 脚本的绝对路径。很多新手会将其误认为是文件名的固定字符串，实际上它会根据部署的路径动态变化。

4. 标准输出 (stdout) 与 标准错误 (stderr)

在 Linux 系统中，每个进程都有三个默认的输入/输出流：标准输入 (stdin)、标准输出 (stdout)、标准错误 (stderr)。system() 函数仅截取标准输出，因此如果命令执行报错，需要通过 2>&1 或 2>/dev/null 等重定向手段来处理错误流才能看到报错信息。

5. Shell (壳)

操作系统的外壳，是用户与操作系统内核交互的接口。当 PHP 的 system() 函数被调用时，它会启动一个 Shell 环境来解析并执行传入的字符串。

四、题目思考

1. 这跟前面关卡的区别

  • 与 Burp-Labs 的区别：Burp-Labs 考验的是 HTTP 协议、代理拦截和逻辑漏洞，主要通过修改请求包来“欺骗”应用。而 RCE-Labs 考验的是服务器后端代码的执行逻辑，需要利用系统命令去“接管”服务器。
  • 关卡设计的递进：Level 1 是白盒源码泄露，且无过滤，直接拼接执行。后续关卡会逐渐增加黑名单过滤、空格过滤、无字母数字执行等限制，迫使你掌握更高级的绕过技巧。

2. 这种题目出现的原因（底层逻辑与历史原因）

在早期的 Web 开发中，为了便捷，程序员大量使用 PHP 的 system、exec、shell_exec 等函数来调用系统工具（如调用 ping 检查网络、调用 ffmpeg 处理视频）。这些函数底层是通过 C 语言的 popen() 或 exec() 系统调用实现的，它直接将字符串传递给操作系统的 Shell 解析。操作系统无法区分这个字符串是程序员写死的，还是用户拼接的，只要语法合法，一律执行。这就是命令注入漏洞的最底层原因。

3. 这种漏洞在实际中的应用

在真实的红蓝对抗（护网行动）中，RCE 是最核心的得分手段。拿下 RCE 后，攻击者通常会反弹 Shell，进而进行内网横向移动、安装内存马、窃取数据库权限等。对于防守方而言，通过 WAF 拦截包含系统命令关键字（如 cat、ls、|）的请求是常见的防御手段。

4. 如何抽象理解概念（大白话）

把后端服务器想象成一个没有主见的传话筒。用户输入什么，它就传给系统什么。你不加验证就把用户输入当成“指挥官”去指挥系统的 CPU 做事，这就是 RCE。安全的原则是：“永远不要信任用户的任何输入，不要将用户输入直接当作系统指令执行”。
