Git泄露-Log - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 Git泄露 源码审计

这道题是 Git 源码泄露系列中的 Log 场景。开发人员将 .git 目录错误地部署到了线上环境。我们需要下载整个 Git 版本控制数据，通过查看提交历史（Commit Log）以及回溯被删除的文件，最终提取出 Flag。在这个过程中，我踩遍了 CTFHub 靶场的环境坑、WAF 拦截坑以及 Git 工具选择坑，这篇 Writeup 将详细记录完整的排错过程。

一、题目信息

  • 题目名称：Git泄露 - Log
  • 题目平台：CTFHub
  • 题目类型：Web / 信息泄露 / Git源码泄露
  • 涉及工具：Mac 终端、Python (git-dumper 库)、Git 命令行
  • 最终Flag： ctfhub{...} （请替换为实际获取的值）

二、解题过程（详细步骤与踩坑全记录）

1. 踩坑第一步：环境过期与“彩蛋”陷阱

初次尝试在终端使用 wget -r -np -nH --cut-dirs=1 http://靶场地址/.git/ 下载源码。

结果下载下来的是一堆 HTML 代码，而不是 Git 文件。原来环境已过期，CTFHub 返回了环境过期提示页。有趣的是，这个提示页里包含了一个技能树的“彩蛋 Flag”：ctfhub{b644d27d...}（这个彩蛋我先提交到技能树彩蛋分类里了）。

解决：回到 CTFHub 网页端点击“环境续期”，或“停止并销毁环境”后重新开启一个新环境，获取新的 URL。

2. 踩坑第二步：Wget 与 Git Clone 的双重拦截

拿到新环境地址后，我尝试再次下载：

  • 直接使用 wget：服务器返回 403 Forbidden，被 WAF 拦截。
  • 为 wget 添加 --user-agent="Mozilla/5.0..." 伪装成浏览器：依然返回 403 Forbidden。
  • 尝试使用 git clone http://.../.git：报错 repository not found。原因在于 CTFHub 暴露的只是一个静态的 .git 文件夹，并非支持 `git-upload-pack` 协议的真实 Git 服务器。

3. 成功破局：使用 git-dumper 工具

面对 WAF 拦截和 Git 协议不匹配的问题，最专业的解法是使用专门为这种漏洞场景打造的 Python 工具 git-dumper。

在终端安装并运行：

pip3 install git-dumper

cd ~/Downloads
git-dumper http://challenge-b54dc74f2be6301e.sandbox.ctfhub.com:10800/.git/ git_log_2

终端开始飞快下载一系列 objects/ 文件，最终提示“Running git checkout .”，成功将静态文件还原为了完整的 Git 仓库。

4. 查看历史，发现“删库跑路”

进入下载好的目录，查看提交历史：

cd git_log_2
git log

输出结果令人惊喜又绝望：

  • 最新提交（HEAD）名为 remove flag（Flag 被删了！）
  • 上一个提交名为 add flag（Flag 在这里被加进来过）
  • 最老的提交名为 init

5. 终极时空回溯：找回被删除的 Flag

既然 Flag 被删除了，我们就需要“穿越”回上一个版本。有三种方法可以拿到它：

方法一（使用 git show 查看具体提交）：

复制 add flag 那一次提交的哈希值（例如 915ee18），执行：

git show 915ee18

方法二（使用 git diff 对比变化）：

直接查看最近一次提交做了什么改动（会显示删除的绿色减号内容）：

git diff HEAD^ HEAD

方法三（终极暴力搜索大法）：

不管 Flag 被修改、删除过多少次，直接在 Git 的所有历史记录里全局搜索：

git grep "ctfhub{" $(git rev-list --all)

成功在当前屏幕上看到最终的 Flag。

最终 Flag： ctfhub{55a4e0804f235655b11ce0ba} （请填入实际得到的值）

三、知识点总结（往脑子里装的东西）

  • Git 泄露原理： 部署代码时，如果忘记删除 .git 文件夹，攻击者就能还原源码，甚至查看开发者提交过的所有记录。
  • 工具选择： wget 容易触发 WAF，git clone 无法克隆静态目录。针对此场景，git-dumper 是最优解，能自动化完成对象拉取和仓库重建。
  • Git 历史利用： git log 查看历史，git show 查看具体修改，git diff 对比差异，git grep 结合 git rev-list --all 可以搜寻所有版本的代码。
  • 环境意识： 靶场环境是有生命周期的，过期后一切请求都会返回提示页面，此时需要去网页端续期并更新靶场 URL。

四、踩坑启示录（极其宝贵的实战经验）

💡 不要把时间浪费在猜测上： 当遇到 wget 403 时，不要疯狂重试，立刻换工具。渗透测试的本质是“通过不同的通道去获取信息”。

💡 Git 可以“起死回生”： 只要数据被提交过，哪怕开发者后来删除了，只要 .git 目录还在，利用 Git 的对象存储机制就能百分百还原。

做一道题，就要往自己脑子里装点东西。
