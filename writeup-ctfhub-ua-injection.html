UA注入 - CTFHub Web 入门 Writeup

2026年9月18日 CTFHub Web安全 SQL注入 User-Agent SQLMap

这是我做的最后一道 SQL 注入类型题。题目提示“输入点在User-Agent”。有了上一道“Cookie注入”的经验，我立刻意识到这是 HTTP 头部注入的变种。经历了环境过期、SQLMap 初次报错等折磨后，最终使用 SQLMap 一键脱库成功。

一、题目原理（大白话解释）

什么是 UA（User-Agent）？ 浏览器每次访问网站，都会向服务器递一张“名片”，上面写着“我是 Mac、我是 Chrome 浏览器”。

漏洞原理： 后端代码极其粗心，直接把这张名片的内容拼接到 SQL 语句里。比如后台代码可能写成 select * from news where id=UA。我们在名片里写上恶意 SQL 语句，服务器就会执行它。

二、与 Cookie 注入的对比

  • 输入点不同： Cookie 注入藏在 Cookie 头里，UA 注入藏在 User-Agent 头里。
  • 注入逻辑完全相同： 都是后端没有对用户可控的输入进行过滤，直接拼接到 SQL 语句中。
  • 实战意义： 在真实渗透中，除了表单和 URL，所有的 HTTP 头（Cookie、User-Agent、Referer、X-Forwarded-For）都可能是注入点。

三、踩坑记录与终极方案（SQLMap 实战）

1. 踩坑一：环境过期导致 SQLMap 报错

我首先尝试用 SQLMap 进行扫描，命令如下：

sqlmap -u "http://challenge-xxx.sandbox.ctfhub.com:10800/" --headers="User-Agent: *" --dump --batch

结果 SQLMap 报错 [CRITICAL] all tested parameters do not appear to be injectable。

原因分析： CTFHub 环境只有半小时寿命。我折腾太久导致环境过期，页面返回统一的 404，SQLMap 发什么都一样，自然判定没有注入点。

解决： 去 CTFHub 点击“停止并销毁环境” -> 重新“开启题目”，拿到全新的 URL 和端口。

2. 成功破局：SQLMap 一键脱库

拿到新地址后，使用增强命令，直接自动脱库：

sqlmap -u "http://challenge-c8b5834660abb2b6.sandbox.ctfhub.com:10800/" --headers="User-Agent: *" --level=3 --dump --batch --random-agent

终端迅速打印出数据库、表名、列名，最后直接输出了 Flag。

最终 Flag： ctfhub{2aaba792796eedba8d18bc93}

四、SQLMap 参数深度解析（每一行代码的意思）

这条命令为什么能成功？我们把参数拆开来看：

  • -u "URL"：指定靶场地址。SQLMap 会自动化分析这个 URL 的响应。
  • --headers="User-Agent: *"：核心！ 星号 * 的作用是“激活注入探测”。它告诉 SQLMap：“别猜了，注入点就在 User-Agent 这个头部里，赶紧测它！”
  • --level=3：把探测等级从默认的 1 提升到 3，让 SQLMap 增加测试的 HTTP 头种类和 Payload 数量。对付 WAF 或隐蔽的注入点非常有效。
  • --dump：一键脱库。一旦发现注入点，自动把数据库里的所有表、列、数据全部下载下来。
  • --batch：自动模式。当 SQLMap 问你要不要继续、用哪个字典时，全部默认选“是”，防止命令卡住。
  • --random-agent：让 SQLMap 每一次请求都随机生成一个真实的浏览器 User-Agent，防止被服务器 WAF 识别并拦截。

五、深度思考：VS Code 脚本 vs SQLMap 的区别

1. 定位不同（手动挡 vs 自动挡）

  • VS Code 写 Python 脚本（手动挡）： 你需要自己构思逻辑、自己处理 Cookie、自己转换 URL 编码。适合逻辑复杂、工具无法自动识别时的定制化攻击。
  • SQLMap（自动挡）： 这是一把“万能钥匙”。它内置了海量的 Payload 字典和绕过 WAF 的规则。你只需要告诉它“目标在哪”，它就能自动完成探测、注入、提权、脱库的全过程。

2. 效率与稳定性的取舍

  • 手写脚本耗时极长，遇到环境过期或 WAF 拦截容易崩溃，但好处是你能清楚每一行代码在干什么。
  • SQLMap 速度极快，能自动处理空格、逗号、单引号绕过等繁杂细节。但在 CTFHub 这类短生命周期环境中，也可能因为跑太久而中途断掉。

六、SQLMap 底层原理剖析

SQLMap 是怎么知道注入点在 User-Agent 的？它的探测步骤非常严谨：

  1. 探测存活与 WAF： 发送无害请求，确认目标可访问，并检查是否被防火墙拦截。
  2. 判断注入类型： 发送 UA=1 AND 1=1 和 UA=1 AND 1=2，对比返回页面的长度、状态码、时间差。如果存在差异，说明存在布尔盲注或时间盲注。
  3. 确定回显位： 发送 UA=1 UNION SELECT 1,2,3...，观察页面哪些数字被回显，从而判断出列数和回显位置。
  4. 自动化提取： 利用 information_schema 自动查询数据库名 -> 表名 -> 列名，最后读取数据。

七、知识点总结与防御思考

💡 HTTP 头注入： 除了 UA 和 Cookie，Referer 和 X-Forwarded-For 也经常被用来做注入点，原理完全相同。

💡 防御手段： 永远不要信任任何客户端提交的数据（包括 HTTP 头）；SQL 语句必须使用参数化查询（Prepared Statements）。
