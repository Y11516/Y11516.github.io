二、解题步骤

1. 分析题目考什么

源码中正则变为 $pattern = '/\x20/';。弹窗提示“尝试用 Tab 键（URL编码为 %09）代替空格”。核心考点是利用 Shell 词法解析器对空白字符的宽容度，绕过针对 ASCII 空格的黑名单。

血泪踩坑记录：工具依赖症与浏览器拼 URL 的降维打击

错误尝试：受前面关卡 Nginx 拦截换行符的影响，我盲目推荐使用 Burp Suite 发送复杂 Payload。

用户反馈：“为什么不拼url？”（直接灵魂拷问）

改进与成功：直接在浏览器地址栏输入 ?cmd=cat%09/flag，成功回显。这证明了：不要迷信工具，能直接用 URL 解决的问题，绝不乱用 Burp。同时，不要被前期的经验固化思维，每到一个新环境，一定要重新侦察源码。

2. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$cmd = $_GET['cmd'] ?? '...';
$pattern = '/\x20/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与逐字解析

?cmd=cat%09/flag

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

命令逐字解析：

  • cat：读取文件的命令。
  • %09：Tab 键（水平制表符，ASCII 0x09）的 URL 编码。
  • %2Fflag：/flag。
  • 最终效果：Shell 的词法解析器会将 Tab、空格、换行符都视为空白字符。因此，cat[Tab]/flag 对 Shell 来说，与 cat /flag 完全等价，顺利读取 Flag。

3. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的空格绕过：在护网中，WAF 常常拦截空格。红队经常使用 ${IFS}、%09、<、{} 等替代方案，让命令继续执行。
  • 系统运维中的空白符：写 Shell 脚本时，Tab 和空格在语法上通常可以互换，但为了代码风格统一，通常约定使用空格或 Tab 中的一种。理解它们的等价性，是写出健壮脚本的基础。

三、名词大全与原理深度复盘

1. 空格在 Shell 中的本质与替代方案

在 Linux Shell 中，空格（0x20）、Tab（0x09）、换行符（0x0A）统称为 空白字符（Whitespace）。Shell 的词法分析器（Lexer）会将它们作为命令与参数的分隔符。

  • Tab (%09)：最常用的替代方案，与空格完全等价。
  • $IFS / ${IFS}：Shell 的内部环境变量（Internal Field Separator），默认包含空格、Tab、换行符。如 cat$IFS/flag。
  • {} 大括号扩展：如 {cat,/flag}，Shell 会将其扩展为 cat /flag。
  • < 重定向符：如 cat，不需要空格分隔。

2. WAF 与 防火墙 的区别

  • 防火墙（Firewall）：工作在网络层和传输层，主要负责控制 IP 和端口的进出。它会拦截非标准端口的 TCP 连接（如 9002），这就是反弹 Shell 容易失败的原因。
  • WAF（Web 应用防火墙）：工作在应用层，专门检查 HTTP 请求的内容。它维护一个黑名单字典，包含 cat、sed、空格等敏感词。它只看“请求长什么样”，不看“命令执行后会变成什么”。

3. 核心网络基础与护网认知（陌生人也能看懂版）

  • 外网（公网/互联网）：拥有全球唯一的门牌号（公网 IP，如 8.8.8.8），任何人任何车都能开到你家门口。
  • 内网（局域网）：门牌号是“小区内部编号”（如 192.168.1.19），只有小区内部的人才能互相找到。外面的人想找你，必须经过小区保安（路由器/NAT）允许并做地址转换。
  • 完全隔离的内网：小区不仅不让外面的人进，甚至把大门用砖头砌死了（物理隔离）。这种环境下，反弹 Shell 和重定向写入 100% 都会失效。
  • HTTP 是公网吗？这是一个经典的误解！HTTP 不是网络，它是语言（协议）。无论访问内网 OA 还是百度官网，用的都是 HTTP 语言。
  • 操作系统与网络的关系：电脑操作系统是管理网络硬件的“交通警察”。你监听 80 端口成功、9002 端口失败，根本原因就是操作系统或 Docker 的虚拟网卡策略，只放行了 80 端口的出站，拦截了 9002 端口。
  • 护网是在攻击内网吗？护网是一场“攻城战”：第一阶段是“外网打点”（攻打城门），寻找对外门户的漏洞；第二阶段是“内网渗透”（巷战与横向移动），以边界服务器为跳板在内网提权、抓密码；第三阶段是“拿下靶标”（直捣黄龙），控制核心数据库或域控。内网渗透是决定胜负的主战场。

四、题目思考

1. 这跟前面关卡的区别

前面关卡考的是“命令的连接符”（;、&&、||）和“命令替换”（反引号）。Level 36 首次引入了“命令与参数的分隔符”（空格）的绕过。这提醒我们：Shell 解析器与 WAF 的字符集认知存在天然差异，利用这种差异是绕过的核心。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发者常常将用户输入与系统命令拼接。为了防御，WAF 会尝试拦截空格，因为空格通常是命令注入的第一步。但 Shell 对空白字符的宽容度极高，使得这种防御形同虚设。

3. 这种漏洞在实际中的应用

在护网和红队行动中，遇到 WAF 拦截空格是家常便饭。利用 ${IFS}、%09、< 等手段绕过空格拦截，是渗透测试人员的基本功。同时，防守方也据此推出了“语义分析”型的高级 WAF，不仅看关键字，还会还原命令执行后的真实意图。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。监考老师（开发者）说：“不准用逗号”。于是你把逗号换成了句号或者感叹号。老师（WAF）没看懂，但读者（Shell）完全理解你的意思。

5. 他的本质

本质是利用 Shell 词法解析器对空白字符的宽容度，绕过应用层防火墙对特定字符（空格）的黑名单匹配。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：不要使用字符串拼接来构造系统命令！应使用编程语言提供的安全 API（如 PHP 的 escapeshellarg），或者直接使用白名单限制用户输入。同时，WAF 应拦截 Tab、换行符、$IFS、{} 等所有可能替代空格的字符。
  • 破解方（红队）：如果 Tab 也被拦截，尝试使用 ${IFS}（Level 37）、$IFS（Level 38）、{}（Level 39）或者直接使用重定向符 <（如 cat）。
