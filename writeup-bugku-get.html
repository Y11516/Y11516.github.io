GET - Bugku Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 后端传参

这是我第一次从“查看前端代码”跨越到“与后端服务器交互”。这道题直接泄露了后端的 PHP 代码，让我理解了 GET 传参的基本原理。

一、题目信息

  • 题目名称：GET
  • 题目平台：Bugku CTF
  • 题目类型：Web / 源码泄露 / 后端参数传递
  • 涉及工具：浏览器（URL 手动拼接）、F12 开发者工具（查看源码）

二、解题步骤

1. 发现源码泄露

打开靶场后，页面没有显示正常的交互界面，而是直接把后端的 PHP 源代码打印了出来。这本身就是一种“源码泄露”漏洞。

2. 解读后端代码逻辑

通过 Fn + F12 或右键查看源代码，我读懂了这段 PHP 代码：

<?php
$what=$_GET['what'];       // 从URL中获取名为"what"的参数
echo $what;                // 输出这个参数的值
if($what=='flag')          // 如果参数的值等于字符串"flag"
echo 'flag{****}';         // 就输出真正的Flag
?>

3. 构造 Payload 进行传参

代码告诉我们，它需要一个名为 what 的 GET 参数，且值必须为 flag。
我回到浏览器地址栏，在原本的 IP 地址后面拼接了 /?what=flag。

修改后的 URL 形如：

http://160.202.254.160:19944/?what=flag

按下回车，服务器接收到了我的参数，页面成功弹出了 Flag！

最终 Flag： flag{...}

三、知识点总结（往脑子里装的东西）

  • HTTP GET 传参：URL 格式中的 ?key=value 就是 GET 传参。后端用 $_GET['key'] 来接收这些数据。
  • 前后端的本质区别：之前改 `maxlength` 属性只是在骗我自己的浏览器（前端）。但后端代码在服务器上，我改不了它，只能顺着它的逻辑去构造 URL 参数。
  • 源码泄露的危害：服务器直接把 PHP 源码显示给用户，等于把防守布局全盘托出，让攻击者可以精准构造攻击参数。

做一道题，就要往自己脑子里装点东西。
