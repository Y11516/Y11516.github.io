Upload-Labs Pass-13

2026年9月27日 Upload-Labs Web安全 文件上传 图片马

一、题目信息

  • 题目名称：Upload-Labs Pass-13 (图片马 / 文件头检测绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 文件头伪造 / 图片马
  • 靶场链接：http://localhost:8082/Pass-13/index.php（本地环境）
  • 涉及工具：Mac 终端（Terminal）、Python（可选）

二、解题步骤

1. 分析题目考什么

本题的核心考点是文件头检测（Magic Bytes）绕过。Pass-13 后端使用了 getimagesize() 或类似函数来检测文件的前几个字节，只有符合图片格式（GIF、JPG、PNG）的文件才会被放行。攻击者通过在 PHP 代码前面加上合法的图片文件头（如 GIF89a），制作成“图片马”，即可成功绕过检测。

2. 怎么想（破题思路）

  • 直接上传纯 shell.php 会被后端拦截，提示“只允许上传图片”。
  • 图片马技术：将 PHP 代码拼接到图片文件头之后，使其既能通过图片检测，又保留木马功能。
  • 必须分别制作 .gif、.jpg、.png 三种格式的图片马，全部上传成功才算过关。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接粘贴 Python 代码到终端报错

踩坑情况：把 Python 脚本直接粘贴到 zsh 终端里运行，报错 zsh: parse error near ')'。

原因分析：zsh 是 Shell 环境，不能识别 Python 语法（如 import、f.write()）。

改进方式：对于生成文件这种简单任务，直接使用终端命令（echo、printf）即可，不需要写 Python 脚本。

详细实操步骤（Payload逐字解释）

第一步：终端一键生成三种图片马

在 Mac 终端依次输入以下命令：

# 生成 GIF 图片马
echo -e "GIF89a" > shell.gif

# 生成 JPG 图片马
printf '\xFF\xD8\xFF' > shell.jpg

# 生成 PNG 图片马
printf '\x89PNG\r\n\x1a\n' > shell.png

逐字解析：

  • GIF89a：GIF 图片的文件头（Magic Bytes）。
  • \xFF\xD8\xFF：JPG 图片的文件头。
  • \x89PNG\r\n\x1a\n：PNG 图片的文件头。
  • ：一句话木马代码。

第二步：依次上传

回到靶场页面，依次上传 shell.gif、shell.jpg、shell.png 三个文件。由于文件头合法，后端会提示“上传成功”。

第三步：理解图片马的执行方式

图片马上传成功后不会自动执行。在实战中，需要配合服务器上的文件包含漏洞（LFI），用 include('shell.gif') 等方式触发其中的 PHP 代码。本关只要三种后缀都成功上传，即可通关。

4. 怎么迁移（跨领域联想）

  • 文件签名（Magic Bytes）技术：不仅是图片，ZIP、PDF、Office 文档都有固定的文件头（例如 ZIP 是 PK）。理解文件头原理，有助于设计更安全的文件上传验证（不能只看后缀，也不能只看 Content-Type，要综合检测）。
  • 文件包含漏洞（LFI）：图片马必须与文件包含漏洞组合才能发挥最大威力。这体现了安全漏洞的组合拳效应——单独的文件上传可能只是信息泄露，但配合 LFI 就是 RCE（远程代码执行）。
  • 跨平台文件差异：Mac 上的 echo -e 和 printf 在处理十六进制转义时略有差异，这提醒我们在跨平台生成二进制文件时，必须确保字节序完全一致。

三、名词大全与原理深度复盘

1. 文件头（Magic Bytes / File Signature）

文件开头的几个字节，用于标识文件类型。如图片文件头的特征：GIF 是 GIF89a，JPG 是 \xFF\xD8\xFF，PNG 是 \x89PNG。后端常通过它来判断上传文件是否合法。

2. getimagesize() 函数

PHP 中的内置函数，用于获取图片的尺寸和类型。它会自动读取文件头，如果不是合法图片则返回 false。攻击者可以通过伪造文件头绕过它。

3. 图片马

将 WebShell 代码嵌入到合法图片文件中的攻击手法。图片马可以正常显示，但当它被包含进 PHP 文件时，里面的恶意代码就会被执行。

4. 靶场环境差异与截断漏洞（Pass-11/12 复盘）

PHP 5.3.4 之后的版本彻底修复了 %00 空字节截断漏洞。在 Mac 上运行高版本 PHP，无法通过 GET/POST 的 %00 截断来绕过上传路径限制。因此 Pass-11 和 Pass-12 在本环境无法复现，属于环境限制。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-09 的区别：Pass-09 利用 Apache 多后缀解析漏洞（文件名欺骗）。Pass-13 是利用文件头伪造，让后端误以为是合法图片，属于内容层面的欺骗。
  • 与 Pass-11/12 的区别：Pass-11/12 是路径截断漏洞，Pass-13 则是检验文件内容的真实性。

2. 这种题目的出现原因（为什么存在）

开发者为了防御文件上传漏洞，可能升级了检查手段，比如检查文件头。但道高一尺魔高一丈，攻击者通过伪造文件头绕过了检测。这说明防御不能只看“表面特征”，必须进行内容级校验（如重新编码图片）或存储层隔离。

3. 这种应用在实际中如何体现？

在真实的 RCE 漏洞利用链中，攻击者常上传图片马并结合文件包含漏洞来获取 Shell。防御方应禁止上传目录执行脚本，并将文件上传到独立的 OSS 存储中，从架构层面彻底断绝 RCE 的可能性。

4. 如何抽象理解概念（大白话）

把靶场比作一个“查岗的门卫”：

  • Pass-13 的门卫不再看你的名字（后缀），而是闻你身上的味道（文件头）。
  • 你把自己伪装成一张“明信片（GIF89a）”，但夹层里藏着刀（PHP 代码）。
  • 门卫闻到了明信片的味道，以为你是个好人，放行了。等到大楼内的管家（LFI）打开这张明信片时，刀就亮出来了。

做一道题，就要往自己脑子里装点东西。
