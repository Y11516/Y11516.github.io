DVWA-Low-不安全的验证码 (Insecure CAPTCHA)

2026年10月2日 DVWA Web安全 环境异常记录

一、题目信息

  • 题目名称：DVWA Insecure CAPTCHA (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 验证码逻辑漏洞 / 环境配置异常
  • 靶场链接：http://192.168.242.80/vulnerabilities/captcha/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是不安全的验证码逻辑。通常是由于后端在修改密码时，只在第一步校验了验证码，但在第二步（真正提交修改）时却没有校验，或者验证码可以被重复使用。

2. 怎么想（破题思路）

  • 正常填写验证码，抓包分析请求流程。
  • 尝试将请求中的 step 参数从 2 改为 1，看看能否跳过验证码校验阶段。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：环境缺少 reCAPTCHA API Key

踩坑情况：打开页面后，顶部直接报错 reCAPTCHA API key missing from config file: /var/www/html/config/config.inc.php，导致无法显示验证码框，无法继续做题。

原因分析：DVWA 的 Insecure CAPTCHA 关卡依赖 Google reCAPTCHA 服务。本地 Docker 镜像默认没有配置 Google 的 API Key，且 Google 服务在国内网络环境下无法正常加载。

改进方式：由于申请 Google API Key 并修改 Docker 容器配置文件极其繁琐，且该关卡实战价值有限（护网中此类逻辑漏洞出现频率极低），建议直接跳过此关，将时间投入到 SQL 注入、XSS 等核心漏洞的巩固中。

4. 怎么迁移（跨领域联想）

  • 真实的验证码逻辑漏洞：在部分电商或金融 App 中，重置密码的第一步会发送短信验证码，但第二步修改密码时如果只凭用户 ID 提交修改，攻击者就可以绕过短信验证码直接修改任意用户的密码。

三、名词大全与原理深度复盘

1. reCAPTCHA

Google 提供的一项免费验证码服务，用于区分人类和机器。由于国内网络限制，通常无法直接加载。

2. 验证码绕过 (CAPTCHA Bypass)

攻击者通过抓包改包、自动化识别（OCR）、验证码复用等手段，绕过网站设置的验证码防护机制，常用于配合暴力破解。

四、题目思考

1. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者对业务逻辑的安全校验不完整。验证码作为一种人机识别手段，应当与业务操作强绑定（如一次性令牌），否则极易被绕过或复用。

2. 如何抽象理解概念（大白话）

把验证码比作“门禁卡”：

  • 正常情况：进大门要刷卡（验证码），进办公室还要刷卡（提交修改）。
  • 漏洞情况：大门刷卡，但进办公室时保安不查了（逻辑缺陷），攻击者可以不刷卡直接溜进办公室。

做一道题，就要往自己脑子里装点东西。
