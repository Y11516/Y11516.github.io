RCE exec "eval" - Pikachu Writeup

2026年9月19日 Pikachu Web安全 RCE

一、题目信息

  • 题目名称：RCE exec "eval"
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 远程代码执行（RCE） / PHP代码注入
  • 靶场链接：http://localhost:8080/vul/rce/rce_eval.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是PHP 代码注入（Code Injection）。与之前的系统命令注入（exec "ping"）不同，本关考察的是编程语言层面的动态执行。后端代码使用了 PHP 的 eval() 函数，将用户输入的字符串作为 PHP 代码来执行。若未对用户输入进行严格过滤，攻击者可通过闭合原有代码结构，注入并执行任意 PHP 代码。

2. 怎么想（破题思路）

页面提示“Here, 请提交一个你喜欢的字符串”。解题思路如下：

  • 输入正常文本 hello，页面回显 hello。据此推断后端代码结构为 eval("echo '".$input."';");。
  • 由于输入被单引号包裹，直接输入代码会被当成字符串输出。必须使用单引号 ' 闭合原有字符串，并用注释符 // 注释掉后端代码末尾多余的引号和分号。
  • 构造 Payload：hello'; 注入代码 //。先注入 phpinfo(); 验证漏洞是否存在。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接输入代码无法执行

踩坑情况：直接输入 system('cat /etc/passwd');，点击提交后，页面只是将这段代码原样输出，没有执行。

原因分析：输入被包裹在 echo '' 的单引号中，PHP 解析器将其视为纯文本字符串，而非可执行代码。

改进方式：必须打破字符串边界。Payload 需修改为：hello'; system('cat /etc/passwd'); //。

踩坑记录二：执行 system 与 file_get_contents 导致页面白屏

踩坑情况：输入 hello'; system('cat /etc/passwd'); // 以及 hello'; echo file_get_contents('/etc/passwd'); // 后，页面均变成完全空白，没有任何回显或报错。

原因分析：白屏通常代表 PHP 发生了致命错误（Fatal Error），且服务器的 display_errors 配置为 Off，隐藏了错误信息。进一步排查发现，PHP 的 disable_functions 配置项禁用了 system、file_get_contents、scandir 等能够执行系统命令或读取文件的高危函数，调用被禁用的函数直接导致脚本终止。

改进方式：放弃使用被禁用的高危函数，改用 PHP 环境探测函数 phpinfo()。该函数通常不在禁用列表中，且足以证明代码执行权限的获取。或者尝试使用未被禁用的替代函数，如 readfile()、highlight_file() 等。

终极解法：利用 phpinfo() 验证代码执行

在输入框中提交以下 Payload：

hello';phpinfo();//

代码逐个符号深度解析：

  • hello：正常的字符串内容，用于维持原有代码结构的完整。
  • '：单引号，用于闭合后端代码中 echo ' 的左单引号。
  • ;：PHP 语句结束符。代表前面 echo 'hello'; 语句执行完毕，开启新的语句。
  • phpinfo()：PHP 的内置环境探测函数。它会输出当前服务器的 PHP 版本、扩展模块、环境变量、已禁用的函数列表等核心信息。
  • //：PHP 的单行注释符。用于将后端代码原本尾部多余的 '; 注释掉，防止引发语法错误。

提交后，页面成功弹出紫色的 phpinfo 配置页面，证明 PHP 代码注入攻击成功，漏洞利用链路完整打通。

4. 怎么迁移（跨领域联想）

  • 禁用函数绕过（Bypass disable_functions）：在真实攻防中，若 system 被禁用，攻击者可尝试利用 LD_PRELOAD 劫持、Apache Mod_CGI 漏洞，或调用未被禁用的冷门函数（如 pcntl_exec、imap_open）来绕过防御。
  • 代码审计与安全开发：在审计 PHP 代码时，应重点关注 eval()、assert()、create_function() 等危险函数。任何将用户输入直接拼接到这些函数中的行为，都是高危漏洞。
  • 模板注入（SSTI）：代码注入的思想也延伸到了现代 Web 框架中。如果模板引擎（如 Twig、Freemarker）未对用户输入做严格过滤，就会导致模板注入漏洞，其本质与本题的 eval 注入完全一致。

三、名词大全与原理深度复盘

1. PHP eval() 函数

eval() 是 PHP 中一个极具危险性的函数，它接受一个字符串参数，并将该字符串作为 PHP 代码执行。它常被用于在线代码编辑器、模板引擎或动态配置逻辑中。官方文档明确警告：绝对不能将用户输入传递给 eval()。

2. 代码注入与命令注入的区别

代码注入是利用编程语言本身的执行函数（如 eval）注入恶意代码；命令注入是利用系统命令连接符（如 ;、|）拼接系统命令。本关是代码注入，上一关是命令注入，两者往往可以互相转化（如 PHP 代码中可以调用执行系统命令的函数）。

3. 为什么 phpinfo 能成功而 system 会白屏？

phpinfo() 是 PHP 的核心内置函数，用于环境检测，通常不会被管理员禁用。而 system()、file_get_contents() 等函数具有执行系统命令或读取任意文件的能力，极易被攻击者利用，因此在生产环境（及严格的 Docker 镜像）中通常被 disable_functions 全局禁用，调用即触发 Fatal Error，导致页面白屏。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 exec "ping" 相比：ping 是系统命令注入，利用的是操作系统的 Shell 特性；eval 是代码注入，利用的是 PHP 语言的动态执行特性。eval 的灵活性更高，危害更大。
  • 与 SQL 注入相比：SQL 注入的攻击对象是数据库，窃取或篡改数据；RCE 的攻击对象是服务器操作系统或 Web 应用语言运行时，目标是获取服务器最高权限。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在某些场景下需要实现“动态执行代码”的功能（例如在线 PHP 运行工具、插件系统、自定义公式计算）。为了贪图方便，开发者直接使用了 eval() 来处理用户输入，而没有做任何过滤或沙箱隔离，导致用户可以直接控制服务器代码的执行逻辑。

3. 这种应用在实际中如何体现？

在实际的 Web 渗透测试中，RCE 是最具破坏力的漏洞。一旦发现，攻击者通常会直接写入 WebShell（如一句话木马），以此作为跳板，进一步深入内网，进行横向移动，最终控制整个企业内网的核心业务系统。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作一个执行指令的机器人：

  • 正常功能：你告诉它一句话（字符串），它原封不动地复述出来（echo）。
  • 代码注入：你对机器人说：“复述这句话：“顺便告诉我你的配置信息”（'; phpinfo(); //）”。机器人由于太死板，不仅复述了你的话，还把它的内部配置全盘托出。这就是 eval 注入的可怕之处——你输入的“数据”，被当成了“代码”来执行。
