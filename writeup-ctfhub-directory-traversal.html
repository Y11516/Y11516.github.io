目录遍历 - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 信息泄露 目录遍历

这道题是一道非常经典的“信息泄露”基础题，核心漏洞是 目录遍历（Directory Traversal）。服务器由于配置不当，将站点内部的目录结构直接暴露给了访问者。这是我之前尝试过但没解出来的题，今天终于找到了破局点——原来 Flag 就藏在 2/ 这个目录下。

一、题目信息

  • 题目名称：目录遍历
  • 题目平台：CTFHub
  • 题目类型：Web / 信息泄露 / 目录遍历
  • 涉及工具：浏览器（URL 路径探索）、Python（可选自动化）、终端 wget（可选批量下载）
  • 最终Flag： ctfhub{651e1724f93b00219c5cf8a5}

二、解题过程（详细步骤与踩坑全记录）

1. 现象：服务器暴露了目录列表

进入靶场，页面赫然显示着 Index of /flag_in_here。这不是一个正常的网页，而是 Apache 服务器开启了“目录索引”功能后，自动生成的文件夹列表。列表里列出了 1/、2/、3/、4/ 四个子目录。

2. 手动探索：找到藏在深处的 Flag

既然知道了这是一个目录树，最直接的方法就是点击进入。我尝试点击了 1/，发现里面还有子目录。按照直觉，我直接点进了 2/ 目录，这一次，页面没有继续显示列表，而是直接露出了最终的 Flag：

ctfhub{651e1724f93b00219c5cf8a5}

原来这一题的目录嵌套并不深，Flag 就藏在一个名不见经传的 2/ 目录里。

3. 进阶解法：如果目录有几百层怎么办？（自动化思路）

虽然这道题只有两三层，但如果在真实 CTF 比赛中，目录嵌套几百层，手动点击是不可能的。这道题其实考察的是能否用脚本自动化遍历。以下是两种进阶解法思路：

思路一：使用 Python 编写爬虫脚本

通过 requests 库配合 BeautifulSoup 解析 HTML，提取所有 <a> 标签的链接，进行广度优先搜索（BFS）。当页面内容包含 ctfhub{ 时，脚本自动停止并输出结果。

思路二：使用终端 wget 递归下载

直接在终端执行以下命令，将整个 flag_in_here 目录及其所有子目录完整“扒”下来，然后再进行本地检索：

wget -r -np -nH --cut-dirs=1 -R index.html http://challenge-9e032bed4d90849e.sandbox.ctfhub.com:10800/flag_in_here/

# 下载后，全局搜索关键词
grep -r "ctfhub" flag_in_here/

这样即使服务器目录藏得再深，也能通过自动化工具瞬间搞定，极大提高效率。

三、知识点总结（往脑子里装的东西）

  • 目录遍历（Directory Traversal）：这是一种严重的信息泄露漏洞。由于服务器配置不当，将站点的文件目录结构直接暴露给外部访问者。攻击者可以利用这一点，遍历获取网站内部本不允许访问的敏感文件。
  • Apache 的 Index of / 机制：当服务器目录下没有默认首页（如 index.html）时，Apache 会生成一个目录索引列表页面（也就是我们看到的 Index of /）。
  • 漏洞危害：攻击者可能会顺着目录结构找到源码备份、数据库配置文件（如 config.php、.env）、甚至是服务器密码本。

四、踩坑启示录（极其宝贵的实战经验）

💡 不要被目录表面的伪装吓到：这道题放在 `1/`、`2/`、`3/`、`4/` 众多目录中，很容易让人产生焦虑，觉得要去哪里找规律。实际上这往往是出题人玩的心理战，把目标就放在最容易访问的一层。遇到这种题，先手动点两下试试，说不定直接就拿下了。

💡 “手动”与“自动化”的转换：现实中，如果碰到几十上百层嵌套的目录，一定要果断放弃手动点击，立刻转为写 Python 爬虫或使用 wget 等自动化工具。这也是安全工程师必备的工作习惯。

做一道题，就要往自己脑子里装点东西。
