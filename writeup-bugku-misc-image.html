这是一张单纯的图片 - Bugku MISC Writeup

2026年9月10日 Bugku CTF MISC 图片隐写 HTML实体编码

这是我第一次接触 MISC（杂项）方向的题目。这道题的标题叫“这是一张单纯的图片”，但 CTF 里的“单纯”往往意味着“套路极深”。它教会了我如何用命令行工具探索文件的底层数据，并利用编码转换提取出隐藏的信息。

一、题目信息

  • 题目名称：这是一张单纯的图片
  • 题目平台：Bugku CTF
  • 题目类型：MISC / 图片隐写 / 编码转换
  • 题目提示：Key0
  • 涉及工具：Mac 终端（Terminal）、浏览器控制台（Console）

二、解题步骤

1. 下载图片，观察表象

下载附件后发现是一张简单的简笔画兔子（file.jpg）。右键用图片查看器打开毫无异样，文件名也平平无奇。结合提示“Key0”，我意识到真正的信息隐藏在文件内部，而非图片表面。

2. 终端提取隐藏字符串

既然不能从表面看出，我决定深入文件的二进制底层。在 Mac 终端中，使用 strings 命令提取图片中的所有可打印字符串，并用 grep 筛选关键字（这里我尝试了题目提示的“key”）：

strings ~/Desktop/file.jpg | grep "key"

（如果没搜到，可以用 strings file.jpg | grep "&#" 搜索 HTML 编码特征）

终端果然返回了一段非常怪异的长字符串，全部由 &#数字; 构成，例如：key{...。这明显是一种编码格式。

3. 识别与解码 HTML 实体

通过查询，我得知这是 **HTML 实体编码（HTML Entities）**。其中 k 代表字母 k，e 代表字母 e，{ 代表左大括号 {。

为了快速解码，我打开了浏览器的开发者工具（Option + Command + J），在控制台（Console）中使用 document.write() 函数将这串编码作为字符串输出：

document.write("key{...")

回车后，浏览器立刻将其解析成了人类能读懂的明文！

最终 Flag： key{you are right}

三、知识点总结（往脑子里装的东西）

  • MISC 图片隐写原理：JPEG 图片的二进制结构允许在文件末尾或元数据区附加额外数据，而不会影响图片的正常显示。使用 strings 等命令可以提取这些肉眼不可见的“尾巴”。
  • HTML 实体编码：以 &#数字; 或 &#x十六进制; 表示特殊字符。在 Web 安全（如 XSS）和 MISC 隐写中极其常见。
  • 编码转换工具：学会了利用浏览器控制台（Console）的 document.write() 来快速进行 HTML 实体解码。
  • 注意 Flag 格式：不要盲目只认 flag{...}，很多题目会使用 key{...} 或题目提示的自定义格式（如本题的 Key0）。
