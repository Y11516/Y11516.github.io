DVWA-Medium-暴力破解 (Brute Force)

2026年10月2日 DVWA Web安全 暴力破解 Burp Suite

一、题目信息

  • 题目名称：DVWA Brute Force (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 暴力破解 / 逻辑漏洞 / 防御机制分析
  • 靶场链接：http://192.168.242.80/vulnerabilities/brute/
  • 涉及工具：Burp Suite Community Edition、Google Chrome

二、解题步骤

1. 分析题目考什么

本题的核心考点是在中等安全级别下进行暴力破解，并理解其防御机制。与 Low 级别相比，Medium 级别在后端增加了两个关键改动：一是使用 mysqli_real_escape_string 对输入进行转义（防御 SQL 注入），二是在密码错误时执行 sleep(2) 延迟（增加爆破的时间成本）。

2. 怎么想（破题思路）

  • 输入错误的密码（如 123456），观察页面响应时间。
  • 发现页面会卡顿约 2 秒才返回错误，说明后端触发了 sleep(2)。
  • 使用 Burp Suite 抓包，确认请求依然是 GET 请求，且没有动态 Token。
  • 由于密码库未变，直接尝试已知密码 admin / password 即可登录（此时不会触发延迟）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：Burp 爆破速度极慢，导致 8GB Mac 卡顿

踩坑情况：尝试用 Burp Intruder 加载字典进行爆破，发现每跑一个密码都要等 2 秒，跑了十几个密码就花了近半分钟，且电脑风扇狂转。

原因分析：Medium 级别的 sleep(2) 会强制每次错误请求延迟 2 秒。Burp 社区版本身有并发限制，加上本地 8GB 内存吃紧，导致爆破效率极低。

改进方式：放弃在本地跑大字典。只跑几个测试密码验证延迟机制，或者直接使用正确的密码 password 登录，将重点放在分析其防御代码上。

详细实操步骤（Payload逐字解释）

第一步：验证延迟机制

输入 admin / 123456，点击 Login。

响应结果：页面卡顿约 2 秒后提示 Username and/or password incorrect.。这证明了后端执行了 sleep(2) 函数。

第二步：使用正确密码登录

输入 admin / password，点击 Login。

响应结果：页面瞬间响应，登录成功，显示 Welcome to the password protected area admin。这说明正确密码不会触发延迟。

第三步：源码分析（View Source）

点击页面右下角的 View Source，可以看到 Medium 级别的核心防御代码：

$user = mysqli_real_escape_string($GLOBALS["___mysqli_ston"], $user);
$pass = mysqli_real_escape_string($GLOBALS["___mysqli_ston"], $pass);
...
else {
    sleep( 2 );
    $html .= "<pre><br />Username and/or password incorrect.</pre>";
}

解释：mysqli_real_escape_string 阻止了 SQL 注入，sleep(2) 增加了爆破的时间成本，但并未从根本上杜绝暴力破解。

4. 怎么迁移（跨领域联想）

  • 银行金库的延时设计：现实中的金库如果在输错密码后需要等待一段时间才能再次尝试，这会极大地消耗劫匪的耐心。Medium 级别的 sleep(2) 正是这种思路的软件实现。
  • 防御策略的演进：从 Low 的无限制，到 Medium 的延迟，再到 High 的 Token 验证，体现了安全防御从“事后补救”到“事前预防”的演进。

三、名词大全与原理深度复盘

1. 时间延迟防御 (Time Delay Defense)

一种通过强制增加响应时间来抵御暴力破解的手段。攻击者每尝试一次密码，服务器就延迟数秒返回，这将极大增加爆破的时间成本。

2. mysqli_real_escape_string

PHP 的 MySQL 扩展函数，用于转义 SQL 语句中的特殊字符（如单引号、双引号、反斜杠等）。它常用于防御 SQL 注入，但无法防御暴力破解。

3. 暴力破解的时间成本

在无限制的情况下，攻击者可以用脚本每秒尝试上百个密码。但在有延迟的情况下，假设延迟 2 秒，遍历 10000 个密码需要耗费 5.5 小时，这足以让大部分攻击者放弃。

4. 多因素认证 (MFA)

彻底解决暴力破解的最佳方案。除了密码，还需要手机验证码、指纹等第二因素。即便攻击者猜中了密码，也无法登录。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何防护，可以直接用 Burp 快速爆破。Medium 级别引入了延迟机制，使得爆破效率大幅降低。
  • 与 High 级别的区别：High 级别不仅引入了延迟，还增加了动态 Token 和更多的随机性，使得纯粹的自动化爆破变得极其困难。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者只做了“缓解措施”，而没有做“根治”。增加 sleep(2) 虽然能防住简单的脚本小子，但对于有充足时间的黑客或分布式僵尸网络来说，依然可以通过分布式请求绕过时间限制。

从历史角度看，很多金融系统在早期就是只加了延迟，后来随着算力提升，逐渐升级到了账户锁定、多因素认证等更强的手段。

3. 这种的应用

在护网中，如果遇到有延迟的登录接口，攻击者通常会放弃暴力破解，转而寻找其他漏洞（如 SQL 注入、弱口令泄露等）。防御者则会利用延迟和日志监控，及时发现并封禁攻击 IP。

4. 如何抽象理解概念（大白话）

把 Medium 级别的暴力破解比作“强行闯关”：

  • Low 级别：门口没有保安，你可以无限次冲进去试错。
  • Medium 级别：门口有个保安，你每试错一次，他就把你拦在门外 2 分钟。虽然你依然能试，但试 1000 次需要 2000 分钟，你大概率会放弃。
  • 正确的做法：不是继续硬试，而是去找钥匙（SQL注入拿密码）。
