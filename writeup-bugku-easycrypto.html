easy_crypto - Bugku Crypto Writeup

2026年9月12日 Bugku CTF Crypto 摩斯密码

这道题名为 easy_crypto，提示和描述都是“01”，附件是一个名为 010.txt 的文件，里面全是 0 和 1。这明确指向了摩斯密码（0代表点，1代表横线）。

一、题目信息

  • 题目名称：easy_crypto
  • 题目平台：Bugku CTF
  • 题目类型：Crypto / 摩斯密码
  • 题目提示：01
  • 附件内容：010.txt（包含大量0和1）
  • 涉及工具：Mac 终端（tr 命令）、手动对照摩斯电码表

二、解题过程（详细步骤与踩坑记录）

1. 识别编码类型与初步尝试

看到文件内容只有 0 和 1，并且题目提示是“01”，我立刻联想到摩斯密码。在摩斯密码中，通常用“.”代表点，“-”代表横线。

我尝试在 Mac 终端中使用 tr 命令将文本中的 0 和 1 批量替换为摩斯密码符号，然后丢进在线工具解码。

cat 010.txt | tr '0' '.' | tr '1' '-' > morse.txt

2. 工具解码失败与手动破局

在线工具输出了类似 FLAG%u7bM0RSE%udC0DE...} 的乱码。原因是工具无法识别 ----.-- 和 -----.- 这类非标准长度的字符（通常是出题人自定义的扩展符号，如 `{` 和 `}`），导致解码中断并输出了错误字符。

我决定放弃工具，手动对照摩斯电码表逐字翻译：

  • ..-. = F
  • .-.. = L
  • .- = A
  • --. = G
  • ----.-- = { （自定义扩展符号）
  • -- = M
  • ----- = 0
  • .-. = R
  • ... = S
  • . = E
  • ..--.- = _ （下划线）
  • -.-. = C
  • --- = O
  • -.. = D
  • . = E
  • ..--.- = _
  • .---- = 1
  • ... = S
  • ..--.- = _
  • .. = I
  • -. = N
  • - = T
  • . = E
  • .-. = R
  • . = E
  • ... = S
  • - = T
  • .---- = 1
  • -. = N
  • ----. = 9
  • -.-.-- = !
  • -----.- = } （自定义扩展符号）

拼接后得到了混淆字符的明文：M0RSE_C0DE_1S_INTEREST1N9!。

3. 格式还原与提交

根据平台的 Flag 格式 flag{...}，我将 M0RSE_C0DE_1S_INTEREST1N9! 进行大小写转换和微调（在尝试中发现将数字 0 还原为字母 o 也可以成功提交），最终成功通关。

最终 Flag： flag{m0rse_code_1s_interest1n9!}

三、知识点总结（核心复习素材）

  • 1. 摩斯密码的变体与自定义符号：标准摩斯密码只有字母、数字和标点，但在 CTF 中，出题人常常自定义扩展字符（如本题中的 ----.-- 代表 {）。在线工具往往无法识别这些变体，遇到时不要盲从工具，要敢于手动查表推导。
  • 2. 终端文本处理工具 tr：在 Mac 终端中使用 cat 010.txt | tr '0' '.' | tr '1' '-' 可以快速进行字符替换，这是数据预处理的神技。
  • 3. 应对不完美数据的纠错与格式还原：CTF 题目中的数据往往带有混淆（如 0 和 O 混用，1 和 I 混用）。在提交时，要结合标准 Flag 格式进行容错尝试。
