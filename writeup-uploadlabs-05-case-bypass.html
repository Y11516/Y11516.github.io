Upload-Labs Pass-05

2026年9月26日 Upload-Labs Web安全 文件上传 大小写绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-05 (后缀大小写绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 代码审计 / 大小写绕过
  • 靶场链接：http://localhost:8082/Pass-05/index.php（本地环境）
  • 涉及工具：Chrome浏览器 (F12开发者工具)、Network面板

二、解题步骤

1. 分析题目考什么

本题的核心考点是后缀大小写绕过。通过对比 Pass-04 和 Pass-05 的源码可以发现，Pass-05 删除了 strtolower() 函数，导致黑名单匹配是严格区分大小写的。攻击者只需上传后缀为 .PHP 或 .Php 的文件，即可绕过黑名单。

2. 怎么想（破题思路）

  • 在 Pass-05 页面直接上传 shell.Php，前端 JS 弹窗拦截。
  • 在 F12 Console 中执行 checkFile = function() { return true; } 覆盖前端校验。
  • 重新上传 shell.Php，后端黑名单只匹配小写 .php，遇到大写直接放行。
  • 在 Network 面板中找到被靶场重命名后的真实路径，访问并验证。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：前端 JS 残留拦截

踩坑情况：上传 shell.Php 时，页面弹窗提示禁止上传。

原因分析：虽然 Pass-05 后端代码删除了 strtolower()，但前端 JS 校验依然存在，且对大小写混合的文件名也进行了拦截。

改进方式：按 F12，在 Console 中执行 checkFile = function() { return true; }，禁用前端拦截。

踩坑记录二：文件上传成功后访问提示 404

踩坑情况：上传了 pass05_shell.Php，但访问该文件时提示 404 Not Found。

原因分析：靶场源码第14行明确写着 $img_path = UPLOAD_PATH.'/'.date("YmdHis").rand(1000,9999).$file_ext;，这意味着**后端会将你上传的文件重命名成一串带时间戳和随机数的数字**，你原来的文件名被丢弃了。

改进方式：在 F12 的 Network 面板中，找到上传请求，在响应头或返回的 HTML 中找到真实的数字文件名（如 202609261206186590.Php），访问这个真实路径进行验证。

踩坑记录三：环境差异（php -S 不支持大写后缀）

踩坑情况：访问真实的 202609261206186590.Php 文件时，页面没有执行 PHP 代码，而是直接输出了 PHP 源码（<?php ... ?>）。

原因分析：本次靶场使用的是 php -S localhost:8082 启动的 PHP 内置服务器。内置服务器非常死板，默认只将全小写 .php 结尾的文件交给 PHP 解析器。因为后缀是大写 .Php，内置服务器把它当成静态文本直接返回。

改进方式：这不影响本次通关（文件已成功上传并绕过黑名单）。如果要在本地完全模拟真实环境，建议使用 MAMP、phpStudy 等 Apache 集成环境，即可正常解析执行。

详细实操步骤（Payload逐字解释）

第一步：禁用前端 JS

按 F12 打开 Console，输入并回车：

checkFile = function() { return true; }

第二步：准备 WebShell 并改后缀

在本地新建 shell.php，内容为：

<?php echo "PASS-05-SUCCESS"; @eval($_POST['cmd']); ?>

将其复制一份并重命名为 pass05_shell.Php（首字母大写）。

第三步：上传并获取真实路径

选中 pass05_shell.Php 上传，页面提示“上传成功”。

在 F12 的 Network 面板中，找到对应的 POST 请求，观察返回的 HTML 中是否有类似 ../upload/202609261206186590.Php 这样的路径。

第四步：验证

访问该真实路径。如果显示源码或空白，说明文件已经成功上传到了服务器上，本次注入（绕过黑名单）成功。

4. 怎么迁移（跨领域联想）

  • 编程语言的大小写规范：在 PHP、Python 等语言中，变量名和函数名是区分大小写的，而 HTML、SQL 的某些部分则不区分。这种差异常常成为开发漏洞的温床。开发者必须清晰地了解所使用语言的特性。
  • 输入验证的规范化：在安全防御中，对任何用户输入（如文件后缀）进行过滤前，必须先执行“规范化”处理（如统一转为小写、去除空格、URL 解码等）。否则，攻击者就能利用大小写、空格、特殊字符等变体绕过。
  • 环境差异与漏洞触发：同一个漏洞在不同环境下的触发条件不同。Pass-05 在某些 Apache 环境下靠大小写就能执行，而在 `php -S` 环境下则只能绕过黑名单而无法执行代码。这提醒我们，渗透测试一定要结合实际环境（Context）来判断。

三、名词大全与原理深度复盘

1. strtolower() 函数

PHP 中用于将字符串转换为小写的函数。在文件上传安全中，它常被用于统一后缀格式，防止攻击者通过大小写混合（如 .pHp）绕过黑名单。Pass-05 删除了此函数，导致黑名单校验失效。

2. in_array() 函数

PHP 中用于检查数组中是否存在某个值的函数。默认情况下，in_array() 的匹配是区分大小写的。例如 in_array('.PHP', array('.php')) 会返回 false。

3. Linux 文件系统的大小写敏感

在 Linux 环境下，shell.Php 和 shell.php 是两个完全不同的文件。而在 Windows 环境下，它们被视为同一个文件。利用 Linux 的大小写敏感特性，攻击者可以绕过只匹配小写的黑名单。

4. 代码审计思维

通过对比 Pass-04 和 Pass-05 的源码，直观地发现了 strtolower() 的缺失。这种通过阅读源码来寻找安全逻辑漏洞的方法，就是代码审计。它是渗透测试中最高效、最根本的漏洞挖掘方式之一。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-04 的区别：Pass-04 有 strtolower()，大小写绕过无效，必须使用 .htaccess。Pass-05 删除了该函数，大小写绕过重新生效。
  • 与前两关的共同点：依然需要先绕过前端 JS（F12 覆盖函数），再处理后端逻辑。

2. 这种题目的出现原因（为什么存在）

许多开发者在处理黑名单时，思维还停留在“列出所有危险后缀”。但他们忽略了攻击者可以通过大小写、空格、点号、特殊字符等多种方式对输入进行“变形”。这本质上是防御思维不够完善，没有意识到对输入进行“规范化”处理是安全防御的第一步。

3. 这种应用在实际中如何体现？

在真实的渗透测试中，面对严格的黑名单，攻击者通常会先尝试各种变形。大小写绕过是其中最基础的一种。如果后端屏蔽了大小写，还会尝试使用双写（如 .pphphp）、空格（.php ）、点号（.php.）、以及 Windows 的文件流特性（.php::$DATA）。防御者则应果断采用“白名单”机制。

4. 如何抽象理解概念（大白话）

把靶场比作一个“严格的门卫”：

  • Pass-05 的门卫手里有一份黑名单，写着“禁止携带‘刀’（.php）进入”。
  • 门卫非常死板，只认小写。你拿着写着“刀（.PHP）”的包裹走过去，门卫一看，大写字母，不认识，直接放你进去了。
  • 如果门卫在检查前规定：“所有包裹名称都必须先统一翻译成小写再看”，那你就无法蒙混过关了。这就是 strtolower() 存在的意义。
