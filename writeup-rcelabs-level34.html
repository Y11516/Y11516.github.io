RCE-Labs Level 34 - 反引号优先级与换行符截断

2026年10月5日 RCE-Labs 命令替换 源码审计

  • 1.题目名称：RCE-Labs Level 34 (反引号优先级)
  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 命令拼接 / 源码审计
  • 4.靶场链接：http://靶机IP:8080/less-34/
  • 5.涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

源码中依然存在强制拼接 $cmd = "ls " . $cmd;。弹窗提示“反引号里的命令优先级高，会先执行，再执行外面的命令”。核心考点是利用 Shell 的命令替换机制，截断系统预置命令。

血泪踩坑记录：反引号导致 stderr 被吞

错误尝试：直接使用反引号 Payload：?cmd=%60cat%20%2Fflag%60（即 `` `cat /flag` ``）。

失败响应：页面没有任何回显（一片空白）。

根本原因：

  • PHP 拼接后命令为 ls `cat /flag`。
  • Shell 优先执行反引号内的 cat /flag，拿到结果 flag{TEST_Dynamic_FLAG}。
  • 命令被替换为 ls flag{TEST_Dynamic_FLAG}。因为文件不存在，ls 报错：ls: cannot access 'flag{...}': No such file or directory。
  • 致命陷阱：这个报错信息输出到的是 **标准错误流（stderr）**。而 PHP 的 system() 函数默认只回显 **标准输出（stdout）**。Flag 明明在报错信息里，却被 PHP 无情丢弃了。

改进与成功：放弃反引号，改用**换行符 `%0A`** 截断 ls。在 Shell 里，换行符相当于执行了两次命令，完美截断了 ls 前缀。

2. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$cmd = $_GET['cmd'] ?? '...';
$cmd = "ls " . $cmd;
$pattern = '/;|&|\|/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与逐字解析

?cmd=%0Acat%20%2Fflag

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

命令逐字解析：

  • %0A：换行符。在 Shell 里，它会被解释为一条命令的结束，相当于执行了回车换行。
  • cat %2Fflag：cat /flag。
  • 最终效果：拼接后执行 ls \n cat /flag。Shell 先执行 ls（无输出），然后换行执行 cat /flag。因为 cat 的输出是标准输出（stdout），PHP 的 system() 可以完美捕获并回显到页面上。

3. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的命令截断：在真实内网中，遇到命令被拼接了前缀，经常利用换行符 %0A、逻辑或 ||、反引号进行截断。关键在于理解 Shell 的解析顺序和标准流的重定向。
  • 系统运维中的换行执行：写 Shell 脚本时，换行符是天然的“命令分隔符”。通过分号、换行符将多条命令堆叠在一个脚本里执行，是自动化运维的基础操作。

三、名词大全与原理深度复盘

1. 反引号 ` 与 $() 的深度对比

它们都是 Shell 的**命令替换符（Command Substitution）**。

  • `命令`（反引号）：旧式写法。容易和单引号混淆，且不支持嵌套。
  • $(命令)（美元符+小括号）：新式写法。支持嵌套，可读性更好（如 $(cat $(echo /flag))）。
  • 共同点：Shell 优先执行里面的命令，然后把结果替换回来，最后再执行外面的命令。优先级最高。

2. 标准输出 (stdout) 与 标准错误 (stderr) 的陷阱

  • stdout（文件描述符 1）：命令正常执行的结果输出。PHP 的 system() 会捕获并回显它。
  • stderr（文件描述符 2）：命令执行失败时的报错输出。PHP 的 system() **默认不会回显它**，直接丢弃。
  • 这就是为什么反引号执行 cat 成功，但由于变成了 ls 的报错参数，导致 stderr 被丢弃，页面空白。
  • 解决思路：如果必须用反引号，可以把 stderr 重定向到 stdout：?cmd=%60cat%20%2Fflag%202%3E%261%60（加 ` 2>&1`），这样报错信息也能被捕获。

3. 换行符 `%0A` 的妙用

%0A 是 URL 编码的换行符（LF）。在 Shell 脚本里，换行符就是原生的命令分隔符。它比 ;、&&、|| 更隐蔽，常常能绕过 WAF 对符号的拦截。但要注意，Nginx 有时也会对 %0A 产生警觉，遇到 400 错误时需用 Burp 发送原始包。

4. 核心网络基础与护网认知（陌生人也能看懂版）

  • 外网（公网/互联网）：拥有全球唯一的门牌号（公网 IP，如 8.8.8.8），任何人任何车都能开到你家门口。
  • 内网（局域网）：门牌号是“小区内部编号”（如 192.168.1.19），只有小区内部的人才能互相找到。外面的人想找你，必须经过小区保安（路由器/NAT）允许并做地址转换。
  • 完全隔离的内网：小区不仅不让外面的人进，甚至把大门用砖头砌死了（物理隔离）。这种环境下，反弹 Shell 和重定向写入 100% 都会失效。
  • HTTP 是公网吗？这是一个经典的误解！HTTP 不是网络，它是语言（协议）。无论访问内网 OA 还是百度官网，用的都是 HTTP 语言。
  • 操作系统与网络的关系：电脑操作系统是管理网络硬件的“交通警察”。你监听 80 端口成功、9002 端口失败，根本原因就是操作系统或 Docker 的虚拟网卡策略，只放行了 80 端口的出站，拦截了 9002 端口。
  • 护网是在攻击内网吗？护网是一场“攻城战”：第一阶段是“外网打点”（攻打城门），寻找对外门户的漏洞；第二阶段是“内网渗透”（巷战与横向移动），以边界服务器为跳板在内网提权、抓密码；第三阶段是“拿下靶标”（直捣黄龙），控制核心数据库或域控。内网渗透是决定胜负的主战场。

四、题目思考

1. 这跟前面关卡的区别

Level 31 考的是 ;，Level 32 考的是 &&，Level 33 考的是 ||，Level 34 考的是**反引号优先级**。这四关把 Shell 的命令连接符和替换符几乎考了个遍。这提醒我们：不要被前期的经验固化思维，每到一个新环境，一定要重新侦察源码。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发者常常在不经意间将用户输入与系统命令拼接（如 ls ）。如果过滤不严，攻击者就可以利用 Shell 的分隔符、反引号来截断原本的命令。这类题目正是模拟开发者修补漏洞时的“漏网之鱼”。

3. 这种漏洞在实际中的应用

在护网和红队行动中，遇到 WAF 是家常便饭。利用分隔符、通配符、变量替换、反引号替换等手段绕过关键字拦截，是渗透测试人员的基本功。同时，要懂得分析 400、403、500 等状态码的差异，判断是 Nginx、WAF 还是后端代码在拦你。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。监考老师（开发者）强行在你面前放了一块“请保持安静”的牌子（ls ）。你不能用分号（;）或者逻辑符（&&、||），因为它们被拦截了。于是你举起了一张纸（反引号），上面写着“我要交卷”，虽然老师让你把纸放在“请保持安静”的牌子后面（触发了 `ls` 报错），你没得到回应（stderr 被吞）。最后你直接用力敲了一下桌子（换行符 `%0A`），声音打断了所有规则，你直接喊出了“我要交卷”，老师终于把卷子（flag）递给了你。

5. 他的本质

本质是利用 Shell 的命令替换机制和命令分隔符，截断应用层强制拼接的上下文，将原本的“参数”提升为“独立的命令”，从而执行恶意 Payload。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：不要使用字符串拼接来构造系统命令！应使用编程语言提供的安全 API（如 PHP 的 escapeshellarg），或者直接使用白名单限制用户输入。同时，WAF 应拦截反引号、换行符、;、|、& 等所有命令分隔符。
  • 破解方（红队）：如果所有分隔符都被拦截，尝试使用换行符 %0A。如果写文件也被拦截，考虑利用语言特性（如 PHP 的 include 包含文件，或利用已上传的木马）来实现读取。
