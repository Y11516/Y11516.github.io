SQLi-Labs Less-41

2026年9月29日 SQLi-Labs Web安全 SQL注入 盲注 + 堆叠注入

一、题目信息

  • 题目名称：SQLi-Labs Less-41 (GET - BLIND based - Integer - Stacked)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 时间盲注 / 数字型堆叠注入
  • 靶场链接：http://localhost:8081/Less-41/（本地环境）
  • 涉及工具：Chrome浏览器 (F12 开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是数字型盲注与堆叠注入的结合。Less-41 没有引号闭合，且没有报错回显。必须利用 sleep() 函数制造延迟来验证注入是否成功。

2. 怎么想（破题思路）

  • 页面提示“numeric value”，确认是数字型，无需闭合引号。
  • 构造时间盲注 Payload：?id=1 and if(1=1,sleep(3),0)-- -。
  • 最终通过 F12 的 Network 面板观察请求耗时，若超过 3 秒，说明注入成功。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：习惯性加引号导致失败

踩坑情况：习惯性地输入 ?id=1'，导致语法错误或无效注入。

原因分析：Less-41 是数字型注入，没有引号需要闭合。

改进方式：直接使用 ?id=1 and ... 或 ?id=1; ...，不加任何引号。

详细实操步骤（Payload逐字解释）

第一步：构造 Payload

在浏览器地址栏输入：

http://localhost:8081/Less-41/?id=1%20and%20if(1=1,sleep(3),0)--%20-

第二步：Payload 逐字解析

  • 1：数字型参数，无需闭合。
  • %20and%20：URL 编码的空格和逻辑与。
  • if(1=1, sleep(3), 0)：时间盲注，强制数据库停顿 3 秒。
  • --%20-：注释符，阻止后续 SQL 执行。

第三步：验证结果

页面无变化，但 F12 的 Network 面板中，该请求的耗时显示为 3.xx s，证明时间盲注成功。

4. 怎么迁移（跨领域联想）

  • 盲注的实战意义：在真实渗透中，一旦发现页面无报错回显，且防御较严，时间盲注是最后的手段。
  • 堆叠注入的破坏力：堆叠注入不仅能查数据，还能直接对数据库进行增、删、改操作。
  • 安全开发启示：使用参数化查询（Prepared Statements）是防御 SQL 注入的终极方案。

三、名词大全与原理深度复盘

1. 时间盲注 (Time-Based Blind SQL Injection)

当页面没有回显位，且过滤了报错信息时，攻击者通过构造 if(条件, sleep(N), 0) 或 sleep(N) 来制造延迟。如果条件成立，页面响应时间会显著增加。

2. 堆叠注入 (Stacked Query Injection)

利用分号 ; 在同一数据库连接中执行多条 SQL 语句。常见于后端使用 mysqli_multi_query() 的 PHP 应用。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-40 的区别：Less-40 是字符型（需要闭合 ')），Less-41 是数字型（无需闭合）。
  • 与 Less-39 的区别：Less-39 是数字型堆叠注入（有回显），Less-41 是数字型堆叠注入（盲注，无回显）。

2. 这种题目的出现原因（为什么存在）

开发者在开发某些后台功能时，可能为了图方便，使用了 mysqli_multi_query() 来执行来自用户的多个操作。同时，出于安全考虑，屏蔽了错误回显，但依然留下了盲注和堆叠注入的风险。

3. 这种应用在实际中如何体现？

在实战中，堆叠注入通常出现在后台管理、批量操作、数据导入导出等接口。由于它能直接修改数据库，往往比普通查询注入危害更大。

4. 如何抽象理解概念（大白话）

把靶场比作一个“沉默的快递站”：

  • 普通注入：你在快递单上写“查一下我的包裹”（SELECT），快递员会直接告诉你结果。
  • 盲注：你问“查一下我的包裹”，但快递员（网站）不说话。你只能问“如果包裹在，你就发呆3秒”。他发了3秒呆，你就知道包裹在。
  • 堆叠注入：你甚至在快递单上写了“查一下包裹；顺便把我的地址改成黑客基地”。如果快递站支持多行处理，你的第二句话就会生效。
