PHP反序列化 - Pikachu Writeup

2026年9月20日 Pikachu Web安全 PHP反序列化

一、题目信息

  • 题目名称：PHP反序列化
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / PHP反序列化漏洞 / 代码执行
  • 靶场链接：http://localhost:8080/vul/unserilization/unser.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是PHP反序列化漏洞（PHP Object Injection）。PHP 的 serialize() 用于将对象转为字符串，unserialize() 用于将字符串还原为对象。如果后端接收了用户传入的序列化字符串并执行反序列化，且程序中存在拥有危险魔术方法（如 __destruct、__wakeup、__toString）的类，攻击者就可以通过构造恶意的序列化 Payload，控制对象属性，从而触发代码执行（RCE）或文件操作。

2. 怎么想（破题思路）

页面提示“这是一个接受序列化数据的api”，提供了一个输入框。

  • 首先需要找到后端代码中的类定义（白盒审计）。但在该靶场中，由于没有源码，我们根据已知的漏洞利用经验直接构造。
  • 根据 Pikachu 的经典设计，后端有一个名为 S 的类，里面包含一个可控的变量（通常是 test 或 cmd）。
  • 该类的 __destruct() 魔术方法中执行了 eval($this->test); 或 system($this->test);。
  • 我们需要构造一个序列化字符串，类名为 S，属性名为 test，值为我们想要执行的系统命令（如 whoami）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：试图在 F12 里搜索 class 和 eval 毫无结果

踩坑情况：在页面按 F12 打开 Elements 面板，搜索 `class` 或 `eval`，什么都搜不到。

原因分析：浏览器里展示的只是“经过 PHP 后端解析后”生成的纯 HTML 代码。真正的 PHP 源码存在于服务器端，是看不见的。所有关于后端类定义、魔术方法的代码逻辑，都需要基于漏洞利用常识或代码审计来获取。

改进方式：放弃在 F12 里寻找后端逻辑，根据反序列化的经典利用 Payload 格式直接构造并提交测试。

踩坑记录二：把 Payload 输错位置（输到了 F12 搜索框）

踩坑情况：误把 Payload 输进了 F12 开发者工具的搜索框里，发现没有反应。

原因分析：F12 的搜索框功能是“在代码中寻找文本”，而不是“向后端发送请求并执行代码”。

改进方式：必须将 Payload 粘贴到网页左侧的真正的白色输入框中，然后点击“提交”按钮，才会触发后端反序列化。

踩坑记录三：执行 phpinfo() 显示原样文本

踩坑情况：提交包含 phpinfo(); 的 Payload，页面直接回显了文本“phpinfo();”，没有弹出紫色页面。

原因分析：由于该 Docker 镜像环境的 disable_functions 配置，可能导致 phpinfo() 被禁用，或者因为反序列化逻辑没有正确执行。

改进方式：改用系统命令执行函数（如 system、exec），并在属性值中填入 whoami。当页面回显 `pikachu` 时，即证明系统命令被执行，漏洞利用成功。

终极解法：构造反序列化 Payload 执行系统命令

在输入框中提交以下 Payload：

O:1:"S":1:{s:4:"test";s:6:"whoami";}

代码逐个符号深度解析：

  • O：Object，表示这是一个对象。
  • :1:：表示对象名的长度为 1 个字符。
  • "S"：对象名，即后端定义的类名。
  • :1:：表示对象内部有 1 个属性（成员变量）。
  • {：对象属性的开始标志。
  • s:4:"test"：这是一个字符串（s），长度为 4（4），内容为 test（即被执行的属性名）。
  • ;：分隔属性名和属性值。
  • s:6:"whoami"：属性值是一个字符串（s），长度为 6（6），内容为 whoami（系统命令）。
  • ;：属性结束标志。
  • }：对象属性结束标志。

提交后，页面回显 `pikachu`，证明后端在执行反序列化时，触发了魔术方法并成功执行了系统命令，RCE 漏洞利用成功。

4. 怎么迁移（跨领域联想）

  • POP 链构造（Property Oriented Programming）：在复杂的现代框架中，很难通过一个简单的类直接执行命令。攻击者需要寻找多个类之间的调用关系，将它们串联起来形成一条利用链（POP Chain），最终导向危险函数。
  • Phar 反序列化：在 PHP 中，很多文件操作函数（如 file_get_contents）在解析 phar:// 伪协议时，会自动触发 Phar 文件内部的元数据反序列化，这通常用于绕过对 unserialize() 函数的限制。
  • 代码审计与安全开发：在开发中，严禁反序列化用户可控的数据（如 Cookie、GET/POST 参数）。如果必须使用，应使用 JSON 等更安全的数据格式，或通过签名（HMAC）校验序列化数据的完整性。

三、名词大全与原理深度复盘

1. 序列化（Serialize）与反序列化（Unserialize）

序列化是将对象转换为可存储或传输的字符串格式的过程；反序列化则是将字符串还原为对象。PHP 使用 serialize() 和 unserialize() 来完成这两项操作。攻击者利用的是 unserialize() 自动实例化类并调用魔术方法的特性。

2. PHP 魔术方法（Magic Methods）

PHP 中以双下划线 __ 开头的方法，会在特定条件下自动触发。常见的反序列化利用点包括：

  • __destruct()：对象被销毁时触发。
  • __wakeup()：执行 unserialize() 时触发。
  • __toString()：对象被当作字符串使用时触发。

3. 为什么属性值必须是长度精确的字符串？

PHP 在解析序列化字符串时，会严格按照指定的长度来读取字符串内容。如果长度不匹配（例如把 `whoami` 写成 `s:5:"whoami"`），解析就会失败，导致反序列化中断，Payload 失效。这是构造反序列化 Payload 时最常见的错误。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 RCE exec "eval" 相比：eval 注入是直接在前端输入 PHP 代码；PHP 反序列化是通过构造特殊的序列化字符串，通过触发后端已有的类方法（魔法函数）来间接执行代码。
  • 与 SQL 注入相比：SQL 注入是攻击数据库层，通过拼接 SQL 语句；反序列化是攻击应用逻辑层，利用对象生命周期的特性执行代码。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者为了让对象可以跨页面传递或持久化存储，使用了序列化机制。但当用户输入被直接传入 unserialize() 时，攻击者就可以控制对象的属性，进而触发危险的操作。这与开发人员对序列化机制的安全性认识不足有关。

3. 这种应用在实际中如何体现？

在真实的 Web 应用中，反序列化漏洞常出现在使用 Java（CommonsCollections 链）、PHP（ThinkPHP/Laravel 框架链）、Python（Pickle）的项目中。这类漏洞通常能导致远程代码执行（RCE），危害极大，往往被列为高危漏洞。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作一个快递员：

  • 序列化：你把一辆自行车（对象）拆成零件，贴上清单（序列化字符串）寄给朋友。
  • 反序列化：朋友收到后，按照清单组装。
  • 漏洞：你在清单上偷偷加了一句“组装完成后，帮我把家里的垃圾扔了，并把钥匙留给路过的人”。朋友是个死板的人，不仅组装好了自行车，还顺手执行了你的额外指令。这就是反序列化漏洞的本质——利用信任，让服务器在“拼装对象”时执行了非预期的恶意操作。
