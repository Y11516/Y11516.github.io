Over Permission(垂直越权) - Pikachu Writeup

2026年9月20日 Pikachu Web安全 越权

一、题目信息

  • 题目名称：Over Permission - 垂直越权
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 越权访问漏洞 / 垂直越权（低权限访问高权限）
  • 靶场链接：http://localhost:8080/vul/overpermission/op2/op2_login.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是垂直越权（Vertical Privilege Escalation）。与水平越权（同级用户互看数据）不同，垂直越权是指低权限用户（如普通员工 pikachu）通过 URL 猜测、接口未鉴权等方式，直接访问或操作只有高权限用户（如管理员 admin）才能访问的后台管理功能。

2. 怎么想（破题思路）

题目提示了普通用户（pikachu）和超级管理员（admin）的账号。解题思路如下：

  • 使用普通用户 pikachu / 000000 登录，观察其权限范围。
  • 发现普通用户登录后，页面提示“欢迎来到后台管理中心,您只有查看权限!”，说明系统虽然给了查看列表的权限，但并未严格隔离后台接口。
  • 尝试直接猜测并访问管理员专属的编辑页面（如 op2_admin_edit.php）。
  • 如果页面返回了“创建用户”的表单，说明后端只校验了“是否登录”，而没有校验“是否具有管理员权限”，垂直越权成功。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：普通用户界面没有管理入口

踩坑情况：使用 pikachu 登录后，页面只有“查看用户列表”的功能，没有“添加用户”、“删除用户”等按钮，无法通过点击按钮触发越权。

原因分析：前端页面通过权限判断隐藏了管理员按钮，但后端接口可能并没有做权限校验。

改进方式：进入“查看用户列表”页面，观察 URL 结构（如 op2_user.php），推测管理员编辑页面的命名规则（如 op2_admin_edit.php），直接在地址栏进行 URL 猜测访问。

终极解法：通过 URL 猜测直接访问管理员接口

第一步：普通用户登录

在登录框输入 pikachu / 000000，点击 Login。

第二步：进入查看列表页面

在后台管理中心点击“查看用户列表”，观察浏览器地址栏，URL 为：.../op2/op2_user.php。

第三步：构造并访问管理员页面 URL

在地址栏手动将 op2_user.php 修改为 op2_admin_edit.php，按回车：

http://localhost:8080/vul/overpermission/op2/op2_admin_edit.php

代码逐个符号深度解析：

  • op2_user.php：普通用户列表页面，负责展示用户数据。
  • op2_admin_edit.php：越权目标。这是管理员专属的编辑页面，负责处理用户创建逻辑。
  • 通过直接替换文件名，我们跳过了前端页面的按钮限制，直接请求了后端的管理接口。

第四步：验证垂直越权

页面成功显示：“hi,pikachu,欢迎来到后台管理中心”，并且展示了“创建用户”的表单。这证明普通用户 pikachu 成功窃取了管理员 admin 的权限，垂直越权攻击成功。

4. 怎么迁移（跨领域联想）

  • API 接口安全：在现代前后端分离架构中，前端（Vue/React）会根据用户角色隐藏菜单，但后端 API 如果仅依赖 JWT（JSON Web Token）解析出的用户信息，而未判断用户角色（Role），攻击者就可以直接调用 API 接口进行越权操作。
  • 代码审计：审计代码时，应重点关注所有包含 admin、edit、delete 等敏感操作的接口。查看这些接口是否在进入业务逻辑前，进行了 if ($_SESSION['role'] !== 'admin') die('Access Denied'); 这样的权限校验。
  • 企业权限管理（RBAC）：规范的权限管理应采用 RBAC（基于角色的访问控制）模型。后端在进行任何数据库操作前，必须严格校验当前用户的角色是否具有执行该操作的权限，绝不能依赖前端隐藏按钮来保证安全。

三、名词大全与原理深度复盘

1. 垂直越权（Vertical Privilege Escalation）

指低权限用户通过非法手段获取并执行高权限用户的功能。例如，普通用户访问管理员页面、普通会员执行 VIP 操作。垂直越权的危害极大，一旦成功，往往意味着系统后台被完全控制。

2. 水平越权与垂直越权的区别

水平越权是“同级别”之间的越权（如用户A查看用户B的订单）；垂直越权是“跨级别”的越权（如普通用户查看管理员后台）。水平越权通常由于参数可控导致，垂直越权通常由于接口未做角色校验导致。

3. 为什么会出现垂直越权？

根本原因在于开发者将“安全校验”放在了前端。开发者认为只要把“添加用户”的按钮隐藏了，普通用户就无法操作。但 HTTP 请求是可以通过工具直接构造的，前端隐藏按钮毫无意义，后端缺乏鉴权是导致该漏洞的唯一原因。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与水平越权相比：水平越权是查看同级别其他用户的数据，只涉及数据越权；垂直越权是获取管理员级别的系统操作权限，涉及功能越权，危害等级更高。
  • 与 SQL 注入相比：SQL 注入是攻击数据库底层，属于技术层面的漏洞；垂直越权是业务逻辑层面的漏洞，不涉及代码语言缺陷，完全是因为权限设计不当。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在进行模块化开发时，只对登录接口进行了身份认证（Authentication），但未对具体的管理接口进行权限授权（Authorization）。只要用户处于登录状态，无论其角色是什么，都可以调用所有接口。

3. 这种应用在实际中如何体现？

在真实的渗透测试中，垂直越权漏洞常出现在企业 OA 系统、电商后台管理系统。攻击者通过越权可以添加管理员账号、修改订单金额、删除核心数据，造成巨大的经济损失。这也是 OWASP Top 10 中“失效的访问控制”的核心体现。

4. 如何抽象理解概念（大白话理解）

如果把公司比作一个系统：

  • 正常逻辑：你是公司的普通文员（pikachu），你只能进普通办公室。CEO 办公室（admin_edit.php）你是进不去的。
  • 垂直越权：你发现CEO办公室的门禁只检查“你是不是本公司的人”（Cookie），不检查“你是不是CEO”。你拿着一张普通员工卡（pikachu 的会话），直接刷卡进了CEO办公室，甚至还用里面的电脑开除了几名员工。这就是垂直越权的本质——门禁只看你有没有卡，不看你的职位。
