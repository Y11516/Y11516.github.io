一、题目信息

  • 题目名称：读取源代码
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程代码执行） / 文件包含 / PHP 伪协议利用
  • 靶场链接：http://challenge-ccda50ff65aa382a.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 php://filter 伪协议读取服务器上的源代码或敏感文件。后端代码强制要求 file 参数必须以 php:// 开头。由于题目提示 Flag 在 /flag 文件中，且无法直接执行代码（上一题的 php://input 不适用），我们需要使用 PHP 的过滤器链，将目标文件内容进行 Base64 编码后读出，从而绕过服务器的解析器。

2. 怎么想（破题思路）

  • 页面提示“我没有 Shell，如何获取 Flag？Flag 在 /flag”。这意味着我们需要直接读取这个文件。
  • 源码限制 file 参数必须以 php:// 开头。常规的本地文件包含（LFI）如 ?file=/flag 会被拦截。
  • 尝试使用 php://input 读取 /flag 是行不通的，因为 php://input 是读取 HTTP 请求体，而不是读取本地文件系统。
  • 思路：使用 PHP 的过滤流 php://filter。为了确保文件内容原样输出（不被 PHP 解析器执行，或因为二进制/特殊字符导致乱码），我们选择 convert.base64-encode 过滤器将内容进行 Base64 编码。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接包含 /flag 被拦截

踩坑情况：尝试访问 ?file=/flag，页面报错并提示 Hacker!!!。

原因分析：源码中的 substr($_GET["file"], 0, 6) === "php://" 强制检查参数前缀，不符合条件的直接进入 else 分支被拦截。

改进方式：必须使用 php:// 开头的伪协议。

踩坑记录二：使用 php://input 试图读取 /flag

踩坑情况：习惯性套用上一题的 Payload ?file=php://input，并在 POST 里写代码读取 flag，结果失败或无回显。

原因分析：php://input 用于执行我们输入的代码，而不是读取本地文件。要读取本地文件，必须换用能指向本地资源的流。

改进方式：改为使用 php://filter，搭配 resource=/flag 指向目标文件。

详细实操步骤

第一步：构造 Payload

直接在浏览器地址栏访问以下 URL：

http://challenge-ccda50ff65aa382a.sandbox.ctfhub.com:10800/?file=php://filter/convert.base64-encode/resource=/flag

Payload 逐字深度解析：

  • ?file=：后端接收的参数名。
  • php://：满足源码中 substr(..., 0, 6) === "php://" 的前缀校验。
  • filter：声明使用的是过滤器协议。
  • convert.base64-encode：调用内置的转换过滤器，将文件内容转换为 Base64 编码格式。
  • resource=/flag：指定过滤器要处理的资源路径，即根目录下的 flag 文件。

第二步：获取 Base64 字符串

访问上述 URL 后，页面会直接回显一长串 Base64 编码的字符串（如 Y3RmaHViezh...）。

第三步：解码并提交

复制这串乱码，去 [Base64 在线解码](https://www.base64decode.org/) 粘贴并解码，得到明文 Flag：ctfhub{8bfd4ee9ea738ebd62e31f33}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 源码泄露与代码审计：在实战中，找到 LFI 漏洞后，第一步往往是利用 php://filter 读取 index.php、config.php 等源码，通过审计代码发现数据库密码、隐藏的后门接口或更深入的利用点。
  • 绕过 WAF：部分 WAF 会拦截包含 php:// 关键字的请求。攻击者可以通过 URL 编码、大小写混合或二次编码（如 %70%68%70://）来绕过 WAF 的规则。
  • 其他封装协议组合：除了 filter，还有 data://（执行代码）、zip://（读取压缩包内文件）、phar://（反序列化利用）等，它们构成了 PHP 伪协议极其强大的攻击面。

三、名词大全与原理深度复盘

1. php://filter 伪协议

PHP 提供的一个元封装器，用于对文件流进行过滤处理。它允许你在读取文件之前，先对数据流进行转换（如编码、解码、大小写转换等）。它最常用于渗透测试中的源码读取。

2. 为什么必须使用 Base64 编码？

因为 include 会执行 PHP 代码。如果我们直接包含 /flag，且它是 PHP 文件，里面的代码会被执行（注释被吞掉）而无法回显；如果是二进制文件，直接输出可能会导致乱码或触发 WAF。Base64 编码将所有特殊字符转化为可打印的 ASCII 字符，确保数据原封不动地传回给攻击者。

3. 伪协议的安全边界

PHP 的伪协议本身不是漏洞，但一旦开发者在 include、file_get_contents 等函数中让用户可控，漏洞就产生了。防御伪协议攻击的根本在于：严格过滤用户输入，禁止包含动态变量，或将 allow_url_include 设为 Off。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 php://input 的区别：php://input 是从 HTTP 请求体中读取用户发送的代码并执行（输出数据流向是：客户端 -> 服务器）；php://filter 是读取服务器上的本地文件并传给客户端（输出数据流向是：服务器 -> 客户端）。
  • 与本地文件包含（LFI）的区别：常规 LFI 是直接包含文件并执行它；而本题是包含一个“过滤器”，让文件内容在经过过滤器转换后再输出，通常不执行代码。

2. 这种题目的出现原因

源于开发人员的功能滥用与安全边界缺失。开发人员为了方便读取文件，使用了 include，却没有白名单限制用户能读什么。PHP 内置的伪协议本就是强大功能，当用户输入没有被严格过滤时，它就成了绕过限制读取任意文件的利器。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，源码泄露往往比一个简单的 Flag 更有价值。通过读取源码，攻击者可以发现 SQL 注入点、未授权访问接口、硬编码的密钥等，从而将单一的 LFI 漏洞升级为完整的系统沦陷。

4. 如何抽象理解概念（大白话理解）

把服务器比作一家银行的金库：

  • 普通读取（LFI）：你想直接去金库拿一份文件，但保安（PHP 解析器）会检查文件内容，如果是“危险文件”（PHP 代码），会被当场销毁。
  • php://filter 伪协议：你告诉管理员：“我想借阅金库里的那份 /flag 文件，但我害怕路上被人偷看，请帮我用一个**密码本（Base64 编码器）**把内容全部转换成密码字母。”
  • 绕过与结果：保安看着满纸的“密码字母”（Base64 字符串），认为没有危险，直接放行。你拿到这份“密码信”后，用你自己的解码本翻译出来，里面正是你想要的 Flag。
