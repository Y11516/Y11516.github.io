二、解题过程（详细步骤）

1. 阅读源码，发现关键函数

访问靶场后，页面直接显示了源代码。关键逻辑如下：

<?php
error_reporting(0);
include "flag1.php";
highlight_file(__file__);
if(isset($_GET['args'])){
    $args = $_GET['args'];
    if(!preg_match("/^\w+$/",$args)){
        die("args error!");
    }
    eval("var_dump($$args);");
}
?>

2. 分析漏洞点：变量变量与正则限制

代码中最关键的是 eval("var_dump($$args);")。在 PHP 中，$$args 叫做“变量变量”，它会将变量 $args 的值作为另一个变量的名字来解析。

如果我们传入 args=GLOBALS，那么 $$args 就会变成 $GLOBALS。最终执行的代码是 var_dump($GLOBALS)。

但是代码上方有一个正则过滤：preg_match("/^\w+$/", $args)。它要求参数只能由字母、数字、下划线组成。所以直接传入 $GLOBALS 会失败，我们必须去掉 $，只传 GLOBALS。

3. 构造 Payload 并获取 Flag

在 URL 后拼接参数：

http://160.202.254.160:14783/?args=GLOBALS

回车后，代码成功执行了 var_dump($GLOBALS)。在页面打印出的大量全局变量中，包含了 flag1.php 里定义的 $flag 变量，成功拿到 Flag！

三、知识点总结（核心复习素材）

  • 1. PHP 变量变量（Variable Variables）：$$args 会把 $args 的值当成变量名。如果 $args = 'GLOBALS'，那么 $$args 就等价于 $GLOBALS。这是一个非常容易被利用的动态特性。
  • 2. 超全局变量 $GLOBALS：它包含了当前脚本中所有的全局变量。如果存在文件包含（include），那么被包含文件中定义的变量也会出现在 $GLOBALS 中，从而导致敏感信息泄露。
  • 3. 正则表达式的局限：/^\w+$/ 限制了输入不能包含特殊字符，但无法阻止我们传入合法的变量名（如 GLOBALS）。在代码审计中，要关注过滤条件是否能被合法的业务逻辑绕过。
