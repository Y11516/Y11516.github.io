一、题目信息

  • 题目名称：命令注入-过滤空格
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程命令执行） / 命令注入 / 黑名单绕过
  • 靶场链接：http://challenge-ce435aa6b848a573.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是过滤空格后的命令注入绕过。后端代码使用 preg_match_all("/ /", $ip, $m) 检测并拦截了用户输入中的空格字符。攻击者需要利用 Linux Shell 的特性，寻找无需空格即可分隔命令与参数的替代方案（如 ${IFS}、%09、< 等）。

2. 怎么想（破题思路）

  • 页面提示“这次过滤了空格，你能绕过吗”。
  • 源码中 preg_match_all("/ /", $ip, $m) 限制了输入中不能包含空格。
  • 没有空格，我们就无法写出 base64 flag.php 这样的命令。我们需要一个“假的空格”。
  • 方案一：使用 ${IFS}（Internal Field Separator）。这是 Linux 内部字段分隔符，Shell 会自动将其解析为空格。
  • 方案二：使用 %09（Tab 键）。正则只过滤了空格，Tab 键没有被过滤。
  • 读取文件时，如果使用 cat 导致空白，改用 base64。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：尝试用普通空格导致拦截

踩坑情况：直接输入 127.0.0.1; ls /，页面弹出拦截提示。

原因分析：输入中的空格被 preg_match_all 检测到，导致代码走向 else 分支。

改进方式：必须改用 ${IFS} 等替代方案。

踩坑记录二：使用 cat 读取 PHP 文件导致空白

踩坑情况：找到文件 flag_22401280515565.php 后，使用 cat 命令读取，页面显示空白。

原因分析：PHP 解析器会执行 <?php // ctfhub{...} ?> 里的代码，// 后面的内容被当作注释吞掉。

改进方式：必须使用 base64 命令配合 ${IFS} 读取。

详细实操步骤（逐字解析）

第一步：探测根目录

构造 Payload：127.0.0.1;ls

发现目标文件：flag_22401280515565.php。

第二步：使用 base64 命令读取文件（绕过空格）

构造 Payload：

127.0.0.1;base64${IFS}flag_22401280515565.php

Payload 逐字深度解析：

  • 127.0.0.1：让 ping 命令正常执行。
  • ;：命令分隔符。
  • base64：Linux 系统命令，将文件内容转换为 Base64 编码并输出。
  • ${IFS}：重点！这是 Linux Shell 的内部字段分隔符，等同于一个空格，用来绕过正则中的空格过滤。
  • flag_22401280515565.php：目标文件名。

第三步：备选方案（%09 绕过）

如果 ${IFS} 被 WAF 拦截或转义，改用 URL 编码的 %09（Tab 键）：

?ip=127.0.0.1%3Bbase64%09flag_22401280515565.php

第四步：解码并提交

页面回显 Base64 字符串，复制后去在线工具解码，得到 Flag：ctfhub{a9ddc243074227ea09e6d8e5}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 命令替换与 WAF 绕过：在真实渗透中，WAF 常拦截空格、cat、whoami 等敏感字符。攻击者会尝试用 ${IFS}、%09、<、> 替代空格，用 tac、nl、sort 替代 cat，用大小写、拼接、通配符绕过后缀过滤。
  • 安全开发（SDL）：防御命令注入绝对不能用黑名单，必须使用白名单。对用户输入进行 escapeshellarg() 转义，或直接避免使用系统命令。

三、名词大全与原理深度复盘

1. IFS（Internal Field Separator）

Linux Shell 中用于分割单词的字符，默认包含空格、Tab、换行符。在命令注入中，${IFS} 常被用来替代空格，因为 Shell 在解析变量后，会将其当成分隔符。

2. preg_match_all 函数

PHP 用于执行全局正则匹配的函数。在本题中用于检测输入中是否包含空格。一旦匹配成功，返回非零值，加上 ! 后变为 false，从而拦截执行。

3. 为什么 Tab 键能绕过空格过滤？

源码中只过滤了空格字符（ASCII 32），而 Tab 键（ASCII 9）同样可以作为 Shell 的分隔符，却不在黑名单中。在 URL 中，Tab 键用 %09 表示。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“无过滤”的区别：“无过滤”可以随意使用空格和任何命令；“过滤空格”则增加了字符级别的障碍，需要利用 Shell 变量特性。
  • 与“过滤cat”的区别：“过滤cat”针对的是命令名称；“过滤空格”针对的是命令与参数之间的分隔符。两者可以叠加，共同考察命令行的灵活运用。

2. 这种题目的出现原因

开发人员试图通过简单的正则替换或黑名单来防止命令注入，比如“看到空格就拦截”。但 Shell 语法极其灵活，存在大量替代方案，导致这种防御措施形同虚设。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，攻击者一旦发现命令注入漏洞，会使用各种混淆技术绕过 WAF。例如使用 ${IFS}、%09、$IFS$9 等替代空格，使用 ca\t、c'a't、/bin/c?t 绕过命令过滤，这些技巧在实战中极为常见。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个老实的传令兵：

  • 正常流程：你给传令兵一张纸条，上面写着“去敲 127.0.0.1 的门；顺便把保险柜里的 flag 拿出来”。
  • 黑名单（过滤空格）：上级规定，纸条上不能有“空一格”这个动作。传令兵看不懂“拿flag”和“拿 flag”的区别，但他严格执行上级的规定。
  • 绕过（使用 ${IFS}）：你灵机一动，对传令兵说：“不要空一格，用这个叫 ${IFS} 的魔法符号！”传令兵看到这个符号，大脑自动把它翻译成空格，于是老老实实执行了命令。

做一道题，就要往自己脑子里装点东西。
