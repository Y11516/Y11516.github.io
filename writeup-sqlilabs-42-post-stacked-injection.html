SQLi-Labs Less-42

2026年9月29日 SQLi-Labs Web安全 SQL注入 POST堆叠注入

一、题目信息

  • 题目名称：SQLi-Labs Less-42 (POST - Error based - String - Stacked)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / POST型堆叠注入 / 密码篡改
  • 靶场链接：http://localhost:8081/Less-42/（本地环境）
  • 涉及工具：Python (requests库)

二、解题步骤

1. 分析题目考什么

本题的核心考点是POST 型堆叠注入（Stacked Injection）。Less-42 是一个登录表单，后端使用了 mysqli_multi_query() 函数，允许使用分号 ; 同时执行多条 SQL 语句。攻击者不仅可以尝试绕过登录，还能直接执行 UPDATE 语句来修改管理员的密码。

2. 怎么想（破题思路）

  • 尝试使用万能密码 admin'#，发现可以登录，但为了体现“堆叠”威力，我们直接篡改密码。
  • 构造堆叠 Payload：admin'; update users set password='123456' where username='admin';-- -。
  • 将 Payload 作为用户名提交给后端。
  • 由于第一条 SELECT 查询会因为语法或逻辑错误返回 false，页面会跳转到 BUG OFF 页面，但 UPDATE 语句已经执行。
  • 随后用 admin / 123456 登录，验证密码是否被修改。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：浏览器提交后跳转到“嘲讽页”

踩坑情况：在浏览器提交 Payload 后，页面跳转到 BUG OFF YOU SILLY DUMB HACKER，看起来像是失败了。

原因分析：后端执行 mysqli_multi_query() 时，第一条 SELECT 查询失败，导致 PHP 代码进入 else 分支并显示登录失败。

改进方式：不要被表面现象迷惑。只要后端的 UPDATE 语句被执行，密码就已经被修改了。直接去登录页用新密码验证即可。

详细实操步骤（Payload逐字解释）

第一步：编写 Python 脚本

import requests

url = "http://localhost:8081/Less-42/login.php"
payload = "admin'; update users set password='123456' where username='admin';-- -"
data = {"login_user": payload, "login_password": "123", "submit": "Login"}

response = requests.post(url, data=data)
print(response.text)

第二步：Payload 逐字解析

  • admin'：闭合原 SQL 中的字符串。
  • ;：结束第一条查询语句。
  • update users set password='123456' where username='admin'：将 admin 用户的密码修改为 123456。
  • -- -：注释掉后面的 SQL 语句。

第三步：验证结果

运行脚本后，回到浏览器用 admin / 123456 尝试登录。如果成功进入 logged-in.php，说明堆叠注入彻底成功。

4. 怎么迁移（跨领域联想）

  • 权限提升与横向移动：堆叠注入不仅能修改密码，还可以插入新的管理员用户、写入 WebShell、甚至执行系统命令。
  • 代码审计与安全开发：开发中极少使用 mysqli_multi_query（除非是数据库迁移脚本），这本身就是极其危险的信号。防御方必须使用参数化查询。
  • 从查询到控制：与之前的“读取数据”不同，堆叠注入代表攻击者已经具备了“写数据”的能力，这在真实攻防中意味着更高等级的权限和更严重的危害。

三、名词大全与原理深度复盘

1. 堆叠注入 (Stacked Query Injection)

利用分号 ; 在同一数据库连接中执行多条 SQL 语句。常见于后端使用 mysqli_multi_query() 的 PHP 应用。

2. UPDATE 语句

SQL 中用于修改数据的语句。在注入场景中，如果攻击者执行了 UPDATE 语句，就能篡改数据库中的核心数据（如密码）。

3. POST 注入

数据通过 HTTP 请求体提交。与 GET 注入不同，POST 注入无法直接在 URL 修改，必须使用抓包工具或脚本。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-40/41 的区别：Less-40/41 是 GET 型盲注堆叠，Less-42 是 POST 型报错堆叠。
  • 与 Less-24 的区别：Less-24 是通过二次注入逻辑漏洞修改密码，Less-42 是通过堆叠注入暴力修改密码。

2. 这种题目的出现原因（为什么存在）

开发者在实现某些后台功能时，为了图方便使用了 mysqli_multi_query 来处理多语句。如果这些输入未经严格过滤，攻击者就能利用这种功能执行任意 SQL 语句，从而直接控制数据库。

3. 这种应用在实际中如何体现？

在实战中，堆叠注入通常出现在后台管理、批量操作、数据导入导出等接口。由于它能直接修改数据库，往往比普通查询注入危害更大。

4. 如何抽象理解概念（大白话）

把靶场比作一个“快递站”：

  • 普通注入：你在快递单上写“查一下我的包裹”（SELECT）。
  • 堆叠注入：你在快递单上写了“查一下我的包裹；顺便把我的地址改成黑客基地”。
  • 如果快递员（数据库）只会看一行（mysqli_query），他只会执行第一个操作。但如果他支持多行处理（mysqli_multi_query），你的第二句话就会生效。
