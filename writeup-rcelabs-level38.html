RCE-Labs Level 38 - 绕过空格 ${IFS} 与语法结构替代

  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 空格绕过 / Shell语法
  • 4.靶场链接：http://靶机IP:8080/less-38/
  • 5.涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

源码中正则变为 $pattern = '/\x20|\x09|\$IFS/';。此时 WAF 拦截了：ASCII 空格（\x20）、Tab 键（\x09）、以及 $IFS 这个字符串。弹窗提示“绕过空格 ${IFS}”。核心考点是放弃利用变量替换空格，转而利用 Shell 的语法结构（重定向、大括号扩展）来替代空白字符。

踩坑记录：变量替换被彻底封死

尝试 Payload：延续上一关的思路，尝试 ?cmd=cat${IFS}/flag。

失败响应：页面空白（WAF 拦截了 $IFS 字符串）。

根本原因：WAF 正则新增了 \$IFS，直接匹配并拦截了变量名。

改进与成功：既然无法用变量代替空格，那就彻底放弃空格这一概念。利用重定向符 < 或大括号扩展 {}，让 Shell 在不需要空格的情况下，自动完成命令与参数的拼接。

2. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$cmd = $_GET['cmd'] ?? '...';
$pattern = '/\x20|\x09|\$IFS/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与逐字解析

方案一：使用重定向符 <（最简单）

?cmd=cat%3C%2Fflag

逐字解析：%3C 是 <，%2F 是 /。最终执行 cat。Shell 会将 < 解释为输入重定向，自动将 /flag 作为 cat 的输入。全程没有空格、Tab 或 $IFS。

方案二：使用大括号扩展 {}

?cmd=%7Bcat%2C%2Fflag%7D

逐字解析：%7B 是 {，%2C 是 ,，%7D 是 }。最终执行 {cat,/flag}。Shell 会自动将其扩展为 cat /flag。同样完美绕过所有防御。

3. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的语法绕过：在真实护网中，当所有“空白字符替代品”都被封杀时，利用 Shell 原生的重定向符和大括号扩展，是最后的杀手锏。这需要你对 Shell 的语法有极深的理解。
  • 系统运维中的重定向：在 Shell 脚本里，cat 这种写法虽然不常见，但完全合法。理解 Shell 的重定向机制，能帮你写出更灵活、更兼容的自动化脚本。

三、名词大全与原理深度复盘

1. 为什么不用绕过？不绕过会怎么样？（红蓝对抗的本质）

这是最核心的灵魂拷问。答案很简单：不绕过，你连战场都上不去。

  • 蓝队（防守方）：在真实系统中，Web 服务器前面必有 WAF。WAF 是一台“死板”的安检机，只做“文本匹配”。它手里拿着一份黑名单（拦截 cat、空格、$IFS）。一旦发现敏感词，直接丢弃请求（403 Forbidden）或返回 400 Bad Request。请求根本到不了 PHP 那里。
  • 红队（攻击方）：我们必须寻找 WAF 看不懂的“黑话”（绕过），让请求顺利穿透安检，到达 Shell 那里。
  • Shell（执行者）：Shell 是一个极其聪明的“翻译官”，它支持变量替换、语法扩展。只要请求能到达它这里，它就能听懂我们的真实意图，还原出 cat /flag 并执行。
  • 本质上：这是一场“死文本匹配”与“动态语法解析”的博弈。我们赢，就赢在 Shell 的语法灵活性上。

2. Level 35 - 38 空格绕过方案深度对比

关卡 WAF 拦截内容 核心绕过思路 成功 Payload
Level 35 代码拼接 # （注释） 利用换行符 %0A 截断注释 %0Acat%20/flag
Level 36 空格（\x20） 利用 Tab 键 %09 代替空格 cat%09/flag
Level 37 空格、Tab 利用变量替换 ${IFS} cat${IFS}/flag
Level 38 空格、Tab、$IFS 利用重定向 < 或大括号 {} cat 或 {cat,/flag}

总结：WAF 在疯狂做加法（封禁更多字符），我们则在寻找语法层面的降维打击。从“换一个字符”到“换一种语法结构”，这就是 RCE 绕过的进化史。

3. 核心网络基础与护网认知（陌生人也能看懂版）

  • 外网（公网/互联网）：拥有全球唯一的门牌号（公网 IP，如 8.8.8.8），任何人任何车都能开到你家门口。
  • 内网（局域网）：门牌号是“小区内部编号”（如 192.168.1.19），只有小区内部的人才能互相找到。外面的人想找你，必须经过小区保安（路由器/NAT）允许并做地址转换。
  • 完全隔离的内网：小区不仅不让外面的人进，甚至把大门用砖头砌死了（物理隔离）。这种环境下，反弹 Shell 和重定向写入 100% 都会失效。
  • HTTP 是公网吗？这是一个经典的误解！HTTP 不是网络，它是语言（协议）。无论访问内网 OA 还是百度官网，用的都是 HTTP 语言。
  • 操作系统与网络的关系：电脑操作系统是管理网络硬件的“交通警察”。你监听 80 端口成功、9002 端口失败，根本原因就是操作系统或 Docker 的虚拟网卡策略，只放行了 80 端口的出站，拦截了 9002 端口。
  • 护网是在攻击内网吗？护网是一场“攻城战”：第一阶段是“外网打点”（攻打城门），寻找对外门户的漏洞；第二阶段是“内网渗透”（巷战与横向移动），以边界服务器为跳板在内网提权、抓密码；第三阶段是“拿下靶标”（直捣黄龙），控制核心数据库或域控。内网渗透是决定胜负的主战场。

四、题目思考

1. 这跟前面关卡的区别

Level 36 是简单的字符替换（Tab 换空格），Level 37 是巧妙的变量替换（${IFS}），Level 38 则是彻底放弃空白字符，利用 Shell 的语法结构（重定向、大括号）来构建命令。这标志着绕过思维从“寻找替代品”进化到了“利用底层语法”。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发者常常将用户输入与系统命令拼接。为了防御，WAF 会尝试拦截空格、Tab 等空白字符。但由于 Shell 语法极其灵活，重定向符 < 和大括号 {} 在不需要空格的情况下，依然可以完成命令与参数的结合，使得这种防御形同虚设。

3. 这种漏洞在实际中的应用

在护网和红队行动中，遇到 WAF 疯狂封禁字符是常态。利用重定向符绕过空格拦截，是渗透测试人员的基本功。同时，防守方也据此推出了“语义分析”型的高级 WAF，不仅看关键字，还会还原命令执行后的真实意图。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。监考老师（开发者）说：“不准用逗号，不准用句号，连感叹号都不准用”。你实在没办法了，于是你直接把两句话写在一起，用了连笔字（重定向符 < 或大括号 {}）。老师看不懂你的连笔，但读者（Shell）一眼就看懂了。

5. 他的本质

本质是利用 Shell 语法结构（重定向、大括号扩展）对空白的天然容忍，绕过了应用层防火墙对特定字符（空格、Tab、变量名）的黑名单匹配。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：不要使用字符串拼接来构造系统命令！应使用编程语言提供的安全 API（如 PHP 的 escapeshellarg），或者直接使用白名单限制用户输入。同时，WAF 应拦截 Tab、换行符、$IFS、{}、重定向符等所有可能的绕过手段。
  • 破解方（红队）：如果所有空白字符替代品都被拦截，尝试利用 Base64 编码（echo Y2F0IC9mbGFn | base64 -d | bash）、网络外带（DNSLog、HTTP）或写入 WebShell 等方案。
