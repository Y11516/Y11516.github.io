RCE-Labs Level 2 - 黑名单绕过与替代命令

2026年10月3日 RCE-Labs 黑名单绕过 替代命令

一、题目信息

  • 题目名称：RCE-Labs Level 2 (tac 命令倒序读取文件)
  • 题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 黑名单绕过
  • 靶场链接：http://靶机IP:8080/less-2/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

本题核心考察的是黑名单过滤的绕过技巧。Level 1 中我们可以直接使用 cat 命令读取文件，但 Level 2 引入了 WAF（Web应用防火墙）的雏形：通过正则表达式拦截了 cat 关键字。我们需要寻找功能相同但未被拦截的替代命令来读取 flag。

2. 怎么想（破题思路）

  • 打开靶场，看到源码中多了一个变量 $pattern = '/cat/';，并用 preg_match 判断 $cmd 中是否包含此字符串。
  • 如果包含，则 !preg_match 为假，system($cmd) 不会执行。
  • 目标是读取 flag，Linux 中读取文件的命令不止 cat，还有 tac、nl、head、tail 等。由于 tac 字符串中不包含连续的 cat，所以可以完美绕过黑名单。

3. 怎么解（详细步骤与逐字翻译）

源码逐字翻译与符号解析

<?php
# ./flag
highlight_file(__FILE__);
$cmd = $_GET['cmd'] ?? 'echo "<br>Ciallo~(∠・ω< )★"';
$pattern = '/cat/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}
  • $pattern = '/cat/';：定义了一个正则表达式模式。/ 是正则表达式的定界符，中间的 cat 是我们要匹配的字符串。
  • preg_match($pattern, $cmd)：PHP 内置的正则匹配函数。它在 $cmd 中搜索 $pattern。如果匹配到了（即 $cmd 中包含了 cat），返回 true；否则返回 false。
  • !：逻辑非运算符。将 preg_match 的结果取反。因此 !preg_match(...) 的含义是“如果 $cmd 中没有包含 cat，则条件成立”。
  • if(...){ system($cmd); }：如果满足上述条件，则执行系统命令。

踩坑记录：尝试 cat 被拦截

尝试 Payload：?cmd=cat /flag

失败响应：页面没有任何回显（因为被 if 条件拦截，system 根本没执行）。

原因分析：正则表达式 /cat/ 成功匹配到了 payload 中的 cat 子串，触发了黑名单拦截。

改进方式：不能使用包含 cat 子串的命令，寻找其他具有文件读取功能的等价命令。

最终成功 Payload 与解析

访问 URL：

http://靶机IP:8080/less-2/?cmd=tac /flag

成功响应：页面回显 flag{TEST_Dynamic_FLAG}。

解析：tac 是 cat 的反向拼写，功能是将文件内容从最后一行开始倒序输出（tac 也是 concatenate 的反向拼写）。因为其字符串中不包含 c-a-t 的连续顺序，所以成功绕过了黑名单。

拓展：其他可用于读取文件的 Linux 命令

在实战中，WAF 可能会过滤多个关键字。以下是 Linux 中常用于读取文件内容的命令，供日后绕过参考：

  • cat：从第一行正向读取全部内容。
  • tac：从最后一行倒序读取全部内容。
  • nl：读取文件并显示行号。
  • head：读取文件开头几行（默认 10 行）。
  • tail：读取文件末尾几行（默认 10 行）。
  • more：分页读取文件内容（不支持正向切换）。
  • less：分页读取文件内容，支持上下翻页，非常灵活。
  • sort：将文件内容按字母顺序排序输出。
  • uniq：去除文件中相邻的重复行后输出。
  • od：以八进制、十六进制等格式转储文件（适合读二进制文件）。
  • xxd：以十六进制形式查看文件内容。
  • strings：提取文件中的可打印字符串，常用于逆向工程。
  • rev：将文件每一行字符反转后输出。
  • paste：合并文件行输出。
  • sed：流编辑器，如 sed -n '1,100p' /flag 可读取前 100 行。
  • awk：文本处理工具，如 awk '{print}' /flag 可输出全文。
  • grep：文本搜索工具，如 grep . /flag 可匹配任意字符从而输出全文。

4. 怎么迁移（跨学科与跨领域联想）

  • 安全对抗领域：WAF 拦截的是具体的“特征”，而不是“行为”。只要攻击者能找到具有相同功能但不同特征的方法（等价替换），黑名单就形同虚设。
  • 日常生活领域：这就像小区门口保安接到通知“拦住带菜刀的人”，结果你拿着把大砍刀或者长矛进去了。黑名单法往往只能防住最笨的试探，无法防御深思熟虑的攻击。

三、名词大全与原理深度复盘

1. 黑名单 (Blacklist) 与 白名单 (Whitelist)

黑名单是“只禁止已知的恶意行为，其余放行”；白名单是“只允许已知的安全行为，其余全部拦截”。从安全角度来看，白名单永远比黑名单更安全，因为黑名单容易存在“漏网之鱼”（你永远不知道黑客能想出多少种替代方案）。

2. 正则表达式 (Regular Expression)

一种用于匹配字符串中字符组合的模式。在本题中 /cat/ 用于检测字符串中是否包含 cat。正则表达式非常强大，但也常因为开发者写得不严谨（比如没写起始符 ^ 和结束符 $）而被轻易绕过。

3. preg_match() 函数

PHP 中用于执行正则表达式匹配的核心函数。当它检测到匹配项时，会立即停止搜索并返回 1，否则返回 0。如果只是单纯用它来做黑名单过滤，容易被绕过。

四、题目思考

1. 这跟前面关卡的区别

  • Level 1 区别：Level 1 是“裸奔”，服务器完全信任用户的输入；Level 2 增加了黑名单意识，试图通过关键字拦截来限制命令执行。
  • 与后续关卡的区别：后续关卡可能会过滤空格、过滤路径分隔符 /、过滤字母数字等。Level 2 的过滤仅仅是冰山一角。

2. 这种题目出现的原因（底层逻辑与历史原因）

从系统底层来看，Linux 的 shell 解析命令时，只认命令的二进制文件名。例如 cat 对应的二进制文件其实是 /bin/cat。开发者在 WAF 层面用正则字符串去拦截用户输入中的“cat”字符串，这是一种“表面防御”。只要用户输入的是另一个具有相同功能的二进制文件名（如 tac），底层系统依然会正常调用并执行它。这种“特征匹配”与“行为等效”之间的错位，就是黑名单绕过漏洞的根本原因。

3. 这种漏洞在实际中的应用

在护网和实战中，遇到 WAF 是非常常见的情况。此时就需要用到“命令混淆”技术，比如使用 c''at、c\at、$@cat 等拼接手段，或者利用 base64 编码执行。理解黑名单的局限性，是渗透测试人员必备的基本功。

4. 如何抽象理解概念（大白话）

把 WAF 想象成一个拿着小册子的安检员，小册子上写着“禁止携带写着 cat 的物品”。现在你想吃“猫耳朵”（一种面食），安检员看到你带了一包写着 cat 的东西就不让你进。但你其实可以换成拿一包写着“tac”的东西，里面装的是一样的猫耳朵。安检员只看名字，不看实际功能。这就是黑名单过滤绕过的最直观解释。
