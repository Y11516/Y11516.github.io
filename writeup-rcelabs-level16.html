RCE-Labs Level 16 - grep 命令文本搜索

2026年10月5日 RCE-Labs Linux三剑客 正则表达式

一、题目信息

  • 题目名称：RCE-Labs Level 16 (grep 命令文本搜索)
  • 题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 文本搜索
  • 靶场链接：http://靶机IP:8080/less-16/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

黑名单封禁了 strings，但漏掉了强大的文本搜索工具 grep。弹窗提示其为“Linux三剑客”之一。考察的是利用文本搜索工具反向输出全文的利用方式。

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

2. 怎么想（破题思路）

既然 strings 被禁用，我们需要寻找同样能读取文件内容，且名称未被拦截的工具。grep 是 Linux 中用于文本搜索的命令。我们可以利用正则表达式中的通配符 .，让它去匹配每一行中的任意字符，从而实现“读取全文”的效果。

3. 怎么解（详细步骤与逐字翻译）

最终成功 Payload 与逐字解析

?cmd=grep . /flag

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

命令逐字解析：

  • grep：文本搜索工具。
  • .：正则表达式中的元字符，代表“匹配任意单个字符”。
  • /flag：指定要搜索的目标文件。
  • grep . /flag：意思是“搜索 /flag 文件中所有包含任意字符的行”。因为文件中的每一行都至少包含一个字符，所以这等价于输出文件的全部内容。

4. 怎么迁移（跨学科与跨领域联想）

  • 日志分析与故障排查：在 Nginx 日志中定位攻击 IP：grep "192.168.1.1" access.log，或排查系统错误：grep "error" /var/log/syslog。
  • 代码审计：在庞大代码库中寻找敏感函数（如 eval、system）以定位漏洞点，例如 grep -rn "eval(" ./src。

三、名词大全与原理深度复盘

1. grep 命令详细介绍

grep（Global Regular Expression Print）是 Linux 中最强大的文本搜索工具，属于“Linux三剑客”之一。

  • 核心参数 -i：忽略大小写。
  • 核心参数 -r：递归搜索目录。
  • 核心参数 -v：反向匹配，输出不包含匹配项的行。
  • 核心参数 -n：显示匹配行的行号。
  • 核心参数 -e：指定多个匹配模式。

2. 底层原理：正则引擎与逐行读取

grep 的底层逻辑是：逐行读取输入流，并利用正则表达式引擎（如 NFA/DFA）判断当前行是否匹配指定模式。如果匹配成功，就将整行内容输出。其高效性来源于底层的字符串匹配算法（如 Boyer-Moore 算法），能在海量日志中极速定位关键字。在本关中，我们正是利用“匹配任意字符”的逻辑，把搜索工具变成了读取工具。

3. 核心名词解释（陌生人也能看懂版）

  • Linux 三剑客：指 grep（搜索）、sed（编辑/替换）、awk（分析）。它们是 Linux 文本处理的核心工具。
  • 正则表达式 (Regular Expression)：一种描述字符串匹配模式的语言。. 是其中最简单的一个元字符，代表“任意一个字符”。
  • 标准输入流 (stdin) 与 标准输出流 (stdout)：Linux 进程默认的输入和输出通道。grep 从 stdin 读数据，把结果写到 stdout。
  • Boyer-Moore 算法：一种高效的字符串搜索算法，从后往前比较，能跳过大量不必要的字符，是 grep 性能优异的底层原因之一。

四、题目思考

1. 这跟前面关卡的区别

Level 10-14 侧重于“编码与转储”（看到字节），Level 15 侧重于“提取特征”（挑出字符串），而 Level 16 侧重于“搜索与过滤”。grep 的厉害之处在于，你甚至不需要知道完整内容，只要知道它包含某个关键字，就能把它揪出来；如果关键字为 .，它就能把所有内容都“揪”出来。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，很多应用需要调用系统命令（如统计日志、分析文件）。开发者为了让功能更强大，可能会保留 grep 等工具。WAF 在制定黑名单时，往往优先封禁那些“破坏力”最直观的工具（如 cat、tail），而 grep 因为常用于运维排查，被误认为“无害”或难以全面封禁，从而成为了攻击者天然的突破口。

3. 这种漏洞在实际中的应用

在 CTF 比赛中，当常规命令被 WAF 拦截时，利用 grep 的正则特性读取文件是常见套路。在真实的红队行动中，如果拿到一个精简容器（如 Alpine），里面可能没有 cat，但一定会有 grep，它可以成为最后的数据提取手段。

4. 如何抽象理解概念（大白话）

把读取文件比作在一本厚厚的字典里找一句话。cat 是让你从头读到尾；strings 是只挑出完整的句子给你看；而 grep 则是一个“智能搜索器”。你告诉它“我要找包含‘hello’这个词的句子”，它就只把那些句子找出来。而 grep . /flag 相当于告诉它“我要找所有包含任意字符的句子”，它就把整本书都给你搬了出来。

5. 他的本质

本质是利用正则表达式的通配能力（`.`），将原本用于“过滤”的工具，改造为“全量读取”的工具。它绕过了“查看/读取”类命令的黑名单，利用程序的输入输出重定向机制实现了数据的外泄。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：不要依赖关键字黑名单。应对命令注入最好的方式是白名单，只允许固定的参数值，或使用 escapeshellarg() 对用户输入进行严格转义。如果只能使用黑名单，不仅要封禁 cat、grep，还要考虑封禁所有具备读取能力的正则解析工具。同时，应严格限制 Web 进程的系统权限（如禁用 /flag 的读取权限）。
  • 破解方（红队）：如果 grep 也被拦截，可以尝试 awk '{print}' /flag、sed -n '1p' /flag、sort /flag、uniq /flag，甚至使用 php -r 'echo file_get_contents("/flag");' 或 python3 -c 'print(open("/flag").read())' 等语言特性来完成文件读取。
