二、解题过程（详细步骤与踩坑记录）

1. 初步产生 CTF 概念

第一次接触夺旗赛（CTF），完全不知道怎么下手。通过大模型了解到，Web 题的第一反应应该是“信息搜集”。于是开始学习并寻找网页源代码。

学会的几种方法：

  1. 在网址前加 view-source:
  2. 快捷键 Command + Option + F12（或 Fn + F12）
  3. 右键页面空白处，选择“查看网页源代码”

2. 阅读并读懂代码

打开代码后，满屏的代码看似杂乱，但在耐心阅读后找到了关键信息：

  • 第10~15行：setTimeout('myrefresh()', 500); 👉 意思是：网页每隔 0.5 秒就会自动刷新一次（根本停不下来）。
  • 第17行：I want to play Dummy game with othersfiBut I can't stop! 👉 意思是：出题人在吐槽自己，页面疯狂刷新停不下来。
  • 第18行：Stop at panda ! u will get flag 👉 意思是：找到那个“熊猫”，让它停下来，你就能拿到 flag。
  • 第19行：<a style="display:none">flag is here</a> 👉 意思是：这里隐藏了一个链接，上面写着“flag 在这里”，但是被藏起来了。

3. 打开开发者工具，找到隐藏线索

继续尝试使用 Fn + F12 在右侧唤出了完整的开发者代码面板。在 Elements（元素）面板中，我阅读代码并找到了 flag is here 的隐藏行。

4. 停止疯狂的刷新（重要！）

因为页面每0.5秒就会刷新，我改的代码瞬间就会被重置。最终利用黑科技把它“定住”：

  • 按下 Command + Shift + P 唤出命令菜单。
  • 输入 JavaScript。
  • 点击 Disable JavaScript（禁用 JavaScript）。
  • 页面终于彻底停止了刷新！

5. 修改前端代码让 flag 现形

  • 回到右侧代码面板，找到那一行：<a style="display:none">flag is here</a>
  • 双击 none，把它改成 block。
  • 按回车（Enter）确认。
  • 左侧页面上出现了 “flag is here” 的文字！

6. 抓包寻找图片（踩坑之路）

虽然出现了文字，但是并没有直接给出 flag。我尝试了 Command + R 刷新，在 Network（网络）面板里找到了被请求的图片 10.jpg。

我打开了这个图片并保存到电脑，进行了一系列排查：

  • EXIF 信息查看器：没有找到有用信息。
  • 检查响应头（Response Headers）：寻找类似 Flag: flag{...} 或 X-Flag: flag{...} 这样的自定义标头，什么也没找到。
  • 查看响应内容（Response）：也没有找到。
  • 路径暴力猜测：尝试了 panda.jpg、panda.png、Panda.txt 等常见路径，均无结果。

7. 最终绝杀

在尝试了各种抓包和路径猜测都没有结果后，我偶然再次回到 Elements 面板，再次将 display:none 修改为 display:block。这一次，终于触发了隐藏的 Flag，成功完成了作业。

三、知识点总结（核心复习素材）

  • 1. 前端代码是可以修改的：浏览器的开发者工具（F12）允许我们修改 HTML 和 CSS。修改 display:none 为 block 是前端安全中非常基础且常用的绕过手段。
  • 2. 前端反调试的绕过：出题人利用 JS 的 setTimeout 实现无限刷新，这是一种简单的反调试手段。通过禁用 JavaScript 可以完美破解。
  • 3. 信息搜集的重要性：Web 安全的核心是“信息搜集”。从注释、隐藏标签到网络请求，任何一处遗漏都可能错失 Flag。
  • 4. 失败的过程也是经验：虽然 EXIF 和路径猜测没有直接拿到 flag，但这是一个优秀的 Web 安全研究员必须具备的排查思路。

四、深度知识补充（display:none 与 setTimeout 详解）

1. 什么是 CSS 的 display:none？

display:none 是 CSS 中的一个属性值，用于控制 HTML 元素在网页上的显示方式。

  • 它的作用：把元素从页面上彻底“抹掉”。它不仅看不见，而且**不占据任何页面空间**。
  • 与 visibility:hidden 的区别：
    • display:none：元素被“拔掉”了，原来占的位置会被其他元素顶上。
    • visibility:hidden：元素只是“隐身”了，原来占的位置还空着，只是你看不见它。
  • 在 CTF 中的意义：这是前端隐藏信息最基础的手段。出题人经常把 Flag、提示或链接用 display:none 藏起来，肉眼在页面上完全看不到。安全人员必须掌握在 F12 中将其改为 display:block 的破局技巧。

代码示例：

<a style="display:none">这里藏着秘密</a>

在 Elements 面板中，我们双击 none 改为 block，这行字就会神奇地出现在页面上。这相当于我们把出题人藏起来的纸条又翻了出来。

2. 什么是 JavaScript 的 setTimeout？

setTimeout 是 JavaScript 中的一个全局函数，用于在指定的毫秒数后执行一段代码。

  • 它的作用：实现“延时执行”。它不会阻塞后面代码的运行，而是告诉浏览器：“等 X 毫秒后，帮我执行这个函数。”
  • 语法：setTimeout(function, milliseconds)。
    • function：要执行的函数或代码字符串。
    • milliseconds：等待的毫秒数（1000毫秒 = 1秒）。

本题中的代码分析：

function myrefresh() {
    window.location.reload(); // 刷新页面
}
setTimeout('myrefresh()', 500); // 500毫秒后执行 myrefresh

这段代码的意思是：页面加载后，等待 0.5 秒，然后执行页面刷新。由于每次刷新后又会重新执行这段代码，所以页面就陷入了“刷新 → 加载 → 再刷新”的死循环。

3. 如何绕过 JS 的无限刷新？（原理深度剖析）

出题人用 setTimeout 制造无限刷新，目的是让你来不及在 F12 中修改代码。我们破解它的核心思路是切断定时器或阻断 JS 执行。具体有以下几种方式：

  1. 禁用 JavaScript（最粗暴有效）：在浏览器设置中直接关掉 JS。浏览器根本不执行任何脚本，setTimeout 自然不会生效，页面就定格了。这是本题使用的方法。
  2. 清除定时器：在 Console 中输入 clearTimeout(定时器ID)。但我们通常不知道这个 ID，所以不太实用。
  3. 修改代码：在 Elements 面板中，把 500 改成 99999999（大约 27 小时）。这样页面就不会频繁刷新了。
  4. 使用断点：在 Sources 面板中找到对应的 JS 代码，打上断点（Debugger），让代码执行到那里时暂停。一旦暂停，JS 线程被阻塞，刷新就不会发生。

4. 扩展：这题教给我们的“前端不可信”原则

这道题还有一个很重要的思想：前端的一切限制都是可以绕过的。

出题人写了刷新代码、写了隐藏属性，这些全都是在“客户端（浏览器）”运行的。只要我们掌握了开发者工具，就能修改刷新频率、修改隐藏属性、甚至修改 JS 逻辑。

在真实的 Web 安全中，如果一个网站仅靠前端 JS 做验证（比如验证密码对不对、验证你是不是管理员），那攻击者完全可以跳过前端，直接向服务器发请求，或者直接把 JS 改掉。因此，真正的安全校验必须在后端完成。这是这道题带给我们最深层的启发。
