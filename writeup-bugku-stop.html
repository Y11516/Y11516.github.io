你必须让他停下 - CTF Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 Writeup

按照老师的要求，写一篇真正的、用于自我总结的 Writeup。这不仅仅是一份作业，更是我在网络安全之路上迈出的第一步记录。

一、题目信息

  • 题目名称：你必须让他停下（滑稽）
  • 题目平台：Bugku CTF
  • 题目类型：Web
  • 靶场地址： http://160.202.254.160:14679 (环境有效期内)
  • 题目描述： flag0

二、使用工具

  • 浏览器（Chrome / Edge，Mac系统）
  • 浏览器开发者工具（F12）
  • 在线 EXIF 信息查看器（用于排查图片）
  • 大模型（用于辅助理解代码逻辑，也是快速入门新知识的利器）

三、解题步骤（完整曲折的心路历程）

1. 初步产生 CTF 概念

第一次接触夺旗赛（CTF），完全不知道怎么下手。通过大模型了解到，Web 题的第一反应应该是“信息搜集”。于是开始学习并寻找网页源代码。

学会的几种方法：

  1. 在网址前加 view-source:
  2. 快捷键 Command + Option + F12（或 Fn + F12）
  3. 右键页面空白处，选择“查看网页源代码”

2. 阅读并读懂代码

打开代码后，满屏的代码看似杂乱，但在耐心阅读后找到了关键信息：

  • 第10~15行：setTimeout('myrefresh()', 500); 👉 意思是：网页每隔 0.5 秒就会自动刷新一次（根本停不下来）。
  • 第17行：I want to play Dummy game with othersfiBut I can't stop! 👉 意思是：出题人在吐槽自己，页面疯狂刷新停不下来。
  • 第18行：Stop at panda ! u will get flag 👉 意思是：找到那个“熊猫”，让它停下来，你就能拿到 flag。
  • 第19行：<a style="display:none">flag is here</a> 👉 意思是：这里隐藏了一个链接，上面写着“flag 在这里”，但是被藏起来了。

3. 打开开发者工具，找到隐藏线索

继续尝试使用 Fn + F12 在右侧唤出了完整的开发者代码面板。在 Elements（元素）面板中，我阅读代码并找到了 flag is here 的隐藏行。

4. 停止疯狂的刷新（重要！）

因为页面每0.5秒就会刷新，我改的代码瞬间就会被重置。最终利用黑科技把它“定住”：

  • 按下 Command + Shift + P 唤出命令菜单。
  • 输入 JavaScript。
  • 点击 Disable JavaScript（禁用 JavaScript）。
  • 页面终于彻底停止了刷新！

5. 修改前端代码让 flag 现形

  • 回到右侧代码面板，找到那一行：<a style="display:none">flag is here</a>
  • 双击 none，把它改成 block。
  • 按回车（Enter）确认。
  • 左侧页面上出现了 “flag is here” 的文字！

6. 抓包寻找图片（踩坑之路）

虽然出现了文字，但是并没有直接给出 flag。我尝试了 Command + R 刷新，在 Network（网络）面板里找到了被请求的图片 10.jpg。

我打开了这个图片并保存到电脑，进行了一系列排查：

  • EXIF 信息查看器：没有找到有用信息。
  • 检查响应头（Response Headers）：寻找类似 Flag: flag{...} 或 X-Flag: flag{...} 这样的自定义标头，什么也没找到。
  • 查看响应内容（Response）：也没有找到。
  • 路径暴力猜测：尝试了 panda.jpg、panda.png、Panda.txt 等常见路径，均无结果。

7. 最终绝杀

在尝试了各种抓包和路径猜测都没有结果后，我偶然再次回到 Elements 面板，再次将 display:none 修改为 display:block。这一次，终于触发了隐藏的 Flag，成功完成了作业。

四、知识点总结（往脑子里装的东西）

  • 前端代码是可以修改的：浏览器的开发者工具（F12）允许我们修改 HTML 和 CSS。修改 display:none 为 block 是前端安全中非常基础且常用的绕过手段。
  • 前端反调试的绕过：出题人利用 JS 的 setTimeout 实现无限刷新，这是一种简单的反调试手段。通过禁用 JavaScript 可以完美破解。
  • 信息搜集的重要性：Web 安全的核心是“信息搜集”。从注释、隐藏标签到网络请求，任何一处遗漏都可能错失 Flag。
  • 失败的过程也是经验：虽然 EXIF 和路径猜测没有直接拿到 flag，但这是一个优秀的 Web 安全研究员必须具备的排查思路。
