CTFHub 文件上传 - 双写后缀

2026年9月22日 CTFHub Web安全 文件上传 黑名单绕过

一、题目信息

  • 题目名称：文件上传 - 双写后缀
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / 文件上传漏洞 / 黑名单逻辑缺陷绕过
  • 靶场链接：http://challenge-2c9d557d37e00864.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、开发者工具（F12）、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是针对黑名单过滤逻辑缺陷的“双写绕过”。后端代码使用了黑名单机制，并通过类似 str_replace('php', '', $filename) 的函数将文件名中的 php 字符删除。攻击者利用该函数只执行一次替换的缺陷，构造特殊的文件名（如 shell.pphphp），使得替换后恰好拼接成合法可执行的后缀（shell.php），从而绕过黑名单并实现 RCE。

2. 怎么想（破题思路）

  • 尝试上传 shell.php，被服务器拦截或提示非法后缀。这证实了后端存在黑名单过滤。
  • 黑名单的绕过方式有很多，如大小写（PhP）、特殊后缀（phtml）、以及本题的“双写”。
  • 既然它把 php 替换掉，那如果我们写两个 php，它只替换一次，剩下一个 php 不就能执行了吗？于是构造 shell.pphphp 或 shell.phpphp。
  • 上传成功后，后续的“找 Flag -> Base64 读取”与前面题目完全一致。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：文件名构造错误导致无法执行

踩坑情况：尝试构造 shell.pphpp（少写了一个 h），导致替换后变成了 shell.pp 或无法识别，无法执行 PHP。

原因分析：双写要求替换掉一次 php 后，剩下的字符串必须能重新组合成一个完整的 php。比如 pphphp 去掉中间的 php 后，剩下 p + hp = php。

改进方式：标准且稳妥的双写Payload是 shell.pphphp（去掉第一个 php 后，剩下 shell.php）。也可以尝试 shell.phpphp。

踩坑记录二：误以为服务器没有前端验证（或者有）

踩坑情况：某些环境可能存在前端 JS 校验，导致上传被拦截，或者上传后无法执行。

原因分析：题目可能在前端加了一层验证，或者后端验证逻辑比较特殊。

改进方式：遇到拦截，一律先按 F12 -> Settings -> Debugger -> 勾选 Disable JavaScript，排除前端干扰。

踩坑记录三：cat 读取 PHP 文件导致空白

踩坑情况：找到 flag_xxxx.php 后，直接使用 cat 命令读取，页面无回显。

原因分析：PHP 解析器会执行 <?php // ctfhub{...} ?> 里的代码，// 后面的内容被当作注释吞掉。

改进方式：必须使用 base64 命令读取文件原始内容，然后在本地进行解码，避免被 PHP 解析器处理。

详细实操步骤

第一步：准备双写木马

本地新建文件 shell.pphphp（注意后缀），写入代码：

<?php system($_GET['cmd']); ?>

代码逐字深度解析：

  • <?php：PHP 脚本起始标记。
  • system：执行外部系统命令并输出结果的内置函数。
  • $_GET['cmd']：接收 URL 参数 cmd 的值作为系统命令。
  • ; 和 ?>：PHP 语句结束和脚本结束标记。

第二步：上传并验证

在页面上传 shell.pphphp。如果被拦截，禁用 JS 后重试。上传成功后，页面回显路径：upload/shell.php（后端替换后还原了）。

第三步：寻找 Flag 文件

访问：http://.../upload/shell.php?cmd=ls%20/var/www/html/

页面回显发现可疑文件：flag_78208863.php。

第四步：Base64 读取并解码

访问 .../upload/shell.php?cmd=base64%20/var/www/html/flag_78208863.php，获得 Base64 字符串，在线解码得到 Flag：ctfhub{433d2f491253a696b9da95dc}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 安全开发（SDL）与代码审计：开发人员严禁使用黑名单机制。必须使用白名单（只允许 jpg/png），并对上传文件进行重命名（如 MD5、UUID），剥离其执行权限，从根本上杜绝此漏洞。
  • WAF 绕过技术：双写绕过不仅用于文件上传，在 SQL 注入、XSS 中，如果 WAF 使用简单的字符串替换过滤，同样可以使用双写（如 selselectect）来绕过。
  • 真实渗透测试：在实战中遇到黑名单拦截时，要迅速联想各种后缀变体（phtml、php5、php3、大小写混合、双写、00截断等），进行系统性测试。

三、名词大全与原理深度复盘

1. 双写绕过（Double Writing）

这是一种利用后端过滤函数（如 str_replace）仅执行一次替换的逻辑缺陷。开发者认为删除了敏感词就安全了，但攻击者通过构造包含重叠敏感词的字符串，使得删除后剩余部分重新组合成敏感词，达到绕过的目的。

2. 黑名单与白名单的本质区别

黑名单（如禁止上传 .php）是“防君子不防小人”的策略，因为存在无穷无尽的后缀变体和绕过方式（大小写、双写、00截断、特殊后缀）。白名单（只允许 .jpg）是“固若金汤”的策略，因为只允许特定格式，从根本上杜绝了非图片文件的执行。

3. str_replace 函数与底层逻辑复盘

str_replace('php', '', $filename) 是全局替换，但它只扫描一遍。当传入 shell.pphphp 时，它找到中间的 php，将其删除，剩下的字符串拼接为 shell.php。如果不理解这个执行顺序，就会觉得“为什么两个php删掉一个还是php”很反直觉。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 00 截断的区别：00 截断是利用 C 语言底层字符串结束符特性截断路径；而双写绕过是针对 PHP 逻辑层过滤函数的缺陷。
  • 与 MIME 绕过的区别：MIME 是欺骗 Content-Type；双写是直接操纵文件名内容。前者针对请求头，后者针对请求体。
  • 与 .htaccess 的区别：双写是“直拳”，直接绕过黑名单强行传 PHP；.htaccess 是“曲棍球”，通过修改服务器规则让 jpg 执行。

2. 这种题目的出现原因

开发人员对安全过滤函数的认知不足。很多初学者认为写个 str_replace('php', '', $name) 就能拦截所有 PHP 文件，却忽略了替换逻辑本身的缺陷。这是一种典型的“代码逻辑漏洞”。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，双写绕过常被用来绕过 WAF（Web 应用防火墙）。如果 WAF 仅仅使用正则或者简单的字符串替换来过滤 select、script、php 等敏感词，攻击者就可以通过双写（selselectect）或大小写混合（SeLeCt）来绕过。

4. 如何抽象理解概念（大白话理解）

把网站服务器比作一个安检口：

  • 黑名单（安检员）：安检员手里有一张纸条，上面写着“看到‘毒药’两个字，就把它扣下来”。
  • 攻击者（你）：你想带一瓶毒药进去。你第一次在瓶子上写了“毒药”，安检员一看，把这两个字擦掉了，瓶子变成了空白，不能执行。
  • 双写绕过（绝招）：你在瓶子上写了“毒毒药药”。安检员一看，发现了中间的“毒药”，把它擦掉了。结果瓶子上剩下的字拼起来，正好变成了“毒药”！
  • 结果：你成功带毒药进场，安检员还以为自己完成了工作。

做一道题，就要往自己脑子里装点东西。
