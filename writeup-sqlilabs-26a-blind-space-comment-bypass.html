SQLi-Labs Less-26a

2026年9月28日 SQLi-Labs Web安全 SQL注入 时间盲注 / 空格注释过滤

一、题目信息

  • 题目名称：SQLi-Labs Less-26a (GET - Blind Based - All your SPACES and COMMENTS belong to us - String - single quotes - Parenthesis)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 时间盲注 / 空格与注释符过滤 / 括号闭合
  • 靶场链接：http://localhost:8081/Less-26a/（本地环境）
  • 涉及工具：Chrome浏览器 (F12 开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是在盲注场景下绕过对空格和注释符的极端过滤。Less-26a 是 Less-26 的盲注变体，因此： 1. 没有任何报错回显，只能通过时间差（sleep()）判断结果。 2. 过滤了空格（%20）和注释符（--、#），同时过滤了 and 和 or。 3. 闭合方式是单引号加括号（')）。

2. 怎么想（破题思路）

  • 空格被过滤，不能使用空格分割 SQL 语句，考虑用 %0a（换行）或括号 () 替代。
  • 注释符被过滤，不能使用 -- 或 #，必须手动闭合末尾的引号（如 &&('1'='1)）。
  • and 和 or 被过滤，改用 && 或 || 替代（URL 编码为 %26%26 和 %7C%7C）。
  • 在盲注场景下，使用 if(条件, sleep(3), 0) 来制造延迟，确认注入点。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：MySQL 优化器短路导致 sleep 不执行

踩坑情况：使用 id=1 并构造 if(substr(database(),1,1)='s', sleep(3), 0)，页面没有卡顿，耗时仅 29ms。

原因分析：因为 id=1 是主键，MySQL 优化器知道该行必然存在，直接通过索引返回结果，跳过了 sleep(3) 的评估。这叫“优化器短路”。

改进方式：将 id 改为一个不存在的值（如 id=0），让前半部分条件为假，迫使数据库必须执行后面的 sleep(3) 来判断整体真假。

踩坑记录二：页面卡死/空白（执行超时）

踩坑情况：使用 id=0 的 Payload 后，页面加载不出来，F12 显示请求耗时 20.02 s，浏览器一片空白。

原因分析：||（逻辑或）结构可能导致 sleep(3) 被多次执行（如针对不同行进行判断），导致总耗时超过 PHP 的 max_execution_time（默认 30 秒，部分 Docker 镜像可能设定更短）。服务器为了保护自己，掐断了响应，导致页面空白。

改进方式：这恰恰证明了盲注 Payload 生效。只要 F12 的响应时间远大于正常时间（如 20 秒远大于 0.03 秒），就说明注入成功，无需刷新页面。

详细实操步骤（Payload逐字解释）

第一步：构造并发送 Payload

在浏览器地址栏输入以下 URL（使用 id=0 并构造时间盲注）：

http://localhost:8081/Less-26a/?id=0%27)%7C%7Csleep(3)%7C%7C(%271%27=%271)

第二步：Payload 逐字解析

  • 0')：闭合原 SQL 中的 ('$id')，由于 id=0 不存在，前面的查询条件为假。
  • %7C%7C：URL 编码后的 ||（逻辑或），替代被过滤的 or。
  • sleep(3)：核心时间函数，让数据库停止 3 秒。
  • %7C%7C('1'='1)：再次使用 || 连接并手动闭合末尾的引号和括号，保证 SQL 语法完整。

第三步：验证结果

观察 F12 的 Network 面板。如果请求耗时远超正常值（如 20 秒），说明时间盲注成功。

4. 怎么迁移（跨领域联想）

  • 代码审计与 WAF 绕过：在真实环境中，遇到带有 WAF 的站点，SQLMap 常因 Payload 包含空格被拦截。此时需要编写自定义 Tamper 脚本，将空格替换为 %0a 或 /**/，将 and 替换为 &&。
  • MySQL 优化器与执行计划：通过盲注实验，可以深入理解 MySQL 优化器的工作机制。当条件可以通过主键或索引快速判断时，优化器会短路后续逻辑，这在实际开发中也是性能调优的依据。
  • 安全开发启示：依赖黑名单和字符串替换来防御注入极其脆弱。必须从代码层面（参数化查询）和服务器配置层面入手，才能根治 SQL 注入。

三、名词大全与原理深度复盘

1. 时间盲注

当页面没有回显位，且过滤了报错信息时，攻击者通过构造 if(条件, sleep(N), 0) 来制造延迟。如果条件成立，页面响应时间会显著增加。

2. URL 编码

将特殊字符转换为 % 加上两位十六进制数的形式，以便在 URL 中安全传输。%26 代表 &，%7C 代表 |，%27 代表 '。

3. 逻辑短路

在 SQL 中，A && B 如果 A 为假，B 不会被执行；A || B 如果 A 为真，B 不会被执行。MySQL 优化器会主动利用这种特性加速查询。

4. 黑名单过滤

通过正则表达式匹配并删除或拦截特定的危险字符或关键词。其局限性在于无法穷举所有变体，容易被符号替代或编码绕过。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-26 的区别：Less-26 是报错注入（有回显），Less-26a 是时间盲注（无回显）。Less-26a 的闭合方式是 ')，而 Less-26 是 '。
  • 与 Less-25a 的区别：Less-25a 只过滤了 or 和 and，Less-26a 在它们的基础上进一步过滤了空格和注释符。

2. 这种题目的出现原因（为什么存在）

从计算机底层来看，SQL 解析器对空白字符（空格、换行、制表符）的处理逻辑是一致的。开发者认为，只要通过正则把空格和注释符全部删掉，攻击者就无法构建复杂的 SQL 语句。这种漏洞的根源在于“黑名单防御”的先天缺陷。在历史生活中，这类似于古代城门守卫只知道没收刀剑，但不知道敌人可以用长矛或弓箭，防御手段始终滞后于攻击手段。

3. 这种应用在实际中如何体现？

在真实的渗透测试中，面对带有 WAF（Web 应用防火墙）的站点，SQLMap 等自动化工具常常因为 Payload 包含空格或注释符而被拦截。此时就需要编写自定义的 Tamper 脚本，将空格替换为 %0a 或 /**/，将 and 替换为 &&，以此来绕过 WAF 规则。

4. 如何抽象理解概念（大白话）

把题目比作一个“极其苛刻的检查站”：

  • 检查站宣布：禁止带“和（and）”字，禁止带“空白（空格）”，禁止带“橡皮擦（注释符）”。
  • 你原本写了一句“我吃苹果和香蕉”。检查员把“和”字没收了，把空格删了，变成“我吃苹果香蕉”。语法崩了。
  • 你换了一种写法：“我吃苹果&&香蕉”。检查员不认识 &&，放行了。末尾如果写不完整，你就自己画个句号（'1'='1），而不是用橡皮擦。这就是 Less-26a 的核心逻辑：利用语法规则的变体来欺骗过滤机制，同时靠时间差来传递信息。
