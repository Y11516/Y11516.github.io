File Inclusion(local) - Pikachu Writeup

2026年9月19日 Pikachu Web安全 文件包含

一、题目信息

  • 题目名称：File Inclusion(local)
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 文件包含漏洞 / 本地文件包含（LFI）
  • 靶场链接：http://localhost:8080/vul/fileinclude/fi_local.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是本地文件包含漏洞（Local File Inclusion, LFI）。后端代码使用了 PHP 的 include() 函数来动态引入用户请求的文件（如不同球员的介绍页面）。由于未对用户输入的 filename 参数进行严格过滤，攻击者可以利用路径穿越字符（../）跳出 Web 根目录，从而读取服务器上的任意敏感文件。

2. 怎么想（破题思路）

页面提供了一个 NBA 球员选择的下拉框。解题思路如下：

  • 正常选择一个球员（如 Kobe），点击提交。观察浏览器地址栏，发现 URL 变为 ?filename=kobe.php。
  • 既然后端是“取文件名并包含”，我们尝试把文件名替换为系统的绝对路径（如 /etc/passwd）。
  • 由于当前文件位于 /vul/fileinclude/ 目录下，需要使用 ../ 向上穿越四层目录，回到根目录，再定位到 /etc/passwd。构造 Payload：../../../../etc/passwd。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接输入绝对路径导致包含失败

踩坑情况：尝试在参数中直接输入 filename=/etc/passwd，服务器报错或页面无变化。

原因分析：在某些 PHP 配置或操作系统安全策略下，直接通过绝对路径包含系统文件可能会被拦截或解析失败。更常见的情况是，相对路径的处理需要开发者提供正确的相对层级。

改进方式：改用相对路径穿越。从当前 PHP 脚本所在目录向上跳，直到根目录，再去访问目标文件。

踩坑记录二：路径穿越层数计算错误

踩坑情况：输入 ../etc/passwd 或 ../../etc/passwd，页面提示找不到文件。

原因分析：当前脚本位于 /vul/fileinclude/fi_local.php。要回到根目录 /，需要依次跳出的层级为：fileinclude -> vul -> 根目录（即 ../../ 即可，但为了兼容更深层级，通常使用多余的 ../../../../ 也不会出错，因为 Linux 会忽略多余的上层访问）。

改进方式：使用足够长的穿越路径（如 4 个或 5 个 ../），确保能抵达根目录。

终极解法：利用路径穿越读取系统文件

在下拉框选择任意球员（或直接修改地址栏 URL），将 filename 参数修改为以下 Payload：

../../../../etc/passwd

代码逐个符号深度解析：

  • ..：代表上一级目录。在 Linux 系统中，这是目录层级的标准表示法。
  • /：路径分隔符。
  • ../../../../：连续四次返回上一级目录，确保跳出当前 Web 应用的目录结构，直达文件系统根目录 /。
  • etc：Linux 系统存放配置文件的目录。
  • passwd：Linux 系统存储用户账户信息的文件，通常所有用户都可读。

提交后，页面成功回显了系统的用户列表（包含 root、daemon、bin 等），证明本地文件包含攻击成功。

4. 怎么迁移（跨领域联想）

  • 日志文件包含（Log Poisoning）：如果无法直接读取含 Flag 的文件，可以尝试将 PHP 代码写入服务器日志（如 SSH 日志、Apache 日志），然后使用文件包含漏洞去包含该日志文件，从而将 LFI 升级为 RCE。
  • PHP 伪协议利用：结合 php://filter 协议，可以对目标文件进行 Base64 编码输出（例如 php://filter/read=convert.base64-encode/resource=index.php），从而绕过部分文件内容过滤，读取源码。
  • 代码审计与安全开发：防止文件包含漏洞的根本手段是：使用白名单机制（只允许包含指定的文件名），或者使用绝对路径，并过滤掉 ../、..\ 等路径穿越字符。

三、名词大全与原理深度复盘

1. PHP include() 与 require() 函数

这两个函数用于在当前 PHP 脚本中引入并执行另一个文件。include 在包含文件出错时只产生警告（E_WARNING），脚本继续执行；require 在出错时产生致命错误（E_COMPILE_ERROR），脚本终止。在文件包含漏洞中，通常使用的是 include，因为其容错性使得攻击者的 Payload 更有可能被执行。

2. 本地文件包含（LFI）与远程文件包含（RFI）

LFI 只能包含服务器本地的文件（如 /etc/passwd、日志文件）；RFI 可以包含远程服务器上的文件（如攻击者服务器上的 WebShell）。RFI 的利用条件更为苛刻（通常需要 PHP 配置中的 allow_url_include 为 On），LFI 则更为普遍。

3. 路径穿越（Directory Traversal）

攻击者利用 ../ 等相对路径符号，跳出 Web 服务器的根目录限制，访问文件系统中的其他敏感文件。这是 LFI 漏洞利用的核心技术之一。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 RCE 相比：RCE 是直接执行系统命令或代码；文件包含是读取或执行已有文件。文件包含往往作为 RCE 的前置步骤或跳板，攻击者通过包含恶意文件来达到 RCE 的目的。
  • 与文件下载漏洞相比：文件下载是直接将文件内容下载到本地，不经过解析执行；文件包含是将文件内容当作 PHP 代码执行（如果文件内含有 PHP 代码），或者直接输出内容（如读取 /etc/passwd）。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在模块化开发时（例如根据不同的页面参数动态加载不同的模块），直接使用了用户输入的参数来拼接文件路径，而没有对参数进行严格的校验。这种“图方便”的写法，直接将服务器的文件系统暴露给了攻击者。

3. 这种应用在实际中如何体现？

在实际渗透测试中，文件包含是高危漏洞的常客。攻击者经常会结合文件上传（上传图片马）与文件包含（包含图片马中的 PHP 代码）来绕过上传限制，最终获取服务器权限。在 CTF 比赛中，LFI 常常是考点，结合伪协议、日志包含、Session 包含等技巧，可以演变出非常复杂的攻击链。

4. 如何抽象理解概念（通俗理解）

如果把服务器比作一个图书馆：

  • 正常功能：你在前台点了一本《Kobe 传》（选择 kobe.php），管理员去指定书架上把这本书拿给你看。
  • 文件包含漏洞：你对管理员说：“我想看一本叫《../../../../etc/passwd》的书”（把敏感文件当成书名）。管理员没有怀疑，直接去系统深处把整个系统的“用户密码本”（/etc/passwd）原封不动地拿给你看。这就是文件包含的可怕之处——你的“书名”（参数）没有限制，可以操控服务器拿取任意文件。
