1. 遭遇报错，发现异常

我把图片下载到 Mac 桌面，双击用“预览”打开，结果系统直接弹出一个警告框：

“未能打开文件‘dabai.png’。它可能已损坏，或者可能使用了‘预览’无法识别的文件格式。”

我反复尝试了几次，甚至重新下载了文件，依然是这个报错。这说明，问题不是出在下载过程中，而是这个图片文件本身就有问题。

2. 寻找线索，阅读评论区

我在题目评论区寻找灵感，看到大佬们的提示：

  • “修改宽高显示”
  • “010打开，查看文件头，IHDR png图片格式，按照png图片的格式修改图片的高宽，的到flag”

这些提示立刻指明了方向：这张图片的宽高数据被出题人故意修改了，导致图片无法正常解析。

3. 使用在线工具一键修复（最快方案）

由于 Mac 上安装专业的十六进制编辑器比较麻烦，我直接使用了在线工具 tools.qsnctf.com 的“PNG 宽高修复”功能：

  • 浏览器访问：https://tools.qsnctf.com/#//misc/png_dim_fix
  • 上传 dabai.png。
  • 点击“检测并修复”。

工具自动计算出了正确的宽高，并生成了一张修复后的图片。我把它下载到本地，双击打开，上面清晰地展示了 Flag。

4. 备用方案：使用 Python 脚本修复

如果在线工具无法使用，我们也可以用 Python 直接修改文件头数据。我在终端用 Python 写了一个脚本：

import struct

with open('dabai.png', 'rb') as f:
    data = bytearray(f.read())

# PNG 文件头固定为 8 字节，紧接着是 IHDR 块
# 宽和高各占 4 个字节（大端序），高度在偏移量 20-24 字节
# 我们尝试把高度修改为 1000
try:
    width, height = struct.unpack('>II', data[16:24])
    print(f"原始尺寸: {width} x {height}")
    
    new_height = 1000
    data[20:24] = struct.pack('>I', new_height)
    
    with open('fixed.png', 'wb') as f:
        f.write(data)
    print("修复成功！已保存为 fixed.png")
except Exception as e:
    print("出错:", e)

运行脚本后，生成了 fixed.png，打开同样看到了 Flag。

三、原理深度剖析（为什么改宽高就能出 Flag？）

1. 什么是 PNG 的 IHDR？

PNG 图片的文件结构中，紧跟在文件头（8个字节）之后，有一个名为 IHDR 的数据块。它专门用来存储图像的基本信息，其中前 8 个字节分别定义了图片的**宽度（4字节）**和**高度（4字节）**。它们使用“大端序”存储。

2. 出题人是如何隐藏 Flag 的？

出题人写了一个脚本，把图片的高度改得非常小（或者把宽度改小）。这样，当你试图打开图片时，浏览器或看图软件会**根据错误的尺寸去解码后面的像素数据，导致数据错位或截断**，直接报错“文件已损坏”。

但图片的后半部分（被隐藏的、超出当前高度范围的数据）其实完好无损，Flag 就藏在那里。只要把高度改回正确的值，图片就能完整显示，Flag 就露出来了。

3. 为什么修改宽高不会影响图片底层的像素数据？

因为宽高信息只是图片的“头文件”或“说明书”。修改它，就像修改一本书的“目录页数”，书里面的内容（像素数据）并没有被删掉，只是被隐藏了起来。

四、名词解释（新名词大全）

1. PNG

一种常见的图片格式，全称“便携式网络图形”。它支持无损压缩和透明背景，是 CTF 隐写题中最常出现的图片格式之一。

2. IHDR

PNG 图片中专门存储宽、高、位深、颜色类型等信息的核心数据块。宽高数据被修改，图片就会显示异常。

3. 十六进制（Hex）

用数字 0-9 和字母 A-F 表示二进制数据的方式。在查看或修改文件底层数据时，我们通常使用十六进制。

4. 010 Editor

一款专业的十六进制编辑器，可以直接以二进制方式打开文件，直观地修改里面的字节数据（比如修改图片宽高）。

5. Mac 的“预览”

Mac 系统自带的看图软件。当图片的尺寸数据被修改导致数据错位时，它就会无法识别并报错。

6. 大端序 (Big-endian)

一种数据存储方式，高位字节存放在低地址，低位字节存放在高地址。PNG 的宽高数据就是大端序存储的。

五、防御思考与现实意义

这道题告诉我们，仅仅依靠修改文件头信息来隐藏数据是极其容易被破解的。在实际开发中，对文件的完整性校验（如 CRC 校验）非常重要。出题人故意修改了宽高却没有重算 CRC，所以我们才能通过工具轻易修复。如果重算了 CRC，就需要更复杂的计算才能恢复。
