  • 涉及工具：浏览器（URL 构造）

二、解题过程与原理剖析（核心复习素材）

1. 阅读源码，发现逻辑死结

打开靶场，网页直接暴露了后端 PHP 源代码：

<?php
$num=$_GET['num'];
if(!is_numeric($num))
{
    echo $num;
    if($num==1)
        echo 'flag{********}';
}
?>

代码逻辑翻译：

  • 代码从网址里接收一个名叫 num 的参数。
  • 第一关：!is_numeric($num)。要求这个参数不能是纯数字，才能进入下一层。
  • 第二关：$num==1。要求这个参数必须等于数字 1。

在人的常识里，“不是数字”和“等于数字1”是完全矛盾的。这就是题目名字的来源，也是出题人设下的陷阱。

2. 破局原理：PHP 弱类型比较（Weak Typing）

要在 Web 安全里打破这种死局，必须利用语言底层的特性。PHP 有一个著名的历史遗留特性——弱类型比较。

  • is_numeric() 函数的死板：它会从头到尾检查整个字符串。如果你传参 1abc，因为它包含字母，is_numeric("1abc") 会判定它为 False（不是纯数字）。加上前面的 !，变成 !False = True。成功绕过第一关！
  • == 运算符的“自作聪明”：当字符串与数字用 == 比较时，PHP 会尝试把字符串强制转成数字。它会从左往右读，读到 1 后就停下来，丢弃后面的 abc。最终变成了 1 == 1，返回 True。成功绕过第二关！

3. 构造 Payload 并提交

理解了原理后，我们只需要构造一个以数字 1 开头，但后面跟着字母的非纯数字字符串。在浏览器地址栏输入：

http://160.202.254.160:17707/?num=1abc

回车后，网页成功打印出了 Flag。

最终 Flag： flag{...}

三、知识点总结

  • 1. 后端语言 PHP 与前端 HTML 的区别：前端代码运行在用户的浏览器上（可以随意用 F12 修改），而后端 PHP 代码运行在服务器上。我们无法篡改服务器上的代码，只能顺着它的逻辑，利用其语言漏洞（如弱类型）来构造恶意参数。
  • 2. is_numeric() 函数：用于判断变量是否为数字或纯数字字符串。遇到包含字母的字符串会返回 False。
  • 3. PHP 弱类型比较：使用 == 时，PHP 会尝试进行类型转换。字符串转数字时，会截取开头的数字部分。这是 WEB 安全中极其常见的绕过手段。
  • 4. 防御方法：在实际开发中，应尽量使用强类型比较 ===（全等，要求类型和值都一致），并配合 intval() 等函数进行类型转换，以避免弱类型绕过漏洞。
