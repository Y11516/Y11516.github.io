DVWA-Low-文件包含 (File Inclusion)

2026年10月2日 DVWA Web安全 文件包含 LFI

一、题目信息

  • 题目名称：DVWA File Inclusion (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 文件包含 / 路径穿越
  • 靶场链接：http://192.168.242.80/vulnerabilities/fi/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是文件包含漏洞（File Inclusion）。后端代码通过参数 ?page= 动态引入文件，但没有对用户输入的路径进行过滤。攻击者可以利用 ../ 路径穿越符读取服务器任意文件，或利用 php://filter 伪协议读取 PHP 源码。

2. 怎么想（破题思路）

  • 观察 URL，发现 page=include.php，推测后端使用了 include() 函数。
  • 点击页面上的 [file1.php]、[file2.php]、[file3.php] 链接，观察正常业务逻辑。
  • 尝试输入不存在的文件名，报错信息可能会暴露服务器物理路径。
  • 利用 ../ 向上跳转目录，尝试读取 /etc/passwd。
  • 利用 PHP 伪协议 php://filter，将 PHP 文件以 Base64 编码输出，从而获取源码。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：路径深度不够导致页面空白

踩坑情况：初次尝试时，输入了 ../../../../etc/passwd（4 个 ../），页面没有报错，但没有任何回显，一片空白。

原因分析：DVWA 的 Web 目录嵌套较深，4 个 ../ 只跳出了部分目录，没有到达根目录。且 PHP 的 include() 在找不到文件时可能静默失败，不输出错误。

改进方式：增加路径穿越的深度，输入 ../../../../../../../etc/passwd（7 个 ../），最终成功读取到系统用户配置文件。

踩坑记录二：直接包含 PHP 文件看不到源码

踩坑情况：在输入框输入 index.php，页面没有报错，但显示的是页面本身，看不到 PHP 源代码。

原因分析：PHP 的 include() 函数会“包含并执行”文件。如果包含的是 PHP 文件，服务器会执行它，而不是把源码打印出来。

改进方式：使用 php://filter/convert.base64-encode/resource=index.php，强制服务器把源码转成 Base64 字符串输出，之后我们手动解码即可。

详细实操步骤（Payload逐字解释）

第一步：观察正常业务功能（业务背景）

点击页面上的 [file1.php]、[file2.php]、[file3.php]：

  • file1.php：动态生成页面，输出当前用户名和 IP 地址（如“Hello admin, Your IP address is: 192.168.1.19”）。
  • file2.php：静态内容页面，输出一句名言。
  • file3.php：环境探测页面，输出你的浏览器 User-Agent、Referer 和服务器 IP。

这证实了后端代码正是通过 include($_GET['page']); 来动态加载这些本地文件的。

第二步：读取系统敏感文件（LFI）

在输入框输入：../../../../../../../etc/passwd

解释：../ 代表向上一级目录跳转，连续输 7 次就能从 Web 目录跳转到根目录，从而读取 Linux 用户配置文件。

响应结果：页面成功回显 root:x:0:0:root:/root:/bin/bash 等用户列表。

第三步：读取 PHP 源码（伪协议）

在输入框输入：php://filter/convert.base64-encode/resource=index.php

解释：

  • php://filter：PHP 自带的过滤器协议。
  • convert.base64-encode：将读取到的内容进行 Base64 编码。
  • resource=index.php：指定要读取的目标文件。

响应结果：页面返回一长串 Base64 编码字符串。将其复制到解码工具中，即可看到 index.php 的完整源码。

4. 怎么迁移（跨领域联想）

  • 云服务器的配置泄露：很多云服务商的控制面板存在文件包含漏洞。攻击者可以利用该漏洞读取云服务器上的 /root/.ssh/id_rsa（SSH 私钥），直接登录服务器。
  • Web 中间件日志投毒：如果无法上传 Webshell，攻击者可以通过包含服务器日志文件（如 /var/log/apache2/access.log），并在 User-Agent 中写入 PHP 代码，从而间接实现 RCE。

三、名词大全与原理深度复盘

1. 文件包含 (File Inclusion)

指程序动态引入文件的功能。如果引入的文件由用户控制，且未做严格过滤，就可能导致文件包含漏洞。分为本地文件包含（LFI）和远程文件包含（RFI）。

2. 路径穿越 (Path Traversal)

利用 ../ 或 ..\ 等符号，跳出 Web 根目录的限制，访问服务器上的其他敏感文件。

3. PHP 伪协议 (PHP Wrappers)

PHP 内置的多种协议，如 php://filter、php://input、data:// 等。在文件包含漏洞中，它们常被用来读取源码或执行代码。

4. LFI 与 RFI 的区别

  • LFI（本地文件包含）：只能包含服务器本地的文件，如 /etc/passwd。通常配合文件上传漏洞（图片马）实现 RCE。
  • RFI（远程文件包含）：可以包含远程服务器上的文件（如 http://evil.com/shell.txt）。条件更苛刻，但危害更大。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与命令注入的区别：命令注入是在操作系统层面执行命令，而文件包含是在 PHP 代码层面引入文件。文件包含更容易绕过 WAF 的规则。
  • 与 SQL 注入的区别：SQL 注入攻击的是数据库，文件包含攻击的是服务器的文件系统。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者为了方便，使用了动态包含文件的方式，却没有对参数进行白名单限制。例如：include($_GET['page']);。

从历史角度看，这类似于 PHP 早期开发中的典型问题。当时的开发者习惯把页面的各个模块（如头部、尾部）放在不同的文件中，通过参数动态引入。这种懒惰的开发方式造就了大量的文件包含漏洞。

3. 这种的应用

在护网中，文件包含是读取源码的利器。攻击者通过读取 config.php、database.php 等配置文件，获取数据库账号密码，或者通过读取源码找到更多隐藏的接口和漏洞。

4. 如何抽象理解概念（大白话）

把文件包含比作“点外卖”：

  • 正常情况：你告诉外卖员：“帮我把桌上的那本《菜单》拿过来。”（输入 page=menu.php）
  • 恶意情况：你告诉外卖员：“帮我把对面银行金库的钥匙拿过来。”（输入 page=../../../../etc/passwd）
  • 如果外卖员不加思考（没做过滤），他真的会去银行把钥匙拿给你。这就是文件包含漏洞。

做一道题，就要往自己脑子里装点东西。
