DVWA-Medium-反射型XSS (XSS Reflected)

2026年10月2日 DVWA Web安全 XSS 服务端黑名单绕过

一、题目信息

  • 题目名称：DVWA XSS (Reflected) (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 跨站脚本攻击 / 反射型 XSS / 黑名单绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/xss_r/
  • 涉及工具：Google Chrome 浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是绕过 Medium 级别的服务端黑名单过滤。与 Low 级别不同，Medium 级别在服务端使用了 str_replace 函数，将 <script> 标签替换为空字符串。攻击者需要寻找其他可执行的 HTML 标签（如 <img>、<svg>）来绕过过滤并执行 JavaScript。

2. 怎么想（破题思路）

  • 尝试 Low 级别的 Payload <script>alert(1)</script>，发现弹窗失败。
  • 推测服务端使用了 str_replace("<script>", "", $input) 或类似逻辑。
  • 服务端黑名单通常只针对特定标签，我们可以尝试使用 <img> 标签的 onerror 事件来执行脚本。
  • 输入 <img src=x onerror=alert(1)>，成功绕过并弹窗。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：使用 <script> 标签被服务端过滤

踩坑情况：在输入框输入 <script>alert(1)</script>，页面没有弹窗，或者弹窗内容被替换为空白。

原因分析：Medium 级别服务端代码使用了 str_replace 将 <script> 替换为空，导致 Payload 在到达浏览器之前就被破坏了。

改进方式：改用不需要 <script> 标签的 Payload，例如 <img src=x onerror=alert(1)>，利用图片加载失败的事件来触发弹窗。

详细实操步骤（Payload逐字解释）

第一步：验证服务端过滤

在输入框输入：<script>alert(1)</script>，点击 Submit，无弹窗。

第二步：使用 img 标签绕过

在输入框输入：<img src=x onerror=alert(1)>

逐个字符解释：

  • <img>：图片标签，不在服务端黑名单内。
  • src=x：指定一个不存在的图片地址。
  • onerror=alert(1)：当图片加载失败时，执行 alert(1) 弹窗。

响应结果：页面成功弹出提示框，绕过了 Medium 级别的服务端过滤。

第三步：备选方案（Burp 抓包注入 User-Agent）

如果 <img> 也被过滤，可以使用 Burp 拦截请求，将 User-Agent 头修改为 <script>alert(1)</script>，部分版本会将 User-Agent 直接输出到页面中，从而绕过对用户输入参数的过滤。

4. 怎么迁移（跨领域联想）

  • WAF 绕过实战：在真实的护网中，WAF 常常基于黑名单来拦截 XSS 攻击（如过滤 script、onerror 等关键字）。攻击者通常会寻找等价标签（如 <svg>、<details>）或使用编码绕过。
  • 安全开发启示：黑名单防御是“防不胜防”的。正确的做法是使用白名单（只允许特定的安全标签），或者使用成熟的 HTML 实体编码库（如 DOMPurify）对输出进行严格编码。

三、名词大全与原理深度复盘

1. 反射型 XSS

恶意代码作为请求的一部分发送给服务器，服务器将其“反射”回响应中，浏览器执行代码。它是一次性的，必须诱导受害者点击特定链接才能触发。

2. 服务端黑名单过滤

一种在服务器端 PHP 代码中实现的过滤机制。它通常使用 str_replace() 函数将特定的关键字替换为空。这种过滤容易绕过，因为攻击者可以找到未被列入黑名单的等价标签。

3. onerror 事件

HTML 标签的事件属性。当资源（如图片、脚本）加载失败时触发。在 XSS 中常被用来替代 <script> 标签执行 JavaScript。

4. HTML 实体编码 (HTML Entity Encoding)

防御 XSS 的核心手段。将特殊字符（如 <、>、&、"）转换为对应的 HTML 实体，使浏览器将其视为纯文本而非代码。这是 High 级别采用的防御手段。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何过滤，可以直接使用 <script>。Medium 级别加入了服务端黑名单，需要寻找新的标签（如 img）来绕过。
  • 与 DOM 型 XSS 的区别：反射型 XSS 需要服务器将恶意代码拼接到 HTML 中返回。DOM 型 XSS 完全在客户端发生，服务器只返回了静态的 JS 代码，是 JS 代码自己“读取”并“执行”了恶意参数。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者试图用“黑名单”来防御 XSS，但低估了攻击者的创造力。很多 HTML 标签都可以执行 JavaScript（如 img、svg、iframe），只要漏掉一个，防御就会失效。

3. 这种的应用

在护网中，反射型 XSS 常被用来窃取用户的 Cookie（document.cookie），进而实现会话劫持。攻击者会把恶意链接发给管理员，管理员点击后，攻击者就能拿到管理员的 Cookie，登录后台。

4. 如何抽象理解概念（大白话）

把反射型 XSS 比作“快递里塞传单”：

  • 正常情况：你给朋友寄快递，里面只放了一本书（正常文本）。朋友收到后翻看。
  • Low 级别：你在快递里塞了一张“把钥匙扔下楼”的纸条（恶意脚本）。朋友完全照做。
  • Medium 级别：快递员检查快递，看到“钥匙”两个字就没收。你换了个词“门禁卡”，快递员没认出来，朋友还是照做了。这就是黑名单绕过。
