二、解题步骤

1. 分析题目考什么

本题的核心考点是黑名单过滤下的命令注入绕过。后端代码使用 preg_match_all() 函数检测并拦截了用户输入中的 cat 字符串。攻击者需要寻找功能相同但名称不同的替代命令（如 tac、nl、base64），或者利用其他技巧绕过过滤，读取目标文件。

2. 怎么想（破题思路）

  • 页面提示“过滤了cat命令之后，你还有什么方法能读到 Flag？”。
  • 源码中 preg_match_all("/cat/", $ip, $m) 限制了输入中不能包含 "cat" 字符串。
  • 既然不能使用 cat，我们就在 Linux 命令库中寻找替代品。能读取文件内容的命令有：tac（倒序读取）、nl（带行号）、base64（编码读取）、sort、head、tail 等。
  • 直接使用 tac 可能因为 PHP 解析器把注释吃掉导致页面空白，最稳妥的绕过方式依然是使用 base64 编码读取。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接使用 cat 触发拦截

踩坑情况：习惯性地输入 127.0.0.1; cat /flag，页面弹出警告或 Hacker!!!。

原因分析：preg_match_all 匹配到了 "cat"，导致代码走向 else 分支，直接返回错误信息。

改进方式：必须放弃使用 cat，改用其他读取文件的命令。

踩坑记录二：使用 tac 读取文件导致空白

踩坑情况：输入 127.0.0.1; tac flag_xxx.php，命令执行成功（数组里能看到），但输出的内容为空白。

原因分析：Flag 文件是 PHP 文件，内容是 <?php // ctfhub{...} ?>。虽然 tac 成功读取了文件，但 PHP 解析器会执行代码，// 后面的内容被当作注释吞掉，导致无回显。

改进方式：必须使用 base64 命令，因为它会将文件内容原封不动地编码成字符串，不会触发 PHP 解析。

详细实操步骤（使用 base64 绕过）

第一步：探测根目录

构造 Payload 查看当前目录：

127.0.0.1; ls

发现目标文件：flag_22911684218551.php。

第二步：使用 base64 命令读取文件

构造 Payload：

127.0.0.1; base64 flag_22911684218551.php

Payload 逐字深度解析：

  • 127.0.0.1：让 ping 命令正常执行。
  • ;：命令分隔符。
  • base64：Linux 系统命令，将文件内容转换为 Base64 编码并输出。
  • flag_22911684218551.php：目标文件名（不含 "cat" 字符串，成功绕过过滤）。

第三步：解码并提交

页面回显一串 Base64 字符串，复制后去 [Base64 在线解码](https://www.base64decode.org/) 粘贴解码，得到明文 Flag。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 命令替换与 WAF 绕过：在真实渗透中，WAF 常拦截 cat、whoami 等敏感命令。攻击者会尝试用 tac、nl、sort、head 替代，或用变量拼接（如 a=c; b=at; $a$b）绕过。
  • 通配符与正则绕过：可以用 c?t、[c]at 或 ca$1t 等方式绕过简单的正则匹配。
  • 安全开发（SDL）：防御命令注入绝对不能用黑名单，必须使用白名单。对用户输入进行 escapeshellarg() 转义，或直接避免使用系统命令。

三、名词大全与原理深度复盘

1. 黑名单过滤的缺陷

黑名单机制（如过滤 "cat"）存在天然缺陷，因为存在无穷无尽的替代方案。攻击者总能找到功能相同但名字不同的命令，或利用字符拼接、大小写等技巧绕过。白名单机制（只允许特定输入）才是安全的防御手段。

2. preg_match_all 函数

PHP 用于执行全局正则匹配的函数。在本题中用于检测输入中是否包含 "cat"。一旦匹配成功，返回非零值，加上 ! 后变为 false，从而拦截执行。

3. 为什么 base64 命令能绕过读取限制？

cat 命令只是文本查看器，而 base64 是数据编码器。它将文件内容转换为 64 个可打印字符组成的字符串，绕过了 PHP 对 <?php ... ?> 代码的解析与执行，确保原始数据完整输出给攻击者。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“无过滤”的区别：“无过滤”可以随意使用任何命令；“过滤cat”则需要绕过黑名单，考验命令行的灵活运用。
  • 与代码执行（eval）的区别：代码执行是执行 PHP 代码，需要符合 PHP 语法；命令注入是直接执行系统命令，绕过 WAF 的方式更依赖 Linux 技巧。

2. 这种题目的出现原因

开发人员试图通过简单的字符串替换（或黑名单）来防止命令注入。例如，认为“只要禁用了 cat，攻击者就无法读取文件”。这种防御措施治标不治本，因为系统命令的替代方案实在太多了。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，攻击者一旦发现命令注入漏洞，会使用各种替代命令和混淆技术来绕过 WAF。例如使用 ca\t、c'a't、/bin/c?t 或 $IFS 变量绕过空格限制，这些技巧在实战中极为常见。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个老实的传令兵：

  • 正常流程：你给传令兵一张纸条，上面写着“去敲 127.0.0.1 的门；顺便把保险柜里的 flag 拿出来”。
  • 黑名单（过滤 cat）：上级规定，纸条上不能出现“使用锤子”（cat）这个词。
  • 绕过（使用 base64）：你灵机一动，对传令兵说：“不用锤子，用砖头（base64）把保险柜砸开！”传令兵听不懂上级的规则，他只服从命令，于是老老实实用砖头把东西给你拿了出来。

做一道题，就要往自己脑子里装点东西。
