CTFHub SSRF - 数字IP Bypass

2026年9月23日 CTFHub Web安全 SSRF 进制转换绕过

一、题目信息

  • 题目名称：SSRF - 数字IP Bypass
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / SSRF（服务端请求伪造） / 黑名单绕过
  • 靶场链接：http://challenge-89e896f31df0ae59.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 IP 地址的进制转换绕过 WAF 的字符串检测。题目明确提示“ban 掉了 127 以及 172，不能使用点分十进制”。后端或 WAF 通常使用正则匹配字符串 127 或 172 来拦截请求。攻击者可以利用 Linux 底层网络解析函数的特性，将点分十进制 IP 转换为纯十进制、八进制或十六进制，从而在保持“指向 127.0.0.1”的同时，绕过字符串检测。

2. 怎么想（破题思路）

  • 题目提示“ban 掉了 127 以及 172”，说明 WAF 正在检测 URL 参数中是否包含这两个字符串。
  • 目标依然是访问 127.0.0.1/flag.php（本地回环）。
  • 突破口：IPv4 地址本质上是一个 32 位的二进制整数。127.0.0.1 可以表示为十进制整数 2130706433，或者八进制的 0177.0.0.1，十六进制的 0x7f.0.0.1。
  • WAF 只懂字符串匹配，看到 2130706433 会放行；而 Linux 底层的 inet_aton() 等函数会把它正确解析回 127.0.0.1。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：直接使用 127.0.0.1 被拦截

踩坑情况：尝试输入 ?url=http://127.0.0.1/flag.php，页面返回 Hacker!!! 或直接报错。

原因分析：WAF 检测到了字符串中的 127 和 .，触发了拦截规则。

改进方式：将 IP 转换为纯十进制整数 2130706433，避开 WAF 的字符串特征库。

详细实操步骤（逐字解析）

在浏览器地址栏输入以下 Payload（使用十进制 IP）：

http://challenge-89e896f31df0ae59.sandbox.ctfhub.com:10800/?url=http://2130706433/flag.php

Payload 逐字深度解析：

  • ?url=：传递给服务器的参数名。
  • http://：声明使用 HTTP 协议。
  • 2130706433：127.0.0.1 的纯十进制表示形式。计算方式为：127 * 256^3 + 0 * 256^2 + 0 * 256 + 1 = 2130706433。
  • /flag.php：内网中的目标文件路径。

页面直接回显明文 ctfhub{b0cedaad7ff26a851b0c4541}，提交即可通关。

备选方案（如果十进制被拦截）：

  • 八进制：?url=http://0177.0.0.1/flag.php
  • 十六进制：?url=http://0x7f.0.0.1/flag.php
  • 省略写法：?url=http://127.1/flag.php
  • 混合进制：?url=http://0x7f.0.0.1/flag.php（如果只过滤了127）

4. 怎么迁移（跨领域联想）

  • WAF 绕过实战：在真实的红蓝对抗中，WAF 和云安全组经常只对特定的 IP 字符串进行拦截。攻击者会利用进制转换、IP 缩写、甚至 IPv6 格式（如 [::1]）来绕过这些边界防御，从而访问内网服务。
  • 隐匿 C2 基础设施：在 C2（命令与控制）服务器中，攻击者常将 IP 转换为十进制或域名，以逃避威胁情报的 IP 黑名单拦截和沙箱分析。
  • 安全开发（SDL）：开发者在写校验代码时，绝不能直接用字符串匹配来判断 IP。应该使用 ip2long() 或 inet_pton() 将 IP 转换为标准二进制格式后再进行判断。

三、名词大全与原理深度复盘

1. 点分十进制（Dotted Decimal Notation）

即我们日常看到的 192.168.1.1 这种格式。它把 32 位的 IP 地址分成四段，每段 8 位（0-255），用点号分隔，方便人类阅读和记忆。

2. 纯十进制 IP（Integer IP）

IP 地址在计算机底层就是一个 32 位无符号整数。例如 127.0.0.1 对应的二进制是 01111111 00000000 00000000 00000001，转换成十进制就是 2130706433。WAF 通常只识别字符串 127.0.0.1，但对纯数字 2130706433 一无所知。

3. inet_aton() 与 inet_pton()

Linux 中用于将 IP 地址字符串转换为网络字节序整数的函数。它们非常“宽容”，能自动识别十进制、八进制（以 0 开头）、十六进制（以 0x 开头）等格式，并统一转换为正确的网络地址。这是绕过字符串检测的核心底层原理。

四、题目思考

1. 这跟前面的 URL Bypass 有什么区别？

  • 与“URL Bypass”的区别：URL Bypass 利用了 URL 协议结构中的 @ 符号，欺骗的是“前缀校验逻辑”；而数字 IP Bypass 利用的是“进制转换”，欺骗的是 WAF 的“字符串特征库”。一个是结构欺骗，一个是格式欺骗。
  • 与“内网访问”的区别：“内网访问”没有防御，直接输入 127.0.0.1 就行；本题增加了黑名单机制，需要绕过 127 和 172 的关键字检测。

2. 这种题目的出现原因

这类漏洞源于开发人员的安全认知偏差。他们知道要拦截 127.0.0.1，于是用正则去匹配字符串，却不知道 IP 协议本身支持多种进制表示。这本质上是“安全校验规则存在缺陷”，防御方对底层网络协议的理解不够深入。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，SSRF 配合进制转换是绕过企业边界防火墙和云安全组的常见手段。攻击者常利用它访问云元数据（169.254.169.254）、内网 Redis、数据库等服务，是内网横向移动的核心技巧。

4. 如何抽象理解概念（大白话理解）

把服务器比作大楼的安检员：

  • 黑名单校验（安检员）：安检员手里有一张纸条，写着“禁止穿黑衣服（127）的人进入”。
  • 攻击者构造：你本来穿着黑衣服，但你在外面套了一件白大褂（十进制表示）。安检员只看颜色，没看到黑色，就放你进去了。
  • 底层请求（实际执行）：你进去脱掉白大褂，里面还是那件黑衣服。真正的内部工作人员（Linux 底层函数）一眼就认出你是黑衣服，带你去了正确的房间（127.0.0.1）。
  • 结论：安检员只看表面特征，没有检查真正的内容，从而被“格式转换”欺骗。
