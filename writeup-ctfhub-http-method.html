请求方式 - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 HTTP协议 自定义请求方法

这是一道考察 HTTP 协议底层基础概念的题目。目标服务器要求我们使用非标准的 HTTP 方法进行请求，以此来绕过常规的浏览器行为并获取 Flag。

一、题目信息

  • 题目名称：请求方式
  • 题目平台：CTFHub
  • 题目类型：Web / HTTP 协议 / 请求方法
  • 涉及工具：Mac 终端（curl 命令）
  • 最终Flag： ctfhub{aafb695a7d3afe656b98df8a}

二、解题过程

1. 分析页面提示

进入靶场，页面返回了如下关键信息：

  • HTTP Method is GET：说明当前浏览器用的是默认的 GET 请求。
  • Use CTF**B Method, I will give you flag.：明确告诉我们，服务器需要接收一个名为 CTFHUB 的自定义请求方法。
  • Hint: If you got "HTTP Method Not Allowed" Error, you should request index.php.：提示如果直接请求根目录报错，需要指定请求 /index.php。

浏览器地址栏默认只能发送 GET 请求，无法满足题目的要求。因此我们需要借助命令行工具或抓包工具来伪造自定义的 HTTP 请求方法。

2. 使用 curl 构造自定义请求

Mac 系统自带 curl 工具，可以很方便地在终端发送自定义 HTTP 请求。根据题目提示，我们需要请求 /index.php，并使用 CTFHUB 方法。

在终端输入以下命令：

curl -X CTFHUB http://challenge-791b0c69c5877bc7.sandbox.ctfhub.com:10800/index.php

命令解释：

  • curl：发起网络请求的命令行工具。
  • -X CTFHUB：-X 参数用来指定 HTTP 请求方法（Method）。
  • URL：目标服务器的地址，必须精确拼写，不能有多余的字符。

3. 成功获取 Flag

按下回车后，终端成功返回了 HTML 源码，我们在 <body> 标签中找到了 Flag：

good job! ctfhub{aafb695a7d3afe656b98df8a}

三、踩坑记录与排错过程

在操作过程中，我由于粗心犯了一个典型的错误：

第二次尝试时，我输入了：

curl -XCTFHUBhttp://http://challenge791b0c69c5877bc7.sandbox.ctfhub.com:10800/index.php

终端报错：curl: (2) no URL specified。

原因分析：

  • 缺少空格：-X 和 CTFHUB 之间必须有空格，且自定义方法名与 URL 之间也必须有空格。命令参数粘连在一起会导致 curl 无法正确解析。
  • URL 拼写错误：URL 中多写了一个 http://，且 challenge-791 中的短横线 - 被丢失。

修正拼写并重新执行后，成功获取数据。

四、知识点总结（往脑子里装的东西）

  • HTTP 请求方法（HTTP Methods）：HTTP/1.1 协议定义了八种标准方法（GET、POST、PUT、DELETE、HEAD、OPTIONS、TRACE、CONNECT）。除了标准方法外，服务器也可以自定义并接收特定格式的请求方法（如本题的 CTFHUB）。
  • 浏览器的局限：浏览器地址栏默认只能发送 GET 请求，表单可以发送 GET 或 POST 请求。对于 PUT、DELETE 或自定义方法，必须借助代理工具（Burp Suite）或命令行工具（curl）。
  • curl 工具的威力：curl -X 方法名 URL 是 Web 安全测试中极为常用的命令，用于快速验证接口对非标准请求方法的处理方式。
