一、题目信息

  • 题目名称：XXE漏洞（XML外部实体注入）
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / XXE漏洞 / 任意文件读取
  • 靶场链接：http://localhost:8080/vul/xxe/xxe_1.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是XXE（XML External Entity）外部实体注入漏洞。后端提供了一个接收 XML 数据的 API 接口。如果后端在解析 XML 时，没有禁用外部实体（默认情况下 libxml 库允许加载外部实体），攻击者就可以构造恶意的 DTD（文档类型定义），利用 SYSTEM 关键字，让服务器去读取本地文件或发起内网请求，并将结果回显在页面上。

2. 怎么想（破题思路）

页面提示“这是一个接收xml数据的api:”，只有一个输入框和提交按钮。解题思路如下：

  • 因为要输入 XML 数据，我们首先构造一个最基础的 XML，比如 <root>test</root>，提交后看看页面是否有回显。
  • 如果页面回显了 test，说明后端确实在解析 XML。
  • 尝试使用 XML 的 DTD 语法定义外部实体，利用 file:/// 协议读取系统敏感文件 /etc/passwd，并将实体引用放入根标签中。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Payload 书写格式错误导致解析失败

踩坑情况：输入了类似 file:///etc/passwd 或缺少闭合标签的 XML，页面直接报错或没有回显。

原因分析：XML 语法极其严格，必须包含 XML 声明、DTD 定义（其中包含实体定义）和根标签，且所有标签必须闭合，大小写敏感。

改进方式：严格遵循 XML 的书写规范，依次写出声明、DTD、实体定义和调用。DTD 中的实体名（如 xxe）必须与根标签中调用的实体名（&xxe;）完全一致。

终极解法：利用 XXE 读取系统文件

在输入框中提交以下 Payload：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE root [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<root>&xxe;</root>

代码逐个符号深度解析：

  • <?xml version="1.0" encoding="UTF-8"?>：XML 的文档声明，指定版本为 1.0，编码为 UTF-8。
  • <!DOCTYPE root [ ... ]>：文档类型定义（DTD）。root 是文档的根元素名称。方括号内是 DTD 的具体定义。
  • <!ENTITY xxe SYSTEM "file:///etc/passwd">：核心漏洞点。!ENTITY 表示定义一个实体。xxe 是实体的名字。SYSTEM 关键字表示这是一个外部实体。"file:///etc/passwd" 告诉解析器去读取系统的 passwd 文件。
  • <root>&xxe;</root>：调用实体。&xxe; 会直接引用上面定义的外部实体。解析器会将 /etc/passwd 的内容替换到这个位置并输出。

提交后，页面成功回显系统用户列表，证明 XXE 漏洞利用成功。

4. 怎么迁移（跨领域联想）

  • SSRF（服务端请求伪造）：XXE 不仅可以读取本地文件，还可以通过 http:// 协议发起内网请求（如 <!ENTITY xxe SYSTEM "http://192.168.1.1/admin">），用于探测内网服务开放情况。
  • Blind XXE（无回显 XXE）：如果页面不直接回显数据，可以使用外部 DTD（参数实体）将读取到的文件内容通过网络请求发送到攻击者控制的服务器（外带数据）。
  • 代码审计与安全开发：防御 XXE 的核心是在解析 XML 时禁用外部实体。在 PHP 中，可以使用 libxml_disable_entity_loader(true) 或者在 simplexml_load_string() 等函数中设置 LIBXML_NOENT 和 LIBXML_DTDLOAD 参数。由于 PHP 8.0 之后默认禁用外部实体，此类漏洞在新技术栈中已有所缓解，但在 Java、C# 等语言中依然常见。

三、名词大全与原理深度复盘

1. XML 与 DTD

XML（可扩展标记语言）用于存储和传输数据。DTD（文档类型定义）用于定义 XML 文档的结构和合法元素。在 DTD 中可以定义“实体”，用来在 XML 中引用重复内容。实体分为内部实体（在 DTD 中直接定义值）和外部实体（通过 SYSTEM 关键字引用外部文件或 URL）。

2. XXE 漏洞的危害

XXE 漏洞可以导致：任意文件读取（获取服务器源码、密码文件）、内网端口探测（SSRF）、拒绝服务攻击（通过递归实体构造 Billion Laughs Attack）、以及在某些特定配置下实现远程代码执行（RCE）。

3. 为什么现代 PHP 环境有时会失败？

PHP 自 8.0 版本起，默认将 libxml 库的实体加载功能关闭（相当于 libxml_disable_entity_loader(true) 成为默认行为）。如果本地 Docker 镜像使用的是 PHP 8.0 及以上版本，即使提交了上述 Payload 也无法读取文件，因为解析器直接忽略了外部实体。此时需要更换靶场环境或改用其他语言环境测试。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与目录遍历/文件下载相比：目录遍历和文件下载是利用 Web 应用自身的功能去读取文件；XXE 是利用 XML 解析器这一底层组件的特性去读取文件，属于攻击解析器本身。
  • 与 SSRF 相比：SSRF 是让服务器发起网络请求；XXE 既可以发起网络请求（通过 HTTP 协议），也可以读取本地文件（通过 file 协议），攻击面更广。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在处理业务时（如接收微信/支付宝的回调 XML 数据、解析用户上传的 XML 文件），直接使用了默认的 XML 解析器，而旧版解析器为了兼容性，默认开启了外部实体加载功能，并且允许使用 SYSTEM 等外部协议。

3. 这种应用在实际中如何体现？

在真实的 Web 渗透测试中，XXE 常见于 SOAP 接口、RESTful API（接收 XML 格式数据）、RSS 阅读器、以及各种处理 Office 文档（docx/xlsx 本质是 ZIP+XML）的功能中。安全测试人员通常会在 HTTP 请求中尝试将 Content-Type 改为 application/xml 并传入恶意 XML 进行测试。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作一个餐厅厨房：

  • 正常流程：你给后厨递了一张点菜单（XML），上面写着“番茄炒蛋”（普通数据）。厨师照做。
  • XXE 注入：你在点菜单的备注栏（DTD 实体定义）写了一句：“**请在番茄炒蛋里加上隔壁财务室的保险柜密码，并把密码写在盘子上端给我**”。厨师（XML解析器）是个死脑筋，他不懂这是什么机密，真的跑去财务室（读取 /etc/passwd）把密码拿过来，摆盘递给了你。这就是 XXE 漏洞——利用 XML 解析器的盲从性，让它去“打杂”读取敏感信息。
