source - Bugku Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 Git源码泄露 数字取证

这是我迄今为止遇到的最硬核、最像真实渗透测试的一道题。它没有花里胡哨的前端限制，只有一行“Hello,world!”。但这道题让我学会了如何利用 .git 源码泄露漏洞，并在 Mac 终端中一步步找回被遗弃的历史版本（悬空对象），最终拿到 Flag。

一、题目信息

  • 题目名称：source
  • 题目平台：Bugku CTF
  • 题目类型：Web / Git源码泄露 / 历史版本回溯
  • 涉及工具：Mac 终端（Terminal）、git-dumper、Git 命令行工具（git log / git show / git fsck）

二、解题步骤（完整曲折的心路历程）

1. 发现隐藏线索 <!--tig-->

打开靶场，页面上只有一句“Hello,world! This is my friend :”。我按 Fn+F12 查看源码，发现了一句特殊的 HTML 注释：<!--tig-->。

查阅资料后得知，tig 是 Git 的一个命令行可视化工具。这强烈暗示了本题与 Git 版本控制有关。

2. 验证 .git 目录泄露漏洞

在网址后加上 /.git/ 并访问（http://靶场地址/.git/），页面竟然直接列出了 Git 仓库的所有文件（如 HEAD、config、objects/ 等）。这证明服务器没有删除隐藏的版本控制目录，发生了严重的源码泄露。

3. 配置终端环境，下载源码

因为目录文件太多，无法在浏览器里一个个下。我打开了 Mac 的“终端”，准备使用 git-dumper 工具下载整个仓库。

踩坑记录：第一次尝试时，终端报错 command not found: git-dumper。查阅资料后得知，Mac 系统没有把用户级安装的 Python 工具自动加入环境变量。通过执行 export PATH="$HOME/Library/Python/3.9/bin:$PATH" 临时修复了路径问题。

成功执行：

git-dumper http://160.202.254.160:19004/.git/ .

4. 初步分析，遭遇“假 Flag”陷阱

下载成功后，我使用 git log 查看历史。发现了两次提交：

commit d256328b55ccd8c985237e870a16a3e840f2aa2a (HEAD -> master)
    flag is here?

commit e0b8e8e2df0e08f9719df35b8cf68ab4cbd8d3b0
    this is index.html

我迫不及待地用 git show d256328 查看最新提交，结果内容是：+flag{not_here}。

关键反思

这是一个故意设置的诱饵！出题人想看看我是否会就此停止。我意识到，真 Flag 一定藏在更早的提交或被废弃的历史里。

5. 全历史搜索与悬空对象挖掘

我尝试了全历史搜索命令：git grep 'flag{' $(git rev-list --all)，但结果只有那个假 Flag。

抱着试一试的心态，我执行了 Git 的底层检查命令：git fsck --lost-found。这个命令会检查所有丢失的对象。终端赫然输出了两个“悬空提交”（dangling commit）：

dangling commit 40c6d51b81775a1590c1b051d9562222e41c4741
dangling commit 13ce8d9d982aee1efdbc42cbae0acdaaf29d5aa1

6. 绝杀：提取悬空提交的代码

悬空提交意味着开发人员曾经提交过内容，但后来用 git reset 或删除了分支。我复制第一个悬空提交的哈希值，执行：

git show 40c6d51

屏幕上打印出了被遗弃的代码差异。在其中，我看到了真正的 Flag！

最终 Flag： flag{git_is_good_distributed_version_control_system}

三、知识点总结（往脑子里装的东西）

  • .git 源码泄露漏洞：开发人员在上线代码时，如果忘记删除 .git 目录，攻击者就可以直接下载整个版本控制历史，找到被删除的敏感信息。这是极其严重的开发事故。
  • Git 悬空对象（Dangling Commit）：在 Git 中，你“删除”一次提交（比如回退版本），数据其实并没有被立刻物理擦除，而是变成了“悬空对象”。只要没有被垃圾回收，就能通过 git fsck 找回。
  • 终端基础操作与 PATH：学会了在 Mac 终端里配置环境变量（PATH），让安装的命令行工具生效。
  • 信息搜集与甄别：被假 Flag（flag{not_here}）迷惑后，能冷静下来，利用更底层的命令去挖掘真实数据。

做一道题，就要往自己脑子里装点东西。
