SQLi-Labs Less-38

2026年9月29日 SQLi-Labs Web安全 SQL注入 堆叠注入

一、题目信息

  • 题目名称：SQLi-Labs Less-38 (Stacked Query Injection - Future Editions)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 堆叠注入 / 数据篡改
  • 靶场链接：http://localhost:8081/Less-38/（本地环境）
  • 涉及工具：Chrome浏览器 (地址栏直接注入)

二、解题步骤

1. 分析题目考什么

本题的核心考点是堆叠注入（Stacked Injection）。后端使用的是 mysqli_multi_query() 函数，它允许用分号 ; 分隔并同时执行多条 SQL 语句。攻击者不仅能查数据，还能对数据库进行增、删、改等破坏性操作。

2. 怎么想（破题思路）

  • 直接输入 ?id=1，页面回显正常。
  • 尝试在 id 后面加入分号 ; 和第二条语句：?id=1'; insert into users(...) values(...);-- -。
  • 如果页面没有报错，说明后端支持多语句执行。
  • 通过查询新插入的 id（如 999），验证数据是否真正落库。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：单引号闭合

踩坑情况：输入 ?id=1'; insert... 页面报错。

原因分析：Less-38 是单引号闭合的字符型注入，需要先闭合单引号，再用分号结束原有查询。

改进方式：Payload 格式为 1'; 插入语句;-- -。

详细实操步骤（Payload逐字解释）

第一步：构造 Payload 执行插入

在浏览器地址栏输入：

http://localhost:8081/Less-38/?id=1';%20insert%20into%20users(id,username,password)%20values(999,'hacker','123456');--%20-

第二步：Payload 逐字解析

  • 1'：闭合原 SQL 字符串。
  • ;：结束第一条查询语句。
  • insert into users(id,username,password) values(999,'hacker','123456')：向 users 表插入一条 ID 为 999，账号密码均为 hacker / 123456 的新记录。
  • -- -：注释掉原 SQL 剩余的 LIMIT 0,1，防止语法错误。

第三步：验证结果

访问 http://localhost:8081/Less-38/?id=999，页面成功回显 Your Username is : hacker 和 Your Password is : 123456，证明堆叠注入成功。

4. 怎么迁移（跨领域联想）

  • 权限提升与横向移动：堆叠注入不仅限于增删改数据，还可以利用 INTO OUTFILE 写文件、利用 LOAD_FILE 读文件，甚至直接执行系统命令（如果数据库权限足够高）。
  • 代码审计与安全开发：开发中极少使用 mysqli_multi_query（除非是数据库迁移脚本），这本身就是极其危险的信号。防御方必须使用参数化查询。
  • 从查询到控制：与之前的“读取数据”不同，堆叠注入代表攻击者已经具备了“写数据”的能力，这在真实攻防中意味着更高等级的权限和更严重的危害。

三、名词大全与原理深度复盘

1. 堆叠注入 (Stacked Query Injection)

利用分号 ; 在同一数据库连接中执行多条 SQL 语句。常见于后端使用 mysqli_multi_query() 的 PHP 应用。

2. mysqli_multi_query()

PHP 中用于执行多条 SQL 语句的 MySQL 函数。它允许通过 ; 分隔语句，非常危险。

3. 数据篡改 (Data Tampering)

攻击者通过 SQL 注入直接修改数据库内容，例如插入管理员账号、修改密码、删除订单等。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1 到 Less-37 的区别：之前的关卡主要是通过联合查询、报错注入、盲注等方式“读取”数据。Less-38 开启了“写入”时代，利用分号执行独立的 SQL 语句。

2. 这种题目的出现原因（为什么存在）

开发者在开发某些后台功能时，可能为了图方便，使用了 mysqli_multi_query() 来执行来自用户的多个操作。如果这些输入未经严格过滤，攻击者就能利用这种功能执行任意 SQL。

3. 这种应用在实际中如何体现？

在实战中，堆叠注入通常出现在后台管理、批量操作、数据导入导出等接口。由于它能直接修改数据库，往往比普通查询注入危害更大。

4. 如何抽象理解概念（大白话）

把靶场比作一个“快递站”：

  • 普通注入：你在快递单上写“查一下我的包裹”（SELECT）。
  • 堆叠注入：你在快递单上写了“查一下我的包裹；顺便把我的地址改成黑客基地”。
  • 如果快递员（数据库）只会看一行（mysqli_query），他只会执行第一个操作。但如果他支持多行处理（mysqli_multi_query），你的第二句话就会生效。
