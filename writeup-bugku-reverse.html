入门逆向 - Bugku Reverse Writeup

2026年9月11日 Bugku CTF Reverse 反编译

这是我第一次接触逆向工程（Reverse）。面对一个没有源码的二进制可执行文件，我经历了“满头雾水 -> 尝试搜索 -> 写脚本踩坑 -> 降维打击搜索特征码”的完整过程。这篇 Writeup 记录了我最真实的解题思路和工具探索。

一、题目信息

  • 题目名称：入门逆向
  • 题目平台：Bugku CTF
  • 题目类型：Reverse / 编译原理 / 静态分析
  • 题目描述：来源 XJNU，下载附件得到 baby.exe
  • 涉及工具：dogbolt.org 在线反编译器、Mac 终端、xxd 命令、Python

二、解题过程（曲折的探索之路）

1. 反编译：无法运行，那就“拆解”它

我拿到的 baby.exe 是一个 Windows 程序，而我的环境是 Mac，无法直接运行。于是我选择了在线反编译工具 dogbolt.org，把文件拖进去上传。

这个网站非常强大，它集成了 angr（学术界）、BinaryNinja、Ghidra（NSA开源神器）、Hex-Rays（业界第一）等多个反编译器，并排显示它们翻译出来的伪代码。

2. 定位函数：开局受挫

我尝试在反编译代码中搜索 main 函数，希望找到程序入口。但搜出来的全是 mainCRTStartup、TopLevelExceptionFilter 这样的系统初始化代码。

我意识到，程序真正的逻辑被编译器改名隐藏了（可能成了 sub_xxxx）。

接着我尝试搜索明文字符串 Re_1s、flag，以及十六进制特征 0x66（f）、0x6C（l），但在冗长的伪代码里依然没有搜到。

3. 尝试自动化脚本，遭遇路径报错

面对几千行的代码，我试图写 Python 脚本提取所有的 0x 十六进制数据并自动转为明文。但脚本在桌面运行时，报错找不到 code.txt 文件。我尝试用 ls 命令查找桌面文件，也没有结果。

随后我尝试用终端管道结合 Python 一行命令（pbpaste | python3 ...）直接解析剪贴板的内容，也失败了。

4. 降维打击：xxd 命令绝杀

既然反编译的伪代码太长看不完，我决定直接去扒原文件的二进制底层。

在 Mac 终端中，我使用了组合命令：

xxd "baby 2.exe" | grep -i "666c"

命令解释：xxd 负责将二进制文件转储为十六进制和 ASCII 形式，grep -i "666c" 则是在其中过滤包含十六进制 66 6c（即字符 fl）的行。

瞬间，终端里直接打印出了整段十六进制编码！

5. 十六进制转明文

拿到十六进制编码后，我使用 Python 将其转换为人类可读的字符串：

python3 -c "print(bytes.fromhex('66 6C 61 67 7B 52 65 5F 31 73 5F 53 30 5F 43 30 4F 4C 7D').decode('utf-8'))"

最终成功得到 Flag！

最终 Flag： flag{Re_1s_S0_COOL}

三、知识点总结

  • 1. 定位 main 函数：写代码时一定会写 int main，但在逆向工程中，我们面对的是编译后的二进制文件。程序真正的入口可能被改名为 mainCRTStartup 或 sub_xxxx。找不到 main 时，可以尝试通过调用链、参数特征（如 `argc`, `argv`）来寻找真正的逻辑入口。
  • 2. 在线反编译平台 dogbolt.org：这是一家“反编译器大乱斗”平台。它包含了 Angr（学术界）、BinaryNinja（商业级）、Ghidra（NSA开源）、Hex-Rays（IDA Pro核心）等。它们翻译出来的不是源代码，而是“伪代码（Pseudo-C）”，是反编译器根据汇编指令“猜”出来的逻辑，多个工具结果可以互相印证。
  • 3. 什么时候搜索十六进制？在计算机底层只有二进制，为了方便阅读和编写，安全工程师使用十六进制（Hex）表示内存数据。当字符串被编译器“硬编码（Hardcode）”进变量（如 v1 = 0x66）时，搜明文字符串往往搜不到，此时搜索对应的十六进制特征（如 f 对应 0x66）就能一击必中。
  • 4. 面对庞大数据量的自动化思维：面对几百上千行数据，不要用肉眼死盯。可以通过 Python 写脚本提取特征码，或者使用命令行工具组合（如 xxd | grep）进行降维打击。
  • 5. 命令行工具：熟悉了 Mac 下的 ls 查看文件，掌握了 xxd 把二进制转十六进制的能力，以及 Python 的 bytes.fromhex().decode() 编码转换方法。（Windows 下可用 findstr 或 HxD 等十六进制编辑器替代）。

四、逆向工程解题标准流程（沉淀的方法论）

  • 第一步：信息收集：使用 file 命令或 DIE 工具。查看程序架构（32/64位）、文件类型（.exe/.elf）、以及最重要的——有没有加壳。如果有壳，先脱壳，否则不要浪费时间看代码。
  • 第二步：静态分析：使用 IDA Pro（或 Ghidra、Dogbolt）载入。按 Shift+F12 搜 flag、key、success 等关键字，搜不到就搜对应的十六进制特征（如 66 6C 61 67）。寻找 sub_ 开头函数中的交叉引用（Xrefs）。
  • 第三步：动态调试：如果逻辑复杂（比如要输入密码），就把程序放进调试器（x64dbg / gdb），输入假密码，观察程序在哪个 cmp 指令处停下。
  • 第四步：逆运算：如果发现数据被 XOR 异或或 Base64 编码，就写 Python 脚本逆运算还原。

做一道题，就要往自己脑子里装点东西。
