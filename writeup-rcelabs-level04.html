RCE-Labs Level 4 - tail 命令查看文件尾

一、题目信息

  • 题目名称：RCE-Labs Level 4 (tail 命令查看文件尾)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 黑名单绕过
  • 靶场链接：http://靶机IP:8080/less-4/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

本题依然考察黑名单绕过。黑名单累加，已经变成 /cat|tac|head/。题目提示使用 tail 命令读取文件末尾，同时也可以使用 nl 等未被封锁的命令。

2. 怎么解（详细步骤与输出解析）

源码核心逻辑

$pattern = '/cat|tac|head/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload

使用 tail 命令查看文件尾部（默认显示最后10行）：

?cmd=tail /flag

或者使用 nl 命令（带行号读取，回显为 1 flag{TEST_Dynamic_FLAG}）：

?cmd=nl /flag

成功响应：页面回显 flag{TEST_Dynamic_FLAG}。

3. 怎么迁移（跨学科与跨领域联想）

  • 灵活替换：遇到黑名单不要慌，Linux 中读取文件的命令多得是（`tail`、`nl`、`more`、`less`、`sed`、`awk`），总有一个没被封杀。

三、名词大全与原理深度复盘

1. tail 命令的底层机制与核心参数

tail（尾巴）用于查看文件的末尾内容。它在 Linux 系统中效率极高，是运维和 CTF 中的常客。

  • 基础语法：tail [选项] 文件名。默认显示最后 10 行。
  • 核心参数 -n：tail -n 5 /flag 查看最后 5 行。
    CTF神技：tail -n +1 /flag，加号表示从第 1 行读到末尾，等价于 cat，常用于绕过 cat 被拦截的场景。
  • 核心参数 -f：实时追踪文件更新（如 tail -f access.log）。注意，在 PHP 的 system() 中执行 -f 会卡死，CTF 中禁用。
  • 核心参数 -c：按字节查看。如 tail -c 100 /flag 查看最后 100 个字节。

2. 与 cat 的底层区别

  • cat 是顺序读取。它从头调用 read() 系统调用，一直读到文件末尾。若文件有 10GB，cat 会卡死。
  • tail 极其聪明，它依赖 lseek() 系统调用。打开文件后，它直接调用 lseek(fd, -1024, SEEK_END) 把文件指针偏移到末尾向前一小段，再在小段里从后往前找到换行符。因此即使几十GB的日志，tail 也能瞬间出结果。

3. 为什么写入 Web 目录能绕过黑名单？

黑名单拦截的是“读取文本行”的工具，却忽略了“文件操作”和“网络外带”。当你无法在页面回显时，利用重定向符 > 或 cp/mv 把结果写入 Web 目录，再通过 HTTP 访问，是内网 RCE 最稳妥的通关法宝。

四、题目思考

1. 这跟前面关卡的区别

  • 规则累加：Level 2 禁 `cat`，Level 3 禁 `cat|tac`，Level 4 禁 `cat|tac|head`。这说明开发者在不断修补黑名单，但这恰恰暴露了黑名单机制的致命弱点——永远列不全。
  • 绕过思路：题目提示用 `tail`，但我们在实战中可以用 `nl` 或 `sed` 替代。只要掌握了“命令替换”的核心思想，黑名单就形同虚设。

2. 如何抽象理解概念（大白话）

就像安检员每天更新禁止携带的武器名单，今天禁了“菜刀”，明天禁了“砍刀”，后天禁了“西瓜刀”。但厨房里还有“削皮刀”、“水果刀”、“大勺”，只要是金属能做饭的工具，都能达到切菜的目的。只要找到安检员没登记的替代品，就能成功过关。
