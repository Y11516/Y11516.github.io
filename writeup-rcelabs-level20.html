RCE-Labs Level 20 - mv 命令重命名文件与源码泄露

2026年10月5日 RCE-Labs 黑名单绕过 文件操作

一、题目信息

  • 1.题目名称：RCE-Labs Level 20 (mv 命令重命名文件与源码泄露)
  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 文件操作 / 源码泄露
  • 4.靶场链接：http://靶机IP:8080/less-20/
  • 5.涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

黑名单封禁了 cp。源码顶部提示 @include "flag.php";，说明这个文件被当作 PHP 脚本执行了，所以我们直接访问它看不到源码。这关考察的是利用文件重命名工具（mv）绕过 PHP 解析器，从而泄露源码。

2. 怎么想（破题思路）

Web 服务器（如 Nginx、Apache）有一个核心机制：根据文件的扩展名来决定如何处理它。如果请求的是 .php 文件，服务器会把它交给 PHP 解析器执行，所以我们只能看到执行后的空白结果。如果请求的是 .txt 或 .html 文件，服务器会把它当作静态资源，直接把源码内容返回给浏览器。既然 cp 被拦截，我们可以利用同样能改变文件名的 mv 命令，把 flag.php 重命名为 flag.txt，让 Web 服务器直接暴露其源码。

3. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

# flag.php
@include"flag.php";
highlight_file(__FILE__);
...
$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与逐字解析

?cmd=mv flag.php flag.txt

命令逐字解析：

  • mv：move 的缩写，用于移动文件或重命名文件。
  • flag.php：源文件，即包含 flag 的 PHP 脚本。
  • flag.txt：目标文件名，将其重命名为纯文本后缀。

操作流程：

  • 第一步：执行重命名。执行上述 Payload。页面没有任何回显，这是因为 mv 命令默认静默执行，没有输出就是成功。
  • 第二步：访问文件。在浏览器中访问 http://靶机IP:8080/less-20/flag.txt。
  • 成功响应：浏览器直接显示出 flag.php 的源码，里面包含了明文 flag{TEST_Dynamic_FLAG}。

踩坑记录：为什么命令执行后显示空白？

情况：输入 mv 命令后，页面没有任何变化，也没看到 flag。

原因：Linux 哲学是“没有消息就是好消息”。mv、cp、rm 等文件操作命令默认不产生标准输出（stdout）。只有失败时才会报错。所以不能用“有没有回显”来判断这些命令是否成功，而应该去验证文件是否被真的重命名了。

改进：可以通过 ls -la 验证文件是否被重命名，或者直接尝试访问 Web 路径来验证。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的 WebShell 写入：上传 Webshell 时，服务器往往会拦截 .php 后缀。攻击者常将文件上传为 shell.php.txt 或 shell.pHp，然后利用 RCE 漏洞执行 mv shell.php.txt shell.php，瞬间绕过 WAF 拿到 Shell。
  • 供应链攻击与数据泄露：攻击者在窃取数据库后，往往不会直接打印出来（数据量太大），而是将其打包（tar）复制到临时目录，再通过 wget 或 curl 外带出去。

三、名词大全与原理深度复盘

1. mv 命令详细介绍

mv（move）用于移动文件或重命名文件，是 Linux 中最基础的文件操作命令之一。

  • 核心参数 -f：强制覆盖，如果目标文件已存在，不提示直接覆盖。
  • 核心参数 -n：不覆盖已存在的文件。
  • 核心参数 -v：显示移动/重命名的详细过程（在 RCE 中一般不用，因为它会产生回显）。
  • 核心参数 -b：覆盖前先备份。

2. 底层原理：rename() 系统调用与 Web 解析机制

mv 命令底层调用 rename() 系统调用。它在同一个文件系统内直接改变目录项的名称（修改 inode 的链接），不涉及数据的复制，因此速度极快且无回显。

Web 服务器（如 Nginx、Apache）根据请求文件的扩展名来决定如何处理。遇到 .php 会交给 PHP 解析器执行，遇到 .txt、.html 则会作为静态资源直接返回源码。本题就是利用了这一点，将敏感的 PHP 文件重命名为无法解析的文本文件。

3. 核心名词解释（陌生人也能看懂版）

  • 静态资源 (Static Resource)：Web 服务器直接读取并返回给浏览器的文件，不需要经过后端语言（如 PHP、Java）处理，如 .txt、.html、.jpg。
  • 解析器 (Parser)：负责执行或转换代码的程序。PHP 解析器会执行 .php 文件中的代码。
  • 源码泄露 (Source Code Disclosure)：由于配置错误或漏洞，导致攻击者能够直接获取服务器端脚本的源代码，而不是其执行结果。
  • 扩展名 (File Extension)：文件名后缀（如 .php, .txt），是操作系统和 Web 服务器判断文件类型的重要依据。

四、题目思考

1. 这跟前面关卡的区别

Level 19 考的是“复制外带”，Level 20 考的是“重命名绕过解析”。虽然都是文件操作命令，但 mv 比 cp 多了一层破坏性或隐蔽性。它不需要复制文件，只需要改变文件名，就能改变文件在 Web 层面的解析方式。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发人员经常需要对文件进行备份、移动或重命名操作。如果对用户输入过滤不严，将系统命令与用户输入拼接，就会导致命令注入。黑名单机制只能封禁已知的“读取”命令（如 `cat`）和“复制”命令（如 `cp`），但无法封禁所有“文件操作”命令（如 `mv`）。这种“功能重叠”是黑名单机制天然存在的漏洞。

3. 这种漏洞在实际中的应用

在护网和真实攻防中，攻击者拿到 RCE 后，通常会利用 `mv` 修改文件后缀来绕过 WAF 的上传限制（例如上传 `.php` 被拦截时，先上传为 `.txt`，再用 `mv` 改回 `.php` 执行）。此外，它还可用于破坏服务器配置或隐藏恶意文件。

4. 如何抽象理解概念（大白话）

把读取文件比作“去保险柜拿金条”。前面是撬锁（cat）、砸墙（base64）；Level 19 是把保险柜搬到客厅（cp）；Level 20 是直接把保险柜的标签从“贵重物品”改成了“普通快递”（mv）。结果快递员（Web 服务器）看都不看，直接就把里面的东西（源码）给您送上门了。

5. 他的本质

本质是利用文件系统的基本操作（重命名），改变了文件的上下文（由 PHP 引擎执行变更为由静态 HTTP 服务器处理），从而绕过了应用层的防御。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：严格限制 Web 进程的文件系统权限，确保 Web 用户无法修改敏感文件（如 flag.php）的名称。在代码层面，严禁将用户输入拼接进系统命令，使用白名单限制命令参数。同时，确保 Web 服务器配置正确，禁止直接访问敏感文件。
  • 破解方（红队）：如果 mv 被拦截，可以尝试使用 cp（如果未被拦截）、ln（创建硬链接/软链接），或者利用 PHP 特性（如 rename() 函数）、Python 脚本（如 os.rename()）来实现文件重命名。
