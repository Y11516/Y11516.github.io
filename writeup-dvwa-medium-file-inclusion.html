DVWA-Medium-文件包含 (File Inclusion)

2026年10月2日 DVWA Web安全 文件包含 黑名单绕过

一、题目信息

  • 题目名称：DVWA File Inclusion (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 文件包含 / 黑名单绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/fi/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是在 Medium 安全级别下绕过黑名单过滤，实现文件包含。Medium 级别源码增加了 str_replace 函数，将 http://、https://、../、..\ 等字符替换为空。但通过双写绕过（....//）可以重新拼接出 ../，从而绕过过滤。

2. 怎么想（破题思路）

  • 直接使用 Low 级别的 Payload ../../../../etc/passwd，页面返回空白，说明 ../ 被过滤。
  • 根据源码分析，str_replace 将 ../ 替换为空。如果输入 ....//，替换后剩下的字符会重新组合成 ../，从而实现绕过。
  • 由于 DVWA 目录嵌套较深，需要增加 ....// 的数量（建议使用 5 个）才能跳到根目录。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：路径深度不足导致页面空白

踩坑情况：使用 4 个 ....// 尝试读取 /etc/passwd，页面显示为空白，没有任何回显。

原因分析：DVWA 的靶场目录结构很深（如 /var/www/html/vulnerabilities/fi/），从 fi/ 目录向上跳 4 层只能到达 /var/，并没有到达根目录 /。

改进方式：增加路径穿越的深度，将 ....// 的数量增加到 5 个，从而成功读取到 /etc/passwd。

详细实操步骤（Payload逐字解释）

第一步：验证黑名单过滤

输入：../../../../etc/passwd

响应结果：页面空白，说明 ../ 被替换为空。

第二步：使用双写绕过

输入：....//....//....//....//....//etc/passwd

解释：

  • 后端执行 str_replace("../", "", $file)。
  • 输入字符串中的 ....// 在替换中间的 ../ 后，剩下的字符重新组合为 ../。
  • 5 个 ....// 最终会变成 5 个 ../，从而跳出 Web 目录到达根目录。

响应结果：页面成功回显 root:x:0:0:root:/root:/bin/bash 等用户列表。

第三步：备用方案（php://filter 伪协议）

如果直接读文件失败，可以使用伪协议读取源码：

php://filter/convert.base64-encode/resource=....//....//....//....//....//etc/passwd

解释：php://filter 中的 ../ 同样会被过滤，因此依然需要使用 ....// 绕过。页面会返回 Base64 编码后的文件内容，手动解码即可阅读。

4. 怎么迁移（跨领域联想）

  • WAF 绕过实战：在真实的护网中，WAF 过滤 ../ 是常见规则。攻击者会尝试各种编码和双写方式（如 ....//、%2e%2e%2f）来绕过。这与本题的逻辑完全一致。
  • 安全开发启示：黑名单防御很容易被绕过。正确的做法是使用白名单（只允许包含特定的文件名，如 file1.php），或者对用户输入进行严格的路径校验，禁止向上跳转。

三、名词大全与原理深度复盘

1. 双写绕过 (Double Write Bypass)

一种黑名单绕过技术。通过重复输入被过滤的关键字，使得过滤函数在替换一次后，剩下的字符重新组合成攻击者需要的字符串。例如 ....// 经过 str_replace("../", "", ...) 处理后，最终变成 ../。

2. str_replace

PHP 的字符串替换函数。它是单次遍历的，不会递归查找，这就给双写绕过留下了可乘之机。

3. php://filter 伪协议

PHP 内置的流包装器。常用于读取 PHP 源码（将其转换为 Base64 编码输出），在文件包含漏洞中非常实用。

4. 白名单防御

最安全的防御策略。例如，后端代码只允许 include 数组中的特定文件名（如 ["file1.php", "file2.php", "file3.php"]），从根本上杜绝了任意文件包含的可能。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有过滤，直接使用 ../ 即可。Medium 级别加入了黑名单，需要使用 ....// 进行双写绕过。
  • 与 High 级别的区别：High 级别使用了更严格的正则表达式过滤，甚至加入了 |、..\ 等，且使用了白名单机制，绕过难度极大。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者试图用“黑名单”来防御攻击，但低估了攻击者的创造力。简单的字符替换无法覆盖所有可能的路径穿越形式，只要漏掉一个变种，防御就会失效。

3. 这种的应用

在护网中，如果遇到带 WAF 的站点，攻击者会通过 Burp Suite 的 Intruder 模块，批量测试各种路径穿越的变种（如 URL 编码、双写、Unicode 编码等），以寻找 WAF 的绕过方式。

4. 如何抽象理解概念（大白话）

把双写绕过比作“套娃”：

  • 正常情况：门卫看到“刀”就没收。你带“刀”进去，会被拦住。
  • 漏洞情况：门卫只认“刀”字。你把刀鞘上写着“刀”字，门卫没收了刀鞘。结果你手里还握着一把真的刀。这就是双写绕过的本质——过滤掉一部分，剩下的重新组合成恶意内容。

做一道题，就要往自己脑子里装点东西。
