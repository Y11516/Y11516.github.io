SQLi-Labs Less-25a

2026年9月28日 SQLi-Labs Web安全 SQL注入 时间盲注

一、题目信息

  • 题目名称：SQLi-Labs Less-25a (GET - Blind Based - All your OR & AND belong to us - Intiger based)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 时间盲注 / 关键字过滤绕过
  • 靶场链接：http://localhost:8081/Less-25a/（本地环境）
  • 涉及工具：Chrome浏览器 (F12 开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是时间盲注与关键字过滤绕过的结合。Less-25a 过滤了 OR 和 AND，且页面没有报错回显（盲注）。攻击者必须使用 && 替代 AND，并利用 sleep() 函数制造延迟，通过观察响应时间来判断条件真伪。

2. 怎么想（破题思路）

  • 页面提示“All your OR and AND belong to us”，明确过滤了这两个关键字。
  • 页面上方提示“Please input the ID as parameter with numeric value”，是整数型注入，无需闭合引号。
  • 构造 URL：?id=1 %26%26 sleep(3)，验证 && 替代方案是否生效。
  • 如果页面卡顿 3 秒，说明盲注有效，再构造条件判断来猜解数据。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：页面无报错回显，误以为注入失败

踩坑情况：输入 Payload 后，页面内容没有任何变化，只显示“Welcome Dhakkan”，误以为注入失败。

原因分析：Less-25a 是盲注关，没有报错回显。唯一的反馈是页面响应时间（延迟）。

改进方式：打开 F12 的 Network 面板，查看请求的 Time 列。如果耗时超过 3 秒，说明盲注成功。

踩坑记录二：SQL 短路导致 sleep 未执行

踩坑情况：输入 ?id=1 && sleep(3)，如果 id=1 不存在，页面会瞬间返回，不卡顿。

原因分析：SQL 逻辑短路。如果 id=1 为假，&& 后面的 sleep(3) 不会执行。

改进方式：使用 if(1=1, sleep(3), 0) 或确保 id 为存在的值（如 id=1 到 id=14）。

详细实操步骤（Payload逐字解释）

第一步：验证 sleep 函数是否生效

在浏览器地址栏输入：

http://localhost:8081/Less-25a/?id=1%20%26%26%20if(1=1,%20sleep(3),%200)

逐字解析：

  • %20：URL 编码后的空格。
  • %26%26：URL 编码后的 &&，替代被过滤的 AND。
  • if(1=1, sleep(3), 0)：条件判断函数。如果条件成立，延迟 3 秒；否则返回 0。

第二步：验证结果

打开 F12 的 Network 面板，勾选 Disable cache。刷新页面。如果请求的 Time 显示为 3 秒以上，盲注成功。

4. 怎么迁移（跨领域联想）

  • 符号替代法：在 WAF 绕过中，关键字过滤是常见防御手段。除了 && 替代 AND，还可以使用 %26%26、|| 替代 OR。
  • 盲注的特性：盲注的特点是没有回显，一切信息都通过布尔状态（对错）或时间（延迟）来判断。时间盲注的隐蔽性极高，是真实渗透中的“核武器”。
  • 环境差异与踩坑：在 Mac + Docker 环境中，时间盲注正常工作。遇到环境问题时，应果断跳过或改用其他注入方式。

三、名词大全与原理深度复盘

1. 时间盲注 (Time-Based Blind SQL Injection)

当页面没有回显位，且过滤了报错信息时，攻击者通过构造 if(条件, sleep(N), 0) 来制造延迟。如果条件成立，页面响应时间会显著增加。

2. 关键字过滤与符号替代

后端过滤了 OR 和 AND，但 SQL 支持 || 和 && 作为替代符号，这让过滤变得很容易绕过。

3. 逻辑短路

在 SQL 中，A && B 如果 A 为假，B 不会被执行。在构造盲注 Payload 时，必须确保前面的条件为真。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-25 的区别：Less-25 有报错回显（Error based），Less-25a 是盲注（Blind Based）。
  • 与 Less-24 的区别：Less-24 是二次注入，Less-25a 是直接的时间盲注。

2. 这种题目的出现原因（为什么存在）

开发者试图通过过滤关键字和屏蔽报错来阻止 SQL 注入，但盲注的出现证明即使没有回显，攻击者依然可以通过时间差来获取信息。这警示我们：防御必须依赖参数化查询，而非字符串过滤和错误遮蔽。

3. 这种应用在实际中如何体现？

在实战中，遇到不报错、页面内容无变化的站点，时间盲注是首选。但时间盲注执行效率极低，通常需要借助 Python 脚本或 SQLMap 进行自动化猜解。

4. 如何抽象理解概念（大白话）

把靶场比作一个“沉默的守卫”：

  • Less-25a 的守卫不回答你的问题，也不告诉你对错。
  • 你问他：“如果密码是 s 开头，你就发呆 3 秒。”
  • 他发了 3 秒呆，你就知道他心中的答案了。这就是时间盲注。

做一道题，就要往自己脑子里装点东西。
