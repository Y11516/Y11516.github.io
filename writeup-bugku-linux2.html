Linux2 - Bugku MISC Writeup

2026年9月12日 Bugku CTF MISC 磁盘镜像分析

这道题名为 Linux2，分类为 MISC。附件是一个名为 brave 的无格式文档，大小约 20.5 MB。题目提示 flag 格式为 KEY{}。这其实是一道 Linux 磁盘镜像分析题。

一、题目信息

  • 题目名称：Linux2
  • 题目平台：Bugku CTF
  • 题目类型：MISC / Linux 磁盘镜像 / 文件内容提取
  • 题目提示：key的格式是KEY{}
  • 附件内容：brave（无格式文档，实为 Linux 镜像）
  • 涉及工具：Mac 终端（file、strings、grep）

二、解题过程（详细步骤与踩坑记录）

1. 识别文件真实类型

直接双击下载的文件打不开。我打开终端，进入文件目录并输入 file brave 进行检测。终端提示信息中包含 Linux rev 1.0 ext4 filesystem data，证实它是一个 Linux 磁盘镜像文件，无法直接双击打开。

2. 遭遇“假 Flag”陷阱

起初，我试图用 Python 脚本把镜像里的图片提取出来。打开提取的图片，上面写着 flag{f0rens!cs!sC00L}。但当我把这个以 flag{ 开头的字符串提交到平台时，系统提示错误。

踩坑提醒：这说明这是出题人故意放进去的“假 Flag”。真正的 Flag 是直接藏在文件深处的纯文本字符串。题目提示明确要求格式是 KEY{}，因此图片里的内容是一种误导。

3. 核心操作：strings 与 grep 的过滤魔法

既然图片是假的，真正的 Flag 一定以纯文本形式隐藏在文件里。由于文件是一个包含成千上万文件和二进制数据的镜像，直接看会眼花缭乱。我们用“提取文本 + 关键字过滤”的组合命令，一步到位提取出真 Flag。

过滤过程详细解析：

  • 第一步：strings brave（捞沙子里的金子）
    这个命令会扫描整个二进制镜像文件，把所有**连续可读的字符**（字母、数字、标点）全部提取出来。执行结果就是终端瞬间弹出几万行文本。
  • 第二步：|（管道符 - 自动流水线）
    这个竖线的作用是**建立流水线**。它把左边 `strings` 跑出来的几万行结果，直接传送给右边的命令去处理，不需要手动复制粘贴。
  • 第三步：grep "KEY"（精准筛金子）
    `grep` 是专门用来做“关键字过滤”的工具。它接到数据后，逐行检查，只保留包含 `KEY` 这一关键词的行，把其他无关的几万行全部丢弃。

完整的命令是：

strings brave | grep "KEY"

按下回车后，终端瞬间输出了真正的 Flag：

KEY{24f3627a86fc740a7f36ee2c7a1c124a}

最终 Flag： KEY{24f3627a86fc740a7f36ee2c7a1c124a}

三、知识点总结（核心复习素材）

  • 1. Linux 磁盘镜像文件：在 CTF 中，常常会给出没有后缀名或后缀为 .img 的文件。它本质上是 Linux 系统的磁盘分区镜像，包含完整的文件系统，无法直接双击打开，需要挂载或使用特定工具分析。
  • 2. strings 与 grep 的黄金组合：strings brave 提取所有可打印文本，| grep "KEY" 过滤出包含关键字的行。这是处理二进制文件、流量包、镜像文件时最高效的排查手段。
  • 3. 警惕“假 Flag”陷阱：出题人常会在图片或显眼位置放置假 Flag，以此迷惑选手。遇到图片里的 Flag 时，务必对照题目提示（如本题要求的 KEY{} 格式）进行二次确认。
