POST - Bugku Web 入门 Writeup

2026年9月13日 Bugku CTF Web安全 HTTP协议 curl / fetch

这道题名为“POST”，分类为 Web。题目要求通过 POST 方式传递参数，获取 Flag。这篇 Writeup 不仅记录了解题过程，还深入剖析了 GET 与 POST 的本质区别，以及两种伪造请求的工具（终端 curl 和浏览器 fetch）。

一、题目信息

  • 题目名称：POST
  • 题目平台：Bugku CTF
  • 题目类型：Web / PHP 代码审计 / POST 传参
  • 靶场链接：http://靶场地址
  • 涉及工具：Mac 终端、Python（requests 库）

二、解题过程（详细步骤）

1. 阅读源码，发现逻辑死结

打开靶场，页面直接显示了后端的 PHP 源代码：

<?php
$what=$_POST['what'];
echo $what;
if($what=='flag')
echo 'flag{****}';
?>

代码逻辑非常清晰：它需要一个叫 what 的参数，且值必须为 flag。与上一道 GET 题不同的是，这里使用的是 $_POST 来接收参数，而不是 $_GET。

2. 思维定势与碰壁

因为刚做完了 GET 题，我第一反应是在浏览器地址栏后面拼接 ?what=flag，结果毫无反应。这是因为浏览器地址栏只能发送 GET 请求，而无法发送 POST 请求。

3. 核心知识点觉醒：GET 与 POST 的区别

我查阅资料并恍然大悟：这道题的接收方式是 $_POST['what']。

  • GET 传参：参数拼在网址里（?what=flag），就像明信片，内容可见。
  • POST 传参：参数藏在 HTTP 请求体（Body）里，就像包裹，地址栏看不到。

由于浏览器地址栏默认只能发 GET 请求，所以我无法在那里手动构造 POST 请求。

4. 使用终端 curl 命令“寄包裹”（成功）

我打开了 Mac 的终端（Terminal），使用 curl 命令来手动构造一个 POST 请求：

curl -X POST -d "what=flag" http://靶场地址

命令解释：-X POST 告诉服务器这是一个 POST 请求；-d "what=flag" 是将参数 what=flag 装进“包裹”（请求体）。

按下回车，终端立刻返回了带有 Flag 的网页源代码！

最终 Flag： flag{...}（请替换为你实际提交成功的答案）

三、知识点总结（核心复习素材）

  • 1. HTTP GET 请求：参数附带在 URL 中，可见，有长度限制，常用于获取数据。可以直接在浏览器地址栏修改。
  • 2. HTTP POST 请求：参数放在请求体（Body）中，相对隐蔽，常用于提交数据（如表单提交）。无法在地址栏直接修改。
  • 3. 绕过工具：当需要发送 POST 请求时，可以使用终端的 curl 命令，或者在浏览器控制台使用 fetch() 函数来构造。
  • 4. 源码泄露：服务器暴露了使用 `$_POST` 接收参数的逻辑，让攻击者可以精准构造请求体。

四、额外深度问答（新名词全解析）

问题一：什么是终端 curl 命令？

大白话解释：你可以把它理解成“在终端里假装自己是一个浏览器，向服务器发请求”。

curl 是 Mac/Linux 系统自带的一个命令行工具，名字是 “Client URL” 的缩写。它的作用就是：在终端里发 HTTP 请求，然后把服务器返回的内容打印在终端里。

还记得你做“POST”题的时候吗？当时服务器需要你传一个 what=flag 的参数。浏览器地址栏只能发 GET 请求，但我们用 curl 就可以发 POST：

curl -X POST -d "what=flag" http://160.202.254.160:19587
  • curl：启动工具
  • -X POST：告诉服务器我要发 POST 请求
  • -d "what=flag"：我要携带的数据（-d 是 data 的缩写）
  • 后面接地址

运行后，终端会直接把服务器返回的 HTML 代码打印出来，里面就藏着 flag。

✅ 什么时候用 curl？

  • 需要发 POST 请求，但浏览器地址栏只能发 GET。
  • 想批量测试很多 URL（写脚本循环调用）。
  • 想让请求不经过浏览器，避免被 Cookie、缓存、JS 干扰。

问题二：什么是浏览器控制台里的 fetch() 函数？

大白话解释：你可以把它理解成“在浏览器里用 JavaScript 代码向服务器发请求”。

fetch() 是浏览器内置的一个 JavaScript 函数。你在 F12 的 Console（控制台）里输入它，就能让浏览器帮你发请求。

举个你之前做过的题的例子：

还记得你做“game1”那道游戏题吗？当时你用 fetch 试图伪造高分：

fetch("/?s=999999")
    .then(response => response.text())
    .then(data => console.log(data));
  • fetch("/?s=999999")：向当前网站发送请求，携带满分参数
  • .then(...)：等服务器回应后，把服务器返回的内容打印出来

✅ 什么时候用 fetch？

  • 你想利用浏览器里已有的 Cookie / Session（因为 fetch 会自动带上当前网站的登录状态）。
  • 你想和当前页面交互（比如拿到数据后自动显示在网页上）。
  • 你在做 Web 渗透，想模拟用户在浏览器里点击某个按钮的行为。

问题四：为什么两者都能“拿 Flag”？

因为服务器不知道请求是浏览器发的还是 curl 发的。服务器只看：

  1. 请求方法（GET / POST）
  2. 请求参数（比如 what=flag 或 score=999999）
  3. 请求头（比如 Cookie、User-Agent）
  4. 请求体（POST 才有）

只要这些数据对了，服务器就乖乖把 flag 吐出来。这就是为什么“用 curl 伪造请求”和“用 fetch 伪造请求”在 CTF 里效果完全一样。

问题五：新名词全解析（补充知识）

1. HTTP 协议

浏览器和服务器之间通信的“规则书”。你访问网页、提交表单，本质就是按 HTTP 协议发请求、收回应。

2. GET 请求

HTTP 协议中的一种请求方法。参数直接写在 URL 里（如 ?what=flag），可见、有长度限制，常用于获取数据。

3. POST 请求

HTTP 协议中的另一种请求方法。参数放在“请求体（Body）”里，不可见、无长度限制，常用于提交数据。

4. 请求体（Body）

POST 请求中携带数据的“包裹箱”。地址栏看不到里面的内容。

5. 请求头（Headers）

HTTP 请求中用于携带元信息的部分，比如 Cookie（登录凭证）、User-Agent（浏览器标识）、Content-Type（数据类型）。

6. Cookie

服务器发给浏览器的一小段数据。浏览器每次访问同一个网站，都会自动带上它。它的作用是让服务器“记住你是谁”。

7. Session

服务器端记录用户状态的机制。Cookie 里通常存的是 Session ID，服务器根据这个 ID 找到对应会话。

8. Shell / 终端 / 命令行

你在 Mac 上敲命令的那个黑底白字窗口，就是“终端”。zsh 是终端里的“解释器”，负责把你敲的命令翻译给系统执行。

9. 参数（Parameter）

请求中携带的数据。GET 参数写在 URL 里，POST 参数写在 Body 里。

10. 代码审计

阅读别人的代码，找逻辑漏洞。你做题时看 PHP 源码，就是在做代码审计。
