POST - Bugku Web 入门 Writeup

2026年9月10日 Bugku CTF Web安全 HTTP协议

如果说上一道 GET 题是让我学会了“在明信片上写字”，那这道 POST 题则教会了我“怎么寄包裹”。它完美揭示了 HTTP 协议中 GET 和 POST 两种最基础、最核心的请求方式的区别。

一、题目信息

  • 题目名称：POST
  • 题目平台：Bugku CTF
  • 题目类型：Web / 源码泄露 / POST 传参
  • 涉及工具：Mac 终端（Terminal）的 curl 命令、浏览器 F12 控制台

二、解题步骤（踩坑与破局过程）

1. 发现源码，发现又是传参

打开靶场，页面直接显示了后端的 PHP 源代码：

<?php
$what=$_POST['what'];
echo $what;
if($what=='flag')
echo 'flag{****}';
?>

意思很明确：它需要一个叫 what 的参数，且值必须为 flag。

2. 思维定势与碰壁

因为刚做完了 GET 题，我第一反应是在浏览器地址栏后面拼接 ?what=flag，结果毫无反应。

3. 核心知识点觉醒：GET 与 POST 的区别

我查阅资料并恍然大悟：这道题的接收方式是 $_POST['what']。

  • GET 传参：参数拼在网址里（?what=flag），就像明信片，内容可见。
  • POST 传参：参数藏在 HTTP 请求体（Body）里，就像包裹，地址栏看不到。

由于浏览器地址栏默认只能发 GET 请求，所以我无法在那里手动构造 POST 请求。

4. 使用终端 curl 命令“寄包裹”

我打开了 Mac 的终端（Terminal），使用 curl 命令来手动构造一个 POST 请求：

curl -X POST -d "what=flag" http://靶场地址

命令解释：-X POST 告诉服务器这是一个 POST 请求；-d "what=flag" 是将参数 what=flag 装进“包裹”（请求体）。

按下回车，终端立刻返回了带有 Flag 的网页源代码！

最终 Flag： flag{...}（请替换为你实际提交成功的 Flag）

三、知识点总结（往脑子里装的东西）

  • HTTP GET 请求：参数附带在 URL 中，可见，有长度限制，常用于获取数据。可以直接在浏览器地址栏修改。
  • HTTP POST 请求：参数放在请求体（Body）中，相对隐蔽，常用于提交数据（如表单提交）。无法在地址栏直接修改。
  • 绕过工具：当需要发送 POST 请求时，可以使用终端的 curl 命令，或者在浏览器控制台使用 fetch() 函数来构造。
  • 源码泄露：服务器暴露了使用 `$_POST` 接收参数的逻辑，让攻击者可以精准构造请求体。

做一道题，就要往自己脑子里装点东西。
