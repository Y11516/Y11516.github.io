CTFHub RCE - 命令注入-综合练习

2026年9月22日 CTFHub Web安全 RCE 综合过滤

一、题目信息

  • 题目名称：命令注入-综合练习
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程命令执行） / 命令注入 / 黑名单综合绕过
  • 靶场链接：http://challenge-9294b02259474b01.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是综合过滤下的命令注入绕过。后端代码使用了极其严格的正则表达式 preg_match_all("/(\/|\||&|| |\||cat|flag|ctfhub)/", $ip, $m)，同时过滤了斜杠 /、管道符 |、与符号 &、空格、cat、flag 和 ctfhub。攻击者需要综合利用此前学到的所有技巧：用 %0a 代替运算符，用 ${IFS} 代替空格，用 base64 代替 cat，用通配符 * 绕过关键字过滤。

2. 怎么想（破题思路）

  • 页面提示“同时过滤了前面几个小节的内容，如何打出漂亮的组合拳呢？”
  • 源码分析：过滤了 /、|、&、空格、cat、flag、ctfhub。
  • 突破口分析：
    • 运算符：; 可能被拦截，尝试 %0a（换行符）。
    • 空格：使用 ${IFS} 替代。
    • 命令：使用 base64 替代 cat。
    • 目录名/文件名：使用通配符 * 或 ? 替代被过滤的 flag 字符串。
    • 路径分隔符：使用 cd 命令进入目录，避免使用 /。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：使用分号 ; 连接命令导致拦截

踩坑情况：输入 127.0.0.1;ls，页面回显 Array 并提示匹配到了分号。

原因分析：正则中包含了空匹配分支，可能导致 ; 也被意外过滤。

改进方式：改用 URL 编码的换行符 %0a 作为命令分隔符。

踩坑记录二：直接输入 flag 被拦截

踩坑情况：输入 ls flag_is_here，被拦截。

原因分析：正则明确过滤了 flag 字符串。

改进方式：使用通配符 f* 来匹配 flag_is_here。

详细实操步骤（逐字解析）

第一步：探测根目录

构造 Payload（使用 %0a 绕过分号和运算符过滤）：

127.0.0.1%0als

发现目录：flag_is_here。

第二步：进入目录并查看文件

构造 Payload（使用 cd、${IFS}、f* 绕过路径、空格、关键字过滤）：

127.0.0.1%0acd${IFS}f*%0als

发现文件：flag_25791660619906.php。

第三步：使用 base64 读取 Flag（终极连招）

构造 Payload：

127.0.0.1%0acd${IFS}f*%0abase64${IFS}fla*

Payload 逐字深度解析：

  • 127.0.0.1：让 ping 命令正常执行，作为伪装。
  • %0a：URL 编码的换行符，用作命令分隔符（绕过 |、&、; 的过滤）。
  • cd：切换目录命令，不使用斜杠 /。
  • ${IFS}：Linux 内部字段分隔符，替代空格，绕过空格过滤。
  • f*：通配符，匹配以 f 开头的目录（即 flag_is_here），绕过 flag 关键字过滤。
  • %0a：再次分隔命令。
  • base64：读取文件并转为 Base64 编码，替代 cat，避免 PHP 解析导致空白。
  • ${IFS}：替代空格。
  • fla*：通配符，匹配以 fla 开头的文件（即 flag_xxx.php）。

第四步：解码并提交

页面回显 Base64 字符串，复制后去在线工具解码，得到 Flag：ctfhub{054265595695f89c081c398c}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • 真实渗透测试中的 WAF 绕过：在实战中，WAF 往往会综合拦截各种敏感字符。攻击者需要灵活组合 URL 编码、大小写、通配符、变量拼接等技术，这正是本题考察的“组合拳”能力。
  • 代码审计中的正则分析：本题的正则 /(\/|\||&|| |\||cat|flag|ctfhub)/ 存在缺陷。空匹配分支 || 不仅会导致逻辑错误，还可能浪费性能。这提醒开发者在编写安全校验时，必须严谨测试正则表达式。
  • 安全开发（SDL）：防御命令注入的根本在于使用白名单或对参数进行严格转义（escapeshellarg()），绝不能依赖黑名单。

三、名词大全与原理深度复盘

1. 命令注入中的综合绕过思维

命令注入的绕过并非简单的“替换字符”，而是一套系统的方法论：
- 控制流绕过：用 %0a 替代 ; / | / &。
- 语法绕过：用 ${IFS} 替代空格，用 $@ 或 $() 替代空格。
- 语义绕过：用 base64 / tac / nl 替代 cat。
- 资源绕过：用 cd 替代绝对路径，用 * 或 ? 替代被过滤的关键字。

2. URL 编码与 HTTP 传输机制

在 HTTP 请求中，URL 只能传输 ASCII 字符。特殊字符（如空格、换行符、分号）需要经过 URL 编码（Percent-encoding）才能发送。例如，换行符 \n 编码为 %0a，空格编码为 %20，$ 编码为 %24，{ 编码为 %7B，} 编码为 %7D。这既是防御者过滤的依据，也是攻击者绕过的突破口。

3. 通配符（Wildcard）在 Shell 中的作用

Linux Shell 支持通配符 *（匹配任意字符）和 ?（匹配单个字符）。在命令注入中，通配符常用于绕过对文件名或目录名的关键字过滤，如 f* 匹配 flag_is_here。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“单一过滤”的区别：前面的题仅过滤一种字符或关键字，本题综合了路径、空格、命令、关键字等多种限制。这不仅要求掌握了每一个单独的绕过技巧，更需要将它们无缝组合在一起。
  • 与“无过滤”的区别：无过滤可以无脑执行；综合练习必须精准选择未被过滤的符号和替代命令，考验全局思考和灵活的应变能力。

2. 这种题目的出现原因

开发人员误以为只要把常见的危险字符（如空格、cat、flag、斜杠）全部拉黑，就能彻底杜绝命令注入。但这种“打补丁”式的黑名单防御极其脆弱，攻击者总能找到漏网之鱼或替代方案。根源在于开发者对 Shell 语法和 HTTP 协议缺乏深度理解。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，命令注入是获取服务器权限的“直通车”。当 WAF 严密防守时，攻击者会使用各种混淆技术（如变量拼接、编码转换、通配符）绕过防御，从而反弹 Shell 并控制整个服务器。企业防御必须采用白名单机制，并禁用危险函数（如 exec、system）。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个老实的传令兵：

  • 综合过滤：上级规定，纸条上不能写“空格”、“cat”、“flag”，还不能用“分号”和“斜杠”。
  • 组合拳绕过：你灵机一动，对传令兵说：“不要空一格，用这个叫 ${IFS} 的魔法符号！”；“不要用分号，用换行符（%0a）”；“不要写 flag，写个 f 带个星号（f*）”；“别用猫（cat），用砖头（base64）！”
  • 结果：传令兵看不懂上级的规则，只服从命令。你成功用一套漂亮的组合拳，绕过了所有关卡，拿到了 Flag。
