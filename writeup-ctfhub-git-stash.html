Git泄露-Stash - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 信息泄露 Git泄露

这道题属于 Git 源码泄露中的 Stash 场景。和普通 Log 题不同，Flag 并不在常规的提交历史（git log）里，而是被开发者临时藏匿（git stash）了起来。这篇 Writeup 详细记录了从工具被拦截，到最终使用 git-dumper 工具提取出 Flag 的完整过程，并用最通俗的比喻解析了每一条终端命令。

一、题目信息

  • 题目名称：Git泄露 - Stash
  • 题目平台：CTFHub
  • 题目类型：Web / 信息泄露 / Git源码泄露
  • 涉及工具：Mac 终端、Python (git-dumper)
  • 最终Flag： ctfhub{788456e084088eb774d84150}

二、Git 核心原理通俗解释

  • 什么是 Git？ 把它想象成一个“游戏存档系统”。git commit 就是新建一个存档，并附带一句留言（如“add flag”）。.git 文件夹就是存放所有历史存档的“保险箱”。
  • 什么是 Git 泄露？ 开发人员把代码上线时，粗心大意把存放历史存档的“保险箱”（.git 文件夹）一起传到了服务器。攻击者只需访问 http://靶场地址/.git/，就能直接抱走整个保险箱。
  • 什么是 Stash？ 假设你打游戏时妈妈喊你去倒垃圾（紧急修 Bug）。你不想丢弃当前的进度，于是按下“暂停并隐藏”（git stash）。这个被隐藏的进度不会出现在正常的存档列表里，而是藏在了一个“临时收纳箱”中。我们要做的就是打开这个收纳箱。

三、解题过程（详细步骤与踩坑全记录）

1. 踩坑第一步：环境过期与“彩蛋”陷阱

在终端尝试 wget 直接下载 .git 目录，结果下载回来一个环境过期的提示页（附带一个技能树彩蛋 Flag）。**解决：** 去 CTFHub 网页端点击“环境续期”或重新开启环境，获取新 URL。

2. 踩坑第二步：Wget 403 与 Git Clone 404

换了新环境后，直接 wget 报 403 Forbidden，使用 git clone 报 repository not found。原因是 WAF 拦截了常规下载工具，且 CTFHub 暴露的只是静态目录而非真实 Git 服务器。

3. 成功破局：使用 git-dumper 工具

使用专门针对此类漏洞的 Python 工具 git-dumper 完美绕过限制：

pip3 install git-dumper

cd ~/Downloads
git-dumper http://challenge-9f2bcb1dd3a30994.sandbox.ctfhub.com:10800/.git/ git_stash

终端迅速下载了所有历史对象并在本地还原了完整的 Git 仓库。

4. 查看被藏匿的“临时收纳箱”

进入下载好的目录，查看 Stash 列表（注意：不要用 git log，log 里是没有的）：

cd git_stash
git stash list

终端输出 stash@{0}: WIP on master...，证实存在被隐藏的工作区。

5. 提取最终 Flag

使用 -p 参数打印具体的代码差异：

git stash show -p stash@{0}

在打印出的代码变动中，直接找到了明文的 Flag。

最终 Flag： ctfhub{788456e084088eb774d84150}

四、代码逐行大白话解析（新手必读）

  • cd ~/Downloads：打开电脑的“下载”文件夹，准备干活。
  • rm -rf git_stash：强制删除旧的 git_stash 文件夹，保证从头开始，防止文件冲突。
  • pip3 install git-dumper：安装专门用来“偷保险箱”的神兵利器。
  • git-dumper http://.../.git/ git_stash：把网址背后的“保险箱”整个下载回来，放到本地的 git_stash 文件夹里。
  • cd git_stash：进入这个刚刚拼装好的本地仓库。
  • git stash list：打开“临时收纳箱”，查看里面藏了几个紧急保存的进度。
  • git stash show -p stash@{0}：把 0 号临时收纳箱里的东西全部倒出来（-p 表示显示具体代码差异），Flag 就藏在里面。

五、知识点总结（往脑子里装的东西）

  • Git 泄露系列： 分为 Log（提交历史）、Stash（临时藏匿）、Index（暂存区）。针对不同的题目名，使用对应的 Git 命令查找。
  • Git 的起死回生特性： 只要 .git 目录还在，哪怕开发者删除了代码或隐藏了进度，我们都能通过 Git 的对象存储机制完整还原。
  • 排错思维： 当 wget 和 git clone 连续失败时，不要死磕，立刻换用专用工具 git-dumper 是最高效的破局之道。

做一道题，就要往自己脑子里装点东西。
