DVWA-Medium-CSP绕过 (CSP Bypass)

2026年10月2日 DVWA Web安全 CSP 组合利用

一、题目信息

  • 题目名称：DVWA CSP Bypass (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 客户端安全 / CSP 绕过 / 组合漏洞利用
  • 靶场链接：http://192.168.242.80/vulnerabilities/csp/
  • 涉及工具：Google Chrome 浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是绕过 Medium 级别的 CSP 策略，实现脚本执行。与 Low 级别不同，Medium 级别的 CSP 策略移除了 'unsafe-inline'，导致内联脚本（如 <script>alert(1)</script>）被浏览器直接拦截。然而，CSP 中依然保留了 'self' 指令，允许加载同源（当前域名）的外部脚本。攻击者可以利用之前学过的文件上传漏洞，将恶意 JS 文件上传到服务器自身，从而绕过 CSP。

2. 怎么想（破题思路）

  • 尝试 Low 级别的 Payload <script>alert(1)</script>，发现被 CSP 拦截，控制台报错。
  • 检查 CSP 响应头，发现 script-src 'self' 生效，即只允许加载本域名下的脚本。
  • 既然允许加载本域脚本，我们能否把脚本传到本域？可以，利用 File Upload 漏洞。
  • 上传 alert.js 后，利用 <script src="/hackable/uploads/alert.js"></script> 引入，成功弹窗。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：内联脚本被 CSP 拦截

踩坑情况：在输入框中输入 <script>alert(1)</script>，页面没有弹窗，浏览器控制台提示 Refused to execute inline script because it violates the following Content Security Policy directive: "script-src 'self'"。

原因分析：Medium 级别移除了 'unsafe-inline' 指令，浏览器拒绝执行页面内联的 JavaScript 代码。

改进方式：改用外部脚本加载方式。利用文件上传漏洞将 alert.js 上传到靶机 Web 目录，然后通过 <script src="..."> 标签引入，因为 'self' 允许加载同源脚本。

详细实操步骤（Payload逐字解释）

第一步：准备并上传 JS 文件

本地创建 alert.js，内容为：alert('CSP Bypass Medium!');

去 File Upload 关卡上传该文件（如果提示 MIME 类型不符，用 Burp 抓包将 Content-Type 改为 image/jpeg 即可绕过）。

上传成功后，获取路径：/hackable/uploads/alert.js。

第二步：在 CSP 关卡中引入同源脚本

回到 CSP Bypass，在输入框中填入：

<script src="/hackable/uploads/alert.js"></script>

响应结果：页面成功弹出提示框 CSP Bypass Medium!。

原理解释：CSP 的 'self' 指令允许加载当前域下的脚本。虽然这是外部 URL 参数，但它依然属于同源，因此被 CSP 放行。这就是“文件上传 + CSP 绕过”的组合利用。

4. 怎么迁移（跨领域联想）

  • 供应链攻击：在真实场景中，攻击者可能无法直接上传文件，但可以尝试在 CSP 白名单内的某个第三方库（如 CDN）上找到 JSONP 接口或允许上传文件的地方，从而绕过 CSP 执行恶意代码。
  • 漏洞组合利用：本次实战完美展示了“组合拳”的威力。单一漏洞（如低危的文件上传、CSP 配置不当）可能影响有限，但组合起来就能实现高危的远程代码执行。

三、名词大全与原理深度复盘

1. CSP (Content Security Policy)

内容安全策略。一种由浏览器实现的声明式安全机制，通过 HTTP 响应头或 meta 标签，限制页面可以加载哪些资源（如脚本、样式、图片），是防御 XSS 的强力手段。

2. 'self' 指令

CSP 中的一个关键字，表示允许加载与当前页面同源（相同协议、域名和端口）的资源。利用好这个指令，可以只允许加载站内的合法脚本。

3. 同源策略 (Same-Origin Policy)

浏览器的核心安全机制。CSP 的 'self' 正是基于同源策略。只要上传的脚本和当前页面同源，就能被浏览器允许执行。

4. 组合漏洞利用链 (Exploit Chain)

将多个独立的低危漏洞串联起来，实现单一漏洞无法达到的高危攻击效果。这是高级渗透测试的核心能力之一。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别 CSP 允许内联脚本（'unsafe-inline'），直接输 <script> 即可。Medium 级别移除了该指令，必须通过外部同源脚本绕过。
  • 与 XSS 的区别：XSS 是直接注入脚本，CSP 是为了防御 XSS 而生的。本关的核心是如何绕过这道防线。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于CSP 策略配置不当（保留了 'self' 且站点存在文件上传漏洞）。如果 CSP 严格限制了 script-src 只允许特定的 CDN，或者禁止了 'self'，攻击者就无法利用同源上传的文件。

3. 这种的应用

在真实的渗透测试中，遇到带 CSP 的站点时，攻击者会尝试寻找 CSP 白名单中的弱点，或者像本题一样利用其他漏洞（如文件上传、JSONP）来托管恶意脚本。

4. 如何抽象理解概念（大白话）

把 CSP 比作“小区门禁”：

  • 正常情况：门禁只允许业主（同源脚本）进小区。外卖员（外部脚本）一律拦住。
  • 恶意情况：攻击者伪装成业主，把炸弹（恶意脚本）放在了小区快递柜（通过文件上传漏洞）。
  • 门禁一看是“快递柜里的东西”，属于小区内部物品（'self'），就放行了。这就是 CSP 绕过的本质——从内部发起攻击。
