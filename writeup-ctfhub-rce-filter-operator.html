CTFHub RCE - 命令注入-过滤运算符

2026年9月22日 CTFHub Web安全 RCE 过滤运算符

一、题目信息

  • 题目名称：命令注入-过滤运算符
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程命令执行） / 命令注入 / 黑名单绕过
  • 靶场链接：http://challenge-082fc4d1be0e31c6.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是过滤命令运算符后的命令注入绕过。后端代码使用 preg_match_all("/(\||\&)/", $ip, $m) 检测并拦截了用户输入中的管道符 | 和与符号 &。攻击者需要寻找其他命令拼接符（如分号 ; 或换行符 %0a），并结合前面关卡学到的 ${IFS}（替代空格）和 base64（替代 cat）来完成读取。

2. 怎么想（破题思路）

  • 页面提示“过滤了几个运算符，要怎么绕过呢”。
  • 源码中只过滤了 | 和 &。这意味着分号 ; 和换行符 %0a 依然可用。
  • 继续沿用前面的“终极连招”：用 ; 拼接命令，用 ${IFS} 替代空格，用 base64 读取文件防解析。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：习惯性使用管道符导致拦截

踩坑情况：尝试输入 127.0.0.1 | ls 或 127.0.0.1 & ls，页面直接弹出拦截提示。

原因分析：preg_match_all 精准匹配到了 | 或 &，导致代码走向 else 分支。

改进方式：必须改用分号 ;。

踩坑记录二：只使用 `;` 和 `cat` 导致空白页

踩坑情况：输入 127.0.0.1; cat flag_xxx.php，命令执行成功但页面无回显。

原因分析：PHP 解析器把文件内容中的 <?php // ctfhub{...} ?> 中的注释给吞掉了。

改进方式：必须使用 base64 配合 ${IFS} 读取。

详细实操步骤（逐字解析）

第一步：探测目录

构造 Payload：127.0.0.1;ls

发现目标文件：flag_123403143211133.php。

第二步：使用 base64 读取文件（绕过运算符与空格过滤）

构造 Payload：

127.0.0.1;base64${IFS}flag_123403143211133.php

Payload 逐字深度解析：

  • 127.0.0.1：让 ping 命令正常执行。
  • ;：命令分隔符（成功绕过 | 和 & 的过滤）。
  • base64：Linux 系统命令，读取文件并转为 Base64 编码。
  • ${IFS}：替代空格，绕过空格过滤。
  • flag_123403143211133.php：目标文件名。

第三步：备选方案（换行符绕过）

如果 ; 也被拦截，可以使用 URL 编码的换行符 %0a：

?ip=127.0.0.1%0abase64${IFS}flag_123403143211133.php

第四步：解码并提交

页面回显 Base64 字符串，复制后去在线工具解码，得到 Flag：ctfhub{1249b4dc0b2d8f08a5254fd6}。提交即可通关。

4. 怎么迁移（跨领域联想）

  • WAF 绕过实战：真实 WAF 规则往往不如本题严谨。利用符号替换（如用 `;` 替代 `|`，用 `%0a` 替代 `;`）是绕过命令注入防御的常见手段。
  • 安全开发（SDL）：黑名单防御永远有漏网之鱼。必须使用白名单机制，或对用户输入进行 escapeshellarg() 严格转义。

三、名词大全与原理深度复盘

1. 常用命令运算符及其作用

  • ;：顺序执行，前一个命令成功或失败，后一个都会执行。
  • |：管道，前一个命令的输出作为后一个命令的输入。
  • &：后台执行。
  • &&：逻辑与，前一个成功才执行后一个。
  • ||：逻辑或，前一个失败才执行后一个。
  • %0a：换行符，在 Shell 中等同于新的命令。

2. 正则表达式 /(\||\&)/ 深度解析

| 在正则中代表“或”，因此 \| 用于匹配字面量管道符 |。& 同理。/(\||\&)/ 这个正则的目的就是找出字符串中是否存在 | 或 &。这也暴露了开发者的防御思路过于单一。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“过滤空格/目录分隔符”的区别：前两题针对的是“参数内容”和“路径”；本题针对的是“命令连接方式”。防御点在语法层，绕过方案也随之变化。
  • 与“无过滤”的区别：无过滤可以无脑使用任意运算符；本题必须精准选择未被过滤的运算符。

2. 这种题目的出现原因

开发人员试图通过拦截 | 和 & 来阻止攻击者拼接命令。但他们忽略了 ; 和 %0a 同样可以实现命令拼接，这种“补丁式”黑名单防御必然存在遗漏。

3. 这种应用在实际中如何体现？

在红蓝对抗中，如果 WAF 拦截了 `|`，攻击者会立刻尝试 `;`、`&&`、`||`、`%0a` 等替代方案。防御方不能只靠黑名单，必须使用白名单或参数化执行。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个传令兵：

  • 黑名单（过滤运算符）：上级规定：“纸条上不能出现‘和’（&）与‘管道’（|）这两个词。”
  • 绕过（使用分号或换行）：你灵机一动，用“逗号”（;）或者“另起一行”（%0a）来连接命令。传令兵看不懂上级的规则，只认识逗号和换行，于是老老实实执行了你的命令，帮你拿到了 Flag。
