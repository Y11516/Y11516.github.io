二、解题步骤

1. 分析题目考什么

这一关的源码中，开发者在用户输入前强制拼接了 ls 。弹窗提示“使用分号 ; 分隔符执行多个命令”。核心考点是利用 Shell 的命令分隔符，截断或拼接系统预置的命令，强行执行我们的 Payload。

2. 怎么想（破题思路）

踩坑记录：强制拼接 ls 导致常规命令失效

源码分析：$cmd = "ls " . $cmd;。这意味着无论你输入什么，实际执行的命令都会变成 ls 你的输入。

失败尝试：如果你输入 /bin/cat /flag，最终执行的会是 ls /bin/cat /flag，这会导致报错或仅列出文件，无法读取 flag。

改进方式：利用 Shell 的命令分隔符 ;。我们可以输入 ; /bin/ca* /flag，这样拼接后就是 ls ; /bin/cat /flag。Shell 会先执行 ls（无输出），然后顺利执行我们的读取命令。

3. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$cmd = $_GET['cmd'] ?? 'echo "<br>Ciallo~(∠・ω< )★"';
$cmd = "ls " . $cmd;
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与逐字解析

?cmd=ls; /bin/ca* /flag

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

命令逐字解析：

  • ;：Shell 的命令分隔符。它允许在一行中顺序执行多条命令。
  • /bin/ca*：/bin 是 Linux 存放基础命令的目录。ca* 利用通配符匹配到 /bin/cat。由于 WAF 拦截了 cat，我们通过通配符绕过。
  • /flag：要读取的目标文件。
  • 最终效果：WAF 看到的是 ls; /bin/ca* /flag，未包含敏感词 cat，放行。Shell 实际执行了 ls 和 /bin/cat /flag。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的命令拼接：在护网中，如果某个参数被过滤，红队常利用 ;、&、|、&&、|| 等符号，拼接多条命令，从而绕过基于单一命令关键字的检测。
  • 系统运维中的自动化：运维脚本中常用 cd /var/www && git pull && systemctl restart nginx 这样的链式命令，确保前一条成功后再执行下一条。

三、名词大全与原理深度复盘

1. /bin 目录是干什么的？

bin 是 binaries（二进制文件） 的缩写。/bin 是 Linux 的核心目录，存放着系统最基础、最常用的可执行命令（如 ls、cat、cp、bash）。当我们在终端输入 cat 时，系统实际是在 /bin/cat 找到并执行它。
除了 /bin，还有 /sbin（系统管理员命令）、/usr/bin（用户级命令，如 python3、nc）。

2. Shell 的分隔符家族

  • ;：顺序执行。无论前一条成功与否，都执行下一条。
  • &&：逻辑与。前一条成功才执行下一条（短路逻辑）。
  • ||：逻辑或。前一条失败才执行下一条。
  • |：管道。将前一条命令的输出作为下一条命令的输入。

3. WAF 与 防火墙 的区别

  • 防火墙（Firewall）：工作在网络层和传输层，主要负责控制 IP 和端口的进出。它会拦截非标准端口的 TCP 连接（如 9002），这就是反弹 Shell 容易失败的原因。
  • WAF（Web 应用防火墙）：工作在应用层，专门检查 HTTP 请求的内容。它维护一个黑名单字典，包含 cat、sed 等敏感词。它只看“请求长什么样”，不看“命令执行后会变成什么”。

4. 核心网络基础与护网认知（陌生人也能看懂版）

  • 外网（公网/互联网）：拥有全球唯一的门牌号（公网 IP，如 8.8.8.8），任何人任何车都能开到你家门口。
  • 内网（局域网）：门牌号是“小区内部编号”（如 192.168.1.19），只有小区内部的人才能互相找到。外面的人想找你，必须经过小区保安（路由器/NAT）允许并做地址转换。
  • 完全隔离的内网：小区不仅不让外面的人进，甚至把大门用砖头砌死了（物理隔离）。这种环境下，反弹 Shell 和重定向写入 100% 都会失效。
  • HTTP 是公网吗？这是一个经典的误解！HTTP 不是网络，它是语言（协议）。就像“普通话”不是某个地方，而是一种交流方式。无论你是在访问内网的 OA 系统（http://192.168.1.100），还是访问百度官网（http://baidu.com），都是在用 HTTP 这个“语言”说话。所以，HTTP 既可以跑在内网，也可以跑在外网。
  • 操作系统与网络的关系：电脑操作系统是管理网络硬件的“交通警察”。你的网卡是公路，操作系统负责定义 IP 地址、网关，并内置防火墙（如 iptables）。当你监听 80 端口成功、9002 端口失败时，根本原因就是操作系统或 Docker 的虚拟网卡策略，只放行了 80 端口的出站，拦截了 9002 端口。
  • 护网是在攻击内网吗？简单来说，护网是一场“攻城战”：第一阶段是“外网打点”（攻打城门），寻找对外门户的漏洞；第二阶段是“内网渗透”（巷战与横向移动），拿下边界服务器后，以它为跳板，在内网里提权、抓密码、扫描其他机器；第三阶段是“拿下靶标”（直捣黄龙），控制核心数据库或域控。所以，内网渗透绝对是护网中最核心、最残酷、决定胜负的主战场。

四、题目思考

1. 这跟前面关卡的区别

Level 28 和 29 考的是“如何变形命令本身”（通配符）。Level 30 考的是“如何拼接命令”（变量）。Level 31 首次引入了“如何利用 Shell 语法结构截断/绕过系统预置命令”（分隔符）。WAF 绕过的维度越来越深。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发者常常在不经意间将用户输入与系统命令拼接（如 `ls `）。如果过滤不严，攻击者就可以利用 Shell 的分隔符来截断原本的命令，并执行自己想要的命令。这种漏洞源于对 Shell 解析机制的不理解。

3. 这种漏洞在实际中的应用

在护网和红队行动中，遇到 WAF 是家常便饭。利用分隔符、通配符、变量替换等手段绕过关键字拦截，是渗透测试人员的基本功。同时，防守方也据此推出了“语义分析”型的高级 WAF，不仅看关键字，还会还原命令执行后的真实意图。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。监考老师（开发者）强行在你面前放了一块“请保持安静”的牌子（`ls `）。你不能直接开口说话，于是你用一个“分号”（`;`）结束了他的牌子约束，然后小声说“我要交卷”，监考老师（Shell）听到了你的真实意图，帮你把卷子（flag）收上去了。

5. 他的本质

本质是利用 Shell 的命令分隔符，截断应用层强制拼接的上下文，将原本的“参数”提升为“独立的命令”，从而执行恶意 Payload。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：不要使用字符串拼接来构造系统命令！应使用编程语言提供的安全 API（如 PHP 的 escapeshellarg），或者直接使用白名单限制用户输入。同时，WAF 应拦截 ;、|、& 等命令分隔符。
  • 破解方（红队）：如果分隔符被拦截，尝试使用换行符 %0A、反引号 `` ` ``、$() 等替代分隔方式。如果系统预置了 ls，可以利用 ls 的参数注入（如 ls -la; 命令），或者利用 sed、awk 等工具来执行命令。
