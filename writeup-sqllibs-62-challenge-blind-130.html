SQLi-Labs Less-62

2026年10月1日 SQLi-Labs Web安全 SQL注入 挑战模式 / 时间盲注 (130次)

一、题目信息

  • 题目名称：SQLi-Labs Less-62 (GET - challenge - Blind - 130 queries allowed - variation 1)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 挑战模式 / 时间盲注 / 单引号括号闭合 / 限制尝试次数
  • 靶场链接：http://localhost:8081/Less-62/（本地环境）
  • 涉及工具：Chrome浏览器、VS Code、Python3 (requests库)

二、解题步骤

1. 分析题目考什么

本题的核心考点是在限制 130 次尝试的极端条件下，完成基于时间盲注（Time-based Blind SQL Injection）的数据提取。Less-62 无法使用 UNION 联合查询，且页面没有回显差异（布尔盲注失效），闭合方式为 ')。必须通过构造 SLEEP() 延迟函数来推断数据，并利用 Python 脚本进行自动化二分法爆破。

2. 怎么想（破题思路）

  • 页面提示“You have made : 4 of 130 attempts”，意味着只有 130 次机会，手动注入几乎不可能完成。
  • 尝试布尔盲注（AND 1=1 与 AND 1=2），发现页面返回内容完全一致，布尔盲注不可行。
  • 转向时间盲注，利用 IF(condition, SLEEP(3), 0) 判断条件真假。
  • 编写 Python 脚本，采用二分法（Binary Search）快速逼近 ASCII 码值。
  • 关键突破：Less-62 的尝试次数依赖 Cookie 跟踪，在脚本中不携带 Cookie 即可完全绕过 130 次限制。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：布尔盲注失效

踩坑情况：尝试 ?id=1') AND 1=1-- - 和 ?id=1') AND 1=2-- -，发现页面完全一致，无法判断真假。

原因分析：Less-62 是一个盲注关卡，后端代码没有将查询结果或错误信息输出到前端，导致页面没有布尔差异。

改进方式：果断放弃布尔盲注，转向时间盲注。

踩坑记录二：Python 脚本语法错误与长度硬编码

踩坑情况：第一版脚本在拼接 SQL 语句时，字符串未闭合导致 Python 语法错误（截图显示第8行和第15行缺少 ' LIMIT 0,1)"）。随后由于脚本硬编码了字符串长度（如固定为11或24），导致获取结果为空或乱码。

原因分析：字符串拼接时遗漏了引号和括号。盲注时，如果长度探测错误，后续的字符爆破就会全部错位，二分法返回的边界值（如32或127）在终端显示为空白或不可见字符。

改进方式：重写脚本，增加 get_length() 函数自动探测长度，并加入重试机制防止网络抖动导致误判。

踩坑记录三：查询到了错误的列名（id 列）

踩坑情况：脚本运行后，自动探测列名得到 id（长度为2），随后提取出的 Secret Key 竟然只是数字 1。

原因分析：information_schema.columns 表默认返回表中的所有列。在 challenges 库中，表结构通常是 id 列在第一位，secret_xxxx 列在后面。脚本没有过滤，直接拿到了第一列的 id 和它的值 1。

改进方式：在 SQL 查询中增加过滤条件 AND column_name LIKE 'secret_%'，跳过 id 列，直接定位到目标列。

详细实操步骤（Payload逐字解释）

第一步：验证时间盲注可行性（手动测试）

?id=1') AND IF(1=1, SLEEP(3), 0)-- -

逐个字符解释：

  • ?id=1'：闭合原有的单引号。
  • )：闭合原有的右括号。
  • AND：逻辑与操作符，连接后续的条件。
  • IF(1=1, SLEEP(3), 0)：如果 1=1 为真，执行 SLEEP(3) 延迟3秒，否则执行0立即返回。
  • -- -：注释掉后面的 SQL 语句。

成功响应：页面卡顿约3秒后返回正常内容。说明时间盲注可行。

第二步：编写 Python 自动化脚本（核心逻辑）

脚本采用二分法，每次请求通过判断响应时间是否大于阈值来确定条件真假。核心函数解释：

def check_condition(payload):
    full_url = url + "?id=1') AND " + payload + "-- -"
    # 发起请求，记录耗时，超过阈值则返回 True

二分法获取字符：

payload = f"IF(ASCII(SUBSTR({expression},{position},1))>{mid}, SLEEP(2), 0)"
  • SUBSTR(expression, position, 1)：从目标字符串中截取第 position 个字符，长度为1。
  • ASCII(...)：将截取到的字符转换为 ASCII 码值。
  • IF(... > mid, SLEEP(2), 0)：判断 ASCII 码是否大于中间值，如果是则延迟2秒。

第三步：执行脚本，获取数据

脚本运行日志（截图内容精炼）：

  • 列名获取成功：secret_JQ86（过滤了 id 列后，自动探测长度11）
  • Secret Key 获取成功：T2v5jiJsgbsVpPk1WeTRbQRp（长度自动探测为24）

4. 怎么迁移（跨领域联想）

  • 医疗诊断中的“排除法”：时间盲注类似于医生无法直接看到病灶（无回显），只能通过打针后观察患者是否出现特定反应（延迟），结合二分法（逐层缩小范围），最终锁定病因。
  • 代码调试与系统排错：在无法直接打印错误日志的封闭系统中，开发者通过注入探针（Debug代码）并观察系统响应时间或资源占用，来定位性能瓶颈。

三、名词大全与原理深度复盘

1. 时间盲注 (Time-based Blind SQL Injection)

一种SQL注入技术。在页面既不返回数据，也不返回错误信息，甚至没有布尔差异（真/假页面完全相同）的极端情况下，攻击者通过在SQL语句中插入延迟函数（如 SLEEP()），根据页面响应时间的长短来判断注入的条件是否成立。

2. 二分法 (Binary Search)

一种在有序数组中查找特定元素的搜索算法。在盲注中，将 ASCII 码范围（32-126）不断折半，每次请求可以排除一半的可能性，将每个字符的爆破次数从最多94次减少到约7次，极大地提高了效率。

3. information_schema

MySQL 自带的系统数据库，它存储了关于数据库自身的信息，包括所有数据库名、表名、列名等。它是 SQL 注入中获取元数据的核心入口。

4. SUBSTR() / ASCII() / IF() / SLEEP()

SUBSTR(str, pos, len) 用于截取字符串；ASCII(char) 用于将字符转化为整数值；IF(cond, true_val, false_val) 是条件判断函数；SLEEP(n) 是 MySQL 内置的延迟函数，让查询暂停 n 秒。

5. 无 Cookie 绕过限制

Less-62 尝试次数限制是基于 Cookie 的会话跟踪实现的。Python 脚本在 requests.get() 时不携带 Cookie 字段，服务器每次都会将其视为一个全新的会话，从而完全绕过 130 次的尝试限制。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-59/60 的区别：Less-59 和 60 是双查询报错注入（Double Query），依赖报错回显数据，限制5次。Less-62 是无回显的时间盲注，限制130次，需要脚本自动化。
  • 与 Less-54~57 的区别：Less-54~57 是 Union 联合查询注入，虽然限制10~14次，但有直接的回显位置，可以通过 group_concat() 一次性获取所有数据。Less-62 没有任何回显。
  • 闭合方式区别：Less-59 是数字型，Less-60 是双引号加括号 ")，Less-62 是单引号加括号 ')。

2. 这种题目的出现原因（为什么存在）

这种漏洞存在的根本原因在于代码层直接拼接 SQL 语句，且没有使用预编译（Prepared Statements）。开发者将用户输入的 id 直接拼接在 SQL 查询后，导致攻击者可以闭合引号并执行恶意 SQL。

从计算机底层来说，SQL 解析器在解析语句时，无法区分哪些是开发者写的 SQL 代码，哪些是用户传入的数据。当用户输入 ') AND SLEEP(3)-- - 时，解析器会将其当作合法的 SQL 语法执行。这在历史上类似于早期 PHP/ASP 应用中广泛存在的 SQL 注入漏洞，著名的如 2011 年索尼 PlayStation Network 被黑事件，攻击者正是利用了未过滤的 SQL 查询参数，窃取了上亿用户的数据。

3. 这种的应用

时间盲注在实战中应用广泛。当遇到带有 WAF 的站点，或者后端代码封装极好、没有任何报错和回显时，联合查询和报错注入都会失效。此时，时间盲注是唯一能有效提取数据的手段。在渗透测试中，常配合 SQLMap 的 --time-sec 参数或自定义 Python 脚本使用，用于评估数据库安全风险。

4. 如何抽象理解概念（大白话）

把时间盲注比作“蒙眼猜数字”：

  • 你被蒙住眼睛，面前有一个黑盒子，里面藏着一串密码。
  • 你无法看到密码，也无法听到盒子里的声音（无回显）。
  • 但你可以向盒子里投币。如果你投的币符合某个条件，盒子会“卡顿3秒”才吐出来（时间延迟）。
  • 你利用“二分法”，先问“密码第一个字母的ASCII码大于100吗？”，盒子卡顿了3秒，说明大于100；再问“大于113吗？”，盒子没卡顿，说明在100到113之间。
  • 如此反复，最终把密码完整猜出来。这就是时间盲注的底层逻辑。

做一道题，就要往自己脑子里装点东西。
