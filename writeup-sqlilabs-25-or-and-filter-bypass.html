SQLi-Labs Less-25

2026年9月28日 SQLi-Labs Web安全 SQL注入 OR/AND 过滤绕过

一、题目信息

  • 题目名称：SQLi-Labs Less-25 (GET - Error based - All your OR & AND belong to us - string single quote)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 关键字过滤绕过
  • 靶场链接：http://localhost:8081/Less-25/（本地环境）
  • 涉及工具：Chrome浏览器 (地址栏直接注入)

二、解题步骤

1. 分析题目考什么

本题的核心考点是过滤了 SQL 关键字 OR 和 AND 的绕过。后端代码使用了 preg_replace('/or|and/i', '', $_GET['id']) 将用户输入中的所有 OR 和 AND 替换为空。攻击者需要使用它们的符号替代符：&&（代表 AND）、||（代表 OR），并注意 URL 编码。

2. 怎么想（破题思路）

  • 页面提示“All your OR and AND belong to us”，明确告知过滤了这两个关键字。
  • 尝试使用 and，Payload 被破坏，无法注入。
  • 改用 && 替代 and，在 URL 中需要编码为 %26%26。
  • 构造报错注入 Payload，成功回显数据库名。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接使用 AND 导致 Payload 被破坏

踩坑情况：使用常规的 ?id=1' and updatexml(...) -- -，页面无法执行，提示 SQL 语法错误。

原因分析：后端正则匹配到了 and，将其替换为空，导致 SQL 语句变成 id='1' updatexml(...)，语法完全错误。

改进方式：使用 && 替代 AND，使用 || 替代 OR。在 URL 中，& 必须编码为 %26，因此最终 Payload 为 %26%26。

详细实操步骤（Payload逐字解释）

第一步：构造 Payload

?id=1' %26%26 updatexml(1,concat(0x7e,(select database()),0x7e),1) -- -

逐字解析：

  • 1'：闭合原 SQL 中的单引号。
  • %26%26：URL 编码后的 &&，替代被过滤的 AND。
  • updatexml(...)：报错注入函数，拼接查询结果并触发报错。
  • -- -：注释掉原 SQL 末尾的 ' LIMIT 0,1。

第二步：验证

页面回显 XPATH syntax error: '~security~'，注入成功。

4. 怎么迁移（跨领域联想）

  • 符号替代法：在 WAF 绕过中，关键字过滤是常见防御手段。除了 && 替代 AND，还可以使用 /*!50000AND*/ 内联注释、大小写混合（aNd，若未过滤大小写）、URL 编码等。
  • 正则匹配的局限性：使用正则表达式进行过滤，往往可以被绕过。攻击者可以利用编码、替代符、内联注释、空格替换等方式突破。这再次证明白名单与参数化查询的必要性。
  • 环境差异与踩坑：在 Mac + Docker 环境中，报错注入正常工作。遇到环境问题时，应果断跳过或改用时间盲注，不要死磕。

三、名词大全与原理深度复盘

1. 关键字过滤

后端使用正则表达式过滤特定的 SQL 关键字（如 OR, AND, UNION, SELECT）。攻击者可以使用符号（&&, ||）或编码绕过。

2. URL 编码

在 HTTP 协议中，特殊字符（如 &、空格、单引号）必须编码。在 URL 中，&& 需要编码为 %26%26，空格编码为 %20。这是 Web 安全中最基础的传输细节。

3. updatexml() 报错注入

在 MySQL 5.x 环境中，利用 updatexml() 函数解析非法 XPath 字符串时的报错，将查询结果拼接在报错信息中带出。回显长度上限为 32 字节。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-23 的区别：Less-23 过滤了注释符，Less-25 过滤了 OR 和 AND 关键字。
  • 与 Less-24 的区别：Less-24 是二次注入，Less-25 是直接的 GET 注入。

2. 这种题目的出现原因（为什么存在）

开发者试图通过过滤关键字来阻止 SQL 注入，但这是一种黑名单式的防御，存在极大的局限性。攻击者总能用替代符、编码、注释等方式绕过。这警示我们：防御必须从代码层面（参数化查询）和服务器配置层面入手，而非依赖字符串过滤。

3. 这种应用在实际中如何体现？

在实战中，遇到 WAF 拦截 AND 或 OR 时，渗透测试人员会优先尝试 &&、||、%26%26、%7C%7C 等变体。防御方应使用参数化查询，或使用 WAF 的正则优化来匹配这些替代符。

4. 如何抽象理解概念（大白话）

把靶场比作一个“严格的语文老师”：

  • Less-25 的语文老师把“和”这个字从字典里撕掉了。如果你用“和（AND）”造句，句子就被撕烂了。
  • 你换了个数学符号“&&”来表示“和”，老师没撕掉这个符号，你的句子就完整了。
  • 这就是替代符绕过核心逻辑。

做一道题，就要往自己脑子里装点东西。
