RCE-Labs Level 35 - 绕过注释 # 与换行符截断

2026年10月5日 RCE-Labs 注释绕过 源码审计

一、题目信息

  • 1.题目名称：RCE-Labs Level 35 (绕过注释 #)
  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 命令拼接 / 注释绕过
  • 4.靶场链接：http://靶机IP:8080/less-35/
  • 5.涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

源码中开发者在用户输入前强制拼接了 $cmd = "# " . $cmd;。弹窗提示“井号 # 会将后续内容注释掉，尝试绕过 #”。核心考点是利用 Shell 的换行符截断注释，使被拼接的恶意命令重新生效。

血泪踩坑记录：工具依赖症与浏览器拼 URL 的降维打击

错误尝试：受前面关卡 Nginx 拦截换行符的影响，我盲目推荐使用 Burp Suite 发送复杂 Payload，试图绕过不存在的防御。

用户反馈：“为什么不拼url？”（直接灵魂拷问）

改进与成功：直接在浏览器地址栏输入 ?cmd=%0Acat%20%2Fflag，成功回显。这证明了：永远不要迷信工具，能直接用 URL 解决的问题，绝不乱用 Burp。同时，不要被前期的经验固化思维，每到一个新环境，一定要重新侦察源码。

2. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$cmd = $_GET['cmd'] ?? '...';
$cmd = "# " . $cmd;
system($cmd);

最终成功 Payload 与逐字解析

?cmd=%0Acat%20%2Fflag

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

命令逐字解析：

  • %0A：换行符（LF）。在 Shell 里，换行符是原生的命令分隔符，相当于在终端里按下回车。
  • cat %2Fflag：cat /flag。
  • 最终效果：拼接后变成 # \n cat /flag。第一行的 # 只注释掉了它所在的那一行（即前面的空白），换行符开启了第二行，第二行的 cat /flag 被 Shell 正常执行并回显。

3. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的命令截断：在真实内网中，遇到命令被拼接了注释符前缀，经常利用换行符 %0A、回车换行 %0D%0A、逻辑或 || 进行截断。关键在于理解 Shell 的解析顺序和标准流。
  • 系统运维中的注释：写 Shell 脚本时，# 是最常用的注释符号。通过换行符将多行命令堆叠在一个脚本里执行，是自动化运维的基础操作。

三、名词大全与原理深度复盘

1. Shell 注释符 `#` 的底层机制

在 Shell 脚本中，# 表示注释，即该符号后的所有内容都会被 Shell 解析器忽略，直到遇到换行符。它常被开发者用来写注释，或者被防御方用来“注释掉”用户的输入。但它无法跨行注释，这就是换行符能绕过它的根本原因。

2. 换行符 `%0A` 的妙用

%0A 是 URL 编码的换行符（LF）。在 Shell 脚本里，换行符就是原生的命令分隔符。它比 ;、&&、|| 更隐蔽，常常能绕过 WAF 对符号的拦截。但要注意，Nginx 有时也会对 %0A 产生警觉，遇到 400 错误时需改用 Burp 发送原始包，或者使用 %0D%0A。

3. WAF 与 防火墙 的区别

  • 防火墙（Firewall）：工作在网络层和传输层，主要负责控制 IP 和端口的进出。它会拦截非标准端口的 TCP 连接（如 9002），这就是反弹 Shell 容易失败的原因。
  • WAF（Web 应用防火墙）：工作在应用层，专门检查 HTTP 请求的内容。它维护一个黑名单字典，包含 cat、sed 等敏感词。它只看“请求长什么样”，不看“命令执行后会变成什么”。

4. 核心网络基础与护网认知（陌生人也能看懂版）

  • 外网（公网/互联网）：拥有全球唯一的门牌号（公网 IP，如 8.8.8.8），任何人任何车都能开到你家门口。
  • 内网（局域网）：门牌号是“小区内部编号”（如 192.168.1.19），只有小区内部的人才能互相找到。外面的人想找你，必须经过小区保安（路由器/NAT）允许并做地址转换。
  • 完全隔离的内网：小区不仅不让外面的人进，甚至把大门用砖头砌死了（物理隔离）。这种环境下，反弹 Shell 和重定向写入 100% 都会失效。
  • HTTP 是公网吗？这是一个经典的误解！HTTP 不是网络，它是语言（协议）。无论访问内网 OA 还是百度官网，用的都是 HTTP 语言。
  • 操作系统与网络的关系：电脑操作系统是管理网络硬件的“交通警察”。你监听 80 端口成功、9002 端口失败，根本原因就是操作系统或 Docker 的虚拟网卡策略，只放行了 80 端口的出站，拦截了 9002 端口。
  • 护网是在攻击内网吗？护网是一场“攻城战”：第一阶段是“外网打点”（攻打城门），寻找对外门户的漏洞；第二阶段是“内网渗透”（巷战与横向移动），以边界服务器为跳板在内网提权、抓密码；第三阶段是“拿下靶标”（直捣黄龙），控制核心数据库或域控。内网渗透是决定胜负的主战场。

四、题目思考

1. 这跟前面关卡的区别

Level 34 考的是反引号优先级和标准流陷阱，Level 35 考的是注释符截断。这提醒我们：不要被前期的经验固化思维，每到一个新环境，一定要重新侦察源码。同时，不要迷信工具，能直接用 URL 解决的问题，绝不乱用 Burp。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发者常常在不经意间将用户输入与系统命令拼接（如 # ）。开发者可能误以为 # 能“注释”掉用户的恶意输入，但这是一种错误的防御手段。如果过滤不严，攻击者就可以利用 Shell 的换行符来截断原本的注释。

3. 这种漏洞在实际中的应用

在护网和红队行动中，遇到 WAF 是家常便饭。利用分隔符、通配符、变量替换、换行符绕过注释等手段，是渗透测试人员的基本功。同时，要懂得分析 400、403、500 等状态码的差异，判断是 Nginx、WAF 还是后端代码在拦你。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。监考老师（开发者）用一张写满字的纸条（# ）封住了你的嘴。你不能用分号或者逻辑符，因为它们被拦截了。于是你用力敲了一下桌子（换行符 %0A），声音打断了所有规则，你直接喊出了“我要交卷”，老师终于把卷子（flag）递给了你。

5. 他的本质

本质是利用 Shell 的命令分隔符（换行符），截断应用层强制拼接的上下文，将原本的“参数”提升为“独立的命令”，从而执行恶意 Payload。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：不要使用字符串拼接来构造系统命令！应使用编程语言提供的安全 API（如 PHP 的 escapeshellarg），或者直接使用白名单限制用户输入。同时，WAF 应拦截反引号、换行符、;、|、& 等所有命令分隔符。
  • 破解方（红队）：如果所有分隔符都被拦截，尝试使用换行符 %0A。如果写文件也被拦截，考虑利用语言特性（如 PHP 的 include 包含文件，或利用已上传的木马）来实现读取。
