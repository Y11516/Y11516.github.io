SQLi-Labs Less-31

2026年9月28日 SQLi-Labs Web安全 SQL注入 时间盲注 / HPP

一、题目信息

  • 题目名称：SQLi-Labs Less-31 (GET - Blind - IMPIDENCE MISMATCH - Having a WAF in front of web application)
  • 题目平台：SQLi-Labs 本地靶场（Docker 环境）
  • 题目类型：Web安全 / SQL注入 / HTTP参数污染 (HPP) / 时间盲注 / 单引号括号闭合
  • 靶场链接：http://localhost:8081/Less-31/（本地环境）
  • 涉及工具：Chrome浏览器 (F12 开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是在 WAF 环境下，结合 HTTP 参数污染（HPP）与 MySQL 优化器短路特性。Less-31 是 Less-30 的变体，闭合方式为单引号加括号 ')。后端使用了 HPP 的防御逻辑，我们可以通过发送两个同名参数绕过 WAF，并触发了 MySQL 的短路特性，直接回显了数据。

2. 怎么想（破题思路）

  • 确认页面存在 WAF 防护，利用 HPP 绕过：发送 ?id=1&id=Payload。
  • 闭合符号是单引号加括号 ')，拼接后尝试构造 1') || if(1=1, sleep(3), 0) || ('1'='1。
  • 预期是触发时间延迟，但实际上 MySQL 优化器发现 id=1 命中主键，直接短路返回了结果，导致页面回显了 Dumb / 123456。
  • 这表明 HPP 绕过已经完全生效，且成功获取了数据库中的账号密码，目标达成。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：sleep 未生效，但意外回显了数据

踩坑情况：构造了 if(1=1, sleep(3), 0) 的盲注 Payload，但 F12 显示耗时仅 20ms，没有延迟，页面却回显了 Your Login name:Dumb 和 Your Password:123456。

原因分析：这是 MySQL 优化器的“短路”特性。当 id=1 命中主键索引时，数据库直接返回了该行记录，跳过了后面的 sleep(3) 执行。因为 PHP 后端配置了显示查询结果，所以我们直接看到了数据库里的数据。

改进方式：无需改进。这实际上说明 HPP 绕过 WAF 和注入均已成功，可以直接提取数据过关。

详细实操步骤（Payload逐字解释）

第一步：构造 Payload

在浏览器地址栏输入：

http://localhost:8081/Less-31/?id=1&id=1%27)%20%7C%7C%20if(1=1,sleep(3),0)%20%7C%7C%20(%271%27=%271)

第二步：Payload 逐字解析

  • ?id=1：HPP 烟雾弹，欺骗 WAF。
  • &id=1%27)：第二个参数，闭合原 SQL 的单引号和括号。
  • %20：URL 编码的空格。
  • %7C%7C：URL 编码的 ||（逻辑或）。
  • if(1=1, sleep(3), 0)：原意是制造延迟，但因为 MySQL 短路，实际未执行。
  • (%271%27=%271)：手动补齐末尾的括号和引号，替代被过滤的注释符。

第三步：验证结果

页面回显 Dumb / 123456，说明查询成功，且 HPP 绕过生效。

4. 怎么迁移（跨领域联想）

  • WAF 绕过的经典套路：HPP 是实战中常用的 WAF 绕过手段。除了 SQL 注入，它还可以用于绕过 XSS 过滤器、越权控制等。
  • MySQL 优化器短路：在 SQL 中，如果查询条件能通过索引快速定位到数据，优化器会跳过后面的复杂逻辑（如 sleep）。这在真实注入中可能导致盲注失效，需要寻找替代方案（如改用其他字段、强制全表扫描）。
  • 安全开发启示：后端应用与 WAF 必须遵循一致的安全解析标准。依赖 WAF 作为唯一防线是极其危险的，参数化查询才是根本。

三、名词大全与原理深度复盘

1. HTTP 参数污染 (HPP)

指攻击者向 HTTP 请求中注入多个同名的参数，导致不同的 Web 组件（如 WAF、PHP）在解析这些参数时取值逻辑不一致，从而引发安全漏洞。

2. 优化器短路

当数据库可以通过索引快速返回结果时，查询优化器会跳过不必要的函数执行（如 sleep()），导致盲注延迟失效。

3. 单引号加括号闭合

后端 SQL 语句为 WHERE id=('$id')，攻击者必须使用 ') 闭合。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-30 的区别：Less-30 是双引号闭合 "，Less-31 是单引号加括号闭合 ')。
  • 与 Less-29 的区别：Less-29 是报错注入（有回显），Less-31 是盲注（无回显）。

2. 这种题目的出现原因（为什么存在）

现代 Web 架构通常由 WAF、负载均衡器、Web 服务器和应用程序组成。不同的组件对 HTTP 协议的实现细节有微小差异。攻击者利用这种差异，就能让 WAF 看到的“安全内容”与后端执行的“恶意内容”分离，从而绕过防御。

3. 这种应用在实际中如何体现？

在实战中，如果发现目标使用了 WAF，渗透测试人员常尝试 HPP 绕过，比如在参数中混入重复参数。防御方应确保 WAF 和后端应用对参数的处理逻辑一致。

4. 如何抽象理解概念（大白话）

把靶场比作一个“双关卡检查站”：

  • 第一道关卡是 WAF 检查员。第二道关卡是后端 PHP 检查员。
  • 你提交了一张表格，上面写着“第一行：我的名字是张三（安全）。第二行：我的名字是李四（炸弹）”。
  • 第一道关卡只看第一行，觉得安全，放行了。
  • 第二道关卡只看最后一行，把炸弹带了进去。

做一道题，就要往自己脑子里装点东西。
