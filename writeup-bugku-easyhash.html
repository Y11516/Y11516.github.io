easy_hash - Bugku Crypto Writeup

2026年9月12日 Bugku CTF Crypto 哈希爆破

这道题名为 easy_hash，它通过提供一个批量计算单字符 MD5 的 Python 脚本和输出文件，考验了我对“单字符彩虹表反查”的理解，以及利用 Python 脚本进行批量逆向的能力。

一、题目信息

  • 题目名称：easy_hash
  • 题目平台：Bugku CTF
  • 题目类型：Crypto / MD5 单字符反查
  • 附件内容：归档.zip（包含 flag.py 和 output 文件）
  • 涉及工具：Python 脚本、Mac 终端

二、解题过程（详细步骤）

1. 阅读源码，发现规律

解压附件得到 flag.py 和 output 两个文件。阅读 flag.py 发现，它的逻辑是：把原始的 flag 字符串拆分成单个字符（chars = list(content)），然后对每一个字符分别计算 MD5，最后按顺序写入 output 文件。

2. 分析漏洞：单字符哈希的脆弱性

完整的字符串 MD5 是极难逆向的，但 单个字符的 MD5 空间非常小（包括大小写字母、数字、标点符号，总共只有 95 个可打印字符）。我们完全可以枚举所有字符的 MD5 值，建立一个“反向字典”去查询。

3. 编写脚本破解（踩坑记录）

我编写了一个 Python 脚本，生成所有可打印 ASCII 字符（32-126）的 MD5 值映射，然后逐行读取 output 文件中的哈希值，将其映射回原字符：

import hashlib

with open('output', 'r') as f:
    hashes = [line.strip() for line in f.readlines() if line.strip()]

char_map = {}
for i in range(32, 127):
    char = chr(i)
    md5_hash = hashlib.md5(char.encode()).hexdigest()
    char_map[md5_hash] = char

flag = ""
for h in hashes:
    flag += char_map.get(h, "?")
print(flag)

遇到的错误：首次运行时，报错 FileNotFoundError: [Errno 2] No such file or directory: 'output'。原因是我的 solve.py 和 output 文件不在同一个目录下（因为解压后的文件在子文件夹里）。使用 mv 命令将两者移动到同一目录后，脚本成功运行并拼接出完整的 Flag。

最终 Flag： flag{We1c0me_t0_the_w0r1d_0f_md5}

三、知识点总结（核心复习素材）

  • 1. 单字符 MD5 的脆弱性：哈希算法的安全性依赖于输入空间的庞大。如果只对单个字符进行哈希，攻击者可以使用彩虹表（预计算所有可能的哈希值）或直接暴力枚举来快速还原明文。
  • 2. 哈希的正确使用方式：真正的哈希应该作用于完整的数据段。例如，密码存储应使用加盐（Salt）后的哈希，且盐值应足够长，以增加彩虹表攻击的难度。
  • 3. Mac 终端高级操作与路径概念：实战了 cat > solve.py << 'EOF' 的 heredoc（内联重定向）技巧创建脚本。同时深刻理解了 Linux/Mac 中的相对路径与绝对路径，以及遇到 FileNotFoundError 时如何排查文件存放位置。
