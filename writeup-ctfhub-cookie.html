Cookie - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 Cookie欺骗 越权漏洞

这道题考察的是 Web 安全中非常经典的“客户端信任漏洞”。服务器仅凭浏览器发送的 Cookie 数据来判断用户身份，由于验证逻辑不严谨，导致攻击者可以通过修改本地 Cookie 实现权限提升（越权）。

一、题目信息

  • 题目名称：Cookie
  • 题目平台：CTFHub
  • 题目类型：Web / Cookie欺骗 / 越权
  • 题目提示：Cookie欺骗、认证、伪造
  • 涉及工具：浏览器开发者工具（Application 面板）
  • 最终Flag： ctfhub{...} （请填入实际获取的值）

二、解题过程

1. 寻找线索与认知误区

进入靶场，页面显示：hello guest. only admin can get flag.（你好，访客。只有管理员才能获取 flag）。

根据提示，我们需要伪装成管理员。第一反应是打开 F12 开发者工具，在 Elements（元素）面板中寻找线索，但仔细翻看 HTML 源代码后发现，里面只有简单的文本，并没有关于身份验证的隐藏字段。

原因分析：Cookie 属于浏览器的本地存储数据，每次请求时通过 HTTP Header 发送，它并不在网页的 HTML 骨架（DOM树）中，所以去 Elements 面板里找是找不到的。

2. 在 Application 面板修改 Cookie

1. 打开 F12 开发者工具，切换到 Application（应用）面板。

2. 在左侧边栏找到 Storage（存储） -> Cookies，点击展开并选中当前题目的域名。

3. 右侧表格中出现了当前 Cookie 列表。令人意外的是，并没有出现预想的 user=guest，而是发现了一条名为 admin，值为 0 的 Cookie。

逻辑分析：在计算机世界中，0 代表 False（否），1 代表 True（是）。当前服务器问“你是管理员吗？（admin=0）”，浏览器回答“不是”，所以页面显示 guest。

3. 越权成功

在右侧表格中，双击那条 Cookie 的 Value，把 0 修改为 1，按回车确认。然后回到网页按 Cmd + R 刷新页面。

重新请求时，浏览器发送了 admin=1。服务器验证通过，页面成功弹出了 Flag！

最终 Flag： ctfhub{...}

三、知识点总结（往脑子里装的东西）

  • Cookie 机制：HTTP 协议是无状态的，服务器为了记住用户身份，会将一小段数据（Cookie）下发到浏览器。浏览器在后续每次请求中都会自动携带它。
  • 客户端信任漏洞：如果服务器完全信任 Cookie 中的内容，没有进行签名或加密校验，攻击者就可以任意篡改 Cookie 的值（如把 0 改为 1），实现权限提升。
  • Application 面板：F12 开发者工具中专门用于查看和管理浏览器本地数据的面板，包括 Cookie、LocalStorage、SessionStorage 等。它不参与页面的渲染，只负责数据存储。
  • F12 开发者工具：网页的“X光机”和“控制台”。常用的面板包括：Elements（看网页骨架）、Console（跑 JS 代码）、Network（抓包看请求）、Application（看本地存储数据）。

四、踩坑记录

1. 找错面板：一开始在 Elements 面板中寻找身份验证的线索，但 Cookie 不属于页面 DOM 结构，无法在这里看到。

2. 预判失败：原以为 Cookie 键名是 user 或 role，结果发现键名是 admin，且值为数字 0。意识到出题人是用布尔值控制权限后，修改为 1 才顺利拿到 Flag。
