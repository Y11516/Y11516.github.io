DVWA-High-暴力破解 (Brute Force)

2026年10月2日 DVWA Web安全 暴力破解 Python脚本

一、题目信息

  • 题目名称：DVWA Brute Force (High)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 暴力破解 / 动态 Token 绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/brute/
  • 涉及工具：Python3 (requests库)、Google Chrome

二、解题步骤

1. 分析题目考什么

本题的核心考点是绕过 High 级别的动态 Token 防御机制进行暴力破解。与 Medium 级别不同，High 级别引入了两个核心防御：一是动态的 user_token（每次请求后都会刷新），二是强制延迟 sleep(3)。这意味着传统的 Burp Intruder 重放攻击会立刻失效，攻击者必须编写自动化脚本，动态提取 Token 并每次携带。

2. 怎么想（破题思路）

  • 在浏览器直接输入 admin / password 可以登录，但无法用 Burp Intruder 爆破，因为 Token 会变。
  • 必须使用 Python 脚本，先用 requests.get() 获取初始页面的 Token。
  • 在每次尝试密码后，无论成功与否，都要重新从响应中提取新的 Token，再带上它去尝试下一个密码。
  • 由于 sleep(3) 的存在，爆破速度会被大幅拖慢，因此字典不宜过大。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：数据库被重置导致密码不匹配

踩坑情况：脚本成功获取了 Token，但尝试了 123456、password、admin 等常见弱口令都提示失败。

原因分析：在之前的关卡测试中，误点了 Setup / Reset DB，导致数据库重置，管理员密码变成了系统随机生成的强密码，而不在简单的字典中。

改进方式：去左侧点击 Setup / Reset DB，点击 Create / Reset Database 按钮，将数据库恢复为默认状态，密码恢复为 password，再次运行脚本即可成功。

详细实操步骤（Payload逐字解释）

第一步：编写 Python 脚本

核心逻辑是使用正则表达式提取 Token：

token_match = re.search(r"name='user_token' value='(.*?)'", r.text)
if token_match:
    token = token_match.group(1)

第二步：循环爆破

在循环中，每次请求都带上最新的 token：

params = {"username": "admin", "password": pwd, "Login": "Login", "user_token": token}
r = s.get(url, params=params, timeout=5)

第三步：判断结果

如果页面包含 Welcome to the password protected area，则说明密码正确，打印并退出循环。

4. 怎么迁移（跨领域联想）

  • 护网实战：现在的企业系统几乎都加入了验证码和动态 Token。攻击者通常需要编写定制的 Python 脚本，配合 OCR 识别验证码和提取 Token，才能实现自动化爆破。这早已不是纯靠 Burp 点按钮能解决的问题了。
  • API 安全：现代 API 接口通常使用 JWT（JSON Web Token）进行认证。如果 JWT 的签名没有校验，或者包含了可预测的用户信息，攻击者就可以伪造 Token，这与动态 Token 机制的原理密切相关。

三、名词大全与原理深度复盘

1. 动态 Token (Dynamic Token)

服务器每次生成页面时都会分配一个新的随机字符串，并要求客户端在提交表单时回传。它是防御 CSRF 和自动化爆破的最有效手段之一。

2. sleep(3) 延迟防御

在密码错误时，服务器强制执行 sleep(3)，让每个请求至少耗时 3 秒。虽然不能完全阻止爆破，但能极大地增加时间成本，使得大规模字典爆破变得不可行。

3. 正则表达式 (Regex)

一种强大的字符串匹配工具。在自动化脚本中，常被用来从 HTML 页面中提取动态生成的 Token 值。

4. 多因素认证 (MFA)

彻底解决暴力破解的最佳方案。除了密码，还需要手机验证码、指纹等第二因素。即便攻击者猜中了密码，也无法登录。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何防护，可以直接用 Burp 快速爆破。Medium 级别引入了延迟机制，使得爆破效率大幅降低。
  • 与 Medium 级别的区别：Medium 级别只加了延迟，依然可以用 Burp Intruder 跑。High 级别引入了动态 Token，传统的重放攻击彻底失效，必须写自动化脚本。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者试图用“混淆”来代替“验证”。加入动态 Token 确实提高了攻击门槛，但只要 Token 是明文传递的（在 HTML 或 URL 中），攻击者就可以自动提取。真正的防御应该是加入验证码、限制 IP 频率，或者直接采用多因素认证。

3. 这种的应用

在护网中，如果遇到有动态 Token 的登录接口，攻击者通常会放弃暴力破解，转而寻找其他漏洞（如 SQL 注入、弱口令泄露等）。防御者则会利用动态 Token 和日志监控，及时发现并封禁攻击 IP。

4. 如何抽象理解概念（大白话）

把 High 级别暴力破解比作“敲门暗号”：

  • Low 级别：门卫没有暗号，你直接喊“芝麻开门”就能试，喊错了他也不管你。
  • Medium 级别：门卫要求你每喊错一次，必须等 3 分钟再喊，累死你。
  • High 级别：门卫每次都会给你一个随机的数字，你必须把这个数字和暗号一起喊出来。你只能写一个机器人，一边收数字，一边喊暗号，效率极低。这就是动态 Token 的威力。
