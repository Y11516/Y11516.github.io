请攻击这个压缩包 - Bugku MISC Writeup

2026年9月13日 Bugku CTF MISC 明文攻击 bkcrack

这道题名为“请攻击这个压缩包”，分类为 MISC。题目提示“没什么好说的，请尝试各种手段攻击我！”，附件是一个名为 file (15).zip 的加密压缩包。这是一道极其经典的**明文攻击（Known Plaintext Attack）**实战题，也是我第一次在 Mac 终端上完整跑通攻击工具链的里程碑。

一、题目信息

  • 题目名称：请攻击这个压缩包
  • 题目平台：Bugku CTF
  • 题目类型：MISC / 明文攻击 / 密码学
  • 题目描述：BugKu{}
  • 附件内容：file (15).zip（加密的 ZIP 压缩包）
  • 涉及工具：Mac 终端（Homebrew、bkcrack）

二、战前准备：在 Mac 终端搭建环境

1. 认识我们的武器：什么是 bkcrack？

在正式开始之前，必须介绍本次攻击的核心工具：bkcrack。它是一个专门针对 ZIP 压缩包传统加密算法（ZipCrypto）的破解工具。它不靠猜密码，而是利用算法漏洞和已知数据，反推出加密密钥。

2. 先安装“包管理器”：什么是 Homebrew？

Mac 系统默认没有 bkcrack，我们需要一个工具来帮我们下载和安装它。在 Mac 上，这个工具叫 Homebrew（简称 brew）。

什么是 Homebrew？ 你可以把它理解为“命令行版的 App Store”。它专门用来下载各种开源软件和开发工具，是 Mac 开发者的标配。

我打开 Mac 终端，尝试输入 brew install bkcrack，结果报错：

zsh: command not found: brew

报错解释： zsh 是 Mac 终端的解释器，它告诉我“找不到 brew 这个命令”。这说明我还没安装 Homebrew。

3. 安装 Homebrew（过程详解）

我在终端复制粘贴了 Homebrew 官方的安装脚本：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

命令详解：

  • /bin/bash -c：告诉系统用 bash 环境来执行后面的命令。
  • curl -fsSL：curl 是一个下载工具，这里用来下载安装脚本。它会在后台帮你访问那个 GitHub 链接，把脚本内容下载下来。
  • $(...)：这是一个“命令替换”语法。它会先执行括号里的 curl 命令下载脚本，然后把下载到的内容直接交给 bash 执行。

踩坑记录： 运行后，终端提示 Password:。我尝试输入密码，但发现屏幕没有任何变化。这是因为 Mac 终端出于安全考虑，在输入密码时**开启了“盲打模式”**。你只需要盲打输入你的开机密码，然后按回车即可。

等待几分钟下载后，终端出现了 Installation successful!，Homebrew 安装成功。

4. 配置环境变量（极其重要的一步）

安装完 Homebrew 后，它通常会提示你运行两行命令来配置环境变量（类似 echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile）。

名词解释：什么是环境变量？ 它是一个“指路牌”。Mac 系统默认不知道 Homebrew 被安装在哪个文件夹里，我们需要把 Homebrew 的安装路径写进系统配置里，这样你在终端敲 brew 时，系统才知道去哪里找它。我复制并运行了这两行命令。

5. 安装 bkcrack

新开一个终端，输入：

brew install bkcrack

终端开始下载并安装，最后出现 Pouring bkcrack--1.8.1...tar.gz，说明我们的武器正式就位！

三、正式攻击：明文攻击（Known Plaintext Attack）

1. 什么是明文攻击？为什么不需要密码？

在开始敲命令前，我们得先搞懂明文攻击。ZIP 压缩包的传统加密算法叫 ZipCrypto。它有一个致命的弱点：**如果你知道压缩包里面某个文件的一小部分原始内容，就可以利用算法漏洞推算出解密密钥，从而解开整个压缩包。**

逻辑： 我们不需要去猜密码（这是暴力破解）。我们是拿着已知的一部分明文，去反推加密的密钥。

2. 构造已知明文：为什么是那串奇怪的十六进制？

这道题压缩包里有一个 flag.png。无论什么 PNG 图片，它的文件头（前 12 个字节）永远是固定的：

89 50 4E 47 0D 0A 1A 0A 00 00 00 0D 49 48 44 52

这就是我们手里的“已知明文”。我们只需把这个特征告诉 bkcrack，它就能利用这个特征去攻击压缩包。

3. 执行攻击命令

在终端输入以下命令（注意，因为文件名有空格，必须用引号括起来）：

bkcrack -C "file (15).zip" -c flag.png -x 0 89504e470d0a1a0a0000000d49484452

命令参数拆解：

  • -C "file (15).zip"：指定要攻击的压缩包。
  • -c flag.png：指定压缩包内的目标文件。
  • -x 0 89504e...4452：告诉工具已知明文的位置（0 偏移量）和具体内容（那串 PNG 文件头十六进制）。

回车后，终端开始疯狂计算（这叫“Z reduction”和“Attack on Z values”）。这个过程可能需要几分钟到十几分钟，取决于电脑性能。

最终，终端输出了成功的密钥：

Keys: 92802c24 9955f8d6 65c652b8

四、解密文件与最终提取

1. 使用密钥解密数据流

拿到了三组密钥，我们就能直接解密文件了：

bkcrack -C "file (15).zip" -c flag.png -k 92802c24 9955f8d6 65c652b8 -d decrypted.bin

参数解释：

  • -k：指定我们刚才算出来的三组密钥。
  • -d decrypted.bin：将解密后的原始数据流输出到 decrypted.bin 文件中。

运行成功后，终端提示 Writing deciphered data decrypted.bin。

关键知识点： bkcrack 解密出来的**不是**一个完整的 ZIP 包，而是**原始文件的数据流**（没有 ZIP 目录结构）。所以这个 decrypted.bin 本身就是 flag.png 的原始数据。

2. 恢复文件名并查看 Flag

我们需要把后缀名改成图片格式，并打开它：

mv decrypted.bin flag.png
open flag.png

命令解释：

  • mv：Move 的缩写，在这里用于重命名文件。把 decrypted.bin 重命名为 flag.png。
  • open：Mac 特有的命令，用默认软件打开文件，这里会自动用图片查看器打开。

图片打开后，上面清晰地写着一行字，这就是最终 Flag：

最终 Flag： BugKu{不是非得两个文件你才能明文攻击}

五、超详细名词库与原理复盘

1. 终端（Terminal）

Mac 上的“终端”是一个窗口，让你通过输入文字命令（而不是点击鼠标）来控制电脑。它是安全从业者的核心武器。

2. zsh / bash

它们都是“Shell（壳）”，是终端里的“翻译官”。你输入的命令，会先被 zsh 或 bash 解析，然后再交给系统底层去执行。

3. Homebrew (brew)

Mac 的包管理器。就像手机的应用商店，你可以用它一键下载各种工具（如 bkcrack）。

4. bkcrack

专门针对 ZIP 传统加密算法（ZipCrypto）的破解工具。它支持“明文攻击”。

5. ZipCrypto

ZIP 压缩包的传统加密算法。它的安全性远低于现代的 AES-256 加密，存在明文攻击漏洞。

6. 明文攻击（Known Plaintext Attack）

一种攻击方式。攻击者不需要知道密码，只需要知道目标文件中的一部分原始数据（比如 PNG 文件头），就能反推出加密密钥。

7. 十六进制（Hex）

用 0-9 和 A-F 表示数据的方式。因为二进制太长，计算机领域常用十六进制来方便阅读。例如 PNG 的头是 89 50 4E 47，对应 ASCII 字符 PNG。

8. 环境变量（PATH）

系统里的“指路牌”。它告诉终端去哪里寻找你敲的命令。安装 Homebrew 后要配置 PATH，就是为了让终端能找到它。

9. 数据流（Data Stream）

连续的二进制数据。在这里指解密出来的原始文件内容，不含 ZIP 的压缩包结构（比如文件列表、校验码等）。

10. 为什么这道题能成功？（原理复盘）

这道题能成功的核心逻辑是：PNG 格式是公开且固定的。 我们百分之百确定压缩包里的图片是一张 PNG，百分之百确定它的前 12 个字节就是那串固定的十六进制。所以我们可以把这个确定性交给 bkcrack，让它利用算法的数学漏洞，反向推导出加密密钥。这是密码学攻击中“利用已知信息”的经典体现。

11. 防御方法（现实开发中的启示）

在现实的软件开发中，绝对不要使用 ZipCrypto 这种老旧的加密算法来保护敏感数据。应该使用支持 AES-256 加密的压缩软件（如 7-Zip），或者使用专门的加密工具。同时，永远不要在不安全的渠道泄露明文和密文的对应关系。
