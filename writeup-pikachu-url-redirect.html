URL重定向 - Pikachu Writeup

2026年9月20日 Pikachu Web安全 URL重定向

一、题目信息

  • 题目名称：URL重定向（不安全的URL跳转）
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 开放重定向漏洞（Open Redirect） / 逻辑漏洞
  • 靶场链接：http://localhost:8080/vul/urlredirect/urlredirect.php
  • 涉及工具：浏览器（Chrome/Firefox）、开发者工具（F12）

二、解题步骤

1. 分析题目考什么

本题的核心考点是URL重定向漏洞（Open Redirect）。后端提供了一组“性格测试”链接，点击后会通过 URL 参数跳转到对应页面。如果后端没有对跳转的目标 URL 进行白名单校验，攻击者就可以篡改 URL 参数，将用户重定向到外部的恶意钓鱼网站。

2. 怎么想（破题思路）

页面展示了几段鸡汤文字，并提示“我想问一下,你到底是在下面哪一种类型的人:”。解题思路如下：

  • 点击页面上的“像春天的花一样的少年”链接。
  • 观察浏览器地址栏，发现变成了 urlredirect.php?url=http://www.baidu.com（或类似外部地址）。
  • 参数 url 直接控制了跳转目标。尝试修改该参数为任意恶意地址（如 http://www.evil.com），观察是否成功跳转。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接修改参数被后端拦截

踩坑情况：将 url 参数改为 http://www.evil.com 后，页面没有跳转，或者提示“只允许跳转百度”。

原因分析：后端可能引入了简单的字符串过滤，例如检测参数里是否包含 baidu.com。如果包含，就执行跳转；如果不包含，就拒绝。

改进方式：使用 URL 解析绕过。比如利用 @ 符号：http://www.baidu.com@www.evil.com。浏览器会解析为：用户名是 www.baidu.com，真实域名是 www.evil.com，从而绕过对 baidu.com 的检测。

终极解法：篡改 url 参数实现任意跳转

点击链接后，在浏览器地址栏输入以下 URL：

http://localhost:8080/vul/urlredirect/urlredirect.php?url=http://www.evil.com

代码逐个符号深度解析：

  • urlredirect.php?：触发 URL 重定向漏洞的后端脚本。
  • url=：后端用于接收跳转目标的参数名。
  • http://：指定使用 HTTP 协议。攻击者也可以尝试使用 https:// 或 //evil.com（省略协议）。
  • www.evil.com：攻击者预设的钓鱼网站地址。当受害者点击链接时，浏览器会被重定向到该恶意站点。

提交后，浏览器成功跳转到外部恶意网站，证明 URL 重定向漏洞利用成功。

4. 怎么迁移（跨领域联想）

  • 钓鱼攻击（Phishing）：在真实攻击中，攻击者会伪造一个和原网站一模一样的登录页。通过发送带有目标网站真实域名的跳转链接（如 http://trusted.com/redirect?url=http://evil.com），诱导用户点击，从而窃取用户的账号密码。
  • OAuth 授权劫持：在 OAuth 2.0 授权流程中，如果 redirect_uri 参数未做严格校验，攻击者可以将授权码重定向到自己的服务器，从而劫持用户的登录令牌（Token）。
  • 代码审计与安全开发：修复该漏洞的核心是使用白名单机制，或者将参数转为数字 ID（如 ?id=1），后端通过 ID 映射到具体的 URL。绝对不能信任用户传入的 URL 路径。

三、名词大全与原理深度复盘

1. 开放重定向（Open Redirect）

指 Web 应用允许通过 URL 参数将用户重定向到任意指定的 URL。由于 URL 以目标网站的合法域名开头，用户容易放松警惕。攻击者常利用此漏洞进行钓鱼、窃取凭证或绕过安全控制。

2. URL 解析绕过手法

如果后端有简单的过滤，常见的绕过手法包括：

  • @ 符号：http://trusted.com@evil.com（浏览器解析真实域名为 evil.com）。
  • 双斜杠 //：//evil.com（继承当前协议）。
  • 反斜杠 \\：http://evil.com\trusted.com。
  • URL 编码：将 http 编码为 %68%74%74%70。

3. 与 SSRF 的区别

SSRF（服务端请求伪造）是服务器根据用户输入去发起网络请求；URL 重定向是服务器让用户的浏览器去跳转。一个是服务端行为，一个是客户端行为。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 XSS 相比：XSS 是让用户的浏览器执行恶意 JavaScript 代码；URL 重定向是将用户导向一个完全不同的网站，不执行代码，属于逻辑漏洞。
  • 与 CSRF 相比：CSRF 是伪造用户的身份发起请求；URL 重定向是利用用户的信任，诱使其主动点击。两者都利用用户信任，但攻击方式不同。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者在实现“登录后跳回原页面”、“点击外部链接”等功能时，为了图方便，直接将用户传入的 URL 参数用于 header('Location: ' . $_GET['url']) 或前端跳转，而没有校验该 URL 是否属于本站。

3. 这种应用在实际中如何体现？

在实际的安全测试中，URL 重定向本身危害有限，但常被作为攻击链的起点。攻击者可以利用它绕过目标网站的安全验证，将恶意链接伪装成合法域名发送给受害者，极大提高了钓鱼攻击的成功率。

4. 如何抽象理解概念（大白话理解）

如果把公司比作一个系统：

  • 正常功能：你在公司前台问：“去百度怎么走？”前台指给你正确的路。
  • URL重定向漏洞：你问前台：“去某某骗子网站怎么走？”前台没检查目的地，直接给你指路，把你引导到了那个骗子网站。这就叫开放重定向——前台不检查你要去的地方安不安全，盲目把你送过去。
