CTFHub RCE - eval执行

2026年9月21日 CTFHub Web安全 RCE 代码执行

一、题目信息

  • 题目名称：eval执行
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / RCE（远程代码执行） / PHP代码注入
  • 靶场链接：http://challenge-ecadfe415b33210d.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器（仅此而已）

二、解题步骤

1. 分析题目考什么

本题的核心考点是PHP代码执行漏洞（RCE）。页面直接给出了源码，其中使用了 PHP 的 eval() 函数。由于 eval() 会将传入的字符串当作 PHP 代码执行，且没有过滤参数，攻击者只需通过 URL 传入恶意的 PHP 代码，即可直接控制服务器。

2. 怎么想（破题思路）

  • 直接看页面源码，识别出 eval($_REQUEST['cmd'])。这等于服务器提供了一个“万能执行器”。
  • 注意：eval() 执行的是 PHP 代码，所以不能直接传 `ls`，必须传符合 PHP 语法的语句，比如 system('ls');。
  • 利用 system() 函数执行系统命令，先 ls / 找到 Flag 文件名，再 cat 读取它。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：直接传系统命令导致报错

踩坑情况：在 URL 后面尝试拼接 ?cmd=ls，页面报错或毫无反应。

原因分析：eval() 会把 ls 当作 PHP 代码来解析，但 ls 在 PHP 中只是一个未定义的常量，没有加函数调用，也不是合法的 PHP 语句。

改进方式：必须将系统命令包裹在 PHP 可执行函数中，并加上分号结束，也就是 ?cmd=system('ls');。

踩坑记录二：特殊字符被 WAF 过滤

踩坑情况：当执行 cat /flag_27379 时，页面报错或者没有回显。

原因分析：某些环境下，Web 应用防火墙（WAF）可能会过滤目录分隔符 / 或者空格。

改进方式：可以使用 URL 编码 %2f 代替斜杠（在某些PHP版本中会自动解码执行），或者使用环境变量 ${IFS} 代替空格。

详细实操步骤

第一步：分析漏洞源码

页面直接给出了源码：

<?php
if (isset($_REQUEST['cmd'])) {
    eval($_REQUEST['cmd']);
} else {
    highlight_file(__FILE__);
}
?>

代码逐字深度解析：

  • $_REQUEST：PHP 超全局变量，包含了 $_GET、$_POST 和 $_COOKIE 的数据。这意味着无论用 GET 还是 POST 都能传参。
  • isset()：判断变量是否存在。如果 URL 中存在 cmd 参数，则执行 eval()。
  • eval()：PHP 内置函数，把字符串当作 PHP 代码执行。这是本题漏洞的根源。
  • highlight_file(__FILE__)：高亮显示当前文件内容（即我们看到源码的原因）。

第二步：探测根目录

在浏览器地址栏访问：

http://challenge-ecadfe415b33210d.sandbox.ctfhub.com:10800/?cmd=system('ls /');

回显列出了根目录文件，发现目标 flag_27379。

第三步：读取 Flag

访问：

http://challenge-ecadfe415b33210d.sandbox.ctfhub.com:10800/?cmd=system('cat /flag_27379');

页面成功回显 ctfhub{1d695f32bfd22ae90336050d}。

4. 怎么迁移（跨领域联想）

  • 真实渗透测试中的 Webshell 利用：在实战中，如果发现 RCE 漏洞，攻击者通常会利用 eval() 或 assert() 写入一个一句话木马，然后使用中国蚁剑或冰蝎等工具进行连接，获取更稳定的交互式 Shell。
  • 代码审计：审计 PHP 代码时，看到 eval()、assert()、preg_replace()（带 /e 修饰符）、call_user_func() 等函数时，必须高度警惕，检查参数是否用户可控。
  • WAF 绕过技术：当 RCE 被 WAF 拦截时，需要掌握各种绕过技巧，如利用 PHP 反引号执行命令 `ls`、使用 ${IFS} 绕过空格、使用通配符 * 或环境变量截取绕过关键字过滤。

三、名词大全与原理深度复盘

1. RCE（远程代码执行 / Remote Code Execution）

RCE 是 Web 安全中危害最高的漏洞之一。它分为“代码执行”和“命令执行”。本题属于代码执行，因为注入的是 PHP 代码，通过 PHP 代码再调用系统命令。如果攻击者能够 RCE，就等于完全控制了服务器。

2. eval() 与 system() 的本质区别

eval() 属于 PHP 语言结构，执行的是 PHP 代码。例如 eval("echo 1+1;") 输出 2。system() 是 PHP 内置函数，执行的是操作系统命令。例如 system("ls") 列出目录。本题中，eval 是入口，system 是我们在 PHP 里调用的工具。

3. 为什么必须加分号？

在 PHP 中，分号 ; 是语句结束的标志。没有分号的 PHP 代码会报语法错误。传入 ?cmd=phpinfo() 时，PHP 会认为这是一个未闭合的表达式；而 ?cmd=phpinfo(); 才是合法的 PHP 语句。

三、新手高频概念深度答疑（补充篇）

1. `?cmd=system('ls /');` 这一段是什么意思？`ls` 是在干什么？

这串 URL 分为三个部分：

  • ?cmd=：传给服务器的参数名。服务器代码里写着 eval($_REQUEST['cmd'])，所以它通过 cmd 接收你发的东西。
  • system(...)：这是一个 PHP 函数。它的作用是“把括号里的字符串，当成电脑系统的命令去执行”。
  • 'ls /'：这是真正被执行的系统命令。ls 是 Linux 系统里的“list（列出）”命令，意思是看看当前目录下有什么文件。后面的 / 是指“根目录”。

整体意思：你告诉服务器：“请把你（服务器）根目录下的所有文件名，列出来给我看看。”这就好比你在对服务器下命令，让它给你展示地图。

2. `cat` 是捕捉的意思吗？

完全不是！这是一个非常典型的“望文生义”的误区。

在 Linux 系统里，cat 是 concatenate（连接/拼接） 的缩写。它的实际功能是：把文件里的内容直接输出（打印）到屏幕上。

你之前做文件上传时用它 cat /flag，意思是“把根目录下 flag 文件的内容，读出来给我看”。为什么要用 `cat` 来“读”文件？因为在 Linux 命令行里，你不能双击打开文件，只能用 `cat`（看全文件）、`head`（看头部）、`tail`（看尾部）这些命令来阅读文本。

3. WAF 绕过技术是什么？

WAF（Web Application Firewall），中文叫“Web应用防火墙”。你可以把它想象成大楼门口极其严格的安检员。它会检查你发给服务器的每一个字符，一旦发现“危险词汇”（比如 cat、/、空格、system），直接把你拦在门外。

WAF 绕过技术，就是研究怎么伪装、变造你的攻击指令，骗过这个安检员。你在截图里学到的：

  • 安检员不让你用空格？你用环境变量 ${IFS} 代替（它就相当于一个空格）。
  • 安检员不让你用斜杠 /？你用 cd 进入目录，或者用 URL 编码 %2f 代替。
  • 安检员不让你用 cat？你用 tac、nl、sort 甚至 base64 代替。

把危险的东西拆散了、变个形带进去，这就是绕过。

4. 代码执行 和 命令执行 有什么区别？

这是安全圈极其核心的一对概念，截图里提到了。

  • 代码执行（Code Execution）：你注入的是一段编程语言代码。比如你这题注入的是 system('ls');，这是合法的 PHP 代码。服务器上的 eval() 函数把你的字符串当成 PHP 代码运行。漏洞在“编程语言层”。
  • 命令执行（Command Execution）：你注入的是操作系统的原生命令。比如服务器代码写着 $cmd = "ping -c 4 " . $_GET['ip']。你输入 127.0.0.1; ls，服务器拼凑出 ping -c 4 127.0.0.1; ls，然后直接交给了 Linux 系统去执行。漏洞在“操作系统层”。

大白话：代码执行是“你给翻译官写了一张外语纸条”，翻译官读懂后照做；命令执行是“你直接对着大喇叭喊了一句本地话”，系统直接照做。

5. PHP 是编程语言吗？

是的，PHP 是一种专门用于开发网站的“服务器端编程语言”。

它的地位和 Python、Java、Go 类似。只不过它专门为 Web 而生。你写的 <?php system('ls'); ?> 就是一段 PHP 代码。服务器收到这个文件后，会交给 PHP 引擎（解析器）去“读懂并执行”。所以，理解 PHP 的语法（比如末尾要加分号 ;），是看懂这些漏洞的基础。

6. 数据库 和 服务器操作系统 有什么区别？

这俩经常被混淆，你可以用“开公司”来比喻：

  • 服务器操作系统（OS）：比如 Linux（Ubuntu, Debian）。它是大楼的地基、水电煤和保安系统。它管理 CPU、内存、硬盘、网络。你做的 RCE 漏洞，最终拿到的就是操作系统的权限（相当于你成了这栋大楼的保安队长）。
  • 数据库（Database）：比如 MySQL、Redis。它是大楼里的档案柜。软件不能把数据直接写在砖墙上，必须存进档案柜。
  • 关系：数据库是安装在操作系统上的一个软件。如果你拿到了操作系统的权限（RCE），你就可以直接暴力拆开档案柜（读数据库文件）。如果你只拿到了数据库权限（SQL注入），你就只能翻看档案柜里的资料，摸不到大楼的电力系统。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“文件上传”的区别：文件上传是“把刀送进厨房”，需要绕过各种检查并把刀藏在厨房里才能用；而 eval 执行是“厨房直接把刀递给你，让你随便用”，无需任何迂回，直接执行代码。
  • 与 SQL 注入的区别：SQL 注入是攻击数据库，通过拼接 SQL 语句获取数据；而 RCE 是直接攻击服务器操作系统，可以执行任意系统命令，权限更高，危害更大。

2. 这种题目的出现原因

这类漏洞大多源于开发者的“图方便”。在一些需要动态执行代码的场景中（如模板引擎、插件系统、在线代码执行器），开发者直接使用了 eval() 来处理用户输入，却没有做任何过滤。这就把 PHP 最危险的功能暴露给了攻击者。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，一旦发现 RCE 漏洞，攻击者可以：

  • 读取敏感文件（如数据库配置文件、密钥）。
  • 写入 WebShell，获取稳定的服务器控制权。
  • 进行内网横向移动，控制更多机器。

4. 如何抽象理解概念（大白话理解）

把网站服务器比作一个机器人：

  • 普通用户：只能按机器人的按钮，让它做预设好的动作。
  • 代码执行漏洞（eval）：机器人内部有一个后门，允许你直接在它的中央处理器里写入指令。
  • 传参：你不需要绕弯子，直接对着麦克风喊：“去把那个叫 flag 的文件内容读出来！”（`system('cat /flag');`）。机器人就会乖乖照做。
  • 分号：这是机器人听的“命令结束语”。不加分号，机器人不知道你说完了没有，就会一直傻等（报错）。

做一道题，就要往自己脑子里装点东西。
