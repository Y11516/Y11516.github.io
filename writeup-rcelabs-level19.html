RCE-Labs Level 19 - cp 命令复制文件外带

2026年10月5日 RCE-Labs 黑名单绕过 文件外带

一、题目信息

  • 1.题目名称：RCE-Labs Level 19 (cp 命令复制文件外带)
  • 2.题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 3.题目类型：Web安全 / 远程代码执行 (RCE) / 黑名单绕过 / 文件操作
  • 4.靶场链接：http://靶机IP:8080/less-19/
  • 5.涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

黑名单封禁了 find。此时所有读取、搜索、执行命令的捷径都被封死。这关考察的是利用文件操作命令（cp）进行文件外带。思路是：既然我读不了，我就把它搬到你能访问的地方去。

2. 怎么想（破题思路）

既然所有的查看、读取、编码命令都被拦截了，我们无法直接在页面回显内容。但是，Web 服务器有一个特性：/var/www/html 是网站的根目录，放在这里的文件可以通过 HTTP 协议被浏览器直接访问。如果我们能把 /flag “搬运”到这个目录下，就能通过浏览器直接读取了。cp 命令正是负责复制文件的工具。

3. 怎么解（详细步骤与逐字翻译）

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与逐字解析

?cmd=cp /flag /var/www/html/less-19/1.txt

命令逐字解析：

  • cp：copy 的缩写，用于复制文件或目录。
  • /flag：源文件路径，即我们要窃取的目标文件。
  • /var/www/html/less-19/1.txt：目标文件路径。将其复制到 Web 根目录下，并命名为 1.txt。

操作流程：

  • 第一步：执行复制。执行上述 Payload。页面没有回显，这是因为 cp 默认静默执行。
  • 第二步：访问文件。在浏览器中访问 http://靶机IP:8080/less-19/1.txt。
  • 成功响应：浏览器直接显示明文 flag{TEST_Dynamic_FLAG}。

踩坑记录：为什么命令执行后显示空白？

情况：输入 cp 命令后，页面没有任何变化，也没看到 flag。

原因：Linux 的哲学是“没有消息就是好消息”。cp、mv、rm 等文件操作命令默认不产生标准输出（stdout）。只有失败时才会报错。所以不能用“有没有回显”来判断这些命令是否成功，而应该去验证文件是否被真的复制过去了。

改进：可以通过 ls -la /var/www/html/less-19/ 验证文件是否被创建，或者直接尝试访问 Web 路径来验证。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的 WebShell 写入：拿到 RCE 后，最常见的操作是用 cp 将恶意文件复制到 Web 目录，或者写一个 shell.php 进去，从而获得一个稳定的图形化/命令行控制面板。
  • 供应链攻击与数据泄露：攻击者在窃取数据库后，往往不会直接打印出来（数据量太大），而是将其打包复制到临时目录，再通过 wget 或 curl 外带出去。

三、名词大全与原理深度复盘

1. cp 命令详细介绍

cp（copy）用于复制文件或目录，是 Linux 中最基础的文件操作命令之一。

  • 核心参数 -r：递归复制目录（复制整个文件夹时必加）。
  • 核心参数 -p：保留源文件的属性（权限、所有者、时间戳）。
  • 核心参数 -f：强制覆盖，不提示。
  • 核心参数 -v：显示复制过程的详细信息（在 RCE 中一般不用，因为它会产生回显）。

2. 底层原理：系统调用与内核态

cp 命令底层调用 open() 打开源文件，调用 read() 读取数据到内存缓冲区，然后再调用 open() 创建/打开目标文件，最后调用 write() 将数据写入。整个过程属于操作系统的内核态文件读写操作，不经过标准输出（stdout），因此没有回显。

3. 核心名词解释（陌生人也能看懂版）

  • 绝对路径：从根目录 / 开始的完整路径，如 /var/www/html/less-19/1.txt。无论当前在哪个目录，都能准确指向该文件。
  • 相对路径：相对于当前工作目录的路径，如 1.txt。由于当前工作目录是 /var/www/html/less-19，因此相对路径也能成功。
  • Web 根目录 (Web Root)：Web 服务器配置的文档根目录，通常是 /var/www/html。位于该目录下的文件可以通过 HTTP 协议被外部直接访问。
  • 文件外带 (Data Exfiltration)：指攻击者将目标系统中的数据通过某种通道（HTTP、DNS、ICMP）传输到外部受控服务器的过程。
  • 标准输出 (stdout) 与 标准错误 (stderr)：Linux 进程默认的输入和输出通道。cp 成功时无输出（stdout 为空），失败时输出错误信息（stderr）。

四、题目思考

1. 这跟前面关卡的区别

前面所有关卡都属于“原地读取”，在服务器端读取然后在服务器端回显。而 Level 19 实现了“异地读取”，先把数据搬运到一个我们随时可以访问的公开 Web 目录，然后再通过 HTTP 拿回来。这是文件外带的入门版。

2. 这种题目的出现原因（底层逻辑与历史原因）

在 Web 开发中，开发人员经常需要对文件进行备份、移动或复制操作。如果对用户输入过滤不严，将系统命令与用户输入拼接，就会导致命令注入。黑名单机制只能封禁已知的“读取”命令（如 `cat`），但无法封禁所有“文件操作”命令（如 `cp`）。这种“功能重叠”是黑名单机制天然存在的漏洞。

3. 这种漏洞在实际中的应用

在护网和真实攻防中，攻击者拿到 RCE 后，通常不会试图直接通过页面回显大文件内容。他们会将敏感文件（如数据库配置、密码文件）复制到 Web 目录下，然后通过下载工具（如 `wget`、`curl`）打包下载，或者使用 `cp` 在服务器内部进行横向移动和权限维持。

4. 如何抽象理解概念（大白话）

把读取文件比作“去保险柜拿金条”。前面的关卡是尝试各种工具（cat、nl、sed）撬开保险柜。而 Level 19 的 cp 是：既然保险柜不能直接打开，那我就干脆把整个保险柜搬到你家客厅（Web 目录），然后你大摇大摆地走进客厅拿走金条（访问 1.txt）。这就是数据外带最朴素的思想。

5. 他的本质

本质是利用文件系统的基本操作（复制），绕过了应用层对“读取”命令的拦截，并通过 Web 服务器的静态资源解析机制，实现数据的间接读取和外带。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：严格限制 Web 进程的文件系统权限，确保 Web 用户无法读取敏感文件（如 /flag），同时也无法写入 Web 根目录。在代码层面，严禁将用户输入拼接进系统命令，使用白名单限制命令参数。
  • 破解方（红队）：如果 cp 被拦截，可以尝试使用 mv（重命名）、ln（创建硬链接/软链接）、或者利用 tar 打包后再下载。如果这些都被拦截，可以考虑使用语言特性（如 PHP 的 copy() 函数、Python 的 shutil.copy()）来实现文件复制。
