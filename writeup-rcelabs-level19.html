RCE-Labs Level 19 - cp 命令复制文件外带

2026年10月3日 RCE-Labs 黑名单绕过 文件外带

一、题目信息

  • 题目名称：RCE-Labs Level 19 (cp 命令复制文件)
  • 靶场链接：http://靶机IP:8080/less-19/
  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

黑名单封禁了 find。此时所有读取、搜索、执行命令的捷径都被封死。这关考察的是利用文件操作命令（cp）进行文件外带。思路是：既然我读不了，我就把它搬到你能访问的地方去。

2. 怎么解（详细步骤与输出解析）

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

最终成功 Payload 与操作流程

第一步：利用 cp 命令复制文件

?cmd=cp /flag /var/www/html/less-19/1.txt

成功解析：执行后页面只显示了源码，没有回显 Flag。这是正常的！因为 cp 命令默认是静默执行的，没有输出就是成功。如果报错（如权限不足），则会输出错误信息。

第二步：通过 HTTP 协议访问复制出的文件

在浏览器地址栏输入：http://靶机IP:8080/less-19/1.txt

成功响应：浏览器直接显示出明文 flag{TEST_Dynamic_FLAG}。因为 Web 服务器会将 /var/www/html 目录映射为网站的根目录，文件放进去就能被外部访问。

踩坑记录：为什么命令执行后显示空白？

情况：输入 cp 命令后，页面没有任何变化，也没看到 flag。

原因：Linux 的哲学是“没有消息就是好消息”。cp、mv、rm 等文件操作命令默认不产生标准输出。只有失败时才会报错。所以不能用“有没有回显”来判断这些命令是否成功，而应该去验证文件是否被真的复制过去了。

改进：可以通过 ls -la /var/www/html/less-19/ 验证文件是否被创建，或者直接尝试访问 Web 路径。

3. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的 WebShell 写入：拿到 RCE 后，最常见的操作是用 echo "<?php eval(\$_POST[1]);?>" > shell.php 或 cp 将恶意文件复制到 Web 目录，然后通过浏览器访问该 shell，从而获得一个稳定的图形化/命令行控制面板。
  • 供应链攻击与数据泄露：攻击者在窃取数据库后，往往不会直接打印出来（数据量太大），而是将其打包（tar）复制到临时目录，再通过 wget 或 curl 外带出去。

三、名词大全与原理深度复盘

1. cp 命令的底层机制

cp（copy）命令底层调用 open() 打开源文件，调用 read() 读取数据到内存缓冲区，然后再调用 open() 创建/打开目标文件，最后调用 write() 将数据写入。整个过程属于操作系统的内核态文件读写操作，不经过标准输出（stdout），因此没有回显。

2. 文件外带 (Data Exfiltration)

指攻击者将目标系统中的数据通过某种通道（HTTP、DNS、ICMP）传输到外部受控服务器的过程。这里我们利用了 Web 服务器的静态文件解析特性，通过 HTTP 通道将 flag 成功“带”了出来。

3. 绝对路径 vs 相对路径

  • 绝对路径：从根目录 / 开始写，如 /var/www/html/less-19/1.txt。无论当前在哪里都能准确指向该文件。
  • 相对路径：相对于当前工作目录，如 1.txt。由于当前工作目录是 /var/www/html/less-19，因此相对路径也能成功。在实际利用中，绝对路径比相对路径更稳妥。

四、题目思考

1. 这跟前面关卡的区别

前面所有关卡都属于“原地读取”，在服务器端读取然后在服务器端回显。而 Level 19 实现了“异地读取”，先把数据搬运到一个我们随时可以访问的公开 Web 目录，然后再通过 HTTP 拿回来。这是文件外带的入门版。

2. 如何抽象理解概念（大白话）

把读取文件比作“去保险柜拿金条”。前面的关卡是尝试各种工具（cat、nl、sed）撬开保险柜。而 Level 19 的 `cp` 是：既然保险柜不能直接打开，那我就干脆把整个保险柜搬到你家客厅（Web 目录），然后你大摇大摆地走进客厅拿走金条（访问 1.txt）。这就是数据外带最朴素的思想。
