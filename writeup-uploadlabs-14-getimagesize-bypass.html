Upload-Labs Pass-14

2026年9月27日 Upload-Labs Web安全 文件上传 图片马

一、题目信息

  • 题目名称：Upload-Labs Pass-14 (getimagesize() 图片马绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 文件头伪造 / 图片马
  • 靶场链接：http://localhost:8082/Pass-14/index.php（本地环境）
  • 涉及工具：Mac 终端（Terminal）、Python（可选）

二、解题步骤

1. 分析题目考什么

本题的核心考点依然是文件头检测（getimagesize）绕过，与 Pass-13 原理相同。但 Pass-14 要求更严格：必须上传包含完整 WebShell 代码的 .jpg、.png、.gif 三种格式的图片马，全部成功才算通关。

2. 怎么想（破题思路）

  • 直接上传纯 PHP 文件会被 getimagesize() 拦截。
  • 使用之前 Pass-13 的方法生成 GIF 和 PNG 图片马，通常容易成功。
  • 遇到 JPG 失败时，排查原因是 Mac 终端 printf 转义问题或 JPG 文件头（JFIF 结构）不完整。
  • 最终改用“将木马追加到真实图片末尾”的物理方法，100% 绕过。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Mac 终端生成 JPG 文件头失败

踩坑情况：使用 printf '\xFF\xD8\xFF...' > shell.jpg 命令生成的 JPG 文件上传后被拒绝。

原因分析：Mac 的 zsh 对十六进制转义（\xFF）支持不完善，可能把反斜杠当成了普通字符。此外，getimagesize() 对 JPG 的解析比 GIF/PNG 严格得多，仅仅有 FF D8 FF 开头往往不够，需要完整的 JFIF 结构。

改进方式：改用“在真实图片末尾追加 PHP 代码”的物理方法，或者使用 Python 脚本写入完整的 JFIF 头。

详细实操步骤（Payload逐字解释）

第一步：生成 GIF 和 PNG 图片马（复用 Pass-13 方案）

在 Mac 终端依次输入以下命令：

echo -e "GIF89a" > shell.gif
printf '\x89PNG\r\n\x1a\n' > shell.png

第二步：生成 JPG 图片马（物理追加法，100%成功）

在桌面找一张真实的 JPG 图片，重命名为 real.jpg，在终端执行：

echo "" >> real.jpg

逐字解析：

  • >>：追加写入符号（不覆盖原内容）。
  • 原理：保持图片原有结构合法（能通过 getimagesize 检测），在文件末尾追加木马代码。

第三步：上传并验证

回到靶场页面，按 F12 覆盖前端 JS：checkFile = function() { return true; }。依次上传 shell.gif、real.jpg、shell.png，全部提示“上传成功”即通关。

4. 怎么迁移（跨领域联想）

  • 文件签名与结构校验：JPG 的校验比 GIF/PNG 严格，说明不同文件格式的解析器容忍度不同。安全开发中，不能只依赖文件头检测，因为攻击者可以通过物理拼接绕过。
  • 真实图片+追加木马：这是最经典的图片马制作方式。在实战中，攻击者甚至会用“图种”（将 RAR/ ZIP 文件追加到图片后），这也是利用了文件结构末尾可被追加的特性。
  • 文件包含漏洞（LFI）是灵魂：图片马必须配合 LFI 漏洞才能触发执行。单纯的上传无法造成 RCE，这体现了“攻击链”的思维。

三、名词大全与原理深度复盘

1. getimagesize() 函数

PHP 中用于获取图片尺寸和类型的函数。它通过读取文件头来判断是否为合法图片。攻击者通过伪造文件头（如 GIF89a、JFIF）或追加代码到真实图片末尾即可绕过。

2. 图片马 (Image Webshell)

将 WebShell 代码嵌入到合法图片文件中的攻击手法。图片可以正常显示，但当它被 PHP 的 include() 等文件包含函数加载时，其中的恶意代码会被执行。

3. Magic Bytes (文件头)

文件开头的特殊字节序列，用于标识文件类型。如 GIF 是 GIF89a，PNG 是 \x89PNG。但不同格式的严格程度不同，JPG 需要完整的 JFIF 结构。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-13 的区别：Pass-13 三种后缀可以独立测试，Pass-14 强制要求三种后缀全部通过；Pass-14 的 JPG 检测更严格。
  • 与 Pass-09 的区别：Pass-09 是白名单+服务器解析漏洞，Pass-14 是白名单+文件头伪造，绕过的维度完全不同。

2. 这种题目的出现原因（为什么存在）

开发者试图通过 getimagesize() 来彻底禁止上传非图片文件。但该函数仅校验文件头，攻击者可以在真实图片末尾追加代码。这种“半吊子”的防御方式，在实际开发中依然留下了巨大隐患。

3. 这种应用在实际中如何体现？

在实战中，攻击者常将图片马与文件包含漏洞组合使用。防御方应使用图像处理库（如 GD 库）对上传图片进行**重新渲染**（这样追加的 PHP 代码会被丢弃），并将图片存储到非 Web 目录，彻底断绝执行可能。

4. 如何抽象理解概念（大白话）

把靶场比作一个“门卫”：

  • Pass-14 的门卫尝味道（文件头），必须是真正的图片味道。
  • 你在一个真正的面包（真实 JPG 图片）里夹了一根针（PHP 代码）。
  • 门卫尝到了面包的味道，放行了。但如果你把针挂在面包外面（只伪造文件头），门卫一眼就能识破。
  • 这就是“真实图片+追加木马”的物理欺骗逻辑。
