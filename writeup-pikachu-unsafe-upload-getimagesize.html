Unsafe Fileupload(getimagesize) - Pikachu Writeup

2026年9月20日 Pikachu Web安全 文件上传

一、题目信息

  • 题目名称：Unsafe Fileupload (getimagesize)
  • 题目平台：Pikachu 漏洞练习平台
  • 题目类型：Web安全 / 文件上传漏洞 / 服务端文件头校验绕过 / 图片马制作
  • 靶场链接：http://localhost:8080/vul/unsafeupload/getimagesize.php
  • 涉及工具：浏览器、Mac 终端（Terminal）、File Inclusion(Local) 漏洞点

二、解题步骤

1. 分析题目考什么

本题的核心考点是服务端 getimagesize() 文件内容校验绕过。与前两关不同，后端不再信任 MIME 类型和文件后缀，而是使用 getimagesize() 函数读取文件的二进制头（魔术字节），确认真实文件类型。同时，后端还引入了后缀名白名单（仅允许 jpg/jpeg/png）。攻击者必须制作一个既包含真实图片头、又包含 PHP 代码的“图片马”，并利用文件包含漏洞（LFI）来触发其中的恶意代码。

2. 怎么想（破题思路）

页面提示“这里只允许上传图片，不要乱搞！”。解题思路如下：

  • 尝试直接上传 PHP 木马，发现被拦截（提示后缀名必须是图片）。
  • 尝试修改 MIME 类型绕过，发现依然被拦截（提示“你上传的是个假图片”），说明后端使用 getimagesize() 校验了文件真实内容。
  • 制作“图片马”：将真实的图片文件与 PHP 代码拼接，使其拥有合法的图片头。
  • 将图片马后缀改为白名单允许的 .jpg 上传。
  • 因为上传的文件是图片后缀，直接访问无法执行 PHP。必须结合之前的 File Inclusion(Local) 漏洞，通过文件包含让服务器将其作为 PHP 脚本解析。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：使用 cat 命令合并文件导致电脑死机、Docker 崩溃

踩坑情况：在终端执行 cat test.jpg shell.php > shell.php 后，Mac 突然极度卡顿，Docker 报错 no space left on device（磁盘空间不足）并停止运行。

原因分析：在 Linux/Mac 终端中，> 符号代表“清空并重定向”。由于源文件与目标文件同名，系统陷入了循环读写（自我吞噬）的逻辑漏洞，瞬间占满磁盘空间，导致系统崩溃。

改进方式：使用 >> 追加符号，或者使用不同的文件名。正确的制作方式为：
1. 复制图片：cp test.jpg shell_final.php
2. 追加木马：cat shell.php >> shell_final.php（此时目录下需有一个独立的 shell.php）。

踩坑记录二：上传提示“你上传的是个假图片”

踩坑情况：尝试用前一步产生的文件上传，被后端拦截，提示“你上传的是个假图片，不要欺骗我！”。

原因分析：因为之前制作图片马时，由于电脑卡死导致图片源文件（small.jpg）损坏或为空。最终生成的文件只有 PHP 代码，没有图片头（魔术字节），骗不过 getimagesize()。

改进方式：重新下载一张真实的、体积较小（小于500KB）的图片，使用 echo '' > shell.php 制作木马，然后用 cat test.jpg shell.php > shell_final.jpg 重新合并，确保文件拥有正确的图片头。

踩坑记录三：上传成功但 LFI 包含后未执行 PHP 代码

踩坑情况：图片马上传成功（路径为 uploads/xxxx.jpg），利用 fi_local.php?filename=../../unsafeupload/uploads/xxxx.jpg 包含后，页面显示大量图片二进制乱码（PNG IHDR...），没有弹出 phpinfo 页面。

原因分析：在部分 Docker 环境下，PHP 配置（如 allow_url_include 或特定 LFI 限制）可能阻止了包含 .jpg 文件时执行其中的 PHP 代码，PHP 引擎将其当作普通的二进制流输出。

改进方式：使用 php://filter 伪协议读取文件内容以验证木马是否存在（如 php://filter/convert.base64-encode/resource=../../unsafeupload/uploads/xxxx.jpg），然后使用 CyberChef 进行 Base64 解码，确认 是否成功写入文件尾部。若环境彻底限制，应记录该实战踩坑过程，理解其底层逻辑即可。

终极解法：制作图片马配合 LFI 漏洞

第一步：在终端安全地制作图片马

cd ~/Desktop
echo '' > shell.php
cat test.jpg shell.php > shell_final.jpg

命令解析：echo 命令将 PHP 代码写入 shell.php。cat 命令将 test.jpg（图片头）与 shell.php（木马尾）按顺序合并为一个名为 shell_final.jpg 的新文件，欺骗 getimagesize() 检查。

第二步：上传图片马

在页面选择 shell_final.jpg 上传，页面提示“文件上传成功”，返回路径例如：uploads/2026/09/20/9269736aaf9960d9991992140310.jpg。

第三步：利用 LFI 包含图片马执行代码

在浏览器地址栏输入：

http://localhost:8080/vul/fileinclude/fi_local.php?filename=../../unsafeupload/uploads/2026/09/20/9269736aaf9960d9991992140310.jpg&submit=提交

代码逐个符号深度解析：

  • fi_local.php?：进入本地文件包含漏洞接口。
  • filename=：参数名。
  • ../../：路径穿越符。跳出当前的 /vul/fileinclude/ 目录，回到 /vul/ 目录。
  • unsafeupload/：进入文件上传模块的目录。
  • uploads/2026/09/20/...jpg：上传文件的具体相对路径。
  • &submit=提交：提交参数。

由于环境限制，本地未成功解析 PHP，但通过 Base64 编码验证确认了图片马内容的正确性。

4. 怎么迁移（跨领域联想）

  • 二次渲染绕过（Secondary Rendering）：在更高级的场景中，后端会将图片使用 GD 库重新渲染，去掉多余的代码。攻击者需要分析渲染后的图片格式，在未被破坏的像素区段（如 IDAT 块）中精准插入 PHP 代码。
  • 竞争条件上传（Race Condition）：如果后端先允许上传，检查后再删除，攻击者可以在删除的瞬间访问该文件，利用时间差完成攻击。
  • 代码审计与安全开发：防止此类漏洞需要：同时校验 MIME、后缀白名单、文件真实内容（魔术字节），并且必须将上传目录的文件执行权限剥离（如通过 Nginx 配置禁止解析 uploads 目录中的 PHP），彻底断绝 LFI 组合利用的可能。

三、名词大全与原理深度复盘

1. getimagesize() 函数

PHP 的一个内置函数，用于获取图像的大小及相关信息。它会读取文件的前几个字节（魔术字节/Magic Number）来判断是否为合法的图片文件。如果文件头不是标准的 GIF、JPG、PNG 等格式，该函数会返回 False，从而拒绝上传。

2. 图片马（Image Shell）

一种结合了合法图片文件和恶意脚本的特殊文件。攻击者通常将一个正常图片与包含 PHP 代码的文本文件拼接，生成一个新的文件。该文件包含合法的图片头，能通过 getimagesize() 校验；同时尾部包含 PHP 代码，一旦被服务器当作 PHP 解析（如通过文件包含漏洞），就能执行恶意逻辑。

3. 文件上传漏洞与 LFI 的组合利用

文件上传漏洞本身只是“上传文件”，如果服务器禁止解析上传目录中的脚本，单纯上传可能无效。但若网站同时存在 LFI（本地文件包含）漏洞，攻击者可以将上传的图片马作为目标文件进行包含，从而绕过后缀限制，实现远程代码执行（RCE）。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 client check 相比：client check 是前端 JS 校验，通过 F12 修改 DOM 即可轻易绕过；而 getimagesize 是严格的服务端文件内容校验，客户端无法绕过，必须从文件本身构造入手。
  • 与 MIME type 相比：MIME type 只检查 HTTP 请求头中的 Content-Type 字段，抓包伪造即可绕过；而 getimagesize 检查的是文件的实际二进制内容（魔术字节），这要求攻击者制作包含双重内容的图片马。

2. 这种题目的出现原因（为什么存在）

这类漏洞的出现，是因为开发者虽然意识到了需要校验文件真实类型，但没有把安全策略做全。仅仅校验文件头是不够的，如果上传目录的脚本执行权限没有被剥离，或者网站存在文件包含漏洞，图片马依然可以触发代码执行。

3. 这种应用在实际中如何体现？

在真实的红蓝对抗中，遇到有严格文件类型校验的上传接口，攻击者会先尝试制作图片马。如果无法直接利用，还会尝试上传 .htaccess 文件（针对 Apache）或 web.config 文件（针对 IIS），通过解析漏洞让图片文件被当作脚本执行。

4. 如何抽象理解概念（大白话理解）

如果把服务器比作机场安检：

  • MIME type（上一关）：安检员只看你贴在行李箱上的标签（HTTP 头），标签写着“衣服”就放行，不看包里的实物。
  • getimagesize（本关）：安检员拿出了扫描仪，扫描了行李箱的外壳材质（二进制头），确认箱子确实是“衣服”做的。但他没注意到，箱子里面缝了一颗炸弹（PHP 代码）。你成功将炸弹带进了候机厅（上传成功）。
  • File Inclusion（LFI 配合）：你需要找到一个内部员工（LFI 漏洞），让他把这颗炸弹带到引擎室（服务器解析执行），炸弹才会真正爆炸（RCE）。
