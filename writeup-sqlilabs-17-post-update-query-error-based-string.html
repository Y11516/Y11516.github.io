SQLi-Labs Less-17

2026年9月26日 SQLi-Labs Web安全 SQL注入 UPDATE注入

一、题目信息

  • 题目名称：SQLi-Labs Less-17 (POST - Update Query- Error Based - String)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / POST型报错注入 / UPDATE语句注入
  • 靶场链接：http://localhost:8081/Less-17/（本地环境）
  • 涉及工具：Chrome浏览器 (F12开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是基于 UPDATE 语句的报错注入。与之前关卡不同，Less-17 是一个密码重置页面，后端执行的是 UPDATE users SET password = '$passwd' WHERE username='$row1'。注入点在 New Password 字段，而且 User Name 字段被严格过滤（长度截断、单引号转义），需要明确注入位置。

2. 怎么想（破题思路）

  • 页面有两个输入框：User Name 和 New Password。
  • 尝试在 User Name 注入：发现单引号被转义，长度被截断，无法注入。
  • 尝试在 New Password 注入：单引号成功闭合 SQL 语句，页面报错，说明存在注入。
  • 利用 updatexml 函数进行报错注入，获取数据库信息。
  • 或者利用 UPDATE 语句的特性，直接修改 admin 用户的密码，实现通关。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：注入点在 User Name 字段失败

踩坑情况：在 User Name 中输入 admin'，页面没有报错，且无法注入。

原因分析：后端对 User Name 使用了 check_input() 函数，该函数会限制长度（15个字符），并调用 mysql_real_escape_string() 对单引号进行转义（变成 \'）。

改进方式：切换到 New Password 字段进行注入，该字段没有经过过滤。

踩坑记录二：闭合方式错误导致语法报错

踩坑情况：在 New Password 中输入 admin') and ... 或 admin") and ... 都报错。

原因分析：后端语句是 UPDATE users SET password = '$passwd' WHERE username='$row1'，密码字段是单引号包裹，且没有括号。

改进方式：使用 ' 闭合，Payload 为 ' and updatexml(1,concat(0x7e,(select database()),0x7e),1)#。

详细实操步骤（Payload逐字解释）

第一步：验证注入点与报错注入

User Name 输入 admin，New Password 输入：

' and updatexml(1,concat(0x7e,(select database()),0x7e),1)#

逐字解析：

  • '：闭合原 SQL 中的 SET password = ' 的单引号。
  • and updatexml(1,concat(0x7e,(select database()),0x7e),1)：执行报错注入。
  • #：注释掉后面的 ' WHERE username='$row1'。

回显：XPATH syntax error: '~security~'。

第二步：获取表名与列名

查表名（用十六进制避开字符集冲突）：

' and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema=database() and table_name=0x7573657273 limit 0,1),0x7e),1)#

回显 ~users~。接着查列名（把 tables 换成 columns）：

' and updatexml(1,concat(0x7e,(select column_name from information_schema.columns where table_schema=database() and table_name=0x7573657273 limit 0,1),0x7e),1)#

修改 limit 依次得到 ~id~、~username~、~password~。

第三步：终极通关方式（直接重置密码）

既然此页面是密码重置功能，最直接的攻击方式是直接修改 admin 的密码。

User Name 输入：admin。New Password 输入：

', password='123456'#

点击 Submit，页面显示 Password Updated successfully。然后回到 Less-11 或 Less-12 的登录页面，用 admin / 123456 登录即可验证修改成功。

4. 怎么迁移（跨领域联想）

  • 垂直越权与密码重置漏洞：真实世界中，密码重置接口经常成为攻击目标。若未对用户身份进行校验，攻击者可以通过参数污染直接修改他人密码。Less-17 利用 UPDATE 注入实现修改密码，是这类漏洞的底层体现。
  • 数据完整性（Data Integrity）：UPDATE 语句负责修改数据，一旦被注入，可能导致数据库全量数据被篡改（如将所有用户的密码改为同一个）。这警示我们在开发中必须对 UPDATE 操作进行严格的参数化处理。
  • 过滤器绕过思维：防御者往往对登录框的 username 字段严格过滤，却忽略了密码或确认密码等其他交互字段。安全防御是一个整体，不能有短板。

三、名词大全与原理深度复盘

1. UPDATE 注入

SQL 注入的一种类型，发生在 UPDATE 语句中。攻击者可以利用 SET 子句注入恶意代码，从而篡改数据库中的任意数据，常见于密码重置、用户资料修改等功能。

2. check_input() 函数

SQLi-Labs 中的一个常见防御函数，通常用于对 User Name 等敏感字段进行过滤，包括长度限制（如 15 字符）和使用 mysql_real_escape_string 转义单引号。这使该字段无法被用于注入，迫使攻击者寻找其他注入点（如 New Password）。

3. updatexml() 报错注入

利用 updatexml() 函数解析 XPath 格式错误时的报错，将查询结果拼接在报错信息中带出。在 UPDATE 注入中，其用法与 SELECT 注入一致，只是上下文不同。

4. 垂直越权（Vertical Privilege Escalation）

指低权限用户获取高权限用户权限的行为。在 Less-17 中，攻击者可以通过构造注入语句，直接修改 admin 用户的密码，从而获得管理员权限，属于典型的垂直越权漏洞。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-11~16 的区别：之前的关卡都是 SELECT 查询（登录功能），Less-17 是 UPDATE 查询（密码重置功能）。注入点在密码字段而不是用户名字段。
  • 与 Less-15/16 盲注的区别：Less-17 重新开启了报错回显，所以可以使用报错注入。

2. 这种题目的出现原因（为什么存在）

许多系统在重置密码时，开发者可能会认为“只有登录用户才能重置密码”，从而忽略了对重置接口的防御。或者开发者只对 User Name 做了过滤，却忽略了 Password 字段。这提醒我们，安全防御需要在所有输入点统一进行，不能存在侥幸心理。

3. 这种应用在实际中如何体现？

在实战中，攻击者若发现一个注入点，最直接的目的往往是获取数据库权限。但如果注入点位于 UPDATE 语句中，攻击者也可以选择直接篡改数据（如将自己的账号余额改为 999999），或者修改管理员密码以控制整个系统。

4. 如何抽象理解概念（大白话）

把数据库比作一个“带警报器的保险箱”：

  • Less-17 是一扇密码重置门。
  • 虽然门口站着保安（User Name 过滤很严格），但后门没锁（New Password 没有过滤）。
  • 你从后门进去，不仅能偷看保险箱里的秘密（报错注入回显），还能直接给保险箱换一把新锁（修改 admin 密码）。
  • 这就是 UPDATE 注入的可怕之处——它不仅是信息泄露，还会直接破坏数据完整性。
