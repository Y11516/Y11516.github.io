DVWA-Low-暴力破解 (Brute Force)

2026年10月2日 DVWA Web安全 暴力破解 Burp Suite

一、题目信息

  • 题目名称：DVWA Brute Force (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 暴力破解 / 逻辑漏洞
  • 靶场链接：http://192.168.242.209/vulnerabilities/brute/
  • 涉及工具：Burp Suite Community Edition、Google Chrome、Python3 (备用方案)

二、解题步骤

1. 分析题目考什么

本题的核心考点是暴力破解（Brute Force）。当目标系统没有限制登录尝试次数，也没有验证码机制时，攻击者可以通过自动化工具加载字典，不断尝试不同的密码，直至成功登录系统。

2. 怎么想（破题思路）

  • 观察登录表单，输入任意账号密码，页面无验证码，且响应速度极快。
  • 尝试使用 Burp Suite 抓取登录请求，发现请求参数中只有账号和密码，没有其他随机 Token。
  • 将该请求发送至 Intruder 模块，设置密码为可变量，加载常见密码字典。
  • 启动攻击，通过对比不同请求的响应状态或响应长度（Length），找出成功的登录请求。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Burp 社区版弹窗限速与无响应

踩坑情况：点击 Start attack 后，弹出 "Community Edition ... attacks are time throttled" 提示，点击 OK 后没有反应。

原因分析：Burp 社区版限制了攻击速度（约每秒 1 个请求）。同时，攻击窗口可能被主界面遮挡，或者由于本地内存紧张（8GB Mac）导致窗口渲染延迟。

改进方式：耐心等待或使用 Command + Tab 切换至新弹出的攻击窗口。如果字典较大，建议使用 Python 脚本，省内存且速度快。

踩坑记录二：新版 Burp 找不到 Payload Set 和 Payload Options

踩坑情况：进入 Payloads 标签页后，界面只有 "Payload configuration"，找不到旧版教程里的 "Payload set" 和 "Payload Options"。

原因分析：Burp Suite 更新了 UI。在新版中，当 "Payload type" 选为 "Simple list" 后，下方的大空文本框就是原来的 Payload Options 区域。

改进方式：直接在大文本框里点击 "Add" 手动输入，或点击 "Load..." 加载字典文件。同时检查左上角 "Payload position" 是否切换到了 "1"。

详细实操步骤（Payload逐字解释）

第一步：抓包与设置攻击点

输入账号密码（如 admin/123456），开启代理，点击 Login。在 Burp 的 Proxy -> Intercept 拦截到请求后，右键选择 Send to Intruder。

在 Intruder 的 Positions 选项卡中，点击 Clear § 清除所有默认标记。选中 password=123456 中的 123456，点击 Add §。此时状态栏应显示 1 payload position。

第二步：加载密码字典

切换到 Payloads 选项卡，Payload type 保持 Simple list。在输入框中添加常见弱口令：123456、password、admin、root、12345678。

第三步：开始攻击并分析结果

点击右上角 Start attack。在弹出的结果窗口中，观察 Length 列。

  • 失败响应：大部分密码（如 123456、admin）的 Length 均为 4703。
  • 成功响应：唯独 Payload 为 password 的请求，Length 为 4741（增加了 38 字节）。

查看该请求的 Response 内容，确认包含 Welcome to the password protected area admin。说明密码就是 password。

第四步：提交答案

在 DVWA 登录页面输入 admin / password，成功登录，通关成功。

4. 怎么迁移（跨领域联想）

  • 渗透测试中的“弱口令”扫描：真实护网中，外网打点最常用的手法之一就是使用常见账号密码（如 admin/admin, test/123456）进行大量尝试。这与本题原理完全一致，只是字典更大、目标更多。
  • 密码学与撞库攻击：由于现代用户习惯在多个网站使用相同密码，攻击者利用从某网站泄露的账号密码库，去另一个网站尝试批量登录，这种“撞库”本质上也是一种高级的暴力破解。

三、名词大全与原理深度复盘

1. 暴力破解 (Brute Force)

一种通过枚举所有可能性来猜测密码或密钥的攻击方式。它不依赖算法漏洞，而是依赖计算能力和时间成本。防御手段通常包括限制尝试次数、增加验证码、延长响应时间等。

2. Payload / 字典

在攻击中，Payload 指代注入到请求中的可变部分（如本题中的密码）。字典则是一个包含大量常见密码的文本文件。高效的字典通常基于真实泄露数据整理而成，如 RockYou.txt。

3. HTTP 响应长度 (Length)

服务器返回的响应数据包的大小。在暴力破解中，登录成功和登录失败的页面内容不同，通常会导致响应长度出现细微差异。攻击者通过对比 Length，可以快速定位成功的请求。

4. 逻辑漏洞

指程序业务逻辑设计上的缺陷，而非代码语法错误。例如本题的漏洞就是“开发者没有在逻辑层加入登录限制”，导致攻击者可以无限次尝试，属于典型的逻辑漏洞。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入的区别：SQL 注入是构造恶意的 SQL 语句欺骗数据库执行，属于“输入验证”层面的漏洞。而暴力破解属于“逻辑设计”层面的漏洞，代码本身没有语法错误，只是缺少了安全限制。
  • 与文件上传漏洞的区别：文件上传是绕过服务器对文件类型的校验，属于“文件处理”层面的漏洞。暴力破解则不需要绕过任何校验，而是利用系统缺乏防护机制进行海量尝试。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者在实现业务功能时，没有同步考虑安全防护。在早期的 Web 应用中，开发者只关注“用户能否成功登录”，却没有加入“失败次数限制”、“验证码验证”或“IP 访问频率限制”。

从历史角度看，这类似于早期银行金库的设计：如果没有安装报警器和巡逻人员，小偷就可以在原地无限次尝试密码组合，直到打开金库。现代系统引入了“多次错误即锁定账户”或“验证码”等机制，正是为了弥补这一逻辑缺陷。

3. 这种的应用

暴力破解是实战中最高频的攻击方式之一。在企业内网渗透中，攻击者常利用弱口令（如 admin/123456）配合自动化工具，迅速获取服务器权限。在护网演练中，针对 VPN、OA、数据库等暴露在公网的服务，进行弱口令扫描是红队得分的核心手段。

4. 如何抽象理解概念（大白话）

把暴力破解比作“试钥匙”：

  • 你面前有一扇锁着的门，你不知道哪把钥匙能打开它。
  • 但你发现，把钥匙插进去转动后，如果不对，门毫无反应；如果对了，门会“咔哒”响一声并打开。
  • 因为门没有报警系统，也没有限制你试错次数，所以你拿着一大串钥匙，一把接一把地试。
  • 只要钥匙串里包含正确的那把，你最终一定能打开这扇门。这就是暴力破解。

做一道题，就要往自己脑子里装点东西。
