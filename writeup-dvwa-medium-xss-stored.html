DVWA-Medium-存储型XSS (XSS Stored)

2026年10月2日 DVWA Web安全 XSS 持久化攻击

一、题目信息

  • 题目名称：DVWA XSS (Stored) (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 跨站脚本攻击 / 存储型 XSS / 黑名单绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/xss_s/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是绕过 Medium 级别的服务端黑名单过滤，实现存储型 XSS。Medium 级别在服务端使用了 str_replace 将 <script> 标签替换为空。攻击者需要改用不需要 <script> 标签的 Payload（如 <img>），利用事件触发来执行 JavaScript，并将恶意代码持久化存储到数据库中。

2. 怎么想（破题思路）

  • 尝试 Low 级别的 Payload <script>alert(1)</script>，发现无弹窗。
  • 推测后端过滤了 <script> 标签。
  • 改用 <img src=x onerror=alert(1)>，利用图片加载失败的事件来执行脚本。
  • 提交后，恶意代码被存入数据库，所有访问该页面的用户都会触发弹窗。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：使用 <script> 标签被服务端过滤

踩坑情况：在 Message 输入框输入 <script>alert(1)</script>，提交后页面无弹窗，且留言板中显示的留言内容为空。

原因分析：Medium 级别服务端代码使用了 str_replace("<script>", "", $message)，导致 Payload 在存入数据库之前就被破坏了。

改进方式：改用不需要 <script> 标签的 Payload，例如 <img src=x onerror=alert(1)>。

详细实操步骤（Payload逐字解释）

第一步：提交恶意留言

Name 字段随便填（如 test）。

Message 字段输入：<img src=x onerror=alert(1)>

点击 Sign Guestbook。

第二步：验证持久化特性

响应结果：页面刷新后立即弹出警告框 1。按 F5 刷新页面，弹窗会再次出现，说明恶意脚本已成功存入数据库，形成了持久化攻击。

第三步：备选方案

如果 <img> 也被拦截，可以尝试以下不需要 <script> 的 Payload：

<svg/onload=alert(1)>
<details open ontoggle=alert(1)>

4. 怎么迁移（跨领域联想）

  • 论坛蠕虫：2005 年著名的 MySpace Samy 蠕虫，就是利用了存储型 XSS。Samy 在个人资料中插入了一段 JavaScript，任何查看他资料的人都会自动添加他为好友，并复制这段代码到自己的资料中，导致蠕虫在短时间内感染了上百万用户。
  • WAF 绕过实战：在真实的护网中，WAF 常常基于黑名单来拦截 XSS。攻击者通常会寻找等价标签（如 <svg>、<details>）或使用编码绕过。

三、名词大全与原理深度复盘

1. 存储型 XSS

恶意代码被永久存储在目标服务器上（如数据库、文件系统），当其他用户访问该页面时，恶意代码被执行。这是三种 XSS 类型中危害最大的一种，属于持久化攻击。

2. 服务端黑名单过滤

一种在服务器端 PHP 代码中实现的过滤机制。它通常使用 str_replace() 函数将特定的关键字替换为空。这种过滤容易绕过，因为攻击者可以找到未被列入黑名单的等价标签。

3. onerror 事件

HTML 标签的事件属性。当资源（如图片、脚本）加载失败时触发。在 XSS 中常被用来替代 <script> 标签执行 JavaScript。

4. 持久化攻击 (Persistent Attack)

攻击者的恶意载荷被保存在服务器上，持续对后续访问者造成影响。存储型 XSS 是典型的持久化攻击。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别没有任何过滤，可以直接使用 <script>。Medium 级别加入了服务端黑名单，需要寻找新的标签（如 img）来绕过。
  • 与反射型 XSS 的区别：反射型需要诱导用户点击链接，存储型不需要。存储型只需要用户访问页面，脚本就会自动执行。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者试图用“黑名单”来防御 XSS，但低估了攻击者的创造力。很多 HTML 标签都可以执行 JavaScript（如 img、svg、iframe），只要漏掉一个，防御就会失效。

3. 这种的应用

在护网中，存储型 XSS 是攻击后台管理员的主要手段。攻击者将恶意脚本嵌入到用户反馈、留言板等管理员会查看的地方，一旦管理员访问，攻击者就能获取管理员的 Cookie，进而接管后台。

4. 如何抽象理解概念（大白话）

把存储型 XSS 比作“公共饮水机投毒”：

  • 正常情况：你往饮水机里加了一块糖（正常留言），每个喝到水的人都尝到了甜味。
  • Low 级别：你在饮水机里投了毒（<script>），每个来喝水的人都会中毒。
  • Medium 级别：门卫看到“毒”字就拦下。但你换了个词“药”，门卫没认出来，照样投了进去。这就是黑名单绕过。
