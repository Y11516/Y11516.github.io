DVWA-Low-弱会话ID (Weak Session IDs)

2026年10月2日 DVWA Web安全 会话安全 越权

一、题目信息

  • 题目名称：DVWA Weak Session IDs (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 会话管理缺陷 / 越权访问
  • 靶场链接：http://192.168.242.80/vulnerabilities/weak_id/
  • 涉及工具：Google Chrome 浏览器 (F12 开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是弱会话 ID 生成机制。在 Low 级别下，后端使用简单的自增数字（1, 2, 3...）作为 dvwaSession 的值。攻击者可以通过观察自己生成的 Cookie 值，推测出其他用户的会话 ID，并通过篡改 Cookie 实现会话劫持。

2. 怎么想（破题思路）

  • 点击 Generate 按钮，页面会设置一个新的 Cookie。
  • 打开 F12 开发者工具，查看 dvwaSession 的值，发现它是递增的（如 1, 2, 3）。
  • 尝试把 Cookie 的值改成之前的数字（如 1），刷新页面，看是否依然能正常识别身份。
  • 如果能，说明会话 ID 可以被轻易预测和伪造。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：F12 找不到 Cookies 面板

踩坑情况：按 F12 后，在 Elements 或 Console 面板里找不到 Cookie。

原因分析：Cookie 的查看和修改需要在特定的面板里操作，不同版本的 Chrome 叫法可能略有不同。

改进方式：点击 F12 顶部的 Application（应用）标签页，在左侧找到 Cookies，展开后选择当前域名（如 http://192.168.242.80），即可看到 dvwaSession。

详细实操步骤（Payload逐字解释）

第一步：生成 Cookie

在页面上连续点击几次 Generate 按钮。假设你点击了 3 次。

第二步：查看 Cookie 规律

按 F12，点击 Application -> Cookies -> 选择对应域名。

观察 dvwaSession 的值，会发现它依次变成了 1、2、3。这就是“弱会话 ID”的直接证据。

第三步：篡改会话 ID（伪造身份）

双击 dvwaSession 的值，把它改为 1。然后刷新页面。如果服务器依然承认你的身份（页面不报错且保持登录状态），说明你成功“劫持”了编号为 1 的用户的会话。

实战意义：攻击者可以写一个脚本，把 dvwaSession 遍历 1 到 10000，从而批量获取其他在线用户的会话。

4. 怎么迁移（跨领域联想）

  • 现实中的门禁卡：如果酒店房间的门禁卡是简单的“房间号+1”逻辑，住客就可以轻易伪造出一张能打开隔壁房间的卡。弱会话 ID 本质上就是“编号规律太简单”。
  • 用户隐私泄露：在真实业务中，如果订单 ID 是自增的（如 order_id=1001），攻击者可以把 ID 改成 1002 来查看他人的订单信息（这叫水平越权）。

三、名词大全与原理深度复盘

1. Session (会话)

在计算机中，尤其是在网络应用中，Session 是指用户与服务器之间的一次连续交互过程。服务器会为每个会话分配一个唯一的标识符（Session ID）。

2. Cookie

服务器发送给用户浏览器并保存在本地的一小块数据。浏览器在下次向同一服务器发送请求时，会自动携带这个 Cookie。它是维持登录状态的关键。

3. 弱会话 ID (Weak Session ID)

指会话 ID 的生成算法过于简单，容易被攻击者预测或枚举。常见的弱会话 ID 包括：自增数字、时间戳（毫秒级）、简单的哈希值（如 MD5(用户名)）等。

4. 会话劫持 (Session Hijacking)

攻击者通过窃取或猜测用户的 Session ID，伪装成该用户与服务器进行交互，从而获取该用户的权限和数据。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入的区别：SQL 注入是攻击数据库，而弱会话 ID 是攻击会话管理机制。前者是代码层的漏洞，后者是逻辑设计层面的漏洞。
  • 与 CSRF 的区别：CSRF 是利用受害者已有的 Cookie 发起恶意请求，而弱会话 ID 是攻击者自己伪造 Cookie。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者在生成 Session ID 时偷懒，使用了不安全的伪随机数生成器。例如，直接使用 rand(1, 10000) 或者简单的自增 ID。在早年的 Web 开发中，很多 CMS 系统为了图方便，直接使用自增 ID 作为会话标识，导致了大量的越权漏洞。

3. 这种的应用

在真实的护网中，攻击者拿到一个 Session ID 后，会尝试将其减 1 或减 2，看看能否进入其他人的后台。如果成功，就能直接越权获取管理员权限，这是非常致命的漏洞。

4. 如何抽象理解概念（大白话）

把弱会话 ID 比作“酒店房卡”：

  • 正常情况：每张房卡里存着一个完全随机的复杂编号，你根本猜不到别人的房卡编号是多少。
  • 漏洞情况：酒店图省事，房卡编号就是 1、2、3、4 号。你拿到 5 号卡，稍微一猜就知道 1 号卡的编号是 1。你把卡里的编号改成 1，就能直接刷开别人的房间。

做一道题，就要往自己脑子里装点东西。
