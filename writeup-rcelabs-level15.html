  • 题目平台：RCE-Labs 靶场 (灵境平台部署)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 二进制分析基础

  • 涉及工具：浏览器

二、解题步骤

1. 分析题目考什么

黑名单封禁了 base64 等编码工具，但允许了 strings。这是从“编码转换”切换回“文本提取”的关卡。考察的是从二进制或未知文件中提取可读内容的逆向思维。

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

2. 怎么解（详细步骤与输出解析）

最终成功 Payload

直接使用 strings 命令提取可打印字符：

?cmd=strings /flag

成功响应：页面直接回显明文 flag{TEST_Dynamic_FLAG}。

解析：因为 flag 文件是一个纯文本文件，strings 命令自动扫描并提取了其中长度大于等于 4 的可打印字符，完美避开了所有被拉黑的阅读工具，达到了“降维打击”的效果。

3. 怎么迁移（跨学科与跨领域联想）

  • 逆向工程与恶意软件分析：拿到未知的二进制木马（.exe 或 .elf），第一件事就是运行 strings 查看里面是否硬编码了 IP、URL 或加密密钥。这是最基础的静态分析方法。
  • 数字取证：在磁盘镜像或内存转储文件中，通过 strings 可以快速捞出被删除的文本文件残留、聊天记录或系统日志。

三、名词大全与原理深度复盘

1. strings 命令详细介绍

strings 用于在二进制文件中查找可打印的字符串。它诞生于 Unix 早期，最初是为了从纸带或二进制程序中提取文本信息。

  • 核心参数 -n：指定最小字符串长度。默认是 4，例如 strings -n 8 /flag 只提取长度大于 8 的字符。
  • 核心参数 -e：指定字符编码，如 -e l 表示 16 位小端编码。

2. 底层原理：字节流扫描与 ASCII 码

计算机在底层处理文件时，不区分“文本”、“图片”或“程序”，一律看作连续的字节流（Byte Stream）。strings 遍历文件的所有字节，检查每个字节是否属于“可打印 ASCII 字符”（即 0x20 到 0x7E 之间的范围，对应空格、数字、字母、符号）。如果是，就开始记录；一旦遇到不可打印字符（如 0x00 空字节、0xFF 等控制符），就停止记录。如果记录的长度达到阈值（默认 4），就把这段字符作为字符串输出。

3. 核心名词解释（陌生人也能看懂版）

  • 字节流 (Byte Stream)：计算机底层的文件本质上都是一串由 0 和 1 组成的字节。字节流就是这些字节按顺序排列的序列。
  • 可打印字符 (Printable Character)：指能在屏幕上正常显示的字符，包括字母、数字、标点符号和空格。
  • ASCII 码：美国信息交换标准代码。规定了字母、数字、符号与二进制数值的映射关系（例如 'A' 是 65，'a' 是 97）。strings 正是依据此标准来判断哪些字节是可打印的。
  • 静态分析 (Static Analysis)：在不运行程序的情况下，通过分析二进制文件的结构、字符串、汇编代码来了解其行为。

四、题目思考

1. 这跟前面关卡的区别

前面 Level 10-14 侧重于“如何把文件内容完整搬运出来”（转储或编码）。而 Level 15 的 strings 侧重于“精准提取”——它不关心整个文件，只关心文件里有没有“人类能看懂的文本”，这在处理二进制文件时是降维打击。

2. 这种题目的出现原因（底层逻辑与历史原因）

黑名单拦截的是“读取内容”的工具（如 cat、tail、base64），而 strings 属于“提取特征”的工具。开发者很难把所有的“特征提取”工具全部拉黑，否则正常的运维排查工作（比如查找二进制文件里的错误日志）也会受到影响。

3. 这种漏洞在实际中的应用

在 Web 渗透中，如果对方的 flag 被隐藏在二进制文件中，或者目标系统是一个没有 cat 命令的精简版 Alpine/Docker 容器，使用 strings 就是最有效的突破口。在 CTF 的 Misc 方向，这也是必考的基础技能。

4. 如何抽象理解概念（大白话）

把文件比作一本厚厚的字典。cat 是把整本字典按页读出来；base64 是把整本字典拍成照片传给你；而 strings 则是一个“筛子”，它直接过滤掉所有的空白页、乱码页，只把字典里所有能读懂的中文和英文单词挑出来，排成一排给你看。你一眼就能在这排单词里找到你要找的“暗号”（flag）。

5. 他的本质

本质是通过扫描字节流，利用 ASCII 码表过滤非文本数据，从而实现对文本信息的无损提取。它绕过了文件格式的束缚，直击数据的底层本质。

6. 如果我是出题人或者攻击者我会怎么防守或者破解

  • 防守方（蓝队）：如果必须允许用户执行命令，最佳策略是使用白名单。如果只能使用黑名单，除了限制 cat、strings，还要考虑限制 awk、sed、grep 等文本处理工具。同时，应严格限制 Web 进程的用户权限，使其无权读取敏感文件。
  • 破解方（红队）：如果 strings 也被拦截，可以尝试使用 grep -a（将二进制视为文本处理）、perl 脚本或 python 单行命令来扫描文件中的可打印字符，实现同样的提取效果。
