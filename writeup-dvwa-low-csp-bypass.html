DVWA-Low-CSP绕过 (CSP Bypass)

2026年10月2日 DVWA Web安全 CSP 组合利用

一、题目信息

  • 题目名称：DVWA CSP Bypass (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 客户端安全 / CSP 绕过
  • 靶场链接：http://192.168.242.80/vulnerabilities/csp/
  • 涉及工具：Google Chrome 浏览器、VS Code

二、解题步骤

1. 分析题目考什么

本题的核心考点是CSP（内容安全策略）绕过。CSP 是一种浏览器安全机制，通过白名单限制页面可以加载哪些外部资源（如 JavaScript）。在 Low 级别下，CSP 头中包含了 'self' 指令，这意味着允许加载同源（当前域）下的脚本。我们可以利用前面学过的文件上传漏洞，把恶意 JS 文件上传到靶机本身，从而绕过 CSP。

2. 怎么想（破题思路）

  • 页面提示“include scripts from external sources”，且输入框只接受 URL。
  • CSP 限制了我们加载外部（如自己的 Mac）的脚本。
  • 但 CSP 允许加载同源（'self'）的脚本。
  • 我们能否把脚本传到靶机自己身上？可以！利用 File Upload 漏洞。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：跨域网络隔离导致外部脚本无法加载

踩坑情况：尝试在 Mac 上启动 HTTP 服务器托管 alert.js，并在 DVWA 中填入 Mac 的局域网 IP，页面无反应。

原因分析：DVWA 运行在 Docker 容器中，默认使用 NAT 网络模式，容器无法反向访问宿主机的局域网 IP 服务。

改进方式：放弃外部托管，改为利用 File Upload 漏洞将 JS 文件上传到靶机自身的 Web 目录，利用 'self' 白名单绕过 CSP。

详细实操步骤（Payload逐字解释）

第一步：制作并上传 JS 文件

本地新建 alert.js，内容为：alert('CSP Bypass!');。

去 File Upload 关卡上传该文件，上传成功后获取路径：../../hackable/uploads/alert.js。

第二步：在 CSP 关卡中引用同源脚本

回到 CSP Bypass，在输入框中填入：

http://192.168.242.80/hackable/uploads/alert.js

响应结果：页面成功弹出提示框 CSP Bypass!。

原理解释：CSP 中的 'self' 指令允许加载当前域下的脚本。虽然这是外部 URL 参数，但它依然属于同源，因此被 CSP 放行。这就是“文件上传 + CSP 绕过”的组合利用。

4. 怎么迁移（跨领域联想）

  • 供应链攻击：在真实场景中，攻击者可能无法直接上传文件，但可以尝试在 CSP 白名单内的某个第三方库（如 CDN）上找到 JSONP 接口或允许上传文件的地方，从而绕过 CSP 执行恶意代码。
  • 漏洞组合利用：本次实战完美展示了“组合拳”的威力。单一漏洞（如低危的文件上传、CSP 配置不当）可能影响有限，但组合起来就能实现高危的远程代码执行。

三、名词大全与原理深度复盘

1. CSP (Content Security Policy)

内容安全策略。一种由浏览器实现的声明式安全机制，通过 HTTP 响应头或 meta 标签，限制页面可以加载哪些资源（如脚本、样式、图片），是防御 XSS 的强力手段。

2. 'self' 指令

CSP 中的一个关键字，表示允许加载与当前页面同源（相同协议、域名和端口）的资源。利用好这个指令，可以只允许加载站内的合法脚本。

3. 同源策略 (Same-Origin Policy)

浏览器的核心安全机制。CSP 的 'self' 正是基于同源策略。只要上传的脚本和当前页面同源，就能被浏览器允许执行。

4. 组合漏洞利用链 (Exploit Chain)

将多个独立的低危漏洞串联起来，实现单一漏洞无法达到的高危攻击效果。这是高级渗透测试的核心能力之一。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 XSS 的区别：XSS 是直接注入脚本，CSP 是为了防御 XSS 而生的。本关的核心是如何绕过这道防线。
  • 与文件上传的区别：文件上传是利用漏洞上传文件，而 CSP 绕过是利用上传的文件去突破客户端的安全限制，两者结合形成了攻击链。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于CSP 策略配置不当（太宽松）且站点存在文件上传漏洞。如果 CSP 严格限制了 script-src 只允许特定的 CDN，或者禁止了 'self'，攻击者就无法利用同源上传的文件。

3. 这种的应用

在真实的渗透测试中，遇到带 CSP 的站点时，攻击者会尝试寻找 CSP 白名单中的弱点，或者像本题一样利用其他漏洞（如文件上传、JSONP）来托管恶意脚本。

4. 如何抽象理解概念（大白话）

把 CSP 比作“小区门禁”：

  • 正常情况：门禁只允许业主（同源脚本）进小区。外卖员（外部脚本）一律拦住。
  • 恶意情况：攻击者伪装成业主，把炸弹（恶意脚本）放在了小区快递柜（通过文件上传漏洞）。
  • 门禁一看是“快递柜里的东西”，属于小区内部物品（'self'），就放行了。这就是 CSP 绕过的本质——从内部发起攻击。
