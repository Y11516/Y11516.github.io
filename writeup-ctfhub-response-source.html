响应包源代码查看 - CTFHub Web 入门 Writeup

2026年9月16日 CTFHub Web安全 信息泄露 HTML注释

这道题的名字叫“响应包源代码查看”，是一道极其经典的“信息泄露”入门题。它告诉我们：永远不要相信浏览器页面展示的内容，真正的秘密可能藏在原始的 HTML 源码（响应包）里。

一、题目信息

  • 题目名称：响应包源代码查看
  • 题目平台：CTFHub
  • 题目类型：Web / 信息泄露 / HTML注释泄露
  • 涉及工具：浏览器开发者工具（F12 / 查看源代码）、Mac 终端（curl 命令）
  • 最终Flag： ctfhub{8580cc64984a49107d448671}

二、解题过程

1. 访问主页，寻找线索

进入靶场，页面看起来非常干净，只有一行简单的提示文字，没有任何可见的输入框或提示信息。如果只盯着页面上显示的文字，完全找不到 Flag 的踪影。

2. 查看响应包源代码（命令行终端方式）

既然页面上没有，我们就直接查看服务器返回给浏览器的“原始快递”（响应包）。

打开 Mac 终端，输入以下 curl 命令：

curl http://challenge-ccae65fdab01690e.sandbox.ctfhub.com:10800/

curl 会直接打印出 HTML 源代码，而不执行任何渲染。在输出的 HTML 底部，我们立刻发现了一行被注释掉的代码：

<!-- ctfhub{8580cc64984a49107d448671} -->

这就是我们要找的 Flag！

3. 浏览器辅助查看

除了终端，在浏览器里直接右键选择“**查看网页源代码**”（View Page Source），或者按 F12 打开 Elements（元素）面板，同样能在这行注释中找到 Flag。

最终 Flag： ctfhub{8580cc64984a49107d448671}

三、知识点总结（往脑子里装的东西）

  • HTML 注释泄露：开发者可能会在 HTML 源码中留下开发笔记、测试账号、甚至 Flag。因为注释不会在页面上显示，开发者误以为它是安全的，但这属于典型的“掩耳盗铃”。
  • 响应包（Response Body）：服务器返回给浏览器的原始数据。浏览器会解析 HTML、CSS、JS 并渲染出漂亮的页面，而 curl 或“查看源代码”绕过了解析过程，直接把最原始的数据展示给我们。
  • 前端安全的核心原则：永远不要在前端（HTML、JS、CSS）中存放任何敏感信息（如密码、密钥、Flag）。前端代码对于攻击者而言是百分之百透明的。
  • curl 命令：在终端下获取网页源码的最快方式，无需启动庞大复杂的浏览器。

四、踩坑启示录（实战经验）

💡 不要只看渲染后的页面：本次解题的最大体会是，浏览器界面是给普通用户看的。对于安全从业者来说，我们要习惯直接阅读原始响应包。有时候浏览器会隐藏某些 HTML 元素，或者有前端 JavaScript 阻碍查看，直接使用 curl 命令往往能拨云见日。

做一道题，就要往自己脑子里装点东西。
