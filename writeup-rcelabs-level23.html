RCE-Labs Level 23 - echo 命令回显输出与重定向写入

2026年10月5日 RCE-Labs 文件写入 WebShell

一、题目信息

  • 题目名称：RCE-Labs Level 23 (echo 命令回显输出与重定向写入)
  • 靶场链接：http://靶机IP:8080/less-23/
  • 涉及工具：浏览器、Burp Suite（可选）

二、解题步骤

1. 分析题目考什么

黑名单继续累加，ping 和 curl 相继被封禁。题目弹窗提示：“echo 命令怎么重定向写入木马？”。这一关的核心考察点是利用 echo 命令配合重定向符写入文件或 Webshell，并理解无回显场景下的数据外带。

源码核心逻辑

$pattern = '/cat|tac|head|tail|more|less|nl|sort|uniq|od|xxd|hexdump|base32|base64|strings|grep|file|find|cp|mv|ping|curl/';
if(!preg_match($pattern,$cmd)){
    system($cmd);
}

2. 怎么想（破题思路与踩坑记录）

踩坑记录一：反引号被浏览器转义

尝试 Payload：?cmd=echo \`sed -n '1,10p' /flag\` > 3.txt

失败响应：访问 3.txt 时返回了 Web 目录列表，文件未创建。

原因分析：在浏览器地址栏中，反引号 ` 和单引号 ' 属于特殊字符，浏览器会自动进行 URL 编码或截断，导致命令根本没有完整传到服务器。

改进方式：不要试图在 URL 里拼凑过于复杂的命令，改用更简单、无特殊符号的重定向方式。

踩坑记录二：写入木马报错 array given

尝试 Payload：?cmd=echo "" > 1.php，然后访问 1.php?1=sed -n '1,10p' /flag。

失败响应：页面报错 Warning: system() expects parameter 1 to be string, array given in /var/www/html/less-23/1.php on line 1。

原因分析：PHP 在解析 URL 参数时，如果参数名是纯数字（如 ?1=...），极容易将其解析为数组（或与数组语法冲突），导致 $_GET[1] 接收到的是数组而不是字符串，从而引发 system() 报错。

改进方式：回归最简单的重定向写入，利用 sed 读取，直接写入静态文本文件。

最终成功 Payload 与操作流程

第一步：利用 sed 读取并利用 > 重定向写入 Web 目录

?cmd=sed -n '1,10p' /flag > 4.txt

命令逐字解析：

  • sed -n '1,10p' /flag：使用流编辑器读取文件内容。
  • >：Shell 的重定向符，将标准输出写入 4.txt。
  • 4.txt：目标文件名，位于 Web 根目录下。

第二步：通过 HTTP 协议访问写入的文件

在浏览器输入：http://靶机IP:8080/less-23/4.txt

成功响应：浏览器直接显示出明文 flag{TEST_Dynamic_FLAG}。

3. 怎么迁移（跨学科与跨领域联想）

  • 真实的 WebShell 写入：渗透测试中拿下 RCE 后，最经典的动作就是利用 echo "" > shell.php 写入一个 WebShell，从而将不稳定的命令执行转化为稳定的交互式控制。
  • 自动化配置生成：运维脚本中常用 echo 结合重定向快速生成配置文件，例如 echo "port=8080" > app.conf。

三、名词大全与原理深度复盘

1. echo 命令详细介绍

echo 是 Linux Shell（以及 PHP、Windows CMD）中最基础的文本输出命令。

  • 核心参数 -n：输出后不自动换行。
  • 核心参数 -e：解析转义字符（如 \n 换行、\t 制表符）。
  • 核心作用：在 RCE 中，由于它是 Shell 的内置命令（Built-in），不需要启动新的进程，因此响应极快，且常常能绕过基于独立二进制文件（如 /bin/cat）的黑名单。

底层原理：内置命令与系统调用

与其他位于 /bin/ 或 /usr/bin/ 的独立程序不同，echo 直接由 Shell 在用户态解析。当你执行 echo "text" > file 时，Shell 首先解析 >，调用内核的 open() 系统调用创建文件，随后直接调用 write() 将文本写入文件描述符。整个过程不涉及 fork() 和 execve()，极大地提高了执行效率并减少了被 WAF 拦截的几率。

跨领域迁移

  • WebShell 持久化控制：写马是 RCE 利用链中最重要的一环。通过 Web 服务器解析 .php 文件，攻击者能获得长期、稳定的控制通道（后门）。
  • 无回显 RCE 破局：当系统没有回显（看不到命令执行结果）时，利用重定向符将结果写入 Web 目录，再通过 HTTP 访问，是内网环境中最稳妥的数据外带方式。

四、题目思考

1. 这跟前面关卡的区别

前面关卡（Level 1-22）主要围绕“读取、编码、外带”展开。Level 23 首次引入了“写入”的概念。这标志着攻击者从单纯的信息窃取，升级到了对服务器文件系统的直接修改和控制。

2. 如何抽象理解概念（大白话）

把服务器比作一个封闭的房间。前面的关卡是试图把房间里的文件通过窗户（回显）丢出来，或者通过管道（网络外带）传出去。Level 23 的 echo 是你在房间里找到了一台打印机，把文件的内容打印成一本新的书（4.txt），然后直接放在门口（Web 目录）。你不需要再从窗户扔东西，只要绕到门口，直接拿走那本书就行了。这就是最朴素的数据外带思想。
