Upload-Labs Pass-01

2026年9月26日 Upload-Labs Web安全 文件上传 前端验证绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-01 (客户端JS检查绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 前端安全绕过
  • 靶场链接：http://localhost:8082/Pass-01/index.php（本地环境）
  • 涉及工具：Chrome浏览器 (F12开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是前端 JavaScript 验证绕过。Pass-01 在页面的 <script> 标签中定义了 checkFile() 函数，通过判断文件后缀名来阻止非图片文件上传。由于验证只发生在浏览器端，攻击者可以通过删除或篡改前端 JS 代码轻松绕过，从而直接上传 PHP Webshell。

2. 怎么想（破题思路）

  • 尝试直接上传 shell.php，页面弹出 JS 警告提示“该文件不允许上传”。
  • 按下 F12 查看源码，发现表单带有 onsubmit="return checkFile()" 属性。
  • 确认验证逻辑在前端进行，后端并未作校验，因此只要让 checkFile() 返回 true 即可绕过。
  • 在 Console 覆盖 JS 函数，或者直接修改 HTML 元素，再次上传。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：upload 文件夹不存在导致后端报错

踩坑情况：通过前端绕过上传后，页面上一直提示 ../upload文件夹不存在,请手工创建！

原因分析：Upload-Labs 靶场源码使用了 move_uploaded_file() 函数，该函数要求目标物理文件夹必须已存在。如果环境初始搭建时没有自动创建，就需要手动新建。

改进方式：在靶场根目录（包含 Pass-01 到 Pass-20 的目录）中，手动新建一个名为 upload 的文件夹。建好后刷新页面，红字提示消失。

详细实操步骤（Payload逐字解释）

第一步：准备 Webshell

新建一个文本文件，内容为：

<?php @eval($_POST['cmd']); ?>

保存并重命名为 shell.php。

第二步：绕过前端验证（Console 覆盖法）

按 F12 打开开发者工具，切换到 Console 标签，输入以下代码并回车：

checkFile = function() { return true; }

逐字解析：

  • checkFile：这是 HTML 表单中触发验证的 JS 函数名。
  • function() { return true; }：将原函数体替换为直接返回 true。这样无论上传什么格式的文件，前端都会判定为“合法”。

第三步：上传并验证

保持开发者工具打开，在网页上选择 shell.php，点击上传，页面提示“上传成功”。

在浏览器新标签页访问：

http://localhost:8082/upload/shell.php

如果页面是一片空白（没有报错信息，也没有 404），说明 PHP 代码已被服务器成功解析。WebShell 植入成功。

4. 怎么迁移（跨领域联想）

  • 纵深防御（Defense in Depth）：这一关揭示了“只依赖客户端验证”的致命错误。在软件工程中，这相当于把安全性寄托在用户可以随意修改的前端代码上。正确的开发规范要求“永远不要信任客户端输入”，必须在服务端进行严格校验。
  • 沙盒与逃逸（Sandbox Escape）：前端 JS 运行在浏览器的沙盒环境中。覆盖 checkFile 函数类似于“沙盒逃逸”的入门实践——通过改变环境自身的变量定义，来改变程序的行为逻辑。
  • 逆向工程与调试：利用 F12 查看、修改、覆盖前端代码，也是前端开发者日常调试 BUG 的常用手段。安全测试人员将其用于绕过限制，两者在技术本质上是一体两面。

三、名词大全与原理深度复盘

1. 文件上传漏洞（File Upload Vulnerability）

指 Web 应用允许用户上传文件，但未对文件类型、内容、大小进行严格校验，导致攻击者可以上传恶意脚本（如 PHP、JSP），进而控制服务器的漏洞。

2. 前端验证 vs 后端验证

  • 前端验证：通过 JavaScript 在浏览器端拦截非法操作，优点是响应快、节省服务器资源，缺点是攻击者完全可以绕过（如禁用 JS、修改 HTML、抓包改包）。
  • 后端验证：在服务器端对上传文件进行检查（如 MIME 类型、文件头、白名单）。这是安全防线的最后一道关卡，极其重要。

3. Webshell（一句话木马）

一段极简的恶意代码（如 <?php @eval($_POST['cmd']); ?>），上传到服务器后，攻击者可以通过发送 POST 请求来执行任意系统命令，从而实现对服务器的远程控制。

4. move_uploaded_file()

PHP 中用于将上传的临时文件移动到指定目录的函数。如果目标目录（如 upload/）不存在，该函数会返回 false，导致上传失败。

四、题目思考

1. 这跟前面的题有什么区别？

  • 攻击面不同：SQLi-Labs 是攻击数据库（拼接 SQL 语句），Upload-Labs 是攻击服务器文件系统（上传可执行脚本）。
  • 利用方式不同：SQL 注入往往依赖数据库特性（如报错、盲注），而文件上传漏洞直接利用了 Web 服务器（如 Apache/Nginx）解析脚本的能力。

2. 这种题目的出现原因（为什么存在）

很多开发者为了提升用户体验，会在前端用 JS 对文件扩展名做初步校验。但他们可能错误地认为“普通用户无法绕过前端”，或者为了偷懒而没有在服务端写相应的校验代码。这种“掩耳盗铃”式的安全设计，是文件上传漏洞历史中最常见的成因。

3. 这种应用在实际中如何体现？

在真实的渗透测试中，遇到前端 JS 校验只是最简单的一关。实际环境中往往还会遇到后端白名单、MIME 检测、文件头检测、WAF 拦截等。攻击者会通过构造特殊的文件后缀（如 .phtml、.php5）、修改 MIME 类型、拼接文件名、利用解析漏洞等方式，与防御者进行持续的博弈。

4. 如何抽象理解概念（大白话）

把靶场比作一个“门口的安检员”：

  • Pass-01 的安检员非常死板，只看文件后缀。他站在门口（前端），看一眼你的箱子（文件）上写着 .php，直接拦住。
  • 但他只是个临时工，你可以直接在他眼皮底下用魔法（Console 覆盖 JS）控制他的大脑，让他对所有箱子都放行。
  • 就算你成功骗过了安检员，如果你的保险柜（upload 目录）根本没搬进机房（没有建文件夹），你的危险品（木马）也依然没法被带进去执行。

做一道题，就要往自己脑子里装点东西。
