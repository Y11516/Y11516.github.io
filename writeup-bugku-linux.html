linux - Bugku MISC Writeup

2026年9月11日 Bugku CTF MISC Linux基础

这是一道非常经典的 Linux 基础入门题。它完美模拟了安全工程师在日常工作中的真实场景：面对一个打不开的文件，必须放弃图形界面（鼠标双击），用命令行工具去“解剖”它的真实身份。这篇 Writeup 极其详细地记录了我的操作步骤和背后的原理，方便日后复习。

一、题目信息

  • 题目名称：linux
  • 题目平台：Bugku CTF
  • 题目类型：MISC / Linux基础命令 / 信息收集
  • 题目提示：key{}
  • 题目描述：linux基础问题
  • 附件内容：1.tar.gz (一个包含 test 文件夹的压缩包)
  • 使用环境：Mac 终端 (与 Linux 命令高度兼容) / 命令行工具 (tar, file, strings, grep)

二、解题过程（超详细逐行解析）

1. 遭遇图形界面报错：打不开的文件

下载附件 1.tar.gz，用 Mac 自带工具解压后，得到一个 test 文件夹。里面有个名叫 flag 的文件。

我尝试像往常一样双击这个 flag 文件，试图用“文本编辑”打开它，结果系统弹出了**“未能打开文稿 ‘flag’。文本编码 Unicode (UTF-8) 不适用。”** 的报错提示。

思考：这说明它不是普通的 UTF-8 纯文本文件，它的真实身份被隐藏了。此时，必须放弃鼠标，打开 Mac 的“终端”（Terminal），这是安全工程师的武器。

2. 重回起跑线：使用 cd 和 ls 确认目标

打开终端，输入以下命令，确保我们在正确的目录下：

cd ~/Desktop

命令详解：

  • cd (Change Directory)：切换目录命令。
  • ~：这是一个特殊符号，代表当前用户的“主目录”。
  • /Desktop：代表桌面。
  • 整体意思：无论当前在哪个角落，切换到 Mac 的桌面上。

接着，输入 ls 列出桌面上的文件，确认 1.tar.gz 就在眼前。

3. 拆开“快递”：使用 tar 解压文件

使用 Linux 命令解压文件：

tar -zxvf 1.tar.gz

命令详解（参数拆解）：

  • tar：Linux 下用于打包和解包的工具。
  • -z：调用 gzip 算法，用来处理 .gz 后缀的压缩包。
  • -x：eXtract，提取（解压）的意思。
  • -v：Verbose，啰嗦模式，会在解压时打印出正在解压的文件名（比如屏幕上的 x test/），方便我们确认进度。
  • -f：File，指定要操作的文件名。

输入 cd test 进入解压出来的文件夹。现在，我们要直面那个打不开的 flag 文件了。

4. 看破伪装：使用 file 命令查真实身份

既然双击报错，我们就不猜了，直接问系统它是什么：

file flag

终端立刻返回了关键信息：flag: Linux rev 1.0 ext3 filesystem data, UUID=66ce56f1-5b57-492f-82f3-ac067879...

知识点爆炸：原来这个文件根本不是文本，而是一个 Linux ext3 文件系统（磁盘镜像）！这就好比你下载了一个 Linux 的“微型硬盘”，Mac 的文本编辑器当然打不开它，因为它需要被挂载。

5. 沙里淘金：使用 strings | grep 提取明文

既然它是一个数据镜像，里面可能包含海量的乱码和二进制数据。我们不需要挂载它，直接用管道命令过滤：

strings flag | grep "key"

命令详解：

  • strings flag：扫描 flag 文件，将其中**所有连续可打印的字符**（比如英文字母、数字）提取出来，丢弃不可读的乱码。
  • |（管道符）：Linux 的灵魂符号。把左边 strings 输出的庞大数据流，像流水线一样传递给右边的命令进行二次加工。
  • grep "key"：在收到的数据流中，仅过滤出包含 key 这个单词的行。

回车瞬间，终端直接打印出了完整的结果！

三、知识点总结（核心复习素材）

  • 1. Linux 基础命令心法：
    • cd：切换目录（回家、进文件夹）。
    • ls：列出当前目录下的文件。
    • tar -zxvf：解压 .tar.gz 压缩包（拆快递）。
    • file：不看后缀名，直接读取文件头部的“魔术数字”，查看文件真实类型（测谎仪）。
    • strings：提取二进制文件中的可打印文本。
    • grep：过滤文本，搜索关键字。
  • 2. 管道符 | 的威力：它的核心思想是“流水线协作”。让 `strings` 负责提取，让 `grep` 负责过滤，组合起来就能秒杀包含海量数据的二进制文件。这比手动在几十万行乱码里找字要高效一万倍。
  • 3. 文件格式伪装与图形界面局限：Mac/Windows 的图形界面只对普通用户友好。当文件被伪装成 ext3 镜像或非 UTF-8 编码时，图形界面会崩溃。安全工程师必须具备命令行排查能力，不要相信后缀名，要相信 file 命令。
  • 4. 什么是 Linux 基础问题？这道题名字叫 Linux 基础，考的并不是要你安装 Linux 系统，而是考你能否熟练运用 Linux 的命令行工具思维来解决文件层面的问题。
