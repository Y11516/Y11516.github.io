DVWA-Low-命令注入 (Command Injection)

2026年10月2日 DVWA Web安全 命令注入 RCE

一、题目信息

  • 题目名称：DVWA Command Injection (Low)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 远程代码执行 (RCE) / 命令注入
  • 靶场链接：http://192.168.242.80/vulnerabilities/exec/
  • 涉及工具：Google Chrome 浏览器

二、解题步骤

1. 分析题目考什么

本题的核心考点是命令注入（Command Injection）。当 Web 应用需要调用底层系统命令时（例如测试网络连通性），如果直接拼接用户输入的参数，攻击者就可以利用系统支持的拼接符号，在服务器上执行原本不属于该功能的系统命令，从而获取敏感信息或控制服务器。

2. 怎么想（破题思路）

  • 输入 127.0.0.1 验证功能正常，确认后端调用了系统 ping 命令。
  • 尝试拼接系统命令分隔符（如 ;、|、&）。
  • 执行 whoami、ls -la、cat /etc/passwd 等命令，验证是否成功获得远程命令执行权限。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录一：IP 写错导致无法验证功能

踩坑情况：在输入框里输入了 127.0.01（少打了一个点），页面报错或长时间无响应。

原因分析：IPv4 地址由四组数字组成，127.0.0.1 是标准格式。127.0.01 虽然在一些系统中能被容错解析，但在严谨的编程环境中会解析失败，导致 ping 命令卡住。

改进方式：严格输入 127.0.0.1。这是本地回环地址，永远指向本机，能快速验证 ping 功能是否正常。

详细实操步骤（Payload逐字解释）

第一步：验证功能正常

输入：127.0.0.1

响应结果：页面输出 4 个数据包的传输统计（如 64 bytes from 127.0.0.1...），耗时约 1-2 毫秒。说明后端执行了 ping -c 4 127.0.0.1。

第二步：尝试命令拼接（核心）

输入：127.0.0.1; whoami

逐个字符解释：

  • 127.0.0.1：先让服务器执行 ping 命令。
  • ;（分号）：Linux 系统中的命令分隔符。表示“无论前面的命令是否成功，都继续执行后面的命令”。
  • whoami：Linux 系统命令，作用为打印当前执行命令的用户名。

响应结果：Ping 的统计信息下方，多出一行红色的 www-data。说明成功在服务器上执行了额外命令。

第三步：进一步利用（读取文件和目录）

输入：127.0.0.1; ls -la

响应结果：成功列出当前目录下的所有文件，如 index.php、source 等。

输入：127.0.0.1; cat /etc/passwd

响应结果：成功读取 Linux 系统用户配置文件，输出 root:x:0:0:root:/root:/bin/bash、www-data、mysql 等用户信息。此时，攻击者已获得服务器的远程命令执行权限。

4. 怎么迁移（跨领域联想）

  • 系统运维与监控：企业内网常有一套“服务器存活监控平台”，如果监控系统前端未过滤用户输入的 IP，运维人员在输入 8.8.8.8; rm -rf / 时，服务器可能就被清空了。这是一种典型的“运维工具反被利用”的场景。
  • 物联网 (IoT) 设备：很多家用路由器的“网络诊断”功能，就是典型的命令注入重灾区。攻击者可以在 Ping 测试的输入框里拼接命令，直接控制路由器。

三、名词大全与原理深度复盘

1. 命令注入 (Command Injection)

Web 应用程序调用系统命令时，没有对用户输入进行严格过滤。攻击者利用系统支持的命令拼接符号，在服务器上执行恶意命令，属于 OWASP Top 10 中最危险的漏洞之一。

2. RCE (Remote Code Execution)

远程代码执行。指攻击者可以通过网络连接，在目标服务器上执行任意代码或系统命令。命令注入是 RCE 的一种具体表现形式。

3. 命令拼接符大全

  • ;（分号）：顺序执行，前一个命令执行完（无论成功失败）执行后一个。
  • |（管道符）：将前一个命令的输出作为后一个命令的输入，前一个命令的返回值被忽略。
  • &&（逻辑与）：前一个命令成功（返回0）才执行后一个。
  • ||（逻辑或）：前一个命令失败才执行后一个。
  • &（后台执行）：将命令放入后台执行。

4. www-data

Linux 系统中，Apache/Nginx 等 Web 服务默认的运行用户。该用户权限极低，通常只能读写 Web 目录，无法修改系统配置。

5. 回环地址 (Loopback Address)

127.0.0.1，代表本机。它是一个虚拟网卡，无论有无外网，Ping 该地址必定通畅，常用于测试本机网络协议栈是否正常。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 SQL 注入的区别：SQL 注入是攻击数据库层（Select/Insert），而命令注入是攻击操作系统层（执行 Shell 命令）。命令注入的危害通常更大，因为它可以进一步提权、反弹 Shell。
  • 与暴力破解的区别：暴力破解是利用逻辑漏洞（缺乏频率限制），而命令注入是利用代码执行漏洞（缺乏输入过滤）。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者为了方便，直接调用了系统底层命令，却没有使用安全的参数化调用方式。例如，为了测试网络连通性，开发者写下了 shell_exec('ping -c 4 ' . $ip);，把用户输入直接拼接到了命令中。

从历史角度看，这类似于 2014 年爆发的 Shellshock（破壳漏洞）。利用 Bash 环境变量执行恶意命令，席卷了全球数以百万计的 Linux 服务器。本质上都是程序在“执行环境”和“数据”之间没有做好隔离。

3. 这种的应用

在真实的护网攻防中，命令注入是“拿到服务器控制权”的关键一步。攻击者通过上传 WebShell 或利用命令注入获得权限后，通常会进一步读取服务器配置、反弹 Shell 到公网、搭建隧道进入内网，从而控制整个内网架构。

4. 如何抽象理解概念（大白话）

把命令注入比作“帮老板买咖啡”：

  • 老板对助理说：“去楼下买一杯咖啡。”
  • 助理原本应该只执行“买咖啡”这个动作。
  • 但由于助理极度听话（不加过滤），老板说：“去楼下买咖啡；顺便把公司保险柜打开。”
  • 助理听完，先买完咖啡，然后真的去把保险柜打开了。
  • 这里的“；”就是拼接符，“买咖啡”是正常业务，“打开保险柜”就是攻击者注入的恶意命令。程序如果没把这个“；”当作数据，而是当作指令，就产生了命令注入漏洞。
