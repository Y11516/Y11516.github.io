二、解题过程（详细步骤与四次踩坑全记录）

1. 第一步：修复 ZIP 伪加密（复用旧代码）

双击解压附件，系统提示需要输入密码。结合题目名和以往经验，我判断这大概率是“ZIP 伪加密”（出题人修改了标志位，让解压软件误以为需要密码，但其实数据并未加密）。

我尝试使用之前写好的 fix_zip.py 脚本进行修复，但遇到了两个小插曲：

  • 踩坑一： 脚本文件丢失了。我不得不用 cat > fix_zip.py << 'EOF' 命令重新创建。
  • 踩坑二： 运行时提示找不到 file (18).zip。因为在终端中“工作目录”不对。我必须先用 cd ~/Downloads 切换到下载文件夹，才能让脚本找到目标文件。

修复成功后，运行 unzip fixed.zip，成功解压出一个 cyberpunk.txt 文件。

2. 第二步：识破伪装文件（验明正身）

解压出来的文件虽然叫 .txt，但我直接用文本编辑器打开发现全是乱码。在终端输入：

file cyberpunk.txt

终端返回：PNG image data, 435 x 460, 8-bit/color RGBA。这证明出题人把一张 PNG 图片伪装成了文本文件。我直接改名：

mv cyberpunk.txt cyberpunk.png

3. 第三步：遭遇 LSB 隐写与工具缺失（核心难点）

图片能正常打开，但看不出任何异常。评论区提示这是“LSB 隐写”，推荐用 zsteg 工具。

我在终端尝试运行 zsteg cyberpunk.png，结果报错：zsh: command not found: zsteg。说明我的 Mac 没有安装这个工具（Mac 自带的 Ruby 环境安装这种工具经常报错，极难搞定）。

解决方案： 放弃安装工具，用 Python 的 Pillow 库自己写脚本提取！

4. 第四步：Python 脚本的多次报错与修复（重点复盘）

踩坑三：终端创建脚本时的字符错误

我试图用 cat > steg.py << 'EOF' ... EOF 在终端里创建提取脚本。结果运行时报错 zsh: command not found: 5cat。仔细检查发现，复制粘贴时把前面的提示符 5 一起复制了进去。这是终端操作中非常低级但常见错误。

踩坑四：正则表达式匹配失败

把脚本修正后，我写了第一版提取代码。它的最后一步是用正则 re.findall(r'flag\{.*?\}', message) 去匹配结果。运行后提示“未找到”。

原因与修复： 这道题提取出来的明文是 flag is Hel1o_Wor1e，它并不包含大括号 {}，所以我的正则表达式判定失败。我们需要**不做死板的过滤，直接打印提取出的原始字符串**。

最终版 Python 脚本（成功提取）

from PIL import Image

# 打开图片
img = Image.open('cyberpunk.png')
width, height = img.size
pixels = img.load()

# 提取 RGB 三个通道的 LSB（最低有效位）
binary_data = ""
for y in range(height):
    for x in range(width):
        r, g, b = pixels[x, y][:3]
        binary_data += str(r & 1)
        binary_data += str(g & 1)
        binary_data += str(b & 1)

# 二进制转字符串
message = ""
for i in range(0, len(binary_data), 8):
    byte = binary_data[i:i+8]
    if len(byte) == 8:
        message += chr(int(byte, 2))

print("=" * 50)
print("【提取结果】前 300 个字符：")
print(message[:300])
print("=" * 50)

运行这个脚本后，终端成功输出了包含 flag is Hel1o_Wor1e 的明文。

5. 第五步：提交 Flag

将提取出的明文转为标准格式 flag{Hel1o_Wor1e}，提交到平台，成功通关。

最终 Flag： flag{Hel1o_Wor1e}

三、超详细名词解释与底层逻辑

1. ZIP 伪加密

出题人修改了压缩包中“通用目的位标记（General Purpose Bit Flag）”，把未加密的标志位（0）改成了已加密（1）。解压软件看到这个标志，就要求输入密码，其实里面的数据根本没加密。我们用 Python 修改标志位就能直接解压。

2. 什么是 LSB（最低有效位）隐写？

图片是由无数像素组成的，每个像素有 R（红）、G（绿）、B（蓝）三个颜色通道，每个通道的值范围是 0~255。LSB 是指数字的“最低有效位”（Least Significant Bit）。例如数字 254 的二进制是 11111110，最后一位是 0。把这一位改成 1，数字变成 255，肉眼看起来颜色完全一样。黑客就是利用这种“肉眼不可见”的特性，把数据的二进制信息隐藏在图片每个像素的 RGB 最低位里。

3. zsteg 是什么？为什么我们不用它？

zsteg 是专门用来检测 PNG/BMP 图片中 LSB 隐写的自动化工具。但它在 Mac 上安装依赖复杂的 Ruby 环境，极易报错。用 Python 的 `Pillow` 库写几行代码提取，反而更稳定高效。

四、这道题到底在考察什么？我在终端干了什么？

  • 考察点：这道题综合考察了 1. ZIP 文件结构理解（修复伪加密）；2. 文件头识别能力（识破伪装文件）；3. 编程与数据处理能力（用 Python 遍历像素提取 LSB）。
  • 我在终端干了什么？终端里我们进行的是数据流处理。先用 Python 修改 ZIP 的字节标志位，解压后再用 Python 读取图片的每个像素，取出最低位，拼接成字符串。这展示了安全工程师如何在没有图形化工具时，直接用代码搞定一切。

五、现实防御思考

这道题提醒开发者：不要在图片中隐藏敏感信息，因为 LSB 隐写极其容易被自动化工具检测出来。同时也提醒我们，遇到加密文件时，不要盲目去爆破密码（非常耗时），而是要先检查文件头/标志位，确认它是不是伪加密。
