DVWA-Medium-JavaScript攻击 (JavaScript Attacks)

2026年10月2日 DVWA Web安全 客户端验证绕过 JavaScript 混淆

一、题目信息

  • 题目名称：DVWA JavaScript Attacks (Medium)
  • 题目平台：DVWA (本地 Docker / 灵境靶场)
  • 题目类型：Web安全 / 客户端验证绕过 / JavaScript 混淆
  • 靶场链接：http://192.168.242.80/vulnerabilities/javascript/
  • 涉及工具：Google Chrome 浏览器 (F12 开发者工具)、Burp Suite

二、解题步骤

1. 分析题目考什么

本题的核心考点是绕过 Medium 级别的前端 JavaScript 混淆逻辑。与 Low 级别不同，Medium 级别对 phrase 进行了混淆（如反转、ROT13 等），然后再计算 MD5 token。如果直接在控制台修改 DOM 后点击提交，前端的 JS 会重新执行，用混淆后的值覆盖我们的 token，导致校验失败。攻击者需要绕过前端计算，直接向服务器发送正确的 phrase 和 token。

2. 怎么想（破题思路）

  • 尝试 Low 级别的方法（改 DOM，提交），发现被前端 JS 覆盖，提交失败。
  • 查看源码或前端 JS，发现存在 do_something 函数，它会对 phrase 进行混淆并计算 token。
  • 由于混淆是在前端进行的，我们完全可以绕过它。方法有两种：一是用 Burp 抓包直接改请求体；二是在控制台修改 DOM 后，直接调用 form.submit() 跳过按钮事件。
  • 正确的参数为：phrase=success，token=md5("success") = d3d9446802a44259755d38e6d163e820。

3. 怎么解（详细步骤与踩坑记录）

踩坑记录：修改 DOM 后点击按钮，Token 被前端覆盖

踩坑情况：在控制台执行 document.getElementById("phrase").value = "success";，然后点击页面上的提交按钮，页面依然报错。

原因分析：按钮绑定了 onclick 事件，会触发前端的 do_something() 函数。该函数读取当前输入框的值，对其进行混淆后重新计算 MD5，并覆盖 token 输入框。由于混淆后的值不是我们想要的，提交必然失败。

改进方式：在控制台修改完 DOM 后，直接执行 document.getElementsByTagName("form")[0].submit();，绕过按钮的 onclick 事件，直接将数据提交给服务器。

详细实操步骤（Payload逐字解释）

方案一：Burp Suite 抓包（最直接）

开启 Burp 拦截，正常点击提交，拦截到请求后修改请求体为：

phrase=success&token=d3d9446802a44259755d38e6d163e820&Submit=Submit

放行请求，页面显示 Well done!。

方案二：F12 控制台绕过前端

按 F12 进入控制台，依次输入：

document.getElementById("phrase").value = "success";
document.getElementById("token").value = "d3d9446802a44259755d38e6d163e820";
document.getElementsByTagName("form")[0].submit();

解释：form.submit() 会直接触发表单提交，不经过按钮的 onclick 事件，从而绕过前端的二次计算。页面随后显示 Well done!。

4. 怎么迁移（跨领域联想）

  • 电商价格篡改：很多电商网站在前端用 JavaScript 计算商品价格，如果攻击者绕过前端，直接向服务器提交修改后的价格参数，可能导致以极低价格购买商品。
  • 游戏作弊：网页游戏的生命值、金币数往往由前端 JS 控制，玩家可以通过 F12 修改这些数值并直接提交，从而绕过前端的逻辑限制。

三、名词大全与原理深度复盘

1. 客户端验证 (Client-side Validation)

在用户的浏览器中执行的验证逻辑。它只能用于提升用户体验，绝不能作为安全边界。因为用户完全掌控浏览器，可以随意修改。

2. 前端混淆 (Client-side Obfuscation)

通过反转字符串、ROT13、编码等方式，让攻击者难以直接看懂前端逻辑。但混淆不等于加密，攻击者可以通过调试 JS 逆向出逻辑。

3. MD5 哈希

一种广泛使用的密码散列函数。在本关中，token 被设为 md5(phrase)。这种弱 Token 生成方式极易被伪造，只要知道 phrase 是 success，就能直接算出 token。

4. 表单提交绕过 (Form Submit Bypass)

通过直接调用 DOM 的 form.submit() 方法，绕过按钮绑定的 onclick 事件，从而阻止前端 JavaScript 对数据的二次处理。

四、题目思考

1. 这跟前面的题有什么区别？

  • 与 Low 级别的区别：Low 级别可以直接修改 DOM 后点击提交。Medium 级别引入了前端混淆，必须绕过前端计算（Burp 抓包或直接 form.submit()）才能成功。
  • 与 XSS 的区别：XSS 是攻击者往页面注入脚本，攻击其他用户。而本关是攻击者修改自己浏览器里的脚本或 DOM，来欺骗服务器。

2. 这种题目的出现原因（为什么存在）

漏洞存在的根本原因在于开发者盲目信任客户端提交的数据。他们误以为前端的混淆和校验能拦住攻击者，却忽略了攻击者可以完全不经过前端页面，直接伪造请求。

3. 这种的应用

在护网中，如果遇到只做了前端校验的登录框或支付接口，攻击者可以直接绕过前端，提交非法数据。这属于“逻辑漏洞”的一种，危害视业务场景而定，严重时可直接造成资金损失。

4. 如何抽象理解概念（大白话）

把客户端验证比作“超市门口的体重秤”：

  • 正常情况：门口放个体重秤，你自己称一下，觉得太胖就不进去买东西了（前端校验）。
  • 恶意情况：你完全可以无视这个秤，直接冲进超市拿东西（伪造请求）。超市保安（服务器）如果不检查，就会让你得逞。
  • 正确的防御是：保安在收银台再称一次（服务端校验）。
